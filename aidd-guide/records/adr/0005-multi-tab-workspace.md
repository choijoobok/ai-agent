# ADR-0005. 멀티탭 워크스페이스 채택

- 상태: 채택
- 일자: 2026-08-22

## 맥락
국내 기업용 백오피스는 여러 화면을 동시에 열어 오가며 작업하는 패턴이 일반적이다.
멀티탭은 라우팅과 상태 관리 구조를 근본적으로 바꾸므로 초기에 결정해야 한다.

## 결정
멀티탭 워크스페이스를 **초기부터 포함**한다.
비활성 탭은 언마운트하지 않고 CSS 로 숨겨 상태를 보존한다.
탭 최대 개수는 **기본 20개**로 제한한다 — 상한 처리는 [24](../../standard/frontend/_study/frontend-stack.md) §4.8 (2026-08-25 개정, 최초 10개).

## 근거
- 나중에 추가하면 라우팅·상태·데이터 페칭 구조를 전면 수정해야 한다.
- 상태를 보존하지 않는 탭(언마운트 방식)은 검색 조건과 스크롤이 날아가 멀티탭의 이점이 없다.

## 대안
| 대안 | 기각 사유 |
|---|---|
| 단일 화면 라우팅 | 요구사항 미충족 |
| 탭 전환 시 언마운트 | 상태 유실로 실질적 이점 없음 |
| 브라우저 탭으로 대체 | 세션·메뉴 컨텍스트 공유가 어색, 메모리 더 사용 |

## 결과
- 숨겨진 탭의 폴링/타이머를 중지시키는 처리가 필요하다.
- 탭 수 제한과 닫힐 때의 캐시 정리가 필요하다.
- 저장하지 않은 폼이 있는 탭 닫기 시 확인 처리가 필요하다.
- 모든 화면 컴포넌트는 **동시에 여러 개가 살아 있을 수 있다**는 전제로 작성해야 한다
  (전역 싱글턴 상태에 화면별 데이터를 두면 안 된다).
