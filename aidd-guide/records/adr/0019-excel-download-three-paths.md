# ADR-0019. 엑셀 다운로드는 세 갈래다 — 둘은 프론트, 하나는 서버

- 상태: 채택
- 일자: 2026-08-26
- 관련: [ADR-0004](./0004-antd-with-ag-grid.md) · [ADR-0018](./0018-grid-edition-agnostic-vocabulary.md) · [10](../../knowledge/features.md) FILE-02·FILE-05 · [24](../../standard/frontend/_study/frontend-stack.md) §6·§7 · [47](../../knowledge/sys/notification.md) §4.2

## 맥락

[ADR-0004](./0004-antd-with-ag-grid.md) 가 *"엑셀은 Apache POI 로 서버 생성"* 으로 정했고 [ADR-0018](./0018-grid-edition-agnostic-vocabulary.md) 이 그것을 판과
무관한 예외로 못박았다. **그 판단이 한 갈래만 보고 있었다.**

실제로 사용자가 원하는 것은 셋이며 성격이 다르다.

| 사용자가 누르는 것 | 데이터 | 컬럼 스펙 |
|---|---|---|
| **현재 페이지** | 그리드에 **이미 있다** | 그리드와 같다 |
| **전체** | 현재 조회조건으로 페이징 없이 다시 조회 | 그리드와 같다 |
| **임의 API** | 그리드와 **다른 API** | 그리드와 **다르다** |

셋째가 필요한 이유는 화면 구조와 엑셀 구조가 일치하지 않기 때문이다. 입출고 주문은
헤더 1건 + 상품 N건이고 화면은 상단 폼과 하단 그리드로 쪼개 보여주지만, **사용자는 헤더와
상품을 합친 엑셀 하나를 원한다.** 그리드 데이터를 모아 붙이는 방식으로는 나오지 않는다.

첫째는 **서버 호출조차 필요 없다.** 그것을 서버 POI 로 만들면 이미 브라우저에 있는 데이터를
다시 조회해서 다시 내려보내는 일이 된다.

## 결정

**앞의 둘은 프론트에서 생성하고, 임의 API 만 서버가 만든다.**

| 경로 | 생성 | 조회 |
|---|---|---|
| 현재 페이지 | **프론트** | 없음 — 그리드 데이터 그대로 |
| 전체 | **프론트** | 조회조건 그대로, 페이징 없이. **상한 있음** |
| 임의 API | **서버 (POI)** | 그 API 가 정의한 대로 |

사용자에게는 **셋이 같은 버튼 묶음**으로 보일 수 있다 — 임의 API 경로도 *"현재 페이지"* ·
*"전체"* 라는 이름을 그대로 쓸 수 있다. 어느 경로인지는 화면이 `<ExcelDownloadButton>` 에
무엇을 넘겼는지로 정해지며 사용자는 알 필요가 없다.

### 왜 프론트 생성이 기본인가

| | |
|---|---|
| 현재 페이지는 **왕복이 0** 이다 | 이미 가진 데이터를 다시 받지 않는다 |
| **마스킹이 자동으로 지켜진다** | 화면에 마스킹된 값이 그대로 엑셀에 간다 — §PII |
| 서버가 엑셀 서식을 몰라도 된다 | 컬럼 순서·표시 여부가 이미 화면의 상태다(UX-06) |
| 대기 시간이 짧다 | 서버 생성은 요청 스레드를 붙잡는다(FILE-05 의 *"스트리밍은 동기 처리 필수"*) |

### 임의 API 경로만 서버인 이유

| | |
|---|---|
| 구조가 표가 아니다 | 헤더 블록 + 상품 표, 병합, 다중 시트 — POI 가 자유롭다 |
| 컬럼 스펙이 화면과 무관하다 | 프론트에 그 스펙을 심으면 화면이 자기 것이 아닌 컬럼을 알게 된다 |
| 데이터가 여러 쿼리에서 온다 | 프론트가 조립하면 왕복이 여러 번이고 부분 실패가 생긴다 |

## 라이브러리 — SheetJS 를 쓰지 않는다

**SheetJS(`xlsx`)는 npm 배포를 중단했다.** 최신 버전은 `cdn.sheetjs.com` 의 tarball URL 로만
설치되고, npm registry 에 남은 마지막 버전(0.18.5)에는 **수정본 없는 고위험 취약점이 있다.**

| 문제 | 이 프로젝트에서 |
|---|---|
| CDN tarball 을 `package.json` 에 박아야 한다 | **폐쇄망 배포에서 빌드가 깨진다.** 사내 npm 미러는 registry 만 미러링한다 |
| npm 최신본에 미수정 취약점 | 기업 보안 검사를 통과하지 못한다 |
| 유료 모델로 이동 | [ADR-0004](./0004-antd-with-ag-grid.md) 의 *"유료 라이선스는 배제한다"* 와 상충한다 |

**`exceljs`(MIT)를 쓴다** — npm registry 정상, 활발히 유지, 셀 서식·스트리밍 지원.
[20](../../standard/stack.md) §2 의 다른 의존성과 같은 방식으로 버전을 고정할 수 있다.

## 전체 다운로드에는 상한이 있다

페이징 없이 조회하므로 **행 수를 제한하지 않으면 브라우저가 죽는다.** 상한은 시스템
설정이다.

```
ui.excel.max-rows   기본 50000
```

| 상한 초과 | 동작 |
|---|---|
| 조회 결과가 상한을 넘음 | **거부하고 안내한다** — *"조회 조건을 좁혀 주세요"* |
| 서버 생성으로 폴백 | **하지 않는다** — 경로가 하나 늘고, 사용자가 왜 어떤 때만 느린지 알 수 없다 |

서버는 상한 + 1 건까지만 조회해 초과 여부를 판정한다 — 전량을 세면 상한이 무의미하다.

**스트리밍은 임의 API 경로에만 남는다**([10](../../knowledge/features.md) FILE-05). 프론트 생성은 전량을
메모리에 올리므로 스트리밍이 성립하지 않고, 그래서 상한이 필요하다.

## 다운로드 이력 — 프론트 생성도 서버에 알린다

[47](../../knowledge/sys/notification.md) §4.2 는 *"다운로드는 API 요청이므로 `SYS_LO_ACCESS` 가 이미 기록한다"* 로 별도
테이블을 두지 않았다. **프론트 생성에서는 그 전제가 깨진다.**

| 경로 | 서버가 아는 것 |
|---|---|
| 현재 페이지 | **아무것도 없다** — 호출이 없다 |
| 전체 | 조회 요청은 남지만 *"엑셀로 내렸다"* 는 사실은 없다 |
| 임의 API | 남는다 |

개인정보가 포함된 목록을 엑셀로 내린 사실은 **유출 조사에서 유일한 단서**가 될 수 있다
(LOG-04 · [27](../../standard/backend/pii-vault.md)). 그래서 **프론트 생성도 다운로드를 기록한다.**

```
POST /api/common/excel/saveLog   { scope, rowCount, columnKeys }
```

> **payload 가 하나 빠지고 하나 늘었다**(2026-08-30 — 구현). 처음에는
> `{ menuCd, rowCount, columnKeys }` 였다.
>
> | | |
> |---|---|
> | **`menuCd` 를 뺀다** | `X-Menu-Code` 헤더가 이미 나르고 그것이 `SYS_LO_ACCESS.MENU_CD` **컬럼**이 된다([21](../../standard/backend/_study/architecture.md) §6.3 · [45](../../knowledge/sys/logs.md) §4.1). body 에도 담으면 **같은 사실이 한 행에 두 벌**이고, 어긋나는 날 어느 쪽이 맞는지 알 수 없다 — 이력 화면이 메뉴로 거를 때 보는 것은 컬럼 쪽이다 |
> | **`scope` 를 더한다** | 위의 둘 중 **어느 것을 눌렀는가**. `rowCount` 만으로는 *100건짜리 화면의 현재 페이지* 와 *마침 100건이던 전량* 이 같아 보이는데, **전량에만 상한을 둔** 이 ADR 자신이 그 둘의 위험이 다르다고 말하고 있다 |
>
> **트리 그리드는 언제나 `ALL` 이다** — 페이지가 없어 둘이 같고, 그래서 버튼도 드롭다운을
> 열지 않는다([53](../../standard/frontend/_study/grid-standard.md) §2.2 · [62](../../../documents/screen/menu/requirements.md) §4.9).

- **부수 효과다.** 응답을 기다리지 않으며 실패해도 다운로드는 진행된다 —
  [42](../../knowledge/sys/menu.md) §8 의 메뉴 선택 카운트와 같은 성격이다
- **부르는 자리는 버튼이 아니라 파일을 만드는 함수다**(2026-08-30 — 구현 · `workbook.ts`).
  버튼마다 부르면 새 버튼이 **잊을 수 있고, 잊어도 아무 증상이 없어** 드러나지 않는다 —
  내려받고 지날 수 없는 자리에 두면 그 실패가 구조적으로 불가능하다
- **컨트롤러는 아무것도 저장하지 않는다.** 사용 이력 인터셉터가 모든 `/api/**` 를 한 행으로
  남기므로 **요청이 도착하는 것 자체가 기록**이다 — 컨트롤러가 하는 일은 *존재하기* ·
  *모양 보기* · *인증 요구하기* 셋뿐이다. 핸들러가 없으면 404 라 **인터셉터도 돌지 않는다**
- 기록 자체는 `SYS_LO_ACCESS` 가 받는다. **전용 테이블을 두지 않는다** — [47](../../knowledge/sys/notification.md) §4.2 의 판단은
  유지되고, 빠져 있던 것은 *"호출이 없는 경로"* 였다
- PII 컬럼이 포함됐는지는 **서버가 판정한다.** 프론트는 마스킹 정책을 모르므로
  `columnKeys` 만 보내고, 그것이 `SYS_PII_DEF` 에 걸리면 `SYS_LO_PII_ACCESS` 로도 남긴다

## PII — 두 경로의 마스킹이 다르다

| 경로 | 마스킹 |
|---|---|
| 프론트 생성 | **자동으로 지켜진다** — 화면에 이미 마스킹된 값을 쓴다([27](../../standard/backend/pii-vault.md) §2 응답 직렬화 계층을 이미 통과했다) |
| 서버 생성 | **직접 적용해야 한다** |

둘째가 놓치기 쉬운 구멍이다. **엑셀 생성은 응답 직렬화가 아니므로** [27](../../standard/backend/pii-vault.md) §2 의 계층을 타지
않는다. POI 로 셀을 채우는 코드가 마스킹을 건너뛰면, **화면에서는 가려진 값이 엑셀에서는
평문으로 나간다.** 서버 생성 경로는 마스킹을 명시적으로 통과시켜야 한다.

## 결과

- [ADR-0004](./0004-antd-with-ag-grid.md)·[ADR-0018](./0018-grid-edition-agnostic-vocabulary.md) 의 *"엑셀은 서버 POI"* 는 **임의 API 경로에 한정**된다
- [20](../../standard/stack.md) §2 에 `exceljs` 가 들어간다 — 프론트 의존성이 하나 늘어난다
- `<ExcelDownloadButton>` 이 세 경로를 하나의 인터페이스로 덮는다([24](../../standard/frontend/_study/frontend-stack.md) §7)

> **셋을 실제로 덮은 것은 2026-09-02 다.** 그전까지 구현은 **프론트 둘에 박혀 있었고**,
> [53](../../standard/frontend/_study/grid-standard.md) §2.2 는 세 번째를 *"①의 화면 고유 버튼으로 둔다"* 로 미뤄 두었다 — 이 ADR 이
> *"셋이 같은 버튼 묶음으로 보일 수 있다"* 고 적은 것과 어긋난 상태였다.
>
> | | |
> |---|---|
> | **`<DataGrid excel>`** | `page`·`all` 은 **이름을 둔 채 경로만** 서버로. `extra[]` 는 구분선 아래 화면 고유 항목이며 권한은 항목마다(`actionCd`, 기본 `EXPORT`) |
> | **`extra` 는 서버 전용이다** | 프론트 갈래를 열면 *고른 행만* 같은 항목이 생기는데 그것을 이력의 `scope` 가 표현하지 못한다(`PAGE`·`ALL` 둘이다). 서버 생성은 **요청 자체가 기록**이라 그 문제가 없다 |
> | **서버 경로는 `excel/log` 를 부르지 않는다** | 그 엔드포인트는 *호출이 없는 경로* 의 구멍을 메우는 것이다. 또 부르면 한 번 내려받은 것이 **두 행**이 되고, 유출 조사에서 건수가 배로 보인다 |
> | **파일 이름은 서버가 정한다** | `Content-Disposition` — 그리드 제목으로 지으면 **내용과 이름이 어긋난다**. `filename*`(RFC 5987)을 먼저 본다: 옛 `filename=` 은 ASCII 로 뭉개진 대체 이름이라 둘 다 있을 때 뒤를 고르면 **한글 이름이 깨진다** |
> | **실패 응답도 Blob 이다** | `responseType: 'blob'` 이면 `error.response.data.message` 가 언제나 `undefined` 다 — 그대로 두면 서버가 보낸 *"조회 조건을 좁혀 주세요"* 가 사라지고 **네트워크 오류**만 뜬다. Blob 을 글자로 되읽어 봉투를 복원한다(`shared/api/download.ts`) |
> | **200 인데 봉투면 저장하지 않는다** | 파일 엔드포인트가 200 과 함께 봉투를 내는 것은 서버 쪽 실수이며, 그것을 `.xlsx` 라 부르며 저장하면 사용자는 **열리지 않는 파일**을 얻는다 |
>
> **`ui.excel.max-rows` 상한 판정이 서버 경로에서는 서버로 넘어간다.** 프론트가 셀 수 있는
> 것은 자기가 받은 행뿐인데 이 갈래는 **행을 받지 않는다**.
>
> ~~서버 쪽 구현은 아직 없다~~ → **섰다**(2026-09-02 — `SMPL_MD_VERT` · [68](../../playbook/INDEX.md) §5.4).
> `poi-ooxml` 이 [20](../../standard/stack.md) §2 에 들어가고, 시트를 쓰는 도구는 support 에 하나다
> (`ExcelSheetWriter` — 21 §1 이 엑셀을 그 모듈에 준 책임이다). **무엇을 쓸지는 도메인이
> 정한다**: support 가 업무 컬럼을 알면 그 순간 기술 어댑터가 아니게 된다.
>
> | | |
> |---|---|
> | **`SXSSF` 다** | 이 갈래에만 스트리밍이 남는다([10](../../knowledge/features.md) FILE-05). 합본은 행이 **곱으로** 늘어난다 — 주문 500건에 품목이 각 20개면 만 행이다 |
> | **`dispose()` 를 부른다** | 창을 넘긴 행이 임시 파일로 가므로, 닫지 않으면 **프로세스가 끝날 때까지** 남는다. 자주 내려받는 화면에서 그것은 디스크가 서서히 차는 고장이 되고 원인이 드러나지 않는다 |
> | **상한이 서버로 넘어왔다** | 프론트는 첫 응답의 총 건수로 판정했지만 이 갈래는 **행을 받지 않는다**. `ui.excel.max-rows` 를 서버가 읽는다 — 값이 갈리면 *화면에서는 되는데 파일은 잘린* 상태가 된다 |
> | **품목이 없는 주문도 한 줄 나온다** | 안 나오면 그 주문이 파일에서 사라지고 사용자는 *왜 412건이 400건이 됐나* 를 묻는다. 품목 칸이 빈 줄이 **품목이 없다**는 답이다 |
>
> **마스킹은 여전히 부르는 쪽의 일이다** — 이 ADR 이 짚은 구멍 그대로다. 샘플에는 PII
> 컬럼이 없어 지금은 걸리지 않지만, `ExcelSheetWriter` 는 **받은 값을 그대로 쓴다**.
>
> **헤더 문구가 한국어 고정이다.** 서버 생성 엑셀의 문구는 요청의 언어로 만들어야 하는데
> 그 배선이 아직 없다 — 이 갈래에 남은 미결이다.
- **프론트 생성 경로에는 `SYS_API` 행이 생기지 않는다**(2026-08-30 보완 · [ADR-0027](./0027-menu-declared-export-action.md)).
  서버 호출이 없으므로 당연한데, **그 결과가 인가에 미치는 영향을 여기서 적지 않았다** —
  액션은 API 에서 나오므로([ADR-0020](./0020-path-prefix-action-and-seed-generation.md)) `EXPORT` 는 **어느 메뉴에도 정의되지 않은
  액션**이 되어 있었다. 그 자리는 `SYS_MENU.EXPORT_YN` 이 메운다
- **AG Grid Enterprise 의 Excel Export 는 여전히 쓰지 않는다.** 판을 바꿔도 이 셋이 그대로다 —
  Enterprise 는 그리드가 가진 것만 내보내므로 임의 API 경로를 대신할 수 없고,
  프론트 생성 경로는 `exceljs` 로 이미 충족된다

## 기각한 대안

| 대안 | 기각 사유 |
|---|---|
| 전부 서버 POI ([ADR-0004](./0004-antd-with-ag-grid.md) 원안) | 현재 페이지 다운로드가 왕복 2회가 된다. 이미 가진 데이터를 다시 받는다 |
| 전부 프론트 생성 | 헤더+상품 합본처럼 화면 구조와 다른 엑셀을 만들 수 없다 |
| SheetJS | npm 배포 중단 · 미수정 취약점 · 폐쇄망 빌드 불가 — 위 |
| AG Grid Enterprise Excel Export | 그리드가 가진 것만 내보낸다. 임의 API 경로를 못 덮고 [ADR-0018](./0018-grid-edition-agnostic-vocabulary.md) 의 판 독립성도 깨진다 |
| 상한 초과 시 서버 생성으로 폴백 | 경로가 하나 늘고 사용자가 왜 어떤 때만 느린지 알 수 없다 |
