# ADR-0007. LLM 엔지니어링 체계로 llm-engine-template 채택

- 상태: 채택
- 일자: 2026-08-23

## 맥락

이 프로젝트는 LLM 코딩 에이전트를 구현 주체로 삼는다. 이를 위해 규칙·문서·훅·스킬을
아우르는 체계가 필요하다. 직접 설계할 수도 있고, 이미 만들어진 골격을 이식할 수도 있다.

## 결정

저장소에 포함된 **`docs/llm-engine-template`(2026-09-03 삭제 — 이식이 끝나 원판을 지웠다) 을 이식**한다.
적용 시점은 **Phase 11** — 프레임워크 표준·CRUD 패턴·공통 컴포넌트·개발 가이드가 모두 확정된 뒤다.

## 근거

### 왜 자체 설계가 아니라 이식인가

이 템플릿은 13개 카테고리(`00-meta` ~ `13-safety`)의 결정 트리와 메타블록 표준,
lint·평가·관측·안전 인프라를 갖춘 상태로 시작한다. 특히:

| 구성 | 가치 |
|---|---|
| `_meta/lint.mjs` | 메타블록·200줄·BOM·**링크 자동 검증** — 수동 규칙의 한계를 보완 |
| `07-evals` · `08-observability` · `13-safety` | 평가·관측·안전이 처음부터 포함 |
| `stub` 상태 + `type` 필드 | **미완성 문서를 lint 통과시키면서 점진적으로 채울 수 있다** — 백지에서 시작하는 이 프로젝트에 맞다 |
| `_meta/starter-prompt.md` | 이식 후 채우기를 AI 가 주도 |

체계를 처음부터 설계하면 위 요소를 하나씩 다시 발명해야 한다.

### 왜 Phase 11 인가

**코드가 없으면 쓸 수 없는 카테고리가 전체의 대부분이다.**

템플릿 자체가 `06-framework/*` · `09-knowledge/*` · `11-playbook/*` 을
**"전부 stub — 100% 새로 작성"** 으로 분류한다. 프레임워크 가이드·도메인 지식·개발 레시피는
전부 실제 구현에서 나온다. 메타블록의 추적 대상에 **실제 클래스·메서드 시그니처**를 적으려면
그 코드가 먼저 있어야 한다.

코드 없이 먼저 채우면 전부 추측이 된다.

## 대안

| 대안 | 기각 사유 |
|---|---|
| 자체 설계 | 라우팅·메타블록·lint·평가·안전을 처음부터 발명해야 한다 |
| 이론 골격만 참조 | 실행 가능한 형태가 아니다 |
| 규칙을 `AGENTS.md` 한 파일로 | 규모가 커지면 컨텍스트를 잡아먹고 정작 필요한 규칙이 묻힌다 |
| **Phase 2 에 즉시 도입** | 위 사유로 대부분의 카테고리를 채울 수 없다 |

## 결과

- Phase 7~10 산출물이 Phase 11 의 **입력**이 된다.
  특히 CRUD 기본 패턴(Phase 8)이 `03-prompt/overlays` 와 `11-playbook` 의 근거다.
- 상당한 투자다 — 문서 138개, 13개 카테고리. 상세: LLM 엔지니어링 계획
- **이식 첫날부터 `_meta/lint.mjs` 를 CI 에 배선한다.** 나중에 붙이면 이미 어긋난 뒤다.
- 훅 구현은 Node.js 전제 — Windows 개발 환경 호환성을 이식 시 검증해야 한다.

## 조기 도입 예외 (확정)

**요건 정의서 생명주기**(사전 작성 → 구현 → 사후 재확인 → 현행화)는 LLM 엔지니어링 체계와
무관하게 유효한 개발 규율이므로 **먼저 도입한다.**

- 도입 시점: **좌측 메뉴 트리에 대응하는 화면 개발 최초 착수 시**
- 프레임워크 골격 작업에는 적용하지 않는다 (메뉴 화면이 아님)
- Phase 11 에서 요건서를 소급 작성하는 비용을 회피한다
