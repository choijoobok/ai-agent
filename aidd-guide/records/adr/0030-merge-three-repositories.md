# ADR-0030. 세 저장소를 **폴더 넷**으로 합친다 — 나누는 축은 *누가 읽나* 다

- 상태: 채택
- 일자: 2026-09-04
- 관련: [CLAUDE.md](../../../CLAUDE.md) §1 · §4 · [INDEX.md](../../INDEX.md) · [artifact/INDEX.md](../../artifact/INDEX.md) · [ADR-0031](0031-single-hook-runtime.md)

## 맥락

세 저장소가 각자 자란 뒤 합쳐야 할 시점이 왔다.

| 저장소 | 강점 | 약점 |
|---|---|---|
| **ordinary-backoffice** | `llm-guide/` 157파일 26,492줄 — *AI 가 코딩할 때의 규칙*. 기계가 막는 게이트 열넷 | 요구사항 수집·결정·설계 프로세스가 없다. 문서가 중구난방으로 늘었다 |
| **ai-driven-development** | P0~P6 단계 · G0~G6 게이트 · 산출물 지도 32 · 추적성 T1~T12 — *프로젝트 관리* | 개발 표준·패턴이 비어 있다. 폴더 체계가 정리되지 않았다 |
| **agentic-ai** | DESIGN-00~06 3,479줄 — 실제로 만들 시스템의 설계 | 자체 ID 체계가 위 둘과 충돌한다 |

**단순히 세 폴더를 나란히 두면 안 되는 이유가 셋이었다.**

1. **ID 가 부딪힌다.** aidd 의 `G0~G6` 은 게이트이고 agentic-ai 의 `G0~G4` 는 최종 목표다.
   aidd 의 `P0~P6` 은 단계이고 agentic-ai 의 `P-1~` 은 설계 원칙이다. ADR 도 두 계열이었다.
2. **같은 사실이 두 곳에 정의된다.** 두 저장소가 각자 `CLAUDE.md` · 훅 · 문서 규약을 가졌고,
   나란히 두면 매 세션 **어느 규칙이 이기는지**를 AI 가 추측한다.
3. **문서 폭증이 세 저장소의 공통 병이었다.** 특히 *정리한 내역을 적는 문서*, *그 근거를 적는
   문서* 가 늘어나 어느 것이 참인지 알 수 없게 되는 실패가 셋 모두에서 관찰됐다.

## 결정

### 폴더 넷 — 축은 *누가 읽나* 다

```
aidd-guide/   AI 가 읽는 규칙   — 프로세스 + 개발 표준
documents/    AI 가 만드는 산출물 — spec(SSOT) · 결정 · 화면 문서 셋 · 생성 문서
user-guide/   사람이 읽는 안내   — 수행 · 환경 · 개발 · 배포 · 운영
sources/      코드              — 빌드 루트
```

**주제로 나누지 않았다.** "테스트" 는 규칙(`aidd-guide/quality/`)과 절차(`user-guide/`)와
산출물(`documents/spec/70-testcases.yaml`)과 코드(`sources/.../test/`) 넷에 걸치는데, 주제로
나누면 그 넷이 한 폴더에 섞이고 **읽는 사람이 자기 것을 못 찾는다**. 독자로 나누면 각 폴더가
한 종류의 독자에게만 답하므로, 새 문서를 어디 둘지가 *물어보지 않아도* 정해진다.

### ID 는 프로젝트의 것과 가이드의 것을 분리한다

| 체계 | 소유 | 예 |
|---|---|---|
| `REQ-` `UC-` `FEAT-` `ENT-` `API-` `SCR-` `TC-` `ADR-` `ASM-` `CR-` | **프로젝트** — `documents/` | [process/traceability.md](../../process/traceability.md) 가 정의 |
| `LLM-{CAT3}-{NNN}` | **가이드** — `aidd-guide/` | [INDEX.md](../../INDEX.md) 가 정의 |

- **agentic-ai 의 충돌하는 접두는 재채번했다** — 최종 목표 `G0~G4` → `GOAL-0~4`,
  비목표 `N1~` → `NGOAL-01~`, 설계 원칙 `P-1~` → `PRN-01~`. 게이트·단계의 `G`·`P` 를 남겼다:
  그쪽이 매 세션 쓰이는 어휘이고, **자주 쓰는 쪽을 옮기면 옮긴 흔적이 매번 비용이 된다.**
- **`llm-guide` 의 `LLM-` 접두는 그대로 두었다.** 폴더가 번호를 잃고 이름을 얻었어도
  (`06-framework` → `standard`) ID 는 불변 앵커이며, 소스 주석과 다른 문서가 그 번호를 부른다.
- **agentic-ai 의 `DESIGN-NN` 은 해체했다.** 문서 단위 ID 는 그 문서가 쪼개지면 뜻을 잃는다 —
  내용은 `documents/spec/` 의 항목 ID 와 `documents/decisions/` 의 ADR 로 흩어졌다.

### 문서 예산 — 산출물 지도가 유일한 통로다

`documents/` 에 만들 수 있는 자리를 [artifact/INDEX.md](../../artifact/INDEX.md) 의 지도 **39행**이
정하고, `guard-write` 훅이 **그 파일을 읽어** 지도 밖의 새 문서를 차단한다.

**허용 목록을 훅에 적지 않은 것이 이 결정의 핵심이다.** 훅과 지도에 목록이 각각 있으면 갈리고,
갈렸을 때 실제로 이기는 것은 훅이므로 **지도가 거짓말이 된다.** 지도를 읽게 만들면 지도를 고치는
것이 곧 규칙을 고치는 것이 된다.

## 버린 안

| 안 | 왜 버렸나 |
|---|---|
| **세 저장소를 그대로 나란히 두고 루트에 `CLAUDE.md` 하나만 얹는다** | 규칙이 네 곳(`CLAUDE.md` + 저장소 셋)에 남는다. 매 세션 AI 가 우선순위를 추측하며, 추측은 세션마다 다르다 — 프로젝트의 목표인 *일관된 판단* 과 정면으로 어긋난다 |
| **주제별 폴더**(`process/` · `design/` · `code/` · `docs/`) | 한 주제가 여러 독자에 걸친다(위 "테스트" 예). 새 문서를 어디 둘지 매번 판단해야 하고, 판단이 갈리면 같은 것이 두 곳에 생긴다 |
| **`aidd-guide/` 를 번호 체계로 유지**(`00-meta` … `13-safety`) | 번호가 열셋인데 `01` 이 비어 있었고, 06 과 07 사이에 카테고리를 넣을 수 없었다. 프로세스 카테고리 넷이 들어오면서 재채번이 불가피했고, **한 번 겪은 재채번을 다시 겪지 않기 위해** 이름으로 바꿨다. 순서는 ID 와 INDEX 의 결정 트리가 갖는다 |
| **git subtree 로 세 이력을 보존** | 첫 이력이 세 계열로 섞여 `git log` 가 읽히지 않고, 어느 커밋이 어느 저장소의 규칙 아래 있었는지 구분되지 않는다. 옛 저장소를 아카이브로 남겨 이력을 보존한다 |
| **agentic-ai 설계 문서를 원본 그대로 이관** | 편할 뿐이고, `DESIGN-00` 과 `documents/spec/` 이 같은 사실을 두 형식으로 갖게 된다. 승인받지 않은 문서가 *승인된 요건* 으로 읽히는 위험이 더 크다 — 재편성하고 `status: migrated` 로 표시했다 |

## 결과

- **얻은 것**: 규칙의 단일 정의처. 요청 종류 → 폴더가 결정 트리로 계산된다.
  `documents/` 의 문서 수가 기계로 제한된다.
- **잃은 것**: 세 저장소의 커밋 이력이 이 저장소에서 끊긴다. 옛 저장소를 **지우지 않는다** —
  이력이 필요하면 그쪽을 본다.
- **비용**: 이관 시 `llm-guide/` 157파일의 상대 링크를 전부 다시 계산했고, 2,718개 링크 중
  깨진 것 0 을 `lint.mjs` 로 확인했다. **경로를 손으로 고치지 않았다** — 매핑표를 통과시켰다.
- **감시**: `node aidd-guide/meta/_meta/lint.mjs` 가 깨진 링크와 메타블록을 계속 센다.
  `documents/` 의 자리 밖 문서는 `guard-write` 가 막는다.
