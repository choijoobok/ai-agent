# ADR-0025. 참조 코드는 **그룹이 정의**하고, 상세 코드 그리드에 **동적 컬럼**으로 나온다

- 상태: 채택
- 일자: 2026-08-28
- 관련: [10-feature-inventory](../../knowledge/features.md) MASTER-10 · UX-06 · UX-13 · [43-data-model-master](../../knowledge/sys/code.md) §5 · [53-grid-standard](../../standard/frontend/_study/grid-standard.md) §5 · [54-grid-column-contract](../../standard/frontend/_study/grid-column-contract.md) §2.2 · [63-screen-master](../../../documents/screen/code/requirements.md) §2

## 맥락

`SYS_CODE_REF`([10](../../knowledge/features.md) MASTER-10)는 **상세 코드의 속성값을 별도 테이블로 뺀 것**이다.
컬럼으로 `속성값1 … 속성값10` 을 두는 흔한 방식 대신 행으로 뺐고, 그래서 **속성 하나를
추가하려면 그 그룹의 모든 상세 코드에 값을 넣어야 한다** — 본질이 **매트릭스**다.

[63](../../../documents/screen/code/requirements.md) §2.4 는 그것을 **모달 그리드**에 담았다. 코드 행의 *참조 건수* 를 누르면
그 코드의 `(REF_CD, REF_VAL)` 목록이 열린다. **한 코드씩만 보인다.**

**세 가지가 걸렸다.**

| 걸린 것 | 왜 |
|---|---|
| **매트릭스를 한눈에 볼 수 없다** | 코드가 20개면 모달을 20번 연다. *"어느 코드가 아직 안 채워졌나"* 에 답할 수 없다 |
| **그룹이 쓰는 참조 코드 목록이 어디에도 없다** | PK 가 `(GRP_CD, DTL_CD, REF_CD)` 뿐이라 목록은 `SELECT DISTINCT REF_CD` — **행에서의 파생**이다 |
| **삭제 게이트가 잠금이 된다** | 참조를 매트릭스로 보면 모든 상세 코드가 참조 1건 이상이라 [63](../../../documents/screen/code/requirements.md) §2.5 의 게이트가 **아무것도 못 지우게** 만든다 |

둘째가 나머지를 부른다. 목록이 행에서 파생이면 **상세 코드가 0건인 그룹은 참조 코드를
정의할 수 없고**, 마지막 상세 코드를 지우면 **정의가 조용히 사라진다.**

## 결정

**넷을 함께 정한다.**

### 1. 정의 테이블을 신설한다 — `SYS_CODE_GRP_REF`

*"이 그룹이 어떤 참조 코드를 쓰는가"* 는 **그룹의 사실**이지 어느 상세 코드의 사실이 아니다.

```
SYS_CODE_GRP_REF(GRP_CD, REF_CD, REF_NM, REF_DESC, 감사)   ← 정의. 속성이 무엇인가
SYS_CODE_REF(GRP_CD, DTL_CD, REF_CD, REF_VAL, 감사)        ← 값. 매트릭스의 셀
```

**`SYS_CODE_REF` 가 정의 테이블을 FK 로 참조한다**(`GRP_CD`, `REF_CD`) — 그러면
**정의 없는 참조값이 구조적으로 생길 수 없다.** 컬럼 목록은 더 이상 파생이 아니다.

| 그래서 되는 것 | |
|---|---|
| 상세 코드 **0건인 그룹**도 속성을 미리 정의한다 | 값은 나중에 붙는다 |
| **빈 칸이 조인에서 나온다** | 반쪽 행(`REF_VAL` 이 빈 행)을 넣지 않는다 — [63](../../../documents/screen/code/requirements.md) §4.2 의 `yml ⟕ DB` 와 같은 모양이다 |
| **다중 부모 플래그의 목록이 명시된다** | `IS_A` · `IS_B` 가 정의로 남는다. 이전에는 *"행이 있는 것들"* 이었다 |

### 2. 상세 코드 그리드에 **동적 컬럼**으로 낸다

마스터(그룹)를 고르면 하단은 **코드 조회 + 정의 조회** 둘을 받고, 정의 하나가 **컬럼
하나**가 된다. **헤더는 `REF_NM`** 이다.

```
그룹 선택 → ① 그 그룹의 참조 코드 정의 N개
          → ② 상세 코드 행 M개 (+ refs 맵)
          → 컬럼 = 고정 컬럼 + N,  셀 = refs[REF_CD]
```

**서버가 피벗해서 준다.** AG Grid 의 pivot 기능은 Enterprise 이지만 **쓰지 않는다** —
우리가 하는 것은 **컬럼 정의를 갈아 끼우는 것**이고 그것은 Community 다([ADR-0004](./0004-antd-with-ag-grid.md)).

| 얻는 것 | |
|---|---|
| **매트릭스가 한눈에 보인다** | 빈 셀이 곧 *"안 채웠다"* 다 — 별도 배지도 정렬 규칙도 필요 없다 |
| **참조 건수 컬럼이 없어진다** | 값이 컬럼으로 보이므로 건수를 세어 보여줄 이유가 없다 |
| 엑셀이 매트릭스 그대로 | ②는 *지금 보이는 컬럼* 을 낸다([53](../../standard/frontend/_study/grid-standard.md) §2.2) — 동적 컬럼도 함께 나간다 |

- **`colId` 를 직접 준다** — `ref.{REF_CD}`. 주지 않으면 `field` 로 유추되어 교체마다
  컬럼 상태(너비·순서·고정)가 끊긴다
- **값은 `valueGetter`/`valueSetter` 로 읽고 쓴다** — 점 표기(`refs.PARENT`)도 되지만
  `REF_CD` 에 `.` 이 들어오면 **조용히 깨진다**
- **화면이 그리드 API 를 직접 부르지 않는다** — `<DataGrid columns={…}>` 에 배열을 준다.
  [ADR-0018](./0018-grid-edition-agnostic-vocabulary.md) 의 어댑터 경계가 그대로 유지된다

### 3. **동적 컬럼은 UX-13 시그니처에 들어가지 않는다**

[53](../../standard/frontend/_study/grid-standard.md) §5 가 *"화면의 컬럼 목록이 바뀌면 저장된 설정은 폐기한다"* 로 정했고 시그니처를
`전체 − 시스템 − hidden` 으로 계산한다. **참조 컬럼은 그룹마다 다르므로 그대로 두면
마스터 행을 클릭할 때마다 하단 그리드의 개인화가 폐기된다** — 안전장치가 연발되는
오작동이 된다.

```
시그니처 = 전체 컬럼 − 시스템 컬럼 − hidden − 동적 컬럼
```

**53 §5 가 이미 그 방향을 적어 뒀다** — *"저장된 설정에 들어 있지 않은 컬럼이 늘거나
줄었다고 사용자의 표시·순서·고정을 버릴 이유가 없다."*

설정 창 목록에서 빠지는 컬럼이 **셋째 부류**가 된다.

| 목록에 없는 컬럼 | 왜 |
|---|---|
| 상태 · 삭제 | **보이지만 끌 수 없다** |
| `hidden` | **처음부터 없다** |
| **동적** | **화면이 아니라 데이터가 정한다** — 저장해 둘 대상이 아니다 |

### 4. `SYS_CODE_REF.USE_YN` 을 없앤다

**이전 판의 [43](../../knowledge/sys/code.md) §5.1** 이 *"참조를 지우지 않고 끈다"* 로 뒀지만 **컬럼 UI 에는 그것을 표현할
자리가 없다.** 셀 하나는 값 하나이고, 스위치를 따로 두면 **컬럼 수가 두 배**가 된다.

**끄는 것은 값을 비우는 것으로 갈음한다** — 새 번호는 [43](../../knowledge/sys/code.md) §5.4 다. `REF_VAL` 은 `NOT NULL` 이고 **행이 있으면
값이 있다** — 셀을 비우고 저장하면 그 행을 **삭제**한다.

> **이 화면에 같은 규칙이 이미 있다.** [63](../../../documents/screen/code/requirements.md) §2.3 이 코드명에 대해 *"비우면 지운다"* 로
> 정했다 — 빈 문자열을 넣으면 폴백이 죽기 때문이었다. 참조값도 같다: 빈 값을 남기면
> *"없음"* 의 표현이 둘이 되고, **그 절이 스스로** *"읽는 쪽이 매번 두 컬럼을 함께
> 판정하면 그 판정이 빠진 곳이 생긴다"* 고 막았다.

**대가는 끈 값을 기억하지 못하는 것**이다. 감사 4컬럼도 행과 함께 사라진다. 되돌리려면
값을 다시 입력한다 — 참조값은 코드값 하나이므로 **다시 넣는 비용이 낮다.**

## 기각한 대안

| 기각 | 이유 |
|---|---|
| **모달 그리드를 유지한다**([63](../../../documents/screen/code/requirements.md) §2.4 원안) | 매트릭스를 한 코드씩만 보여준다. *"어느 코드가 비었나"* 에 답하려면 모달을 코드 수만큼 연다 |
| **정의 테이블 없이 컬럼을 행에서 파생** | 상세 코드 0건인 그룹이 속성을 못 갖고, 마지막 코드를 지우면 정의가 조용히 사라진다. 컬럼 목록이 **데이터의 우연**에 달린다 |
| **빈 `REF_VAL` 행을 미리 INSERT** | *"없음"* 의 표현이 둘이 된다(§4 와 같은 이유). 아우터 조인이 빈 칸을 만들면 반쪽 행이 필요 없다 |
| **`속성값1 … 속성값10` 컬럼** | MASTER-10 이 이미 기각했다. 상한이 생기고, 어느 칸이 무슨 속성인지가 **화면 밖 약속**이 된다 |
| **헤더를 `CODE_REF_KEY` 의 코드명으로** | 헤더가 메시지 키로 남아 [54](../../standard/frontend/_study/grid-column-contract.md) 계약 예외가 없어지지만, **같은 `REF_CD` 를 그룹마다 다르게 부를 수 없다** — `PARENT` 가 A 에서는 *상위 창고*, B 에서는 *상위 조직* 이다. 그룹별 이름이 이 컬럼의 존재 이유다 |
| **`REF_NM` 이 없으면 코드명으로 폴백** | 명칭의 원천이 둘이 된다. *"왜 어떤 그룹만 전역 이름이 나오나"* 를 설명할 수 없다 — `REF_NM` 을 **필수**로 둔다 |
| **동적 컬럼을 시그니처에 포함(현행 유지)** | 마스터 클릭마다 개인화가 폐기된다. 사용자가 겪는 것은 *"설정이 저장이 안 된다"* 이고 원인을 짐작할 수 없다 |
| **`USE_YN` 을 남기고 컬럼을 값·스위치 둘로** | 정의 10개면 컬럼 20개다. 매트릭스를 한눈에 보려는 목적을 스스로 깬다 |

## 결과

- **`REF_NM` 이 [54](../../standard/frontend/_study/grid-column-contract.md) 의 *"`header` 는 메시지 키"* 계약의 예외가 된다.** 근거는 [43](../../knowledge/sys/code.md) §3 의
  *관리 화면 전용 명칭은 다국어가 아니다* 이며, `GRP_NM` 이 셀 값으로 다국어가 아닌 것과
  **같은 자리**다. 이 헤더는 `CODE_MGMT` 안에서만 보인다
- **[63](../../../documents/screen/code/requirements.md) §2.5 에서 게이트가 하나로 줄고 *확인* 이 둘 생긴다.** 코드 삭제에는 게이트를
  두지 않는다 — 정의를 쓰는 그룹의 코드는 **전부 참조 1건 이상**이므로 게이트를 두면
  **아무것도 지울 수 없다.** 셀은 남의 데이터가 아니라 **그 행의 일부**다
- **그래서 [53](../../standard/frontend/_study/grid-standard.md) §6.2 의 *건수 컬럼 경로* 는 이 화면에서 실물을 얻지 않는다.** 그 경로의
  실물은 **역할 화면**([62](../../../documents/screen/menu/requirements.md) §3.5)이며, 53 §6.2 가 *"한 화면에서 두 경로가 나란히"* 로
  적어 둔 문장은 **게이트와 확인을 가르는 기준**으로 바뀐다 — *DB 가 거부하는가* 다
- **지난 설계의 정렬 문제가 사라진다** — *"값 없는 것 우선"* 정렬도, 그 tie-breaker 도
  필요 없다. **빈 셀이 그 일을 한다**
- **[63](../../../documents/screen/code/requirements.md) §2.3 이 언어 컬럼에 대해 남긴 경고는 유효하다** — 그쪽은 **긴 텍스트**라 셀이
  좁아 못 쓰고([63](../../../documents/screen/code/requirements.md) §3.5) **행으로 둘 자연스러운 자리가 있었다.** 참조값은
  `VARCHAR(200)` 짧은 값이고 행으로 두면 매트릭스가 안 보인다. **경고를 무시한 것이
  아니라 갈리는 지점이 있는 것**이며 [54](../../standard/frontend/_study/grid-column-contract.md) §2.2 가 그 판별을 적는다
- **`REF_CD` 는 여전히 `CODE_REF_KEY` 화이트리스트다**([43](../../knowledge/sys/code.md) §4.3) — **소스가 그 값을
  문자열로 참조하기** 때문이며 정의 테이블이 그것을 대신하지 않는다. 정의 모달의
  `REF_CD` 는 `<CodeSelect codeGrp="CODE_REF_KEY">` 다
- **다중 부모 플래그를 늘릴 때 정의를 먼저 추가해야 한다** — 이전에는 행만 넣으면 됐다.
  대가이며, 얻는 것은 **쓰이는 플래그의 목록이 명시되는 것**이다
- **AG Grid 옵션의 실물 확인이 미결**이다 — 컬럼 교체 시 순서 보존 옵션(`maintainColumnOrder`
  계열)의 36.1 실제 이름과 동작. **폴백: `applyColumnState` 로 직접 복원한다**
- **정의 개수의 실질 상한이 미결**이다 — 컬럼이 옆으로 자란다. `DTL_CD` · 코드명의
  **좌측 고정이 사실상 필수**가 된다([53](../../standard/frontend/_study/grid-standard.md) §4)
