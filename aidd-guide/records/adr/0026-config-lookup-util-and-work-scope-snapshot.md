# ADR-0026. 시스템 설정은 **프로퍼티 소스가 아니라 조회 유틸**이 읽는다 — 작업 스코프 스냅샷

- 상태: 채택 — **구현됨(2026-08-30, 경계 하나)**
- 일자: 2026-08-28
- 관련: [10-feature-inventory](../../knowledge/features.md) MASTER-08 · [30-async-and-concurrency](../../standard/backend/crosscutting.md) §3 · §8 · [43-data-model-master](../../knowledge/sys/code.md) §6 · [63-screen-master](../../../documents/screen/code/requirements.md) §4 · [ADR-0017](./0017-cache-strategy-per-target.md) §3

> **구현 상태 (2026-08-31)** — §1·§3·§4·§5 는 전부 섰다. §2 의 경계 셋 중 **둘**이 있다:
> 요청 필터와 **배치 실행**(`BatchRunner#execute`). 예고한 그대로 — 배치 슬라이스가
> `configs.inNewSnapshot(…)` 한 줄을 그 자리에 넣었고, 그것이 없으면 보존 파기 배치가
> `IllegalStateException` 으로 죽는다([32](../../knowledge/retention.md) §4.1 — 설정을 읽는 첫 배치다).
> `@Async` 데코레이터는 여전히 **부를 곳이 없어** 만들지 않았다.
>
> **배치에서는 경계가 성능이 아니라 정합성이다.** 청크 백 번을 도는 중에 화면에서 보존
> 기간이 바뀌면 **앞 청크와 뒤 청크가 서로 다른 기준으로 지운다** — §2 가 *"배치가 10만
> 건을 도는 도중에 바뀌어도 같은 사고"* 라고 적은 그 상황이 실물이 됐다.
>
> 기동 검사는 `ConfigStartupCheck`(`ApplicationRunner`)이고, 경계 밖 호출은
> `IllegalStateException` 이다. **`sys-config.` 밖은 경계를 요구하지 않는다** — 아래 §6.

## 맥락

[43](../../knowledge/sys/code.md) §6.1 이 설정의 층을 **둘**로 정했다(2026-08-28) — `yml` 이 기본값, `SYS_CONFIG` 가
적용값의 오버라이드다. 그 절은 이어서 *"`SYS_CONFIG` 프로퍼티 소스는 우선순위 맨 앞이다"*
라고 적었고, [ADR-0017](./0017-cache-strategy-per-target.md) §3 은 같은 값을 *"요청 스코프 스냅샷 · lazy 로 채운다 · 대량
루프도 조회는 1회"* 라고 적었다.

**둘은 동시에 참일 수 없다.**

| | 읽는 시점 | 런타임 변경 |
|---|---|---|
| 프로퍼티 소스 | **기동 1회**(바인딩) | 재기동해야 반영된다 |
| 작업 스코프 스냅샷 | **작업마다** | 다음 작업부터 반영된다 |

프로퍼티 소스로 두면 MASTER-08 의 *런타임 변경* 이 성립하지 않는다. **화면은 저장했다고
말하는데 동작은 재기동 전까지 그대로다.**

**그리고 두 층이 하나의 `Environment` 안에 겹쳐 있는 한, 층을 둘로 줄인 이유가 무력해진다.**

| 구멍 | 무슨 일이 일어나나 |
|---|---|
| **`yml` 값을 지운다** | `SYS_CONFIG` 행이 구멍을 메워 `@NotNull` 이 통과한다. **기동이 성공한다** — 43 §6.1 이 없앤 *셋째 층* 을 **DB 행이 대신한다** |
| **고아 키** | 필드를 지워도 행이 남고, 아우터 조인의 왼쪽이 코드라 **화면에 보이지 않는다** |
| **되돌리기가 시한폭탄** | 기본값이 없는 키를 되돌리면 **저장은 성공하고 다음 재기동이 죽는다** |

세 구멍의 뿌리는 하나다 — **`Environment` 가 두 층을 섞어서, 어느 층에서 온 값인지 물을
수 없게 만든다.**

## 결정

### 1. `SYS_CONFIG` 는 프로퍼티 소스가 아니다

```
기동   : yml → @ConfigurationProperties 바인딩 → 검증        ← SYS_CONFIG 가 없다
런타임 : 유틸이 그 위에 SYS_CONFIG 를 덮어 다시 바인딩         ← 유틸만 안다
```

**층이 둘이면 메커니즘도 둘이다.** 섞지 않으니 각 층에 따로 물을 수 있다.

- **`yml` 누락은 메울 것이 없다 → 기동 실패.** 43 §6.1 이 의도한 그대로가 된다.
  *키를 추가하고 `yml` 을 빠뜨림* 과 *있던 `yml` 값을 지움* 이 **같은 방식으로 죽는다**
- **고아 키는 읽을 경로가 없다.** 유틸의 키 집합이 곧 **필드 집합**이다. 지울 필요도 없다 —
  구버전으로 롤백하면 무시되고 **롤포워드하면 되살아난다**
- **환경변수보다 DB 가 이기는 것은 그대로다.** 근거만 *프로퍼티 소스 순서* 에서
  **유틸이 마지막에 덮는다** 로 바뀐다

### 2. 스냅샷의 경계는 **요청이 아니라 작업**이다

ADR-0017 §3 이 요청을 든 것은 요청이 특별해서가 아니라 *"한 덩어리 일 안에서 값이 바뀌면
안 된다"* 를 말하려던 것이다. **배치가 10만 건을 도는 도중에 바뀌어도 같은 사고**이므로,
경계의 이름을 **작업(unit-of-work)** 으로 넓힌다. 요청은 그 한 종류다.

| 작업 | 경계를 여는 곳 | 이미 있는 자리인가 |
|---|---|---|
| HTTP 요청 | 요청 필터 | **`requestId` 를 넣는 그 자리**([28](../../standard/backend/_study/system-logging.md) §3.3) |
| `@Async` | `ContextCopyingTaskDecorator` | **MDC·Locale 을 옮기는 그 자리**([30](../../standard/backend/crosscutting.md) §4) |
| `@Scheduled` | 스케줄러 진입 래퍼 | **`job`·`requestId` 를 넣는 그 자리**([30](../../standard/backend/crosscutting.md) §8) |

**새 자리를 만들지 않는다.**

- **비동기는 부모 스냅샷을 복사해 물려받는다.** [30](../../standard/backend/crosscutting.md) §3.2 의 제목이 *"요청 스코프는
  **복사해서** 넘긴다"* 이며, 그 절이 금지하는 것은 `RequestContextHolder` 라는 **살아 있는
  객체**의 전파다(요청이 먼저 끝나면 무효해진다). 스냅샷은 **불변 값 묶음**이라 그 이유가
  걸리지 않는다 — 금지가 아니라 §3.2 가 시킨 그대로다
- **스케줄러는 자기 스냅샷을 새로 뜬다** — 물려받을 부모가 없다
- **오래 도는 작업이 낡은 값에 묶이는 것은 버그가 아니라 의도다.** ADR-0017 §3 이 원한
  일관성이 그것이다. 반영하려면 **작업을 다시 돌린다**
- **경계 밖 호출은 예외로 죽인다.** 경계 셋이 다 덮이므로 그 바깥 호출은 **배선 누락**이고,
  조용히 허용하면 *루프 도중에 값이 바뀌는* 그 사고가 되돌아온다. 대신
  **`configs.inNewSnapshot(() -> …)`** 을 공개해 기동 검사·테스트가 경계를 직접 연다

조회는 **작업당 `SELECT * FROM SYS_CONFIG` 한 번**이고(19행짜리 표다), 그 안에서는 어느
키·어느 클래스든 쿼리가 없다. **백엔드는 `SYS_CACHE_VERSION` 을 보지 않는다** — [43](../../knowledge/sys/code.md) §8.1 이
*"이 표는 백엔드 노드끼리 주고받는 신호가 아니다. 폴링하지 않으며"* 로 못박았다.

### 3. 값은 **재바인딩**으로 낸다 — DB 값도 같은 검증을 받는다

기동 때 바인딩된 객체는 `yml` 값만 담는다. 유틸은 그것을 그냥 돌려줄 수 없고 **값을 덮어
객체를 다시 만든다.**

```
작업 첫 호출 → SELECT * FROM SYS_CONFIG (1회)
             → yml 위에 덮는다
             → Binder 로 다시 만든다               ← 재바인딩
             → ValidationBindHandler 가 여기서 돈다 ← 딸려오는 것
             → 스냅샷에 넣고 작업 내내 재사용
```

[43](../../knowledge/sys/code.md) §6.2 의 *"제약의 단일 원본은 바인딩 객체"* 가 저장 경로뿐 아니라 **읽기 경로에서도
저절로 지켜진다.** 대가는 **화면을 안 거친 값이 검증을 만나는 것**이다.

```sql
UPDATE SYS_CONFIG SET CFG_VAL = '-1'  WHERE CFG_KEY = 'auth.login.fail-limit';  -- @Min(0) 위반
UPDATE SYS_CONFIG SET CFG_VAL = 'abc' WHERE CFG_KEY = 'auth.login.fail-limit';  -- Integer 인데 문자
```

터지는 시점은 **넣은 순간이 아니라 다음 작업**이고, 죽는 것은 넣은 사람이 아니라 **그
설정을 읽는 아무 요청**이다. `auth.login.*` 이면 로그인이 전부 죽는다.

**둘을 함께 둔다.**

| | |
|---|---|
| **기동 시 예행 바인딩** | `SYS_CONFIG` 전량을 얹어 **전 클래스를 한 번** 바인딩한다. 실패하면 **기동 실패** — 이미 들어가 있던 나쁜 행은 배포자가 본다 |
| **런타임 재바인딩 실패는 예외** | 그 키만 버리고 `yml` 로 되돌리면 **로그만 남고 조용하다** — 화면은 `변경됨` 이라 말하는데 동작은 기본값인, **이 ADR 이 닫으려는 바로 그 실패**다 |

**`SYS_CONFIG` 는 화면이 소유한 테이블이고 SQL 직접 수정은 비지원**이다. 비지원 행위가
시끄럽게 깨지는 것은 원칙 P1 그대로다.

> 재바인딩은 **lazy** 다. 그 작업이 실제로 만진 클래스만 다시 만든다 — 안 쓰는 값 때문에
> 죽을 이유가 없고, **전량 검사는 기동이 한다.**

### 4. props 클래스를 **빈으로 등록하지 않는다**

유틸을 안 거치고 props 를 직접 주입하면 `yml` 값이 나오고 **DB 오버라이드가 조용히
무시된다** — 43 §6.1 이 프로퍼티 소스 순서 규칙으로 막으려던 *"적용되지 않는데 화면은
바뀐 것처럼 보인다"* 가 **형태만 바꿔 되돌아온다.**

`@EnableConfigurationProperties` 를 쓰지 않는다. **기동 검사와 유틸이 `Binder` 로 직접
바인딩한다.**

- **주입할 빈이 없으므로 `@Autowired AuthLoginProps` 는 기동에서 죽는다**(`NoSuchBeanDefinition`).
  조용히 `yml` 값이 나오는 경로가 **없다**
- **애노테이션은 남는다.** `@ConfigurationProperties` 의 `prefix` 가 키의 앞 절반이고,
  `spring-configuration-metadata.json` 생성도 이 애노테이션이 트리거한다([63](../../../documents/screen/code/requirements.md) §4.2) —
  둘 다 빈 등록과 무관하다
- **호출은 타입으로 한다** — `configs.get(AuthLoginProps.class).failLimit()`.
  **call site 에 문자열 키가 없으므로 오타가 런타임까지 가지 않는다**

### 5. `yml` 은 루트 키 `sys-config` 아래에 모은다

```yaml
sys-config:
  auth:
    login:
      fail-limit: 5
```

이것이 **빌드 검사의 범위를 확정한다.**

> **`sys-config` 아래 모든 `yml` 키는 대응하는 필드가 있어야 한다.** 없으면 **빌드 실패**.

루트가 없으면 범위를 접두사 목록으로 관리해야 하고(`spring.*`·`logging.*` 은 우리 필드가
없다), **목록은 관리하는 순간 어긋난다.** [63](../../../documents/screen/code/requirements.md) §4.6 이 접두사 콤보를 *"전 키에서 도출한다 —
관리하지 않는다"* 로 푼 것과 **같은 해법**이다.

검사의 왼쪽은 **`META-INF/spring-configuration-metadata.json`** — [63](../../../documents/screen/code/requirements.md) §4.2 가 설명 원천으로
**이미 쓰는 산출물**이다. 컴파일 에러가 아니라 **빌드 체크 태스크**다.

**방향이 둘이고 둘 다 시끄럽다.**

| 방향 | 언제 | 무엇이 |
|---|---|---|
| 필드 → `yml` (값 없음) | **기동** | `@NotNull` — §1 |
| `yml` → 필드 (필드 없음) | **빌드** | 체크 태스크 — 여기 |

**`CFG_KEY` 는 루트를 뺀 나머지**다 — `auth.login.fail-limit`. 유틸이 `sys-config.` 를 붙인다([43](../../knowledge/sys/code.md) §10).

| 왜 루트를 넣지 않나 | |
|---|---|
| 접두사 콤보가 죽는다 | [63](../../../documents/screen/code/requirements.md) §4.6 의 첫 마디가 전부 `sys-config.` 면 **아무 정보가 없다** |
| 100자를 선불로 낸다 | `CFG_KEY` 는 `VARCHAR(100)` 인데 12자를 늘 잡아먹는다 |
| 변환이 결정적이다 | [43](../../knowledge/sys/code.md) §10 이 경고한 것은 **kebab·대소문자 같은 비결정적 변환**이다. 고정 접두사를 붙였다 떼는 것은 그 절이 든 세 손실(역변환의 결정성·검색 가능성·조립의 단순함) 중 **어느 것도 걸리지 않는다** |

## 6. `sys-config.` 밖은 경계를 요구하지 않는다 (2026-08-30, 구현하며 더함)

`app.security.*` · `app.logging.*` 은 **배포 설정**이다([43](../../knowledge/sys/code.md) §6.1) —
기동 시 필터 체인이나 `DataSource` 의 모양을 정하므로 런타임에 바꿔도 반영될 자리가 없고,
그래서 관리 화면에도 나오지 않는다. **덮을 층이 없으므로 스냅샷도 필요 없다.**

이 절이 없으면 §2 의 *"경계 밖은 예외"* 가 **정상 호출을 죽인다** — `SecurityConfig` 는
기동 중에 `ConcurrentSessionProps` 를 읽고, 그때는 열어 줄 요청이 없다. 규칙의 범위를
**루트 키가 정한다**: `sys-config.` 아래면 경계를 묻고, 밖이면 `yml` 그대로 한 번 만들어
캐시한다.

> **§5 가 정한 루트의 값이 하나 더 늘었다.** 빌드 검사의 범위(§5)와 오버레이의 범위(여기)가
> **같은 한 마디**로 정해진다.

## 기각한 대안

| 기각 | 이유 |
|---|---|
| **프로퍼티 소스 유지 + 기동 시 *`SYS_CONFIG` 를 뺀 기본값* 검사** | `yml` 삭제는 잡지만 **고아 키와 롤백 딜레마가 남는다** — 고아를 기동 실패로 하면 신규 키를 화면에서 바꾼 뒤 롤백할 때 **구버전이 못 뜬다.** 유틸로 옮기면 그 딜레마 자체가 사라진다 |
| **프로퍼티 소스 + `@RefreshScope`** | 리프레시 시점이 새 개념이 되고, 리프레시 도중 요청이 **앞뒤로 다른 값을 본다** — ADR-0017 §3 이 막으려던 그 사고다 |
| **재바인딩 실패 시 그 키만 `yml` 로 폴백** | 로그만 남는다. 화면은 `변경됨`, 동작은 기본값 — §3 |
| **요청 스코프를 그대로 두고 스케줄러는 `yml` 만 본다** | *"스케줄러는 화면 설정을 안 따른다"* 가 **문서 어디에도 없는 규칙**이 된다. 배치가 가장 오래 도는 일이라 **일관성이 가장 필요한 곳**이다 |
| **경계 밖 호출을 임시 스냅샷으로 허용** | 루프 안에서 부르면 매번 조회하고 **매번 값이 다를 수 있다.** ADR-0017 §3 의 사고가 그대로 되돌아온다 |
| **props 클래스를 패키지 사설로 감춘다** | 주입은 막히지만 `configs.get(AuthLoginProps.class)` 도 부를 수 없다. **빈으로 등록하지 않는 것**이 같은 것을 막으면서 호출 형태를 남긴다 |
| **유틸을 문자열 키로**(`configs.getInt("auth.login.fail-limit")`) | 오타가 **런타임까지 간다.** 타입으로 부르면 call site 에 문자열이 없다 |
| **`CFG_KEY` 에 `sys-config.` 를 포함** | 위 표 |
| **백엔드가 `SYS_CACHE_VERSION` 을 폴링** | [43](../../knowledge/sys/code.md) §8.1 이 *"백엔드 노드끼리 주고받는 신호가 아니다"* 로 못박았다. **19행 조회를 아끼려고 폴링을 들이지 않는다** |

## 결과

- **43 §6.1 의 *"프로퍼티 소스는 우선순위 맨 앞"* 이 죽는다.** 같은 문장이 [63](../../../documents/screen/code/requirements.md) §4.2 와
  목업 §2 주석 3 에도 있다 — 셋 다 **유틸이 마지막에 덮는다**로 바뀐다
- **63 §4.2 의 기본값 정의가 단순해진다** — *"`Environment` 에서 `SYS_CONFIG` 소스만 뺀
  유효값"* 에서 **뺄 것이 없어진다.** 화면과 유틸이 같은 `Environment` 를 본다
- **CF-11 이 하나로 수렴한다.** *`yml` 값 없는 키를 추가* 와 *있던 `yml` 값을 지움* 이
  같은 메커니즘으로 죽으므로 **별도 케이스가 필요 없다**
- **고아 키는 *되면 안 되는 것* 이 아니라 *읽히지 않는다* 다** — 경고 로그도, 정리 배치도
  두지 않는다. **롤백과 롤포워드가 저절로 맞는다**
- **ADR-0017 §3 의 이름이 바뀐다** — *요청 스코프* → **작업 스코프**. 결정은 그대로이고
  **적용 범위가 넓어진다**
- **30 §3 전파 표에 한 행이 는다** — 설정 스냅샷은 **복사 전파**이며 §3.2 의 예다
- **프론트는 이 유틸을 쓰는 API 하나만 본다** — 앞뒤가 갈릴 자리가 없다. 프론트 캐시는
  로그인 시 `SYS_CACHE_VERSION` 비교 그대로다([43](../../knowledge/sys/code.md) §8.1 · ADR-0017 §3)
- **`SYS_CONFIG.SYS_YN` 은 여전히 지킬 것이 없다**([43](../../knowledge/sys/code.md) §9 미결). 유틸로 옮겨도 **행을 지우면
  `yml` 이 드러나는 것은 같다**
- **유틸 밖에서 설정을 읽을 방법이 없다는 것이 이 결정의 값이자 대가다** — 테스트에서도
  경계를 열어야 하고, `inNewSnapshot` 이 그 자리다
