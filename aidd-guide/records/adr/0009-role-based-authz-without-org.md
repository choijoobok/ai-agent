# ADR-0009. 조직 계층 없는 역할 기반 권한 + 개인 예외

- 상태: 채택
- 일자: 2026-08-23

## 맥락

백오피스 템플릿에 조직/부서 계층을 넣을지 판단이 필요했다.
초기 검토에서는 사용자 관리·데이터 권한·결재선이 모두 조직에 의존하므로
필수 기능으로 승격하는 안을 제시했다.

## 결정

**조직/부서 계층을 두지 않는다.**

- 메뉴·기능 접근 권한은 **역할(Role) 기반**
- 역할로 표현하기 어려운 경우 **개인별 예외 권한**을 허용 (기간·사유 필수, **허용만**)
- 결재가 필요하면 **신청 메뉴와 승인 메뉴를 분리**하고 각각 다른 역할을 부여해 절차를 표현
- 조직 범위 기반 **데이터 권한도 제외**

## 근거

- 조직/부서 트리는 **그룹웨어·인사 시스템의 성격**이다. 업무 도메인 비종속 백오피스
  템플릿의 범위를 벗어난다.
- 조직을 넣으면 계층 조회·겸직·이동 이력·조직 개편 같은 부수 기능이 연쇄로 따라온다.
  설계 원칙 P2(삭제하기 쉬운 템플릿)에 반한다.
- 결재선 워크플로는 조직 계층 + 상태 머신 + 위임/대결 처리를 요구한다.
  **신청/승인 메뉴 분리**로 대부분의 실무 요구를 훨씬 단순하게 충족할 수 있다.
- 데이터 권한은 조직 개념이 없으면 성립하지 않는다. 필요한 프로젝트는 직접 구현한다.

## 개인 예외 권한 — DENY 를 두지 않는 이유

| | GRANT 만 (채택) | GRANT + DENY |
|---|---|---|
| 우선순위 규칙 | 불필요 (합집합) | 필요 — DENY 가 이기는가, 순서가 있는가 |
| "왜 권한이 없나" 추적 | 쉬움 | 어려움 |
| 특정 사용자 배제 | **역할 분리로 해결** | DENY 행 추가 |

허용과 차단이 섞이면 권한 판정이 디버깅 불가능해진다.

## 메뉴 경로 결합을 두지 않는 이유

메뉴 접근 판정에 **조상 메뉴의 권한을 결합하지 않는다.** 리프 자신의 권한만으로 결정하고,
권한은 **URL 이 있는 메뉴에만** 부여한다.

경로 결합을 택하면 위 DENY 논의와 **같은 문제가 다시 나타난다.**

| 문제 | 내용 |
|---|---|
| **개인 예외가 무력화** | 예외를 주려면 역할의 조상 권한도 열어야 하고, 그러면 그 역할의 다른 사용자 전원에게 영향이 간다. 개별 부여라는 목적이 사라진다 |
| **암묵적 DENY 와 동형** | 리프에 GRANT 가 있는데 접근이 안 되고 원인은 다른 행에 있다. "왜 권한이 없나" 추적이 어려워진다 |
| 실체 없는 제약 | 웹앱에는 "경로 통과" 가 없다. 멀티탭·즐겨찾기·커맨드 팔레트는 조상을 지나지 않는다 |
| 방어 기여 없음 | 실질 게이트는 메뉴 권한 + 메뉴↔API 매핑이다 |

권한을 URL 있는 메뉴에만 부여하면 "조상 권한 없음" 상태가 **구조적으로 존재할 수 없다.**
폴더 단위 일괄 부여 요구는 **판정 모델이 아니라 화면**에서 푼다 — 트리 캐스케이드 +
폴더의 파생 3-state 표시. 상세: [23-security-design](../../standard/backend/_study/security-design.md) §4

## 대안

| 대안 | 기각 사유 |
|---|---|
| 조직 트리 + 조직 기반 데이터 권한 | 템플릿 범위 초과. 부수 기능 연쇄 |
| 조직 테이블만 두고 권한은 역할 | 쓰지 않는 테이블이 남아 오히려 혼란 |
| 결재선 워크플로 엔진 | 업무 도메인 성격이 강하고 구현 비용이 크다 |
| 개인 예외 없이 역할만 | 일시적·개별 권한을 위해 역할이 무한 증식한다 |
| 메뉴 경로 결합 (조상 권한 필수) | 개인 예외가 무력화되고, 암묵적 DENY 와 같은 추적 곤란이 생긴다 |
| 폴더 단위 권한 저장 | 메뉴 재편 시 접근 가능자가 조용히 바뀌고, 하위 신규 메뉴가 자동 노출된다 |
| 개인 예외를 폴더 단위로 확장 | 개인 예외가 **제2의 역할 체계**가 되어 권한 출처 추적이 불가능해진다 |

## 결과

- `SYS_USER_MENU_AUTH`(개인 예외) 테이블이 필요하다. 유효 권한 = 역할 ∪ 개인.
- 개인 예외는 **기간 한정**이 기본이며, 만료 처리 배치가 필요하다.
- 개인정보 접근 권한도 같은 구조를 따른다 (`SYS_ROLE_PII_AUTH` / `SYS_USER_PII_AUTH`).
- 사용자 조회 화면에 조직 필터가 없다. 검색은 역할·상태·계정 기준.
- 권한 캐시 키가 **사용자 단위**가 된다 (역할 단위 캐시 불가 — 개인 예외 때문).
- 조직이 필요한 프로젝트는 템플릿 위에 직접 추가한다. 훅은 남기지 않는다.
