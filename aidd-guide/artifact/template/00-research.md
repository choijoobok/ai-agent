# 외부 조사 자료 서식

> **비규범이다.** 여기 적힌 어떤 서술도 설계 제약이 아니다 — 제약은 `documents/spec/` 이,
> 결정은 `documents/decisions/ADR-*.md` 가 갖는다. **이 문서를 spec 이나 `aidd-guide/`
> 에서 직접 인용하지 않는다**(산출물 지도 §1 의 42행). 인용하는 것은 ADR 뿐이다.
>
> 채우면 → `documents/research/{주제}.md`

## 머리 표 (필수)

| 항목 | 내용 |
|---|---|
| 조사 시점 | `YYYY-MM` — **접근 시점을 적는다.** 외부 자료는 갱신되므로 시점 없는 인용은 검증할 수 없다 |
| 성격 | 사례 조사 / 기술 평가 / 실측(PoC) 중 하나 |
| 근거로 쓰인 결정 | `ADR-###` 목록. **비어 있으면 그 조사는 아직 아무 결정에도 닿지 않았다** — 그 사실을 적는다 |
| 상위 | 이 조사가 답하려 한 질문의 출처 — `REQ-###` · `CON-###` · `NFR-###` · 다른 조사 문서 |

## 1. 이 문서의 성격 (필수)

**무엇을 답하려고 조사했나**를 한 문단으로 적는다. 그리고 **무엇을 답하지 않는가**를 함께
적는다 — 조사의 범위 밖에 있는 것을 적어 두지 않으면, 다음 사람이 이 문서에 없는 답을
있는 것으로 읽는다.

## 2. 관측 (성격에 따라 절 구성이 갈린다)

### 사례 조사일 때
사례마다 **① 무엇을 했나 ② 어떻게 됐나 ③ 우리와 무엇이 다른가**. 셋째가 없으면 사례가
아니라 소문이다. 되돌린 사례·실패 사례를 **반드시 포함**한다 — 성공 사례만 모으면 그것은
조사가 아니라 근거 만들기다.

### 기술 평가일 때
**평가 축을 우리 요건에서 유도해 먼저 세운다.** 축 없이 후보를 나열하면 무엇을 비교했는지
알 수 없다. 그리고 **후보가 주지 않는 것**을 별도 절로 가른다 — 이쪽이 대개 우리가
직접 만들어야 하는 것의 목록이고, 도입 판단의 실제 근거다.

### 실측(PoC)일 때
- **확정된 전제** — 무엇을 이미 정해 놓고 실험했나. 이것이 없으면 결과의 해석이 갈린다.
- **실행 환경과 조건** — 대역한 것을 명시한다(모델·DB·데이터 규모). 대역은 한계의 목록이다.
- **시나리오별 결과** — 시나리오마다 성공 판정 기준을 먼저 적고 결과를 적는다.
- **실행 중 드러난 것** — 문서상의 비교로는 나오지 않았던 것. **이것이 PoC 의 소득이다.**
- **지표** — 코드량·의존성 증분처럼 잰 값. **무엇에 종속된 값인지 함께 적는다.**

## 3. 판단 — 확인된 것 / 확인되지 않은 것 (필수)

**둘을 갈라 적는다.** 확인되지 않은 것을 적지 않으면 조사가 실제보다 넓게 읽힌다.
확인되지 않은 항목마다 **왜 남았나**와 **언제 답할 수 있나**를 적는다.

## 4. 수용 결정과 반영 위치 (필수)

| # | 조사가 말한 것 | 수용 | 반영 위치 |
|---|---|---|---|
|   |  | 예 / 아니오 / 보류 | `ADR-###` · `REQ-###` · `CON-###` · (미반영) |

- **수용하지 않은 것도 적는다.** 왜 받지 않았는지가 나중에 같은 제안이 올 때의 답이다.
- **`(미반영)` 을 비워 두지 않는다** — 조사만 하고 아무 데도 닿지 않은 관측이 있으면
  그것이 이 표에서 보여야 한다.

## 5. 출처 (필수)

인용한 외부 자료의 제목·발행처·접근 시점. **링크만 남기지 않는다** — 폐쇄망에서 열 수
없고, 링크는 썩는다. 무엇을 읽었는지 알 수 있게 제목과 요지를 함께 적는다.
