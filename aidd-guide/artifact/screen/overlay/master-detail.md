# Overlay — 마스터-디테일

**트리거**: 부모 표 하나와 자식 표 하나를 한 화면에서 다룬다.
**필수가 되는 절**: §1-1 연동 · §4-1 을 **그리드마다 하나씩** · §4-5 행 추가 기본값.

## 반드시 묻는 것 일곱

1. **축** — 마스터 컬럼이 몇인가. **대여섯 이상이면 상하, 서넛이면 좌우다.**
   *고르는 것이 아니라 데이터가 정한다*.
2. **연동 기준 컬럼** — 마스터의 어느 컬럼으로 디테일을 조회하나.
3. **미저장 신규 마스터 행을 골랐을 때** — 디테일은 **비활성인가 빈 상태인가**.
   (부모 키가 아직 DB 에 없어 자식을 만들 수 없다.)
4. **미저장 디테일이 있는 채로 다른 마스터로 옮길 때** — **확인 후 폐기인가 차단인가.**
5. **저장 단위** — 마스터·디테일 **각각인가 일괄인가**. 각각이면 *한쪽 저장이 다른 쪽의
   어느 컬럼을 서버에서 다시 계산하는지* 를 적는다.
6. **마스터 삭제 게이트** — 자식이 있는 부모를 지울 수 있나. 막는다면 **근거가 마스터
   응답에 있는가**(자식 건수 컬럼) — 없으면 서버가 사유를 담아 거절하는 쪽이다.
7. **디테일에도 조회 버튼이 필요한가** — *품목만 새로 보고 싶다* 가 있는 화면인가.

## 흔한 누락

| 빠뜨린 것 | 일어나는 일 |
|---|---|
| **③ 미저장 신규 마스터** | 디테일에 행을 넣으면 **FK 위반**으로 저장이 실패한다 |
| **④ 이동 시 폐기 확인** | *보고 있는 것* 과 *고른 것* 이 갈리고, 그 상태로 저장하면 **A 의 자식이 B 로 나간다** |
| **마스터 조회가 디테일을 리셋하는지** | 이전에 보던 행이 결과에 없을 수 있다 — **다른 부모의 자식을 그 부모 것으로 본다** |
| **자식 건수 컬럼** | 삭제 게이트를 화면에서 판정할 수 없다 |
| **디테일 행 추가 시 자동으로 채우는 값** | 부모 키가 비어 나간다 |

## 적지 않는 것

스플리터 · 접힘 · 개인화 키 · 디테일 제목에 부모 값을 붙이는 것 — **전부 표준이다.**
