# 화면 재현 회귀 — Generation 골든셋의 실물판

> [golden-set.md](./golden-set.md) 의 **Generation 골든셋**은 *프롬프트 → 기대 산출물* 이다.
> 이것은 그보다 큰 단위다 — **문서 셋만 주고 화면 하나를 통째로 다시 만들게 하고,
> 실제 구현과 대조한다.**
>
> **재는 것은 AI 의 실력이 아니라 문서의 자립도다.** 같은 모델이 같은 화면을 만드는데
> 결과가 갈린다면 갈린 자리가 곧 **문서가 말하지 않은 자리**다.

## 1. 언제 돌리나

- `aidd-guide/` 의 **standard · playbook 을 크게 고친 뒤** — 고친 것이 실제로 닿았는지 본다
- **새 화면 유형**(트리·차트·업로드 등)을 처음 만든 뒤 — 레시피가 섰는지 본다
- 요건서 템플릿을 고친 뒤
- 그 밖에는 분기 1회면 충분하다. **싸지 않다** — 화면 하나에 40만 토큰 안팎이다

## 2. 절차

### 2-1. 샌드박스 — 정답을 물리적으로 지운다

```bash
git worktree add --detach <스크래치>/sbx-<화면> HEAD
```

그 사본에서 **그 화면의 것만** 지운다.

| 지운다 | 남긴다 |
|---|---|
| `sources/frontend/src/features/{도메인}/` 전체 | 그 화면의 `requirements.md` |
| 그 화면만 쓰는 백엔드 클래스 | 옆 화면이 함께 쓰는 클래스 |
| `documents/screen/{경로}/mockup.html` · `manual.md` · `manual.html` | `aidd-guide/` 전부 · 샘플 여섯 |
| `screenRegistry.ts` 의 그 줄 | 시드 CSV · `messageKeys.ts` · `menu-tree.yaml` |

- **옆 화면의 실물을 남기는 것이 옳다.** `CLAUDE.md` §3 이 *"비슷한 화면의 실물을 읽는다"* 를
  표준으로 정했으므로, 그것을 뺀 실험은 실제 개발 조건이 아니다. 대신 **어디서 근거를
  얻었는지 세어** 문서가 한 몫과 소스가 한 몫을 가른다.
- **게이트는 끈다.** 샌드박스에 `node_modules` 가 없다. 이것도 설계다 — ESLint 가 한글
  리터럴을 잡아 주면 *문서가 그 규칙을 전달했는가* 가 게이트에 가려 안 보인다.
  규칙 준수는 산출물을 정적으로 검사해 채점한다.

### 2-2. 프롬프트 — 빠지면 실험이 무효가 되는 것

1. **샌드박스 절대 경로**와 *"본 저장소를 열지 마라"* — 한 번이라도 열면 무효다
2. `git` 명령 금지(worktree 라 공유 저장소를 건드린다)
3. 만들 것: `mockup.html` · 프론트 전량 · 백엔드
4. **`_EVAL/SOURCES.md`** — 결정마다 `요건서 / 가이드(파일#절) / 옆화면(파일) / 추측` 분류. 최소 25행
5. **`_EVAL/GAPS.md`** — 추측한 것 · 문서끼리 어긋난 것 · 두 갈래로 읽힌 것 ·
   **옆 화면 없이는 못 했을 것** · 라우팅이 안 데려다준 자리
6. *"요건서에 없는 기능을 상상해 넣지 마라 — 없으면 GAPS 에 적어라"*

> **4·5 가 이 실험의 산출물이다.** 소스는 대조 대상일 뿐이고, 고칠 곳을 알려 주는 것은 이 둘이다.

## 3. 무엇을 세나

의미 단위로 센다 — 텍스트 diff 는 주석 때문에 부풀려져 쓸 수 없다.

| 축 | 세는 법 |
|---|---|
| 계약 | `endpoints.ts` 키·URL 집합의 차 |
| 타입 | `types.ts` 의 이름·순서·nullable |
| 화면 | 컬럼 `field`·`width`·`type` · 조회조건 · 버튼 |
| 문구 | 쓰인 `MSG.*` 키 집합의 대칭차 |
| 뼈대 | `@/shared/*` import 집합 |
| 백엔드 | 클래스 목록 · public 메서드 시그니처 · `QuerySpec` 체인 |
| **기계 규칙** | 한글 리터럴 · JSX 한글 · 딥 임포트 · `features` 간 import · URL 리터럴 |
| **근거 분포** | `SOURCES.md` 행 중 각 분류가 낀 비율 |

## 4. 베이스라인 — 2026-09-04 (커밋 `440f6c6`)

**계약**: `endpoints` 13/13 일치 · `MSG` 키 117 중 대칭차 1 · 컬럼 40/41 ·
`@/shared` import 전량 일치 · **기계 규칙 위반 0** · 갈린 결정 **12**(전부 이름·분해)

**근거 분포** — 행 중 그 근거가 낀 비율(중복 있음)

| 화면 | 결정 | 요건서 | 가이드 | **옆화면** | 추측 |
|---|---|---|---|---|---|
| `/log/login` | 50 | 56% | 30% | **50%** | 16% |
| `/notice` | 65 | 58% | 25% | **42%** | 9% |
| `/code` | 60 | 65% | 30% | **37%** | 25% |
| `/role-auth` | 52 | 63% | 13% | **48%** | 23% |

**읽는 법**

- **`옆화면` 이 내려가야 한다.** 이것이 이 회귀의 주 지표다 — 문서가 소스를 대신하는 만큼 내려간다.
- **`요건서` 는 이미 56% 아래로 안 내려간다.** 요건 정의서라는 물건은 제 몫을 하고 있다.
- **`추측` 이 높은 화면이 다음에 쓸 문서를 가리킨다.** 2026-09-04 에는 `/code`(동적 컬럼)와
  `/role-auth`(트리·유효권한 판정)가 그랬다.
- **`가이드` 가 낮은 화면은 레시피가 없는 화면이다.** `/role-auth` 의 13% 가
  [playbook/tree-screen.md](../../playbook/tree-screen.md) 를 쓰게 했다.

## 5. 한계 — 이 숫자를 어디까지 믿나

- **문구 키가 이미 있다.** `messageKeys.ts`·`MsgKey`·시드를 남기므로 *키 이름을 고르는 결정* 이
  빠진다. 문구 일치율이 높은 것은 그 때문이며, 새 화면에서는 이 자리가 다시 열린다.
- **옆 화면의 javadoc 이 대상 화면을 지목한다.** 이 저장소가 잘 쓰였다는 증거이면서
  **실험의 난도를 낮추는 요인**이다. `SOURCES.md` 의 `옆화면` 행이 그것을 드러낸다.
- **도는지는 보지 않는다.** 게이트를 끄므로 검증되는 것은 *설계가 일치하는가* 이지
  *컴파일되는가* 가 아니다.
- **화면당 한 번이다.** 같은 화면을 두 번 돌려 재현끼리 비교하지 않으면
  *문서의 침묵* 과 *실행 편차* 가 갈리지 않는다. 갈린 자리가 전부 문서의 빈칸에
  몰려 있는 것이 앞쪽 해석의 근거다.
