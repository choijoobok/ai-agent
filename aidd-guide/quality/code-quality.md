# 코드 품질 — 기계가 세는 것과 미니게이트

## 5. 기계가 세는 코드 품질 (G4 자동 검사)

사람(AI 포함) 눈으로 보는 체크리스트로는 잡히지 않는 것들이 있다. **AI 가 쓰는 코드에서
가장 확실하게 나빠지는 것은 복사와 에러 처리**이며, 둘 다 리뷰에서 *그럴듯해 보이는*
모양을 한다 — 복사는 각각이 맞는 코드이고, 원인을 평가하지 않는 `catch` 는 잡고 있다.
**그래서 이 둘은 기계가 센다.**

```bash
node .claude/hooks/quality-check.mjs
```

| 검사 | 임계 | 무엇을 막나 |
|---|---|---|
| **중복률** (6라인 이상 연속 블록의 중복 비율) | ≤ 5% | 한 곳만 고쳐지는 복사 |
| **예외 삼킴** (빈 catch, `except: pass`, 로그만 찍고 넘김) | 0건 | 원인을 평가하지 않는 에러 처리 |
| **`@feat` 미태깅 소스** | 0개 | 추적성 T10 이 끊기는 것 |

중복률이 걸리면 **복사한 것을 추출**한다. 임계값을 올리지 않는다.
임계값을 올리는 순간 이 검사는 의미가 없어진다.

> **중복률은 *지울 수 있는 줄* 의 비율이다.** 6줄 창을 한 줄씩 미끄러뜨려 찾은 뒤
> **겹친 창을 한 덩이로 접고, 덩이마다 가장 긴 한 벌을 남긴 나머지**를 센다.
> 접지 않으면 7줄짜리 복사가 창 둘에 걸려 **같은 줄을 두 번 센다** — 그렇게 6.95% 로
> 세어진 것의 참값이 2.91% 였다. **임계 5%는 그대로다**: 고친 것은 *무엇을
> 중복이라 부르는가* 이지 *얼마까지 봐주는가* 가 아니다.
>
> 같은 이유로 `import`·`package` 는 코드로 세지 않는다 — 같은 배럴을 여는 것은
> 복사가 아니라 **같은 것을 쓰는 것**이고, 세면 **파일이 늘수록 중복률이 오른다**.

`--baseline` 으로 기준선을 저장해 두면 슬라이스마다 추이를 볼 수 있다.
**추세가 나빠지는 것이 절대값보다 중요하다.**


## 6. 코드 품질 최소 기준 (슬라이스 미니게이트)

- [ ] TC 전부 통과, skip/xfail 0건
- [ ] 예외를 삼키지 않음 (빈 catch 금지)
- [ ] 사용자 입력이 서버 측에서 검증됨 (클라이언트 검증만 있으면 실패)
- [ ] 권한 검사가 API 레벨에 있음 (화면 숨김만으로는 실패)
- [ ] 트랜잭션 경계가 명시적
- [ ] 로그에 민감정보 없음
- [ ] 하드코딩된 비밀정보 없음
- [ ] N+1 쿼리 없음 (목록 조회 기능)
- [ ] `@feat FEAT-###` 태그 존재
- [ ] **규칙 뒤집기 검사 통과** (§4 방법 1) — 미검증 업무 규칙 0건
- [ ] **`quality-check.mjs` 통과** (§5) — 중복률·예외삼킴·태깅

## 7. 결함 관리

`documents/generated/72-결함대장.md`

| ID | 발견단계 | 심각도 | FEAT | 내용 | 원인분류 | 상태 | 조치 |
|---|---|---|---|---|---|---|---|
| DEF-013 | P5 | High | FEAT-021 | 동시 질의 시 토큰 쿼터 마이너스 | 설계결함 | 수정완료 | ADR-011 낙관락 도입 |

**심각도**: Critical(업무 불가/데이터 손상) · High(주요 기능 오동작) · Medium(우회 가능) · Low(경미)
**원인분류**: 요구사항누락 · 설계결함 · 구현오류 · 환경 · 데이터 — 분류를 남겨야 어느 단계를 보강할지 안다.

**규칙**
- 원인분류가 `요구사항누락` 또는 `설계결함` 이면 **spec 을 먼저 고치고** 코드를 고친다.
- Critical/High 잔여 0이 아니면 G5를 통과할 수 없다.
- 결함 수정 시 **재현 테스트를 TC로 추가**한다 (회귀 방지).
