# 엑셀 올려받기 — 업로드가 아니라 읽기다

> **실물**: `features/sample/excel/`(⑥), 공통물은 `shared/excelupload/`.
>
> **양식은 [excel-download.md](./excel-download.md) 의 *전체 다운로드* 다** — 둘이 갈리면
> 사용자가 내려받은 파일을 이 탭이 거절한다. 한 문서였다가 200줄 상한에 닿아 갈랐다.

## 1. 올려받기 — 업로드가 아니라 읽기다

**파일이 서버에 올라가지 않는다.** 브라우저가 읽어 **그리드에 붓는다.**

| 그래서 | |
|---|---|
| 업로드 엔드포인트 | **없다** |
| `SYS_FILE` | 아무것도 남지 않는다 |
| 저장 | **업무 탭과 같은 `save`** — 새 경로를 만들지 않는다 |
| 저장에 성공하면 | **판을 비운다.** 조회가 없어 재조회가 그 일을 못 하고, 남아 있으면 *저장이 안 된 것* 과 구분되지 않는다 |
| 건별 커밋 | **못 쓴다.** `save` 가 `perRow` 를 받지 않는다 — 규칙이 아니라 타입이 막는다(§5) |

## 2. 최상단 탭 둘이 **같은 것 셋**을 나눠 쓴다

```tsx
<ExcelUploadTab<SampleOrderItem>
  title={label(MSG.SAMPLE_EXCEL_TAB_UPLOAD)} menuCd={MENU_CD}
  columns={columns} keyFields={ITEM_KEY_FIELDS}
  read={readApi} save={saveApi} toSaveRow={toSaveRow} handleRef={upload} />
```

**`title` 과 `menuCd` 는 선택이 아니다.** 앞의 것은 통째 거절 모달의 제목이고 뒤의 것은
저장 권한을 보는 자리다 — **둘을 뺀 예시는 컴파일되지 않는다**(2026-09-06 재현 실험에서
재현 하나가 예시를 그대로 옮겨 적었다).

| 공유하는 것 | 갈리면 |
|---|---|
| **컬럼 배열** | *전체 다운로드* 가 **양식이 아니게 된다** |
| **조회 API** | *화면이 보는 표* 와 *대조하는 표* 가 달라져 **이미 있는 행이 신규로** 잡힌다 |
| **저장 API + `toSaveRow`** | 같은 표에 규칙이 둘 생기고, **그 둘은 반드시 갈린다** |

**`toSaveRow` 를 인자로 받는 것이 결정이다.** 컴포넌트가 스스로 만들면 서버가 **파생
컬럼과 감사 컬럼까지** 받게 되어 업무 탭이 보내는 것과 갈린다 — 같은 경로에 두 가지 요청이
도착한다. **넘기지 않으면 저장이 조용히 아무 일도 하지 않는다.**

## 3. 미리보기가 곧 행 상태다

읽은 뒤 **같은 조회 API 를 한 번** 불러 기존 행과 대조한다.

| 대조 결과 | 상태 |
|---|---|
| DB 에 없다 | `C` |
| 있고 값이 다르다 | `U` |
| 있고 같다 | **상태 없음** — 나가지 않는다 |
| 파일에서 줄이 빠졌다 | **`D` 가 생기지 않는다** |

- **412행에서 세 줄만 고쳤으면 나가는 것도 세 줄이어야 한다.** 전량을 보내면 감사 컬럼이
  전부 갱신되어 *누가 언제 무엇을 고쳤나* 를 잃는다.
- **삭제는 업무 탭의 삭제 컬럼이다.** 파일에서 줄을 지운 것과 *"지워라"* 를 구별할 방법이
  없다.
- **양식에 없는 컬럼은 대조에서도 뺀다.** 기존 행에는 파일에 없는 것이 있다 — 내부 순번·
  내부 식별자·감사 넷. 통째로 비교하면 **모든 행이 변경**이 되어 *세 줄만 나간다* 가
  무너진다. 그래서 대조는 **파일에 있는 칸만** 본다(`matchRows.matchesExisting`).
- **키는 `keyFields` 를 유닛 구분자(`U+001F`)로 이어 붙인다.** 콤마·하이픈이면 `A,B`+`C` 와
  `A`+`B,C` 가 같은 키가 되어 **다른 두 행이 하나로 대조된다.**

## 4. 거절은 통째로 한다

헤더가 다르거나 행이 상한을 넘으면 **읽지 않는다.**

- **조용히 자르면** 사용자는 *올린 것이 다 들어간 줄* 안다.
- **열이 밀린 채 읽으면** 수량 자리에 단가가 들어간 파일이 **저장까지 통과한다.**

## 5. 실패도 통째로 — 대신 **실패분을 파일로** 준다

전건 롤백이 이 화면의 답이다. 488행이 커밋되고 12행이 걸리면 그 파일은 **그대로 다시 못
올린다**(성공분이 중복으로 걸린다) — 사용자가 힘들게 만든 파일을 **지우는 편집부터 하게
만드는** 것이 부분 커밋의 대가라면 값이 맞지 않는다
→ [standard/backend/row-transaction.md](../standard/backend/row-transaction.md) §2.

대신 실패 표 아래에 **실패분 내려받기**가 선다. 표는 읽을 수는 있어도 **고쳐서 다시 낼**
수는 없어서, 남는 일이 화면에서 원본 파일로 옮겨 적는 것이 되기 때문이다.

**시트가 둘인 것이 규약이다.**

| 시트 | 무엇 | 왜 |
|---|---|---|
| 첫째 | **양식 그대로** — 컬럼·순서·머리글 | 고쳐서 **그대로 다시 올린다** |
| 둘째 | 행 번호와 사유 | 읽는 쪽은 첫 시트만 본다 — **사람에게만 보인다** |

**사유를 첫 시트에 열로 붙이면 안 된다.** 읽기가 *양식이 다르다* 며 거절한다 — 뒤에 붙은
열까지 세어 막도록 일부러 만들었다(§4). 그러면 사용자는 그 열을 지우는 편집을 해야 하고,
그것이 이 절이 없애려던 바로 그 일이다.

**둘째 시트의 번호는 첫 시트의 데이터 줄이다** — 머리글을 뺀 순서라 두 시트가 나란히
읽힌다. 사유가 여럿인 행은 한 칸에 이어 붙는다.

## 6. 업로드 탭에 조회 버튼이 없다

행이 서버가 아니라 **파일**에서 오므로 부를 곳이 없고, 눌리면 **읽어들인 412행이 통째로
날아간다.** 그래서 `read` 를 컨트롤러의 `api` 가 아니라 **컴포넌트의 인자**로 받는다 —
`api.read` 에 선언하면 버튼이 선다.

## 7. 화면 안 최상단 탭 — 옮기기 전에 묻는다

```ts
const dirtyOf = (key) => key === TAB_UPLOAD ? (upload.current?.dirty() ?? false) : business.dirty;
// <ScreenTabs menuCd={MENU_CD} items={items} value={tab} onChange={setTab} dirty={dirtyOf} />
```

- **하단 디테일 탭과 규칙이 다르다** — 저기는 한 화면 안의 부분이 갈리고 여기는 **화면
  전체**가 갈린다([master-tabs.md §8](./master-tabs.md)).
- **물음은 `ScreenTabs` 가 낸다.** 화면은 *지금 어느 쪽이 미저장인가* 만 답한다.
- **`dirty` 가 함수인 것은 *지금* 을 물어야 하기 때문이다** — 불리언으로 올리면 매 편집마다
  화면 전체가 다시 그려진다.
- **탭 항목에 `actionCd` 를 준다.** 업로드 탭의 액션이 저장 하나뿐이라 `S` 가 없으면 항목이
  아예 없다. **남는 항목이 하나면 컨트롤 자체를 내지 않는다.**
- **조회조건 폼은 탭 *안*에 둔다.** 밖에 두면 **쓰지 않는 탭에서도 보인다.**

## 8. 양식 그리드는 개인화를 열지 않는다

**화면이 선언하지 않는다** — `ExcelUploadTab` 이 자기 그리드에 이미 `settings={false}` 를
건다. 여기 적는 것은 *왜 그렇게 돼 있나* 이지 화면이 베껴 쓸 코드가 아니다.

이 그리드의 컬럼은 사용자의 표가 아니라 **양식**이다. 하나를 감추거나 순서를 바꾸면 *전체
다운로드* 가 그 상태로 나가고 **자기가 방금 내려받은 파일을 업로드가 거절한다.**

## 9. 커밋 전 체크리스트

- [ ] 업로드 탭과 업무 탭이 **컬럼·조회·저장·페이로드 넷을 공유**하는가
- [ ] 양식 그리드에 `settings={false}` 가 있는가
- [ ] 실패분 내려받기가 만든 파일을 **그 화면이 다시 읽는가**(첫 시트가 양식 그대로인가)
