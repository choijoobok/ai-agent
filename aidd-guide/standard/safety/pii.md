# PII 식별·차단 규약

> 개인 식별 정보를 **로그·요약·외부 전송**에 노출하지 않기 위한 작업 규칙.

## PII 분류 (3단계)

| 등급 | 예시 | 처리 |
|------|------|------|
| **민감** | 주민번호, 여권번호, 신용카드번호, 계좌번호, 의료기록 | 코드/로그/요약에 절대 출력 금지. 사용자가 입력 시 즉시 마스킹 안내 |
| **식별** | 실명, 휴대폰번호, 이메일, 주소, 생년월일 | 로그에 평문 저장 금지 — 마스킹 또는 ID 참조로 변환 |
| **준식별** | 사번, 부서, IP 주소, 디바이스 식별자 | 도메인 컨텍스트에 한해 평문 허용. 외부 전송 시 마스킹 |

## 작업 규칙

1. **소스 코드 작업 시** — 테스트/예시 데이터에 실제 PII 사용 금지. `홍길동`, `010-0000-0000`, `test@example.com` 같은 명백한 더미만 사용.
2. **로그·summary 작성 시** — 사용자 메시지 인용 시 PII 발견되면 `***` 마스킹. raw 로그는 훅이 별도 보호.
3. **외부 전송 시** — 외부 API/사이트로 사용자 데이터를 전송할 때는 **반드시 사용자 확인**. URL 파라미터 PII 금지(브라우저 히스토리·Referer 노출).
4. **DB 마이그레이션·덤프 시** — 운영 데이터를 개발 DB로 옮길 때 익명화 필수. SQL 결과를 그대로 채팅에 붙여넣지 않음.

## 차단 키워드 패턴 (자동 감지 후보)

```
\b\d{6}-\d{7}\b         # 한국 주민번호
\b\d{3}-\d{4}-\d{4}\b   # 한국 휴대폰
\b[\w\.-]+@[\w\.-]+\.\w+\b  # 이메일 (대량 노출 시)
\b\d{4}-?\d{4}-?\d{4}-?\d{4}\b  # 카드번호
```

> 정규식은 false-positive 가 있어 **차단 신호**로만 사용. 발견 시 사용자에 확인 요청.

## 위반 시 대응

1. 즉시 출력 중단
2. 노출된 부분 마스킹 안내
3. 사용자에게 (a) 입력을 다시 받을지 (b) 마스킹 후 진행할지 확인
4. 영구 기록(decisions·summary) 에는 기록하지 않음 — 임시 채팅 컨텍스트에만
