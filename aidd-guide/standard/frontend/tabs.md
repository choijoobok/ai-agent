# 멀티탭 워크스페이스 — 셸 · 탭 · 라우팅

> **가장 구조적 영향이 큰 결정이다.** 화면 하나를 만들 때도 *같은 화면이 동시에 여러 개
> 살아 있을 수 있다* 는 전제가 따라온다.
>
> 유도과정·인터랙션 상세는 [`frontend/tabs.md`](./tabs.md).

## 1. 화면 컴포넌트 작성 전제 — 여기가 제일 중요하다

**같은 화면이 동시에 여러 개 살아 있을 수 있다.**

- **전역 싱글턴 상태에 화면별 데이터를 두지 않는다** — zustand 스토어에 목록 데이터 금지.
- **모듈 스코프 변수·전역 이벤트 리스너로 화면 상태를 관리하지 않는다.**
- **서버 상태는 react-query 키로 격리한다.**

## 2. 탭 하나

```ts
{ key, pathname, menuCd, title, closable, favorite }
```

- **`key` 는 `pathname` 이 아니라 탭 고유 식별자다.** 같은 메뉴를 여러 탭에 띄울 수 있어
  (*"새 탭으로 열기"*) **경로가 탭을 식별하지 못한다.** 탭 : 라우트 = **N : 1**.
- **대시보드는 `closable: false` 인 고정 탭**이며 항상 첫 자리다.
- 엘리먼트에 **탭 `key` 를 React key 로 준다** — 같은 라우트라도 탭이 다르면 **별개
  인스턴스**이며 상태를 공유하지 않는다.

## 3. 비활성 탭은 언마운트하지 않고 숨긴다

**검색 조건·스크롤·입력 중인 폼이 탭 전환 후에도 보존되어야 한다** —
**언마운트 방식은 멀티탭의 의미가 없다.**

그래서 **폼 입력값·스크롤은 스토어에 없다.** 컴포넌트 안에 그대로 남고, `tabStore` 는
*"어떤 탭이 열려 있는가"* 만 안다.

### 대가 — DOM 이 쌓인다

| 항목 | 대책 |
|---|---|
| 전환 비용 | **`display:none` 토글만** — 리마운트·리페치 금지. 전환은 O(1) |
| 레이아웃 비용 | 숨김 탭에 `content-visibility: hidden` — 레이아웃·페인트를 건너뛴다 |
| 폴링·타이머 | 비활성 탭은 `refetchInterval` 중지, `setInterval` 정지 |
| 메모리 | **탭 20개 상한** + 닫을 때 그 탭의 쿼리 캐시 제거 |

**AG Grid 인스턴스가 동시에 여러 개 살아 있게 된다** — 탭 상한이 유일한 방어선이다.

**검증 기준: 탭 20개일 때의 전환 지연이 1개일 때와 같아야 한다.**

## 4. 상한에 닿으면 — 자동으로 닫지 않는다

**묻고 나서 닫는다.** 말없이 가장 오래된 탭을 닫으면 **사용자는 무엇이 사라졌는지 모른 채
작업을 잃는다.**

## 5. 브라우저 뒤로/앞으로 = 탭 이동

일반적인 history back(같은 탭 안의 이전 화면)이 **아니라 탭 방문 순서**를 따른다.
**위치 순서**로 옮기는 `PageUp`/`PageDown` 은 별개다.

전환 시 `pushState` 로 주소창을 바꾼다.

## 6. 새로고침 시 탭을 복원하지 않는다

**대시보드 고정 탭 + 현재 URL 의 탭**으로 시작한다. 그래서 **탭 순서도 저장하지 않는다** —
복원되지 않으므로 저장할 대상이 없다.

## 7. 탭바

**상한이 20개이므로 탭바가 넘치는 것이 기본 상태다.** 넘칠 때 **탭을 줄여 다 보여주지
않는다** — 제목이 잘려 무슨 탭인지 알 수 없게 된다. **너비를 유지하고 스크롤한다.**

| 조작 | 동작 |
|---|---|
| 드래그 | 순서 변경. **대시보드는 대상이 아니고 그 앞으로 옮길 수도 없다** |
| 좌우 화살표 | 몇 개분씩 스크롤. 끝에 닿으면 비활성 |
| 마우스 휠 | 탭바 위에서 가로 스크롤 |
| **활성 탭 자동 노출** | 화면 밖 탭이 활성이 되면 **보이도록 스크롤한다** |

> **활성 탭 자동 노출이 없으면 나머지가 무의미하다.** 키보드나 브라우저 뒤로가기로 옮긴
> 탭이 화면 밖이면 **사용자는 활성 탭을 찾지 못한 채 스크롤해야 한다.**

**드래그는 `@dnd-kit` 하나를 쓴다** — 탭바 · 메뉴 트리 편집 · 즐겨찾기 순서가 **셋이
하나를 공유**하므로 **드래그 동작이 화면마다 다르게 느껴지지 않는다.**

## 8. 컨텍스트 메뉴

| 항목 | 동작 |
|---|---|
| 즐겨찾기 등록 / 제거 | 제거는 이미 즐겨찾기인 경우에만 |
| 탭 닫기 | dirty 폼이면 확인. **대시보드에는 뜨지 않는다** |
| 다른 탭 닫기 | 현재 탭과 **대시보드**를 남긴다 |
| 모든 탭 닫기 | **대시보드만** 남긴다 — 헤더 로고와 같은 동작 |

닫기 계열은 저장하지 않은 폼을 만나면 **일괄 확인 다이얼로그**를 띄운다.

메뉴 트리의 우클릭 메뉴는 이것과 **대칭**이다 — 트리는 **여는 방식**, 탭바는 **닫는 방식**을
묻고 즐겨찾기만 공통이다.

## 9. 라우팅은 메뉴가 정한다

```
menu-tree.yaml  →  MENU_URL  →  screenRegistry.ts  →  화면 컴포넌트
```

- **화면 접근은 서버가 내려준 권한 메뉴 목록으로 라우터가 제한한다.** 서버가 실제로
  지키는 것은 그 화면이 부르는 **API** 다 — **JS 청크는 정적 리소스라 막지 않는다.**
- **`screenRegistry` 의 경로 전부가 문서 셋의 대상**이다(CLAUDE.md §6.1).
- **경로를 바꾸면 `documents/screen/` 폴더도 같은 커밋에서 옮긴다.**

## 10. 셸이 그리드에 높이를 줘야 한다

콘텐츠 영역의 높이가 `auto` 면 화면의 `height: 100%` 가 **0 으로 풀려 그리드가 줄 하나
없이 접힌다.** 셸의 콘텐츠 영역을 **뷰포트에 고정**한다.
