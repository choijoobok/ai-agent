**규칙**: `features/*` 끼리 직접 import 하지 않는다. 공유가 필요하면 `shared/` 로 올린다.
(ESLint `import-x/no-restricted-paths` 로 강제). **언제 올리는가는 §2.1.**

> **존은 기능마다 하나씩이다** (2026-08-28 실측). `target` 과 `from` 을 둘 다
> `./src/features` 로 두면 **`auth` 안에서 `auth` 를 import 하는 것까지 막힌다** — 규칙이
> 뜻하는 것은 *기능 사이*이지 *기능 안*이 아니다. 기능 목록은 `src/features` 를 읽어
> 만든다. 손으로 적으면 새 기능을 빠뜨리고, **빠진 기능은 규칙의 대상이 아니므로 아무
> 경고 없이 다른 기능을 import 할 수 있다.**

### 2.1 두 번째 화면이 쓰는 순간 `shared/` 로 올린다

§2 의 규칙(`features/*` 끼리 직접 import 금지)은 **경계를 막을 뿐 언제 올려야 하는지를
말하지 않는다.** 그래서 실제로 벌어지는 일은 import 가 아니라 **복사**다 — ESLint 는
복붙을 통과시킨다.

| 시점 | 무엇을 한다 |
|---|---|
| 화면 **하나**가 쓴다 | `features/{그 화면}/components/` 에 둔다 |
| **두 번째 화면**이 같은 것을 쓰려 한다 | **그때 `shared/components/` 로 올린다.** 복사하지 않는다 |
| 세 번째부터 | 이미 올라가 있다 |

**두 번째가 기준인 이유** — 하나일 때 올리면 *공통으로 쓸 것 같은* 추측으로 인터페이스가
정해지고, 셋을 기다리면 그 사이에 **복사본 둘이 서로 다르게 자란다.** 두 번째가 나타난
순간이 **요구가 둘 다 드러난 유일한 시점**이다.

#### 올릴 때 지키는 셋

| | |
|---|---|
| **도메인 용어를 지운다** | `shared/` 는 **도메인 비종속**이다(§2). `<UserRoleGrid>` 는 올라갈 수 없고 `<DataGrid>` 는 올라간다 — 업무 이름이 남아 있으면 그것은 아직 `features/` 의 것이다 |
| **§7 목록에 등재한다** | **목록에 없는 공통 컴포넌트는 없는 것과 같다** — 다음 사람이 찾지 못해 또 만든다. 이 문서의 §7 이 그 목록이며 PR 에 함께 넣는다 |
| **복사본을 지운다** | 올리는 커밋에서 원래 자리의 것을 **삭제**한다. 남겨 두면 어느 것이 진짜인지 알 수 없다 |

#### 복사를 막을 수단이 ESLint 에 없다

`import/no-restricted-paths` 는 **경로를 넘는 import** 를 막는다. 같은 파일을 두 features
아래에 각각 두는 것은 규칙을 지나간다. **그래서 이 절은 리뷰 규칙이다** — 코드 리뷰에서
*"이거 다른 화면에도 있지 않나"* 를 묻는 자리를 만든다. 자동화가 가능해지면(중복 코드
검사기) 그때 CI 로 옮긴다 — §10 미결.

> **`shared/` 가 쓰레기통이 되는 반대 실패도 있다.** 한 화면만 쓰는 것을 *언젠가 쓸지도*
> 로 올리면 목록(§7)이 길어지고 아무도 다 읽지 않는다. **올리는 조건은 *두 번째 사용*
> 이지 *공통일 것 같음* 이 아니다.**

## 4. 멀티탭 워크스페이스 설계

가장 구조적 영향이 큰 결정이므로 여기서 요구사항과 방식을 확정한다.
상세 인터랙션 명세는 [51](./main-shell.md).

### 4.1 확정 요구사항

| # | 요구 | 결정 |
|---|---|---|
| 1 | 탭 최대 개수 제한 | **기본 20개.** 초과하려 하면 **확인을 받고** 가장 먼저 연 탭을 닫는다 — §4.8 |
| 2 | **탭이 늘어도 화면 이동 속도가 느려지면 안 된다** | §4.3 성능 요구 |
| 3 | 탭 이동 시 브라우저 주소창 변경 | 전환 시 `pushState`. **탭 : 라우트 = N : 1** — 같은 메뉴를 여러 탭에 띄울 수 있다([51](./main-shell.md) §4.7.1) |
| 4 | **브라우저 뒤로/앞으로 = 이전 탭 / 다음 탭 이동** | §4.4 |
| 5 | 탭 우클릭 컨텍스트 메뉴 | 즐겨찾기 등록 · 즐겨찾기 제거 · 탭 닫기 · 다른 탭 닫기 · 모든 탭 닫기 |
| 6 | 새로고침 시 탭 복원 | **불필요.** **대시보드 고정 탭 + 현재 URL 의 탭**으로 시작 — [51](./main-shell.md) §2.1 |
| 7 | **드래그로 탭 순서 변경** | §4.7 |
| 8 | **탭바가 넘칠 때 좌우 스크롤** | 화살표 클릭 + 마우스 휠 — §4.7 |

### 4.2 기본 구조

- 탭 = `{key, pathname, menuCd, title, closable, favorite}`
- **`key` 는 `pathname` 이 아니라 탭 고유 식별자다.** 같은 메뉴를 여러 탭에 띄울 수 있으므로
  (*"새 탭으로 열기"* — [51](./main-shell.md) §4.7.1) 경로가 탭을 식별하지 못한다
- **대시보드는 `closable: false` 인 고정 탭**이며 항상 첫 자리다 — [51](./main-shell.md) §2.1
- 비활성 탭의 컴포넌트는 **언마운트하지 않고 숨긴다.** 검색 조건·스크롤·입력 중인 폼이
  탭 전환 후에도 보존되어야 하기 때문이다. 언마운트 방식은 멀티탭의 의미가 없다.
- 라우트 정의는 `useRoutes` 로 만들되 **탭별로 매칭한 엘리먼트를 캐시**해 재사용한다.
  엘리먼트에 **탭 `key` 를 React key 로 준다** — 같은 라우트라도 탭이 다르면 별개 인스턴스이며
  상태를 공유하지 않는다

### 4.3 성능 요구 (요구 2)

숨김 방식은 DOM 이 계속 쌓이므로, 탭 수에 비례해 느려지지 않도록 아래를 강제한다.

| 항목 | 대책 |
|---|---|
| 전환 비용 | `display:none` 토글만 — **리마운트·리페치 금지**. 전환은 O(1) |
| 레이아웃 비용 | 숨김 탭에 `content-visibility: hidden` 적용 — 브라우저가 레이아웃·페인트를 건너뜀 |
| 폴링·타이머 | 비활성 탭은 react-query `refetchInterval` 중지, `setInterval` 정지 |
| 메모리 | 탭 20개 상한 + 닫을 때 해당 탭의 쿼리 캐시 제거. **같은 메뉴의 인스턴스도 상한에 포함**된다 |
| 무거운 컴포넌트 | AG Grid 인스턴스가 동시에 여러 개 살아 있게 된다. 탭 상한을 넘기지 않는 것이 유일한 방어선 — **20개는 10개의 두 배 부담**이므로 Phase 8 측정에서 가장 먼저 확인할 값이다 |
| 검증 | **탭 20개 열린 상태의 전환 지연이 1개일 때와 같아야 한다** — Phase 8 에서 측정 |

### 4.4 브라우저 뒤로/앞으로 = 탭 이동 (요구 4)

일반적인 history back(같은 탭 내 이전 화면)이 아니라 **탭 방문 순서**를 따른다.
위치 순서로 옮기는 `PageUp`/`PageDown` 은 별개다 — [51](./main-shell.md) §10.1.

```
탭 전환 시     → history.pushState({tabKey}) — 방문 순서가 history 에 쌓인다
뒤로/앞으로     → popstate 에서 state.tabKey 를 읽어 해당 탭으로 전환
```

| 상황 | 처리 |
|---|---|
| 대상 탭이 이미 닫혔음 | **경로로 다시 맞춘다** — 그 경로의 메뉴가 있으면 탭을 열고, 없으면 대시보드로(`replace`). 아래 |
| 같은 탭을 다시 클릭 | history 엔트리 추가하지 않음 (중복 방지) |
| 탭 내부에서 상세 이동 | 탭 키가 같으므로 별도 엔트리 없음 — **탭 내 뒤로가기는 지원하지 않는다** |
| 최초 진입 | 대시보드 고정 탭 + 현재 URL 의 탭 **하나** — 새로고침하면 같은 메뉴의 인스턴스들이 하나로 합쳐진다(복원하지 않으므로) |

> **"건너뛰고 다음으로" 를 기각했다**(2026-08-29, 구현). `popstate` 안에서 다시
> `history.go(-1)` 을 부르는 방식인데, **남은 엔트리가 전부 죽었으면 앱 밖으로 걸어 나간다** —
> 사용자가 뒤로가기 한 번을 눌렀는데 사이트를 떠나는 것은 되돌릴 수 없는 실패다. 경로로 다시
> 맞추는 쪽은 결과가 예측 가능하고, 죽은 엔트리가 곧 *"그 화면을 다시 연다"* 가 되어
> 사용자의 의도에서 멀지 않다.

> **감수하는 제약**: 탭 내부의 화면 전환(목록 → 상세)에는 브라우저 뒤로가기가 동작하지 않는다.
> 뒤로가기가 탭 이동에 배정됐기 때문이다. 탭 내 복귀는 화면의 "목록으로" 버튼으로 처리한다.
> Phase 4 에서 이 트레이드오프를 목업으로 확인한다.

### 4.5 컨텍스트 메뉴 (요구 5)

| 항목 | 동작 |
|---|---|
| 즐겨찾기 메뉴로 등록 | 즐겨찾기 목록에 추가 — 진입 모달에서 본다([51](./main-shell.md) §4.3) |
| 즐겨찾기에서 제거 | 이미 즐겨찾기인 경우에만 노출 |
| 탭 닫기 | 해당 탭. dirty 폼이면 확인 |
| 다른 탭 닫기 | 현재 탭과 **대시보드**를 남김 |
| 모든 탭 닫기 | **대시보드만** 남김 — 헤더 로고와 같은 동작([51](./main-shell.md) §3.1) |

닫기 계열은 저장하지 않은 폼이 있는 탭을 만나면 **일괄 확인 다이얼로그**를 띄운다.

**대시보드 탭에서는 "탭 닫기" 가 뜨지 않는다** — 고정 탭이다([51](./main-shell.md) §2.1). "다른 탭 닫기" ·
"모든 탭 닫기" 는 그대로 동작한다.

메뉴 트리의 우클릭 메뉴는 이것과 **대칭**이며 [51](./main-shell.md) §4.7 에 있다 — 트리는 여는 방식,
탭바는 닫는 방식을 묻고 즐겨찾기 추가·제거만 공통이다.

### 4.6 화면 컴포넌트 작성 전제

멀티탭은 **같은 화면이 동시에 여러 개 살아 있을 수 있다**는 뜻이다.

- 전역 싱글턴 상태에 화면별 데이터를 두면 안 된다 (`zustand` 스토어에 목록 데이터 금지)
- 모듈 스코프 변수·전역 이벤트 리스너로 화면 상태를 관리하면 안 된다
- 서버 상태는 react-query 키로 격리한다

ESLint 규칙과 골든 레퍼런스로 강제한다.

### 4.7 탭바 조작 — 드래그 순서 변경과 가로 스크롤

상한이 20개이므로 **탭바가 넘치는 것이 기본 상태**다. 넘칠 때 탭을 줄여 다 보여주는
방식(축소)을 쓰지 않는다 — 제목이 잘려 무슨 탭인지 알 수 없게 된다. **너비를 유지하고
스크롤**한다.

| 조작 | 동작 |
|---|---|
| **드래그** | 탭 순서 변경. **대시보드는 대상이 아니고 그 앞으로 옮길 수도 없다**([51](./main-shell.md) §2.1) |
| **좌우 화살표 클릭** | 한 번에 탭 몇 개분씩 스크롤. 끝에 닿으면 비활성 |
| **마우스 휠** | 탭바 위에서 굴리면 가로 스크롤. 탭바는 한 줄이라 세로로 스크롤할 것이 없다 |
| **활성 탭 자동 노출** | 탭 전환으로 화면 밖 탭이 활성이 되면 **보이도록 스크롤한다** |

**활성 탭 자동 노출이 없으면 나머지가 무의미하다.** `PageUp`/`PageDown`([51](./main-shell.md) §10.1)이나
브라우저 뒤로가기(§4.4)로 옮긴 탭이 화면 밖이면, 사용자는 활성 탭을 찾지 못한 채
스크롤해야 한다.

- 순서는 **저장하지 않는다.** 새로고침하면 탭이 복원되지 않으므로(요구 6) 저장할 대상이 없다
- 드래그로 바꾼 순서가 곧 `PageUp`/`PageDown` 의 **위치 순서**다([51](./main-shell.md) §10.1)
- AntD `Tabs` 는 드래그 정렬을 자체 제공하지 않는다 — **`@dnd-kit`** 을 쓴다([20](../../stack.md) §2).
  메뉴 트리 편집([42](../../../knowledge/sys/menu.md) §4)과 즐겨찾기 순서 변경([51](./main-shell.md) §4.5)이 같은
  라이브러리를 쓰므로 **셋이 하나를 공유**한다 — 드래그 동작이 화면마다 다르게 느껴지지 않는다

### 4.8 상한에 닿았을 때 — 자동으로 닫지 않는다

탭이 20개인 상태에서 메뉴를 또 열면 **묻고 나서 닫는다.** 말없이 가장 오래된 탭을 닫으면
사용자는 무엇이 사라졌는지 모른 채 작업을 잃는다.

```
탭이 최대 20개입니다.

가장 먼저 연  [주문관리]  를 닫고  [사용자관리]  를 여시겠습니까?
저장하지 않은 변경이 있습니다.          <- 그 탭이 dirty 일 때만

                              [닫고 열기]  [취소]
```

| 항목 | 규칙 |
|---|---|
| 닫을 대상 | **가장 먼저 연 비고정 탭.** 대시보드는 제외한다 |
| 기준은 **연 시각** | 드래그로 위치를 바꿔도(§4.7) 대상이 바뀌지 않는다 — 위치는 순서일 뿐 나이가 아니다 |
| 대상 탭의 **제목**을 보여준다 | 무엇이 닫히는지 모르면 확인의 의미가 없다 |
| 대상이 dirty 면 | **한 줄 더 표시**한다. 확인을 두 번 받지 않는다 |
| 취소 | **새 탭을 열지 않는다.** 현재 화면 그대로 |

**닫을 대상을 사용자가 고르게 하지 않는다.** 20개 목록에서 하나를 고르는 UI 는 이 순간에
과하고, 원하는 탭이 따로 있으면 취소하고 그것을 직접 닫으면 된다 — 경로가 이미 있다(§4.5).

> **"새 브라우저 탭으로 열기"([51](./main-shell.md) §4.7.2)는 이 상한과 무관하다.** 다른 창이므로 그
> 창의 탭이 새로 세어진다. 상한이 답답할 때의 실질적인 탈출구이기도 하다.

## 5. 메뉴 기반 동적 라우팅

```
로그인 응답 { user, mustChangePassword, menus[], permissions[], menuTree[] }  ← 별도 호출 없음
  → 메뉴의 menuUrl 로 컴포넌트 정적 맵 조회 → 라우트 생성

새로고침 복원만 GET /api/common/auth/getMe 로 같은 형태를 다시 받는다
```

- 컴포넌트는 **정적 맵**으로 관리한다(`Record<string, LazyComponent>`). **키는 `MENU_URL`** 이다 —
  라우트와 맵 키가 같은 값이므로 어긋날 수가 없다. 서버가 준 문자열로 동적 import 경로를
  만들면 번들 분석이 불가능하고 보안상도 좋지 않다.
- **별도의 컴포넌트 키 컬럼을 두지 않는다.** 한 컴포넌트를 여러 메뉴가 재사용하는 경우에만
  이점이 있는데, 프론트가 서버 JAR 에 임베드되어 **원자적으로 함께 배포**되므로
  ([ADR-0001](../../../records/adr/0001-repository-layout.md)) *"프론트 배포 없이 메뉴 추가"* 라는 이점이 성립하지 않는다.
  재사용이 실제로 필요해지면 그때 `SYS_MENU` 에 컬럼을 더한다 — [42](../../../knowledge/sys/menu.md) §10.
- 메뉴에 없는 경로 접근 시 **대시보드로 보내며 토스트로 알린다**(2026-08-29, 구현). 원래는
  *"권한 없음 화면"* 이었으나, 그 화면을 탭으로 만들면 <b>메뉴가 아닌 탭</b>이 하나 생겨
  탭:메뉴 = 1:1 이 깨지고 브레드크럼·`X-Menu-Code` 가 가리킬 대상이 없어진다. 조용히 보내지
  않는 것이 요점이다 — 말없이 대시보드로 가면 사용자는 자기가 잘못 눌렀다고 생각한다.
  **없는 메뉴인지 권한이 없는 것인지 프론트는 구분하지 않는다**(트리에 없다는 사실 하나뿐이다).
- **경로 하나가 탭 여러 개에 대응할 수 있다.** 라우트 매칭은 경로로 하고, 어느 탭인지는
  `pushState` 의 `state.tabKey` 가 갖는다(§4.4).
- 코드 스플리팅: 기능별 `React.lazy`.

### 6.1 셀 데이터 타입 — 내장 9종과 커스텀 4종

AG Grid 36 의 `cellDataType` 은 아홉이며 **전부 Community** 다.

| 내장 | 기본 에디터 | 우리 쓰임 |
|---|---|---|
| `text` | `agTextCellEditor` | 문자 |
| `number` | `agNumberCellEditor` | 숫자 |
| `bigint` | `agTextCellEditor` | **생성 키 표시** — 아래 |
| `boolean` | `agCheckboxCellEditor` | 직접 쓰지 않는다 — `ynFlag` 로 감싼다 |
| `date` · `dateString` | `agDateCellEditor` · `agDateStringCellEditor` | `_DT` 컬럼([40](../../../knowledge/sys/INDEX.md) §4.3). **입력은 AntD 달력으로 교체**한다 — 필터·검색 폼과 같은 것([54](./grid-column-contract.md) §4.5) |
| `dateTime` · `dateTimeString` | 〃 | `_DTM` 컬럼 |
| `object` | `agTextCellEditor` + formatter | **쓰지 않는다** — **값이 객체인 셀**을 위한 타입이며 셀 안에 무언가를 그리는 기능이 아니다. 셀 그리기는 `renderer` 다([54](./grid-column-contract.md) §5.3 · §5.4) |

**커스텀은 넷이다.** `dataTypeDefinitions` 로 정의하며 [ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) 의 어휘에 포함된다.

| 커스텀 | `baseDataType` | 왜 필요한가 |
|---|---|---|
| **`ynFlag`** | `boolean` | DB 가 `CHAR(1) 'Y'/'N'` 이다([40](../../../knowledge/sys/INDEX.md)). AG Grid `boolean` 은 `true/false` 를 기대하므로 `valueParser`/`valueFormatter` 로 잇는다. **에디터는 체크박스가 아니라 `switch`** 이며 자체 구현이다([54](./grid-column-contract.md) §5.2) |
| **`code`** | `text` | 공통코드 값. 표시는 코드명, 저장은 코드값. 에디터는 `select` 또는 `richSelect` |
| **`popupRef`** | `text` | 모달 검색으로 고르는 참조 값 (사용자·거래처 등). `cellEditorPopup` |
| **`list`** | `object` | **배열을 담는 셀** — 바코드 스캔 묶음 등([54](./grid-column-contract.md) §5.6). 항목은 스칼라일 수도 객체일 수도 있다. **DB 컬럼이 배열인 것이 아니라 전송 형태다** — 저장은 서버가 정한다 |

`ynFlag` 는 **모든 테이블에 있는 컬럼**을 위한 것이므로 샘플만의 문제가 아니다 —
템플릿이 제공하지 않으면 화면마다 `valueGetter` 를 손으로 쓴다.

> **`bigint` 는 그리드만으로 해결되지 않는다.** JSON 파싱 시점에 이미 JS `Number` 로
> 뭉개지므로(2^53 상한 — [46](../../../knowledge/sys/batch.md) §3.1) **API 가 생성 키를 문자열로 내려야** 이 타입이
> 의미를 갖는다. 그리드 설정이 아니라 **응답 직렬화 규약**의 문제다.

### 6.2 컬럼 필터는 **조회 결과 내 필터**다 (개정 2026-08-27)

> **이전 결정은 *"컬럼 필터를 기본으로 켜지 않는다"* 였다.** 근거는 **서버 페이징에서
> 클라이언트 필터가 현재 페이지에만 걸린다**는 것이었고 **그 관찰은 그대로 유효하다.**
> 바뀐 것은 **필터를 끄는 대신 무엇을 거르고 있는지 화면이 말하게 한 것**이다 —
> [54](./grid-column-contract.md) §4.2.

| | **검색 폼**(UX-15) | **컬럼 필터** |
|---|---|---|
| 묻는 것 | *"무엇을 가져올까"* | *"가져온 것 중 무엇을 볼까"* |
| 거르는 곳 | **서버** — 조회 조건 | **클라이언트** — 로드된 행 |
| 총 건수 | 다시 계산된다 | **바뀌지 않는다** |

**둘은 성격이 다른 도구이며 컬럼 필터는 서버 조회 조건이 아니다.** 서버로 올리면 검색
폼과 같은 것이 둘이 되고 사용자가 같은 조건을 두 곳에서 걸 수 있게 된다.

- **정렬은 반대로 서버가 한다**([54](./grid-column-contract.md) §3) — 현재 페이지만 정렬하면 쓸모가 통째로
  사라지기 때문이다. 비대칭이 의도다
- 오해를 막는 장치는 셋이다 — **건수 표기**(`이 페이지 20건 중 7건`) · **걸린 컬럼 헤더
  표시** · **초기화가 함께 지움**([54](./grid-column-contract.md) §4.2)
- Community 의 필터는 텍스트·숫자·날짜 셋이고 **Set Filter 는 Enterprise** 다.
  `ynFlag`·`code` 의 체크박스 목록은 **자체 구현**한다([ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) · [54](./grid-column-contract.md) §7)
- 필터 유형·모양·목록의 출처는 **[54](./grid-column-contract.md) §4** 가 갖는다

### 종속 콤보 — `<CodeSelect filterBy>`

부모 콤보의 선택으로 자식 목록을 좁힌다. 화면 코드에 분기를 두지 않는다.

```tsx
<CodeSelect codeGrp="ORDER_KIND" value={kind} onChange={setKind} />
<CodeSelect codeGrp="ORDER_TYPE" filterBy={{ ORDER_KIND: kind }} />
```

컴포넌트가 참조 코드에서 `REF_CD` 를 **규약으로 도출**한다 — 매핑 테이블을 코드에 두지 않는다.

| 데이터 형태 | 도출 |
|---|---|
| 단일 부모 | `REF_CD = 'ORDER_KIND'`, `REF_VAL = kind` |
| 다중 부모 | `REF_CD = 'IS_' + kind`, `REF_VAL = 'Y'` |

어느 형태인지는 **데이터에서 판별**한다(그룹에 `IS_*` 참조가 있는지).
상세: [10-feature-inventory](../../../knowledge/features.md) MASTER-10

> **부모가 바뀌면 자식의 현재 값을 검증하고, 유효하지 않으면 초기화한다.**
> 구분을 출고→입고로 바꿨는데 유형에 `B2B` 가 남아 있으면 화면은 정상으로 보이고
> **저장 시점에 깨진다.** 종속 콤보의 전형적인 버그이므로 컴포넌트 계약에 포함한다.

| **그리드 컬럼 너비** (UX-06) | localStorage — 해상도·화면 비율에 딸린 값 |

전역 스토어에 서버 데이터를 복사해 넣지 않는다.

**UI 설정을 계정에 묶지 않는다.** PC 마다 해상도·화면 비율이 달라 레이아웃 설정을 서버에
저장하면 다른 자리에서 로그인할 때마다 어긋난다. 즐겨찾기가 서버인 것은 모순이 아니다 —
그것은 레이아웃이 아니라 **사용자가 명시적으로 선언한 목록**이고 화면 크기와 무관하다
([42](../../../knowledge/sys/menu.md) §7).

> **그리드 설정은 갈라 둔다 (UX-06, 확정).** **순서·표시여부는 DB**, **너비는 localStorage** 다.
> 너비는 해상도·화면 비율에 딸린 값이라 계정에 묶으면 다른 자리에서 어긋나고, 순서·표시여부는
> 화면 크기와 무관한 *"나는 이 컬럼을 이 순서로 본다"* 다. 사용자가 실제로 개인화하려는 것도
> 순서·표시여부이며 너비는 내용이 보이면 그만이다 — [41](../../../knowledge/sys/user-role.md) §4.3.
>
> 한 그리드의 설정이 두 곳에 나뉘는 것은 감수한다. 시그니처 무효화(UX-13)의 본체는 **DB 쪽**이다 —
> 순서가 깨지면 화면이 어긋나지만, 모르는 컬럼의 너비는 무시하면 된다.

> **UI 설정 중 언어만 서버인 이유는 서버가 알아야 하기 때문이다.** 메일·알림을 어느
> 언어로 보낼지 결정하는 것은 서버이고 `localStorage` 는 서버가 볼 수 없다
> → [41](../../../knowledge/sys/user-role.md) §4.3 · [51](./main-shell.md) §9.1

### 8.1 스토어 셋 — zustand 이며 브라우저 저장소가 아니다

`authStore` · `tabStore` · `uiStore` 는 **zustand 스토어**다([20](../../stack.md) §2).
이름이 `localStorage` 처럼 읽히지만 **브라우저가 제공하는 것이 아니다.**

| | `localStorage` | 스토어 |
|---|---|---|
| 제공자 | **브라우저** (Web Storage API) | **zustand** — 앱 코드 |
| 사는 곳 | 디스크, 오리진별 | **JS 메모리** (모듈 스코프) |
| 수명 | 지워야 사라진다 | **탭 닫기 · F5 에 사라진다** |
| 담는 값 | 문자열만 | 임의 JS 객체 |
| 변경 감지 | `storage` 이벤트 (다른 브라우저 탭) | 구독 → 리렌더 |

`window` 에 붙는 전역 변수도 아니다 — `import` 한 파일에서만 접근한다.

| 스토어 | 담는 것 | 채우는 시점 | 비우는 시점 | `persist` |
|---|---|---|---|---|
| **`authStore`** | `user` · `permissions` · `menus` | 로그인 응답 · 새로고침 복원(`/auth/me`) | **로그아웃 정리만** — 세션 만료는 비우지 않는다 | **안 쓴다** |
| **`tabStore`** | 탭 목록 · 활성 탭 · 탭별 라우트·파라미터 | 메뉴 열기 | 로그아웃 정리 · 로고 클릭([51](./main-shell.md) §3.1) · F5 | **안 쓴다** |
| **`uiStore`** | 테마 · 접힘 · 밀도 · 폰트 · 그리드 높이 | `localStorage` 에서 복원 | **비우지 않는다** | **쓴다** |
| **`messageStore`** | 번들 · 언어 · 버전 | 부팅 시 1회(화면 흐름 §3) · 로그인 응답과 비교 | **비우지 않는다** — 로그아웃해도 유효하다 | **안 쓴다** — 아래 |

- **`messageStore` 는 `persist` 를 쓰지 않고 `localStorage` 를 직접 다룬다**(2026-08-29).
  저장 키에 **언어 축**이 붙고(`backoffice.message:ko`) 버전과 한 덩어리로 넣고 빼야 하는데,
  `persist` 는 스토어 하나에 키 하나다 — 언어를 바꿀 때마다 옛 언어의 번들이 덮여 다음
  접속에 전량을 다시 받는다
- **`label()` 은 훅이 아니라 함수다.** 모달 콜백·토스트·스토어 안에서도 불러야 하기
  때문이며, 그래서 스스로 구독하지 않는다. 대신 **`AppProviders` 가 한 번 구독**해 언어·버전이
  바뀌면 트리 전체가 다시 그려진다 — `key` 를 바꾸는 것이 아니므로 **열린 탭과 입력값은
  그대로 남는다**

- **`authStore` 에 `persist` 를 붙이지 않는 것이 결정이다.** 붙이면 로그아웃 뒤에도 그 PC 에
  이전 사용자의 메뉴 구조가 남는다(화면 흐름 §5.1). **F5 당 왕복 하나**를 그 대가로 감수한다
- **`authStore` 와 `tabStore` 는 같은 메모리 수명을 갖는다.** 그래서 *"탭이 살아 있으면
  로그인 ID 도 있다"* 가 항상 참이고, 재인증 모달의 판정이 **별도 플래그 없이** 성립한다
  ([ADR-0021](../../../records/adr/0021-reauth-modal-preserves-tabs.md) · 화면 흐름 §7.1)
- **폼 입력값·스크롤은 스토어에 없다.** 비활성 탭의 컴포넌트를 **언마운트하지 않고 숨기므로**
  (§4) 컴포넌트 안에 그대로 남는다. `tabStore` 는 *"어떤 탭이 열려 있는가"* 만 안다
- `uiStore` 만 `persist` 를 쓴다 — **기기의 속성**이므로 로그아웃해도 남아야 한다(§8 표)

> **스토어에 서버 데이터를 복사해 넣지 않는다**(§8)는 규칙이 `authStore` 에는 예외처럼
> 보인다. 아니다 — `menus`·`permissions` 는 **조회 결과가 아니라 세션의 속성**이며 화면이
> 아니라 셸이 쓴다. 목록·상세 데이터는 react-query 가 갖는다.

## 9. API 통신 규약 (프론트 측)

| 항목 | 처리 |
|---|---|
| baseURL | `/api` (동일 오리진). 계층 프리픽스(`public`/`common`/`service`)는 [23](../../backend/_study/security-design.md) §4 |
| **URL 선언** | 호출 URL 은 `features/{도메인}/api/endpoints.ts` 에 모으고 **화면은 그 상수만 쓴다.** URL 문자열 리터럴은 ESLint 로 금지한다 — **`baseURL` 이 `/api` 라 실제 선언은 계층 마디부터 시작하므로**(`/common/auth/me`) 금지 규칙도 `/api/` 와 `/public|/common|/service` 를 **둘 다** 잡아야 한다. 앞의 것만 두면 게이트가 조용히 빈다 — 이 선언이 `SYS_MENU_API` 시드의 입력이므로([ADR-0020](../../../records/adr/0020-path-prefix-action-and-seed-generation.md)) **선언 = 사용**이 구조적으로 보장돼야 한다. 선언만 하고 쓰지 않으면 접근 범위가 조용히 넓어진다 |
| **HTTP 층의 입구** | `get`·`post`·`request`·`ApiError` 를 **`@/shared/api` 배럴에서만** 가져온다. `@/shared/api/*` 딥 임포트는 ESLint 로 금지한다(`no-restricted-imports`) — 배럴 안쪽은 예외다(순환). **같은 헬퍼가 두 경로로 들어오면 새 화면이 무엇을 따라야 할지 알 수 없다**(2026-09-02 실측: 딥 14곳 · 배럴 10곳). 배럴에 없는 것은 바깥에서 쓸 것이 아니며, 필요하면 `index.ts` 를 고친다 |
| **호출을 감싸는 자리** | 기능의 HTTP 호출은 **`features/{도메인}/api/{도메인}Api.ts` 함수**로 감싼다 — 화면에는 `post<T>(URL, {…})` 가 남지 않는다. 파일 이름은 **폴더 이름 그대로**이며(`features/code/api/codeApi.ts`) 계층이 다르면 같은 이름이 둘일 수 있다(`shared/code/api/codeApi.ts` — 공통 코드 조회). **예외는 그리드 선언이다**: `read`·`save`·`actions` 는 URL 을 그대로 받는 것이 `<DataGrid>` 의 계약이고([55](./grid-api-contract.md) §3), 그 자리를 함수로 감싸면 컨트롤러가 인자를 다시 나열하게 된다. **열한 기능이 화면에서 직접 부르고 있었다**(2026-09-02) — 같은 질의의 페이지 크기·기본 조건이 화면마다 달라지는 자리다 |
| 인증 | 세션 쿠키 자동. `withCredentials: true` |
| CSRF | `XSRF-TOKEN` 쿠키 → `X-XSRF-TOKEN` 헤더 (axios 기본 동작) |
| **request-id** | 요청마다 UUID 를 **헤더 `X-Request-Id` + 쿼리 `_rid` 양쪽**에 부착. `crypto.randomUUID` **폴백 필수**(secure context 전용) → [29](../../backend/crosscutting.md) §8 |
| **menu-code** | 활성 탭(현재 라우트)의 메뉴 코드를 `X-Menu-Code` 헤더로 매 요청 부착 — 사용 이력·메뉴 활용도용(→ [21](../../backend/_study/architecture.md) §6). 메뉴 문맥 없는 호출(로그인, 하트비트)은 생략 |
| 중복 응답 | `code === 'err.duplicate-request'` 는 **일반 실패 처리보다 먼저 무음 통과** |
| **401** | **재인증 모달** — 탭·입력값을 그대로 두고 셸 위에 띄운다(화면 흐름 §7.1). 곧바로 로그아웃하지 않는다. 재인증이 불가능하거나 사용자가 포기하면 그때 전역 로그아웃(화면 흐름 §9) |
| 403 | 권한 없음 화면 또는 토스트 |
| 5xx | 공통 에러 토스트 + `traceId` 표시 (운영 문의 시 사용) |
| 로딩 | react-query 상태 사용. 전역 스피너는 최소화 |

### TypeScript 는 **6.0.3** 이다 — 7 은 린트가 막는다 (2026-08-28)

프론트 슬라이스에서 스파이크를 돌린 결과다. **폴백을 쓰되 폴백 대상이 문서가 적어 둔
`TS 5.x` 가 아니다** — `6.0.3` 이 GA 이며 typescript-eslint 가 지원하는 상한 안이다.

| 무엇을 확인했나 | 결과 |
|---|---|
| **빌드** — `tsc -b && vite build` | **TS 7.0.2 로 통과한다.** 막힌 것은 빌드가 아니다 |
| **린트** — typescript-eslint 8.68.0 | **거부한다.** 낡은 peer 범위가 아니라 런타임에서 명시적으로 던진다 — *"typescript-eslint does not support TS 7.0"*. peer 는 `>=4.8.4 <6.1.0` 이고 canary 도 같다. [추적 이슈 #10940](https://github.com/typescript-eslint/typescript-eslint/issues/10940) 은 **TS >= 7.1** 을 목표로 한다 |
| **병행 설치** — TS 7 은 빌드, TS 6 은 린트 | **안 된다.** npm 이 `typescript` 를 루트로 호이스팅해 `overrides` 로 눌러도 typescript-eslint 가 7 을 집는다 |
| **TS 6.0.3** | 빌드·타입인지 린트 모두 통과. `npm ci` 재현성도 확인 |

**TS 7 로 올릴 때 고칠 것이 이미 하나 나와 있다** — `baseUrl` 이 제거됐다(`TS5102`).
`paths` 만 남기고 tsconfig 기준 상대경로로 쓰면 된다. **7.1 에서 typescript-eslint 가
지원되면 그때 올린다.**

### 툴체인이 정정한 것 셋 (2026-08-28)

| 무엇 | 사실 |
|---|---|
| **ESLint 10 × `eslint-plugin-import`** | 그 플러그인의 peer 가 `^9` 에서 멈춰 `npm ci` 가 실패한다. **`eslint-plugin-import-x`** 로 교체했다 — 같은 규칙에 `import-x/` 접두이며 eslint 10 을 지원한다 |
