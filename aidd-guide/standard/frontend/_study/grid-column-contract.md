### 1.1 `53` · `56` 과의 분담

| | [53](./grid-standard.md) | 여기 | [56](./grid-edit-validation.md) |
|---|---|---|---|
| 관점 | **화면을 배치하는 사람** | **컬럼을 선언하는 사람** | **편집을 설계하는 사람** |
| 답하는 질문 | 버튼이 어디 있나 · 저장은 언제 나가나 · 디테일은 언제 열리나 | 이 컬럼은 어떻게 정렬·필터·표시되고 **어느 에디터**를 쓰나 | 이 셀을 고칠 수 있나 · 고치면 무엇이 따라오나 · 무엇이 통과를 막나 |
| 단위 | 그리드 하나 | 컬럼 하나 | 한 번의 편집 · 한 번의 검증 |

**셋 다 Phase 6 공통 컴포넌트의 요구사항이다.** 컴포넌트가 이 계약을 만족하면 화면은
**컬럼 배열만 선언**한다.

> **조회 전용 그리드는 여기까지만 읽으면 된다.** [56](./grid-edit-validation.md) 을 갈라낸 것이 그래서다 —
> 컬럼을 선언하는 일과 편집을 설계하는 일은 **같은 순간에 하지 않는다**.

> **검색 폼에는 이 문서의 짝이 아직 없다.** 여기가 *그리드 컬럼 하나*를 선언하는 계약이라면
> **[57](./search-form-contract.md)** 가 *검색 폼 필드 하나*에 대해 같은 일을 한다 —
> 타입 · 연산자 고정 · 기본값 · **조건부** · 폭 · 접기 · 저장된 조건의 직렬화(설계 개요 §4).
> **§4.1 이 컬럼 필터와 검색 폼의 역할을 가른 것**이 그 경계의 시작이다.

### 1.2 어휘는 우리 것이고 판은 어댑터가 고른다

[ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) 이 정한 대로 **화면은 `ag-grid` 를 import 하지 않는다.** 아래 모든 키는
우리 어휘이며, AG Grid `colDef` 로의 변환은 `shared/grid/` 의 어댑터가 한다. Community 에
없는 것은 어댑터가 **자체 구현으로 채운다**(§7) — 화면은 그 차이를 모른다.

## 2. 컬럼 선언 — 한눈에

```ts
{
  field:     'productId',
  header:    'col.product.id',        // 메시지 키 — 43 §3
  type:      'popupRef',              // 24 §6.1 의 13종 중 하나
  width:     120,
  pinned:    'left',                  // 53 §4 — 사용자가 그리드 설정에서 바꾼다
  visible:   true,                    // §2.1 — 초기 표시. 꺼도 설정 창에서 켤 수 있다
  hidden:    false,                   // §2.1 — true 면 설정 창에도 없다. 켤 수 없다

  pk:        true,                    // §5.1 — 신규만 · 필수 · 헤더 `*`. 예외는 { renamable: true }
  sortable:  true,                    // §3
  filter:    'set',                   // §4 — 생략하면 타입이 정한다
  filterOptions: [...],               // set 필터의 표시 순서·라벨을 선언할 때(§4.4)

  options:   (row) => [...],          // §5.7 — richSelect 의 후보. 배열 또는 함수
  nullable:  true,                    // §5.7 — 목록에 (없음) 을 낸다

  renderer:  'badge',                 // §5.4 — 표시만 바꾼다. 값은 원본
  tone:      { … } | [ … ],           // §5.4.1 — badge 의 색을 묶음이 정할 때. 맵이지 함수가 아니다
  display:   (item) => `…`,           // §5.6 — type 이 'list' 이고 항목이 객체일 때
  precision: 'month',                 // §4.5 — 날짜 계열의 정밀도
  editor:    'popupRef',              // §5 — 생략하면 타입이 정한다
  editable:  (row) => …,              // [56] §2.1 — true | false | 함수
  required:  true,                    // §5.1 — true | false | 함수
  popup:     { key, param, apply },   // §6
  afterEdit: (row) => ({ … }),        // [56] §2.3
  validate:  (v, row) => msg | null,  // [56] §3.2
}
```

| 키 | 없으면 | 절 |
|---|---|---|
| `visible` | **`true`** — 보인다 | §2.1 |
| `hidden` | **`false`** — 설정 창 목록에 있다 | §2.1 |
| `sortable` | **`true`** — 파생·시스템 컬럼만 끈다 | §3 |
| `filter` | **타입이 정한다** — `false` 로 끈다 | §4.3 |
| `renderer` | **없다** — 값 그대로 | §5.4 |
| `tone` | **없다** — 코드가 색을 정한다. 맵에 없는 값은 **칠하지 않는다** | §5.4.1 |
| `editor` | 타입이 정한다 | §5 |
| `options` · `nullable` | 없다 — `richSelect` 가 아니면 읽지 않는다 | §5.7 |
| `pk` | **`false`** — 보통 컬럼이다 | §5.1 |
| `editable` | **`false`** — 편집은 명시해야 열린다 | [56](./grid-edit-validation.md) §2.1 |
| `required` | **`false`** | §5.1 |
| `validate` · `afterEdit` | 없다 | [56](./grid-edit-validation.md) §2·§3 |
| `popup` | 없다 | §6 |
| `width` | 판의 기본. **선언한 값은 헤더가 잘리지 않을 폭까지 넓혀진다**(아래) | §2 |

> **`width` 는 최소 폭이 아니라 *바닥값이 하나 더 있는* 값이다**(2026-08-31 — 구현).
> 선언의 폭은 **값**을 보고 고른 숫자다(`90` 짜리 `ynFlag` 칸). 그런데 헤더는 다국어이고
> **한글이 라틴 글자보다 넓어**, 같은 컬럼이 영어에서는 남고 한글에서는 말줄임표가 됐다.
> 그래서 어댑터가 **헤더 글자를 실제로 재고**(캔버스 측정) 그보다 좁은 선언은 그 폭까지
> 넓힌다 — 시스템 컬럼(번호·상태·삭제)도 같다. 층 순서는 **선언 → 헤더 바닥값 → 사용자가
> 끈 폭**이며 마지막이 이긴다([53](./grid-standard.md) §5).
>
> **판의 자동 맞춤(`autoSizeColumns`)을 쓰지 않는다.** 그것은 **값까지** 재므로 긴 값 하나가
> 컬럼을 화면 밖으로 밀고, 사용자가 끌어 놓은 폭과 **매 조회마다 다툰다**.
> `wrapHeaderText` 로 두 줄을 허용하는 안도 버렸다 — 하단 탭처럼 낮은 판에서 그 한 줄이
> **본문에서 나온다**.
>
> **어림하면 아무것도 안 넓어진다**(2026-08-31 — 한 번 어림했다). 여백 몫을 `26 + 20` 으로
> 두었더니 계산한 최소 폭이 **선언한 폭보다 작아** 넓혀지는 컬럼이 하나도 없었고, 화면은
> 고치기 전과 똑같았다 — `계정 상태`(선언 100)가 그대로 잘려 있었다.
>
> 값은 **판의 테마 기본값에서 옮겨 적는다**(ag-grid 36, `themeQuartz` 도 우리 테마도 이것들을
> 덮지 않는다).
>
> | 파라미터 | 값 | 헤더가 쓰는 몫 |
> |---|---|---|
> | `spacing` | 8 | 아래 둘의 바탕 |
> | `cellHorizontalPadding` | `spacing * 2 * scale` = 16 | **양쪽이라 32** |
> | `cellWidgetSpacing` | `spacing * 1.5` = 12 | 글자와 아이콘 사이 |
> | `iconSize` | 16 | 정렬 화살표 · **필터 버튼** — 각각 12 + 16 = **28** |
> | `headerFontWeight` | **500** | 재는 글꼴의 굵기 — 본문(`fontWeight`)이 아니다 |
> | 여유 | **4** | 아이콘 셋마다 16~18 로 갈리고 반올림이 겹친다 |
>
> **필터 버튼을 잊지 않는다.** 판은 **필터를 걸 수 있는 컬럼이면 언제나** 헤더에 그 버튼을
> 그린다(`!suppressHeaderFilterButton && isFilterAllowed`) — 우리는 컬럼 **메뉴**만 껐고
> (`suppressHeaderMenuButton`) 이 버튼은 켜져 있으며, 메뉴 버튼과 달리 `opacity: 1` 이라
> **늘 보인다**. *걸렸을 때만 붙는다* 로 읽고 자리를 비워 두지 않으면 필터 있는 컬럼이
> 계속 잘린다.
>
> **굵기가 본문의 것이 아니다.** `headerFontWeight` 는 `ref: 'fontWeight'` 가 아니라 리터럴
> 500 이라 본문 굵기를 바꿔도 따라오지 않는다 — 400 으로 재면 실제보다 좁게 나온다.
>
> **하나를 바꾸는 날 이 상수도 함께 바뀐다.** 어긋나면 증상이 조용하다(헤더가 다시 잘린다) —
> 그래서 `headerWidth.test.ts` 가 더하는 몫을 값으로 못박는다.
> **`editable` 의 기본이 `false` 인 것이 의도다.** 편집 가능한 컬럼이 소수이며([61](../../../../documents/screen/user/requirements.md) §3.2),
> 기본이 열려 있으면 **읽기 전용이어야 할 컬럼을 빠뜨렸을 때 조용히 편집된다.**
> `deny by default` 와 같은 방향이다([23](../../backend/_study/security-design.md) §4).

### 2.1 숨김은 두 층이다 — `visible` 과 `hidden`

*"지금은 안 보이지만 켤 수 있다"* 와 *"켤 수단이 없다"* 는 **다른 것**이다. 키 하나로
적으면 뒤쪽을 말할 방법이 없어 **화면마다 특례로 새는데**, 상태·삭제 컬럼이 이미 그
특례였다([53](./grid-standard.md) §4). 키를 둘로 가른다.

| | `visible: false` | `hidden: true` |
|---|---|---|
| 초기 화면 | 안 보인다 | 안 보인다 |
| **그리드 설정 창의 컬럼 목록**([53](./grid-standard.md) §5) | **있다** — 체크가 꺼진 채로 | **없다** |
| 사용자가 켤 수 있나 | **그렇다** | **아니다** |
| 개인화 저장(DB) | 대상이다 | **대상이 아니다** — 저장할 상태가 없다 |
| 정렬 · 필터 | 켠 뒤에 건다 | **불가** — 걸 헤더가 없다 |
| 편집 · 검증 | 켠 뒤에 돈다 | **불가** — 아래 불변식 |
| 엑셀([53](./grid-standard.md) §2.2) | **꺼져 있으면 안 나간다** | **언제나 안 나간다** |
| 응답 데이터 | 들어 있다 | **들어 있다** |
| 누가 정하나 | 화면이 **초기값**만, 그 뒤로는 사용자 | **화면만** |

기본은 `visible: true` · `hidden: false` 다 — **아무 것도 쓰지 않으면 보인다.**

#### 둘이 엇갈리면 `hidden` 이 이긴다

`hidden: true` 이면 **`visible` 을 읽지 않는다.** 목록에 줄이 없으므로 그 줄의 체크 상태를
물을 자리가 없다. `editable` 의 기본이 `false` 인 것과 같은 방향이다 — **막는 쪽으로
붙인다**([23](../../backend/_study/security-design.md) §4).

> **이름이 비슷해 보이는 것을 안다.** `visible: false` 와 `hidden: true` 는 소리 내어 읽으면
> 같은 말이다. 가르는 기준은 하나뿐이다 — **설정 창에 그 줄이 있는가.**
> **`visible` 은 줄의 체크 상태**를 정하고 **`hidden` 은 줄의 존재**를 정한다.

#### `visible` 은 편의고 `hidden` 은 통제다

| | 왜 쓰나 | 실물 |
|---|---|---|
| `visible: false` | 컬럼이 많아 **첫 화면이 넓어지는 것**을 막는다 — 필요한 사람이 켠다 | [61](../../../../documents/screen/user/requirements.md) §3.2 의 `○` 컬럼 — 잠금 · 휴면 · 언어 · 감사 4컬럼 등 일곱 줄 |
| `hidden: true` | **켜져서는 안 되는 컬럼**이다 — 권한·화면 모드에 따라 없어야 하는 것, `afterEdit` 가 채워 **서버로만 가는** 파생값([56](./grid-edit-validation.md) §2.3), 렌더러·`editable` 함수가 **근거로만** 읽는 플래그 | Phase 8 샘플 |

고를 때 묻는 것은 하나다 — ***"사용자가 이것을 켜도 되는가."*** **`visible: false` 로
통제하려 들면 통제가 되지 않고**(설정 창에서 켜면 그만이다), 감추기만 하면 될 컬럼에
`hidden` 을 쓰면 **아무도 그 컬럼을 볼 수 없게 된다.**

> **`hidden` 은 표시를 막을 뿐 데이터를 지우지 않는다.** 값은 응답에 그대로 있어 개발자
> 도구에서 보인다. **보여서는 안 되는 값은 서버가 응답에서 빼야 한다**([23](../../backend/_study/security-design.md) §4 ·
> [27](../../backend/pii-vault.md)) — `hidden` 은 그 자리를 대신하지 못한다. 여기서 막는 것은 **화면의 혼잡**이지
> **접근**이 아니다.

#### 불변식 — `hidden` 컬럼은 편집 대상이 아니다

`hidden` 컬럼에 `editable` · `required` · `validate` 를 선언하지 않는다. 검증이 실패하면
[56](./grid-edit-validation.md) §3.3 이 **그 셀로 포커스를 옮겨야 하는데** 사용자가 열 수 없는 컬럼에는 옮길 곳이
없다 — *"포커스를 줄 수 없는 곳에 오류를 남기지 않는다"* 가 그 절의 규칙이다. 선언되어
있으면 **어댑터가 무시하고 개발 모드에서 경고**한다.

**`visible: false` 는 다르다** — 켤 수 있으므로 편집·검증이 정상으로 돈다. 꺼진 컬럼에
실패가 나면 **그 컬럼을 켜고 셀로 이동한다**([56](./grid-edit-validation.md) §3.3) — 필터로 숨겨진 행을 필터를
풀고 찾아가는 것과 같은 규칙이다.

#### 시스템 컬럼은 `hidden` 이 아니다

상태 · 삭제 컬럼도 설정 창 목록에 없지만([53](./grid-standard.md) §4) **성질이 다르다.**

| | 화면 | 설정 창 목록 | 선언하는 주체 |
|---|---|---|---|
| 상태 · 삭제 컬럼 | **보인다** — 항상 | 없다 | **컴포넌트**가 붙인다 |
| `hidden: true` | 안 보인다 | 없다 | 화면 |
| **동적 컬럼**(§2.2) | **보인다** | 없다 | **데이터** |

*"보이지만 끌 수 없는 것"* · *"처음부터 없는 것"* · *"화면의 것이 아닌 것"* 이다.
목록에 없는 이유가 셋이므로

```
설정 창의 목록 = 전체 컬럼 − 시스템 컬럼 − hidden − 동적 컬럼
```

이며 **UX-13 의 시그니처도 이 목록으로 계산한다**([53](./grid-standard.md) §5) — 그 컬럼들이 늘거나
줄어도 사용자의 저장된 설정을 폐기할 이유가 없다.

### 2.2 컬럼 목록이 **데이터에서 오는 경우** — 동적 컬럼

지금까지의 선언은 **화면이 소스에 적는 것**이었다. 컬럼 하나가 **런타임 데이터 한 행**에서
나오는 그리드가 있다 — 첫 실물은 `CODE_MGMT` 의 참조 코드다([63](../../../../documents/screen/code/requirements.md) §2.4 · [ADR-0025](../../../records/adr/0025-reference-code-definition-and-dynamic-columns.md)).

> **섰다 (2026-08-30).** 어휘는 `ColumnDef.dynamic` 과 `patch` 둘이다 — 앞엣것이 *데이터에서
> 온 컬럼* 임을 말하고(헤더가 메시지 키가 아니며 설정 창·시그니처에서 빠진다), 뒤엣것이
> **맵의 한 칸에 되쓰는 방법**이다. 읽기는 이미 있던 `derive` 를 쓴다.
>
> **읽고 쓰는 규칙을 한 파일에 모았다**(`shared/grid/cell.ts`). 어댑터·검증·엑셀이 각자
> `row[field]` 를 하고 있었는데, 파생·동적 컬럼에서는 그것이 틀리고 **한 곳만 고쳐지면
> 조용히 갈린다** — 셀에는 보이는데 파일에는 빈 칸인 식이다.

```
마스터(그룹) 선택 → 정의 N행 조회 → 컬럼 = 고정 컬럼 + N
                 → 셀 = row.refs[REF_CD]
```

| 키 | 동적 컬럼에서 |
|---|---|
| `colId` | **직접 준다** — `ref.{REF_CD}`. 없으면 `field` 로 유추되어 **교체마다 컬럼 상태가 끊긴다** |
| `header` | **메시지 키가 아니다** — §2 계약의 **예외**다. 아래 |
| 값 접근 | **`valueGetter` / `valueSetter`** 로 맵을 읽고 쓴다 |
| 설정 창 · 시그니처 | **둘 다에서 빠진다** — §2.1 · [53](./grid-standard.md) §5 |

#### `header` 가 메시지 키가 아닌 유일한 자리다

§2 는 `header` 를 **메시지 키**로 정했다([43](../../../knowledge/sys/code.md) §3). 동적 컬럼의 헤더는 **정의 행의
명칭 컬럼**이다 — 근거는 43 §3 이 이미 둔 예외, **관리 화면 전용 명칭은 다국어가 아니다**
이며 `GRP_NM` 이 셀 값으로 다국어가 아닌 것과 **같은 자리**다.

**전역 코드명으로 대신할 수 없다.** 같은 `REF_CD` 를 그룹마다 다르게 부르는 것이 그
컬럼의 존재 이유이기 때문이다([43](../../../knowledge/sys/code.md) §5.2).

#### 값은 맵이고, 전송 형태다

행은 `refs: { REF_CD: REF_VAL }` 를 갖는다. **§5.6 의 `list` 와 같은 성격**이다 —
*"배열은 전송 형태이지 저장 형태가 아니다"* 가 맵에도 그대로 걸린다. 서버는 **정의 목록을
루프**해서 값 테이블에 쓴다.

- **빈 셀은 값이 없는 것이고, 비우면 지운다**([43](../../../knowledge/sys/code.md) §5.4) — 빈 문자열을 저장하지 않는다
- **`valueSetter` 가 필요한 이유**가 실질적이다. 편집한 값을 맵에 되써야 하고 그 맵이
  곧 저장 페이로드다

#### 컬럼을 쓸 수 있는 조건 — [63](../../../../documents/screen/code/requirements.md) §2.3 이 언어에 대해 거부한 것과 갈린다

63 §2.3 은 **언어를 컬럼으로 두는 것을 거부**했다(*"그리드가 옆으로 자라고 저장된 컬럼
목록이 어긋난다"*). **경고는 유효하고, 갈리는 지점이 둘이다.**

| | 언어 (거부) | 참조값 (채택) |
|---|---|---|
| 값의 크기 | **긴 텍스트** — 셀이 좁아 못 쓴다([63](../../../../documents/screen/code/requirements.md) §3.5) | `VARCHAR(200)` **짧은 값** |
| 행으로 둘 자리 | **있었다** — 키 × 언어가 자연스러운 행 집합 | 있었지만 **모달이라 한눈에 못 봤다** |
| 성격 | **목록** | **매트릭스** — 빈 칸이 곧 할 일이다 |

**판별은 *매트릭스인가* 다.** 빈 칸 자체가 정보인 데이터는 컬럼이고, 항목을 나열하는
데이터는 행이다. *"저장된 컬럼 목록이 어긋난다"* 는 쪽은 §2.1 의 시그니처 규칙이 받는다.

## 3. 정렬 — 헤더 클릭 3단계, 판정은 서버

**헤더를 클릭할 때마다 오름차순 → 내림차순 → 없음(원래대로)** 을 돈다. AG Grid 기본
동작이며 `sortingOrder` 로 3단계를 명시한다.

| 상태 | 무엇 |
|---|---|
| 오름차순 | `ORDER BY {컬럼} ASC` |
| 내림차순 | `ORDER BY {컬럼} DESC` |
| **없음** | 화면이 선언한 **기본 정렬**로 돌아간다. 기본 정렬이 없으면 서버의 기본 순서 |

- **정렬은 서버가 한다.** 서버 페이징이므로 현재 페이지만 정렬하면 *"전체에서 가장 큰 값"*
  을 묻는 사용자에게 **현재 페이지에서 가장 큰 값**을 보여주게 된다 — 정렬의 쓸모가
  통째로 사라진다
- 정렬이 바뀌면 **페이지를 1로 되돌린다.** 3페이지를 보다 정렬을 바꾸면 그 3페이지는
  다른 데이터다
- **미저장 변경이 있으면 확인 다이얼로그를 띄운다** — 정렬은 재조회이므로 상태가 붙은
  행이 사라진다. 조회·페이지 이동·페이지 사이즈와 **한 규칙**이다([53](./grid-standard.md) §3.1)
- **기본은 단일 정렬**이다. 다중 정렬(`Shift`+클릭)은 화면이 `multiSort: true` 로 켠다 —
  프로토콜은 처음부터 배열로 받아 두고(`sorts: [{field, dir}]`) 기본이 원소 하나일 뿐이다.
  **[72](../../backend/_study/api-conventions.md) §3.7 이 그대로 확정했다**
- **응답이 `mode: 'all'` 이면 정렬도 클라이언트다**([72](../../backend/_study/api-conventions.md) §3.8) — 페이지가 없으니
  *현재 페이지만 정렬한다* 는 문제가 성립하지 않는다. **재조회가 없으므로 편집 중에도
  정렬할 수 있고**, 위 넷의 어긋남도 비교 대상이 없어 사라진다.
  **`offset` 은 결과가 1페이지여도 서버 정렬이다** — 건수에 따라 동작이 갈리면
  사용자가 배운 것이 어느 날 틀리게 된다(〃)
- **응답이 `mode: 'cursor'` 면 `multiSort` 가 꺼진다** — 커서형은 정렬 키가 하나여야
  성립하므로 `sorts` 원소가 둘 이상이면 **400** 이다([72](../../backend/_study/api-conventions.md) §3.8). 화면이 `multiSort`
  를 켜 두었어도 **응답이 커서형이면 그리드가 `Shift`+클릭을 받지 않는다** — 선언보다
  **응답이 진실**이므로 *"켜 놨는데 400 이 난다"* 가 생기지 않는다
- **tie-breaker 는 서버가 붙인다** — 클라이언트가 보내지 않는다([72](../../backend/_study/api-conventions.md) §3.7).
  [22](../../backend/_study/db-portability.md) §4.5 가 *"`ORDER BY` 에 항상 명시적 tie-breaker(PK) 추가"* 라고 정했는데,
  화면에 맡기면 **빠뜨린 곳에서만 페이징이 흔들리고** 증상이 *"2페이지에 1페이지 행이 또 있다"* 라
  원인을 짐작하기 어렵다
- **정렬 가능이 기본값이 아니다** — 서버 화이트리스트에서 **`.sortable()` 을 명시해야 열린다**
  ([72](../../backend/_study/api-conventions.md) §4.1). §2 의 `editable` 과 같은 방향이며, 아래 *끄는 대상* 을 빠뜨려도
  **닫힌 쪽으로 실패한다**
- **정렬할 수 없는 컬럼이 있다**

| 끄는 대상 | 왜 |
|---|---|
| 상태 · 삭제 컬럼([53](./grid-standard.md) §4) | 시스템 컬럼이며 데이터가 아니다 |
| **파생 컬럼** | SQL `ORDER BY` 대상이 아니다 — [61](../../../../documents/screen/user/requirements.md) §3.2.1 의 계정 상태가 그 예다 |
| 팝업으로 채운 표시용 컬럼 | 정렬 대상은 저장되는 원본 컬럼이다 |

**꺼진 컬럼은 헤더가 반응하지 않는다** — 정렬 아이콘이 없고 클릭해도 아무 일이
일어나지 않는다. **별도 표시를 두지 않는다** — 되는 컬럼에 아이콘이 있으므로 **없는
것이 곧 표시**이며, *정렬 불가* 배지를 달면 대부분의 화면이 배지로 덮인다.

> **정렬 UI 를 검색 폼에 두지 않는다.** 정렬 기준과 방향을 고르는 컨트롤을 폼에 두면
> **같은 일을 하는 자리가 둘**이 되고([53](./grid-standard.md) §2.4 가 조회 버튼에 대해 내린 판단과
> 같다), 헤더의 상태와 폼의 값이 어긋날 때 **어느 쪽이 맞는지 사용자가 알 수 없다.**
> **정렬 기준은 언제나 컬럼이므로 컬럼 위가 맞는 자리다** — 폼에는 컬럼이 없다.
> 그래서 [57](./search-form-contract.md) 의 검색 폼에는 정렬 필드가 없고, [72](../../backend/_study/api-conventions.md) §3.7 의 `sorts` 를 채우는 것은
> **헤더뿐**이다.

**헤더 클릭은 그리드 안의 행을 재배열하는 것이 아니라 *재조회* 다.** 128건을 20건씩
보는 화면에서 금액 내림차순을 누를 때 사용자가 묻는 것은 **128건 중 최고액**이지
*"지금 보이는 20건 중 최고액"* 이 아니다. 그리드 내부 정렬은 **정렬이 아니라 착시**다.

```
헤더 클릭 → sorts 갱신 → 페이지 1로 → 재조회 → 서버가 정렬해서 돌려준다
```

**그래서 AG Grid 의 자체 정렬은 꺼야 한다.** 헤더는 **상태 표시와 이벤트 발생**만 하고
행 순서는 **서버가 준 그대로** 둔다. 서버가 정렬해 준 것을 그리드가 한 번 더 정렬하면
넷이 어긋난다.

| | |
|---|---|
| **tie-breaker** | 서버는 `ORDER BY {요청}, {PK}` 다([72](../../backend/_study/api-conventions.md) §3.7). **PK 는 보통 그리드에 없는 컬럼**이라 그리드는 동점을 그 기준으로 나눌 수 없다 — 순서가 갈리고, **커서형에서는 페이지 경계와 어긋나 보인다** |
| **콜레이션** | MySQL 기본은 대소문자 무시인데([22](../../backend/_study/db-portability.md) §4.5) JS 비교는 아니다 |
| **`NULL` 위치** | 벤더마다 다르고(〃) 그리드는 또 다르다 |
| **표시값 ≠ 정렬값** | 렌더러가 코드를 라벨로 바꾼 컬럼은 **라벨로 정렬**된다 — 서버는 코드로 정렬했다 |

> **정렬은 서버, 필터는 클라이언트다 — 비대칭이 의도다.** 둘의 쓸모가 다르기 때문이다.
> **정렬을 현재 페이지에만 걸면 아무 의미가 없지만**(1페이지의 20건을 정렬해 봐야 그것은
> 여전히 1페이지다), **필터는 조회 결과를 왕복 없이 훑는 도구**여서 로드된 행에 걸리는
> 것이 그 목적에 맞는다(§4.1). 같은 헤더에 붙어 있다고 같은 곳에서 돌 이유는 없다.

## 4. 필터 — 헤더 우측 메뉴에 있고, **조회 결과 안에서** 거른다

### 4.1 서버로 보내지 않는다 — 검색 폼과 역할이 다르다

| | **검색 폼**(UX-15) | **컬럼 필터** |
|---|---|---|
| 묻는 것 | *"무엇을 가져올까"* | *"가져온 것 중 무엇을 볼까"* |
| 거르는 곳 | **서버** — 조회 조건 | **클라이언트** — 그리드에 로드된 행 |
| 서버 왕복 | 있다 | **없다** — 즉시 |
| 총 건수 | 다시 계산된다 | **바뀌지 않는다**(§4.2) |
| 지속 | 조회할 때까지 | 조회해도 **유지**된다 |

**컬럼 필터는 조회 결과를 왕복 없이 훑는 도구다.** 서버 조건으로 올리면 검색 폼과 같은
것이 둘이 되고, 사용자는 같은 조건을 두 곳에서 걸 수 있게 된다 — 그러면 *"내가 어디에
무엇을 걸었나"* 가 두 곳에 흩어진다.

### 4.2 그래서 무엇을 거르고 있는지 화면이 말해야 한다

[24](./frontend-stack.md) §6.2 의 원래 우려 — **서버 페이징에서 필터는 현재 페이지에만 걸린다** — 는
그대로 유효하다. 필터를 **끄는 대신 보이게 한다.**

| 장치 | 내용 |
|---|---|
| **건수 표기** | 필터가 걸리면 하단 왼쪽이 `총 128건 · 7페이지 · **이 페이지 20건 중 7건**` 이 된다([53](./grid-standard.md) §2.3) |
| **헤더 표시** | 필터가 걸린 컬럼은 헤더에 표시한다 |
| **초기화** | 검색 폼의 초기화 버튼이 **컬럼 필터도 함께 지운다** |
| 페이지 | 필터가 바뀌어도 **페이지는 그대로**다 — 서버를 부르지 않는다 |
| 조회 | 조회해도 **필터는 유지**되고 새 결과에 다시 걸린다 |

> **탈출구는 페이지 사이즈다.** 한 페이지에 전량이 들어오면 컬럼 필터가 곧 전량 필터가
> 된다([53](./grid-standard.md) §2.3 의 3층). *"필터에 안 걸린다"* 는 사용자에게 줄 답은 **검색 폼을 쓰거나
> 페이지 사이즈를 키우는 것**이며 둘 다 화면에 있다.

> **초기화가 둘을 함께 지우는 이유, 헤더에 표시하는 이유는 같다.** *"왜 데이터가 안
> 나오지"* 의 원인이 **접힌 헤더 메뉴 안의 잊힌 필터**인 상황이 가장 흔한 혼란이다.

### 4.3 필터 유형은 컬럼 타입이 정한다

| 컬럼 타입 | 필터 | 모양 | 비교 |
|---|---|---|---|
| `text` | `text` | 입력 1개 | 부분 일치 |
| **`number`** | `number` | **범위 2개** — 이상 · 이하 | 범위 |
| **`date` · `dateString`** | `date` | **범위 2개** — **달력**(§4.5) | 범위 |
| **`dateTime` · `dateTimeString`** | `date` | **범위 2개** — **시분초 달력**(§4.5) | 범위 |
| **`ynFlag`** | **`set`** | **체크박스**(Y · N) + 전체 | 포함 |
| **`code`** | **`set`** | **체크박스 N개** + 전체 | 포함 |
| `popupRef` | `text` | 입력 1개 | 부분 일치 |
| `bigint` | `text` | 입력 1개 | 완전 일치 — 부분 일치가 의미 없다 |
| `boolean` · `object` | **없음** | — | — |

- **범위는 한쪽만 채워도 된다** — 이상만, 이하만, 또는 둘 다
- **`dateTime` 범위는 시분초까지 받는다.** 날짜만 받으면 *"오늘 09:00~12:00 의 에러 로그"*
  를 볼 수 없다(`64`). 비워 두면 시작은 `00:00:00`, 끝은 `23:59:59` 로 채운다
- **입력은 텍스트가 아니라 달력이다** — 정밀도 셋과 컴포넌트 통일은 §4.5
- **`set` 에는 전체 선택 체크박스**를 둔다. 초기 상태는 **전체 선택**(= 필터 없음)

> **`set` 이 섰다**(2026-08-30 — 구현). `ynFlag` 와 **`options` 를 가진 컬럼**(코드·셀렉트)이
> 체크박스 목록을 받는다. **코드 컬럼에 부분 일치 입력을 내면** 사용자는 화면에 보이는
> *이름* 을 치는데 판은 *코드값* 을 비교한다 — 아무것도 안 걸리고 왜인지 알 수 없다.
>
> | | |
> |---|---|
> | **판의 것을 쓰지 않는다** | AG Grid 의 `agSetColumnFilter` 는 **Enterprise** 다([ADR-0004](../../../records/adr/0004-antd-with-ag-grid.md)의 *유료 라이선스는 배제한다*). 판이 여는 **커스텀 필터** 확장점으로 직접 만든다 — 어휘는 우리 것이라 판을 바꿔도 그 파일만 바뀐다 |
> | **목록은 로드된 행에서** | §4.4 그대로다. 다만 **`ynFlag` 는 예외** — 집합이 둘로 닫혀 있으므로 한쪽이 없어도 둘 다 보여준다. *"켜진 것만 보기"* 는 **꺼진 것이 없을 때도** 물을 수 있는 질문이다 |
> | **스위치 항목은 그 스위치다** | `Y`·`N` 이라는 글자는 셀에 없다 — 목록에만 글자를 두면 **셀과 필터가 다른 어휘**를 쓴다 |
> | **빈 칸도 항목이다** | `(비어 있음)` — 괄호를 두른 것은 그것이 **값이 아니라 값의 부재**이기 때문이다 |
> | **전부 고른 것은 필터가 아니다** | 모델을 `null` 로 되돌린다. 아니면 푸터의 *N건 중 M건* 이 **걸리지 않은 필터를 걸린 것으로** 말한다([53](./grid-standard.md) §2.3) |
> | **전부 해제는 필터다** | 0건을 보겠다는 뜻이며 *전체* 와 다르다 — 여기서 `null` 로 접으면 되돌릴 방법이 없어진다 |
>
> **나머지 유형은 화면을 만들면서 하나씩 붙인다**(사용자 결정 · 2026-08-30) — 날짜 범위와
> 숫자 범위는 아직 판의 기본이다. 필터 컴포넌트는 판의 확장점이라([ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md)의 어댑터
> 경계) 한꺼번에 만들면 **쓰는 화면 없이 규약만 늘어난다** — `62`(메뉴) 슬라이스가 다음이다.

### 4.4 `set` 필터의 목록은 **로드된 행에서 모은다**

결과 내 필터이므로(§4.1) **지금 화면에 없는 값을 고를 이유가 없다.** 코드 마스터 전체를
목록에 넣으면 체크해도 0건인 항목이 대부분이 된다.

| 규칙 | |
|---|---|
| 목록 | **로드된 행의 값**에서 모은다 — 중복 제거 |
| 표시 | **코드명**으로 보여준다 — 값은 코드값이므로 공통코드에서 이름을 붙인다([43](../../../knowledge/sys/code.md) §4) |
| **건수** | 항목마다 건수를 함께 낸다 — `정상 (12)` |
| 정렬 | 코드의 정렬 순서를 따른다. 파생 컬럼은 화면이 선언한 순서 |
| 파생 컬럼 | 같다 — [61](../../../../documents/screen/user/requirements.md) §3.2.1 의 계정 상태도 **로드된 행에서** 모은다 |

> **건수를 함께 내는 것이 §4.2 의 장치와 짝이다.** *"현재 페이지에 무엇이 몇 건 있는가"*
> 를 필터 목록이 그대로 보여주므로, 사용자는 체크하기 전에 이미 범위를 안다.

### 4.5 날짜 필터는 달력이다 — 검색 폼과 같은 것을 쓴다

**AG Grid 의 날짜 필터는 텍스트 입력이다.** 사용자가 `2026-08-27` 을 직접 타이핑해야 하고,
형식이 틀리면 조용히 걸리지 않는다.

**달력으로 바꾼다.** 그것도 **검색 폼(UX-15)이 쓰는 것과 같은 컴포넌트**로 바꾼다.

| | |
|---|---|
| 무엇을 쓰나 | **AntD `DatePicker`** — `<DateRangePicker>`([24](./frontend-stack.md) §7)가 감싸는 그것 |
| 왜 같은 것인가 | 다르면 **같은 화면에서 두 모양의 달력**이 뜬다 — 검색 폼에서는 AntD, 그리드 헤더에서는 AG Grid |
| 테마 | AntD 는 [51](./main-shell.md) §9.7 의 토큰을 이미 받는다. **다크·라이트·색 톤이 자동으로 따라온다** — AG Grid 내장 입력은 AG Grid 쪽 테마를 따르므로 **둘이 어긋난다** |

#### 정밀도는 `precision` 이 정한다

년월만 다루는 컬럼이 있다 — `STAT_YM` 같은 월 버킷([42](../../../knowledge/sys/menu.md) §8)이 그것이며
DB 에서는 `VARCHAR(6)` 이다. **타입을 늘리지 않고 정밀도를 따로 선언한다.**

| `precision` | 달력 | 표시 · 필터 값 |
|---|---|---|
| **`month`** | **년월 달력** — 일 선택이 없다 | `YYYY-MM` |
| `day` (`date`·`dateString` 의 기본) | 일반 달력 | `YYYY-MM-DD` |
| `second` (`dateTime`·`dateTimeString` 의 기본) | **시분초 입력이 붙은 달력** | `YYYY-MM-DD HH:mm:ss` |

```ts
{ field:'statYm', type:'dateString', precision:'month' }   // 년월
{ field:'regDt',  type:'date' }                            // 년월일 — 기본
{ field:'regDtm', type:'dateTime' }                        // 시분초 — 기본
```

- **타입은 값의 형태**(`Date` 냐 문자열이냐)를, **`precision` 은 자릿수**를 말한다.
  타입 이름이 이미 둘을 섞고 있어(`date` vs `dateTime`) 년월만 자리가 없었다 —
  `precision` 이 그 축을 밖으로 뺀다
- **범위 두 칸에 같은 정밀도가 걸린다**(§4.3). `second` 에서 비워 두면 시작은 `00:00:00`,
  끝은 `23:59:59` 로 채운다
- **에디터도 같은 달력을 쓴다**(§5) — 필터에서는 달력이고 편집에서는 텍스트라면 그것이
  더 이상하다

> **이것은 §7 의 "날짜+시분초 범위 필터" 자체 구현에 포함된다.** Community 의 날짜 필터를
> **입력 컴포넌트만 갈아 끼우는 것**이 아니라, 범위 두 칸 · 정밀도 셋 · AntD 달력을
> 우리가 만드는 것이다.

> **2026-08-31 — 에디터와 정밀도가 섰다. 필터는 아직이다.** `precision` 이 어휘에 들어오고
> 셀 편집기가 AntD 달력이 됐다(위 §5 의 구현 노트). **컬럼 필터는 여전히 판의 텍스트
> 입력**이며, 그것을 여는 것은 이 절이 적은 대로 *범위 두 칸* 을 우리가 만드는 일이다 —
> 편집기 하나로는 그 자리가 채워지지 않는다.
>
> **형식 문자열은 시스템 설정이 정한다**({@code ui.date-format.month · day · second} —
> [43](../../../knowledge/sys/code.md) §6.4). 위 표의 값이 그 **기본값**이다. 조직에 따라 년월일 구분자가 `.` 이거나
> `/` 인데, 그것을 화면마다 고치게 두면 **같은 앱 안에서 날짜가 두 모양**으로 보인다.
>
> **시간대는 설정이 아니다.** 서버가 주는 것은 오프셋을 포함한 ISO-8601 이고([21](../../backend/_study/architecture.md) §6-1)
> 브라우저가 자기 시간대로 옮겨 그린다 — 설정으로 두면 *같은 화면을 서울과 하노이에서 볼 때*
> 둘 중 하나가 틀린다.
>
> **`precision: 'month'` 의 저장 값은 그 달의 1일이다**(§8 의 미결에 대한 답의 절반).
> `date` 타입에서 그렇다 — 컬럼의 저장 타입이 `LocalDate` 이므로 날짜 하나를 정해야 하고,
> 1일이 *그 달의 시작* 이라 기간의 시작·종료 어느 칸에서도 읽는 사람의 기대와 어긋나지
> 않는다(끝을 말일로 굳히면 **같은 컬럼이 칸마다 다르게 동작**한다). `VARCHAR(6)` 컬럼은
> `dateString` 이 서는 날의 일이며 그 타입은 아직 없다.

## 5. 컬럼 유형과 기본 에디터

타입의 정의는 [24](./frontend-stack.md) §6.1 이 갖는다. **AG Grid 내장 9종을 전부 쓰고** 커스텀 넷을 더한
**13종**이다.

> **닫힌 집합이 아니라 *늘리는 조건이 있는* 집합이다.** 여기는 업무 도메인을 가리지
> 않는 베이스이므로(설계 원칙) *"지금 화면에 사례가 없다"* 는 막는 근거가 아니다
> ([57](./search-form-contract.md) §1.1). **늘릴 때 지킬 것은 둘** — ① **Enterprise 기능에 기대지 않는다**
> ([ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md)) ② **표시 형식은 타입이 아니라 `renderer` 다**(§5.4) — 통화·퍼센트·전화번호는
> `number`·`text` 에 렌더러를 붙이는 것이지 새 타입이 아니다.

| 타입 | 기본 에디터 | 비고 |
|---|---|---|
| `text` | `text` | **긴 텍스트(`nclob`)는 에디터로 가른다** — `largeText` · `textModal` · `richText`(§5.5) |
| `number` | `number` | |
| `bigint` | `text` | **API 가 문자열로 내려야 의미가 있다** — [24](./frontend-stack.md) §6.1 |
| `boolean` | — | **직접 쓰지 않는다.** `ynFlag` 로 감싼다 |
| `date` · `dateString` | `date` | `_DT` 컬럼. **AntD 달력** — 필터와 같은 것(§4.5) |
| `dateTime` · `dateTimeString` | `date` | `_DTM` 컬럼. 〃 시분초 |

| **`code`** | `select` · `richSelect` | 표시는 코드명, 저장은 코드값. 종속 콤보는 [24](./frontend-stack.md) §7. **`richSelect` 의 계약은 §5.7** |

> 대체하며 어휘는 같다([ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) · §7).

> **어댑터가 아는 것은 지금 일곱이다**(2026-08-29 — 구현). `text` · `number` · `ynFlag` ·
> `code` · `list` · `date` · `dateTime` 이며 에디터는 `text` · `largeText` · `number` ·
> `switch` · `select` · **`date`**(2026-08-31), 렌더러는 `badge` · `tags` 다.
>
> **날짜 에디터는 타입이 고른다.** `date` · `dateTime` 컬럼이 `editable` 이면 선언에

> **조용히 무시**되고, 화면 개발자는 자기가 오타를 냈는지 미구현인지 알 수 없다 —
> 늘리는 자리는 그것을 처음 요구하는 화면이다(`generateApiSeed` 가 첫 업무 API 를 기다린
> 것과 같다). 남은 것은 `popupRef` · `richSelect` · `bigint` · `listModal` 에디터 ·
> **AntD 달력 날짜 필터**(§4.5 — 에디터는 섰고 *필터* 가 남았다) · 렌더러 다섯이다.

### 5.1 컬럼 상태 셋 — 필수 · 편집 가능 · 읽기 전용

`editable` 과 `required` 의 조합이 컬럼의 상태를 정하고, **헤더와 셀 배경이 그것을 함께
말한다.**

| 상태 | 선언 | 헤더 | 셀 배경 |
|---|---|---|---|
| **필수 입력** | `editable` + `required` | **`*`** + 라벨 | 필수 배경 |
| **편집 가능** | `editable` | 라벨만 | **바탕 — 칠하지 않는다**([53](./grid-standard.md) §8.1) |
| **읽기 전용** | (기본값) | 라벨 — **흐린 글자** | 읽기 전용 배경 |

실제 색과 우선순위는 [53](./grid-standard.md) §8 이 갖는다. **색은 헤더 표시를 거드는 것이지 대신하지
않는다** — 색각 이상이 있는 사용자에게 색은 정보가 아니다([53](./grid-standard.md) §8.1).

#### `required` 를 `validate` 안에 넣지 않고 별도 키로 두는 이유

**헤더가 그것을 알아야 하기 때문**이다. 필수 검사를 `validate` 함수 안에 넣으면 규칙이
함수 몸통에 갇혀 **화면이 `*` 를 그릴 근거를 잃는다** — 그러면 화면마다 `*` 를 손으로
붙이게 되고, 검증과 표시가 언젠가 어긋난다.

| 그래서 | |
|---|---|
| `required` 는 **선언**이다 | 헤더 `*` · 셀 배경 · **검증 규칙**이 모두 이 하나에서 나온다 |
| `validate` 는 **그 위에 얹힌다** | 형식 · 범위 · 다른 컬럼에 따른 분기([56](./grid-edit-validation.md) §3.2) |
| 순서 | **필수 검사가 먼저**다. 값이 비어 있으면 `validate` 를 부르지 않는다 |

#### 조건부 필수는 함수다

```ts
required: (row) => row.roleId != null      // 역할을 골랐으면 기간이 필수
```

- **헤더에는 `*` 가 붙지 않는다**(2026-08-30 개정 — 아래)
- **셀 배경은 그 행의 실제 판정을 따른다** — 조건이 성립한 행만 필수 배경이 된다
- `editable` 이 `false` 인 셀에는 `required` 를 적용하지 않는다. **편집할 수 없는 칸을
  필수라고 말하면 사용자가 채울 방법이 없다** — 값은 서버나 후작업([56](./grid-edit-validation.md) §2.3)이 채운다

> **이전 판은 *"`*` 옆에 조건임을 나타낸다"* 였다.** 그러려면 **어휘를 하나 더** 만들어야
> 하는데(별표에 붙는 무엇), **셀 배경이 이미 행마다 정확히 말하고 있다.** 헤더가 할 수 있는
> 말은 *언제나 필수인가* 하나이며, 조건부에 별표를 달면 **필수가 아닌 행에서도 별표가
> 보인다** — 헤더가 거짓말을 하는 쪽보다 침묵하는 쪽이 낫다.

#### `pk` — PK 컬럼은 셋을 한 번에 정한다 (2026-08-30)

PK 컬럼은 **언제나 같은 셋**을 원한다. 화면마다 손으로 적으면 매번 세 줄이고 **빠뜨려도
조용하다** — `editable: true` 로 두면 저장된 PK 가 열리고, 그 저장은 서버에서 *없는 행
수정* 이 된다(신규도 아니라 만들어지지도 않는다).

```ts
{ field: 'grpCd', pk: true }                    // 신규만 · 필수 · 헤더 `*`
{ field: 'grpCd', pk: { renamable: true } }     // 예외 — 저장된 행에서도 연다
```

| `pk: true` 가 정하는 것 | |
|---|---|
| 편집 | **신규 행에서만.** 저장된 행에서는 잠기고 **왜 잠겼는지 말한다**([56](./grid-edit-validation.md) §2.1) — *"고치려면 지우고 다시 만든다"* 는 화면 어디에도 없는 답이다 |
| 필수 | **신규 행에서.** 저장된 행에서는 값이 이미 있고 잠겨 있으므로 다시 물을 것이 없다 |
| 헤더 | **`*`** |

- **`editable` · `required` 를 함께 쓰지 않는다.** 덮어쓸 수 있으면 기본이 기본이 아니다 —
  `pk` 가 이긴다
- **여는 것이 선언이다.** 기본이 잠그는 쪽이라 빠뜨렸을 때 **덜 위험한 쪽**으로 떨어진다
  ([23](../../backend/_study/security-design.md) §4 의 `deny by default` 와 같은 방향)
- **편집이 아예 없는 PK 는 `pk` 가 아니다** — [63](../../../../documents/screen/code/requirements.md) §3.2 의 `msgKey` 처럼 신규 행조차 없는
  화면은 `editable: false` 로 적는다. 채울 수 없는 칸에 별표를 붙이면 *왜 안 되나* 를 묻게 된다

#### 판정은 한 곳이다

`editable` · `required` 는 **어댑터와 검증이 함께 읽는다.** 그 규칙이 두 곳에 있으면 —
실제로 그랬다(2026-08-30) — 한쪽만 고쳐졌을 때 **셀은 잠기는데 검증은 값을 요구한다**:
저장이 안 되는데 이유가 화면 어디에도 없다. 규칙은 `columnRules` 하나이며 `pk` 도 거기서
펴진다.

> **헤더의 `*` 는 글자가 아니라 CSS 다.** 헤더 문자열에 붙이면 그 문자열이 **정렬·필터·
> 엑셀**로 함께 흘러 `그룹 코드 *` 가 파일의 헤더가 된다([53](./grid-standard.md) §2.2). 색은 검증 실패의
> 테두리와 **같은 변수**를 쓴다 — 둘이 같은 것을 말하므로(이 칸을 채워야 한다) 색이 갈리면
> 다른 일로 읽힌다.

### 5.2 `ynFlag` 는 스위치다 — 체크박스가 아니다

**모든 테이블에 `_YN` 컬럼이 있다**([40](../../../knowledge/sys/INDEX.md)). 그만큼 자주 보이므로 모양을 한 번 정한다.

| | 체크박스(기각) | **스위치**(채택) |
|---|---|---|
| 켜짐/꺼짐 구분 | 체크 표시의 **유무** | **위치 + 색** — 멀리서도 보인다 |
| 읽기 전용 | 회색 체크박스가 **입력 칸처럼** 보인다 | 비활성 스위치는 **상태 표시**로 읽힌다 |
| 조회 전용 그리드 | 어색하다 | 자연스럽다 |

**`_YN` 컬럼의 다수는 읽기 전용이다** — `LOCK_YN` · `DORMANT_YN` 처럼 시스템이 거는 것
([61](../../../../documents/screen/user/requirements.md) §2.3). 그것이 체크박스로 보이면 **꺼져 있는 체크박스인지 못 켜는 체크박스인지**
구분되지 않는다.

#### 스위치가 즉시 저장을 뜻하지 않는다

**이것이 이 선택의 유일한 위험이다.** 스위치는 흔히 *"켜는 순간 적용"* 의 시각 언어다.
그러나 그리드의 기본은 **일괄 저장**이다([53](./grid-standard.md) §3.1).

| 스위치를 켜면 | |
|---|---|
| 값이 바뀐다 | 행 상태가 **수정(`✎`)** 이 된다([53](./grid-standard.md) §3.2) |
| 서버로 나가나 | **아니다.** 저장 버튼을 눌러야 한다 |

**행 상태 컬럼이 그 오해를 막는다** — 스위치를 켠 순간 왼쪽 끝에 `✎` 가 붙으므로
*"아직 저장되지 않았다"* 가 같은 행에서 보인다. **상태 컬럼을 숨길 수 없게 한 이유가
여기서 한 번 더 쓰인다**([53](./grid-standard.md) §4).

#### 클릭 한 번으로 토글한다 — 더블 클릭 예외

[56](./grid-edit-validation.md) §2.2 는 *"더블 클릭으로 편집 모드 진입"* 인데 **스위치와 체크 계열은 예외**다. 값이 둘뿐이라
**편집 모드라는 중간 상태가 없다** — 진입해서 고르고 확정할 것이 없다.

| | 진입 | 확정 |
|---|---|---|
| `text` · `number` · `date` … | 더블 클릭 | `Enter` · 포커스 이동 |
| **`switch`** | **없다** | **클릭이 곧 확정** |

`Tab` 으로 이동해 온 경우 **`Space` 로 토글**한다 — 마우스 없이도 닿아야 한다.
읽기 전용 셀의 스위치는 **비활성**이며 클릭해도 아무 일도 없다([56](./grid-edit-validation.md) §2.1 의 거부 메시지가
있으면 낸다).

> **AG Grid 에 `switch` 에디터가 없다** — `agCheckboxCellEditor` 뿐이다. **자체 구현**
> 대상이며 AntD `Switch` 로 만든다(§7.2). 켜짐 색은 Primary 에서 온다([51](./main-shell.md) §9.7).

#### `ynFlag` 만의 것이 아니다 — 값이 둘인 데이터 칸은 전부 스위치다

**권한 트리의 셀이 같은 것을 쓴다**([61](../../../../documents/screen/user/requirements.md) §4.4). 그리드가 아니지만
(AntD Table 의 트리 행) **묻는 것이 같다** — *"이 칸이 켜져 있나"* 이고 읽기 전용인 셀이
섞여 있다. 어휘가 갈리면 **한 화면에 체크박스와 스위치가 같은 뜻으로 공존**한다.

**대신 체크박스가 남는 자리가 셋 있다.**

| 체크박스 | 무엇 |
|---|---|
| **행 선택** | 여러 행 중 실행 대상을 고른다([55](./grid-api-contract.md) §7) |
| **`set` 필터 목록** | 값 목록에서 고른다(§4.3) |
| **그리드 설정 창의 컬럼 표시** | 컬럼 목록에서 고른다([53](./grid-standard.md) §5) |

**가르는 기준 하나** — **스위치는 *그 행의 값*이고, 체크박스는 *목록에서 고르는 것*이다.**
값은 저장되고 선택은 저장되지 않는다.

> **판의 편집기를 아예 열지 않는다**(2026-08-31 실물). 한동안 `def.editable` 을 켠 채로 두고
> `Enter`·`F2` 만 막았는데 **더블 클릭이 남았다** — 스위치를 비껴 **셀 배경**을 두 번 누르면
> 판의 텍스트 편집기가 열려 `true`/`false` 를 손으로 치게 됐다.
>
> **끄는 것이 잃는 것이 없다.** 켜 두었던 근거는 *필수·읽기전용 배경색과 검증의 입력* 이었는데
> 둘 다 **우리 어휘**를 본다 — 배경은 `cellClassRules` 가 `editable` 선언으로 판정하고(§5.1)
> 검증도 같은 함수를 쓴다. 스위치의 커밋은 `valueSetter` 가 아니라 어댑터의 `commitEdit` 를
> 직접 부르므로 경로가 끊기지도 않는다.

### 5.3 `object` 는 그래프가 아니다 — 그래서 쓰지 않는다

**`object` 는 값이 객체인 셀을 위한 타입**이다. 셀 안에 무언가를 그리는 기능이 아니다.

```
{ cityCd:'SEL', cityNm:'서울' }     ← 이런 값이 한 컬럼에 들어 있을 때
```

AG Grid 는 표시 · 필터 · 정렬 · 복사 · 엑셀에 **문자열**이 필요하므로 `valueFormatter` 와
`valueParser` 를 직접 줘야 한다. 주지 않으면 `[object Object]` 가 그려진다.

**우리는 쓰지 않는다.**

| 왜 | |
|---|---|
| 그런 컬럼이 **데이터 모델에 없다** | **DB 컬럼**은 스칼라다([22](../../backend/_study/db-portability.md) — 4벤더 무수정 기동). **셀 값이 배열인 경우는 다르며 `list` 가 덮는다** — §5.6 |
| 참조는 이미 다른 것이 덮는다 | **`popupRef`**(§6)가 *"id 를 고르면 name 도 채운다"* 를 **두 컬럼**으로 푼다 — 한 컬럼에 객체를 넣는 것보다 정렬·필터가 정상 동작한다 |
| 서버 응답 형태를 흐린다 | 중첩 객체를 허용하면 API 응답이 화면마다 달라진다([21](../../backend/_study/architecture.md) §6-1) |

#### 셀 안에 그래프를 그리는 것은 `renderer` 다 — §5.4

`object` 와 **아무 관계가 없다.** 타입은 *"값이 무엇인가"* 이고 렌더러는 *"어떻게 그리는가"* 다.

### 5.4 `renderer` — 표시를 바꾸되 값은 바꾸지 않는다

```ts
{ field:'progressRate', type:'number', renderer:'progress' }
{ field:'statCd',       type:'code',   renderer:'badge' }
```

| `renderer` | 무엇 | 어울리는 타입 | **구현** |
|---|---|---|---|
| (없음 — 기본) | 값 그대로 | 전부 | **있다** |
| **`badge`** | 상태 배지 — 색은 **코드 또는 묶음**이 정한다(§5.4.1) | `code` · `text`(파생) · **`number`** | **있다** |
| **`tags`** | 값 여럿을 태그로 나열 | `text` | **있다** |
| **`link`** | 클릭 가능한 텍스트 — `onClick` | `text` · `bigint` | **있다** |
| **`progress`** | 0~100 막대 | `number` | **없다 → 요구가 왔다**([68](../../../playbook/INDEX.md) §9.9 · `DC_RT`) |
| **`duration`** | **소요 시간** — ms 를 사람 단위로(`1시간 2분 5초`) | `number` | **있다** |
| **`icon`** | 아이콘 + 툴팁 | `code` · `ynFlag` | **없다 → 요구가 왔다**([68](../../../playbook/INDEX.md) §9.9 · `PRIORITY_CD`) |
| **`sparkline`** | **미니 차트** — 셀 안의 추세선 | `number[]` | **없다** — Enterprise(§7.2) |

**어휘를 이 일곱에서 닫는다**(2026-08-28 — `duration` 추가, [65](../../../../documents/screen/batch/schedule/requirements.md) §4.4). 렌더 함수(JSX)를 받지 않는 것은 [55](./grid-api-contract.md) §3.8 이 헤더에서
그렇게 한 것과 같은 이유다 — 화면이 그리드 내부를 알기 시작하면 [ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) 의 판 교체
경계가 무너지고, 모양이 화면마다 갈린다.

> **`duration` 이 왜 렌더러인가**([65](../../../../documents/screen/batch/schedule/requirements.md) §4.4). `ELAPSED_MS` 는 밀리초이고 **`3725000` 을
> 사람이 읽지 않는다.** 서버가 포맷한 문자열 컬럼을 따로 주면 **정렬이 문자열 정렬**이 되고
> (`9분` > `10분`), 화면이 셀에서 계산하면 렌더 함수를 여는 것이다. **값은 원본 `number`(ms)
> 이고 표시만 바뀐다** — `progress` 와 같은 자리이며, **숫자를 사람이 읽는 단위로 바꾸는 것이
> 렌더러의 일**이라는 규칙에서 시간만 빠져 있었다.

#### 구현된 것은 넷이다 (2026-08-30 · 표에 열로 올렸다 2026-08-31)

`badge` · `tags` · `link` · **`duration`**. 나머지 셋(`progress` · `icon` · `sparkline`)은
요구한 화면이 아직 없다 — **어휘가 일곱인 것과 구현이 넷인 것은 다른 사실**이며, 선언만
해 두면 *쓸 수 있는 줄 알고 적었는데 아무 일도 안 일어나는* 컬럼이 생긴다.

> **이 문장이 표 밖에 있어서 §5.5 에서 사고가 났다.** 그쪽은 같은 사실을 `판` 열의
> *자체* 로만 적어 두었고, [66](../../../../documents/screen/notice/requirements.md) §4.3 은 **표만 보고** `textModal` 을 골랐다(§5.5 의 정정).
> 그래서 두 표에 **`구현` 열을 올렸다** — 산문은 근거를 갖고, 열은 **고를 때 눈에 들어온다**.
>
> **렌더러는 유니온이 넷이다** — `RendererType = badge | tags | link | duration`. `progress` ·
> `icon` · `sparkline` 은 **타입에 없으므로 선언 자체가 컴파일 오류**다. 어휘 일곱은
> <i>설계의 목록</i>이고 타입 넷은 <i>지금 쓸 수 있는 것</i>이며, 이 열이 그 둘을 한 표에서 잇는다.

**`duration` 의 표시 형식은 소스에 없다.** [65](../../../../documents/screen/batch/schedule/requirements.md) §6 이 *"`1시간 2분 5초` 인지 `01:02:05` 인지,
다국어에서 갈린다"* 를 미결로 두었는데 **갈리는 것이 맞으므로** 형식 자체를 메시지로 둔다 —
`grid.duration.hms · ms · s · sub` 넷이며 소스는 **0인 단위를 보고 템플릿을 고를 뿐**이다.
문자열을 이으면 언어가 늘 때마다 소스를 고쳐야 한다([90](../i18n.md)).

#### `badge` 는 값 대신 그리되 **글자는 `display` 가 정한다** (2026-08-30)

값이 코드이고 글자가 라벨인 배지가 [65](../../../../documents/screen/batch/schedule/requirements.md) §4.3 에서 처음 나왔다(`SKIP_LOCK` → `건너뜀(락)`).
라벨을 `derive` 로 만들어 넣으면 **`tone` 조회가 라벨 문자열로 가서 색이 하나도 안 칠해지고**,
정렬·필터·엑셀도 라벨을 본다 — §5.4 의 *값은 원본 그대로* 가 깨진다. `display` 는 §5.3 이 이미
*값을 글자로 바꾸는 방법* 으로 정의해 둔 자리이며 `link` 가 같은 뜻으로 쓴다.

> **`renderer: 'badge'` 와 `badge`(내력)를 겹칠 수 있다** — 위 문단이 *겹치면 값이 사라진다*
> 고 적은 것은 **값을 글자로 그리던 때**의 이야기다. 배지가 곧 값인 셀에서는 그 옆에 내력을
> 다는 것이 성립하며([65](../../../../documents/screen/batch/schedule/requirements.md) §4.4 의 `진행 중` + `유령`), **꺼진 것에 이유를 붙이는 규칙**
> ([64](../../../../documents/screen/log/access/requirements.md) §7-3.6)을 따라 `tip` 툴팁이 함께 온다.

#### 5.4.1 `badge` 의 색을 정하는 것은 **둘**이다 (2026-08-28 개정)

이 절은 오래 *"색은 코드가 정한다"* 였다. **실제로 쓰인 사례 셋이 전부 그것을 벗어났다.**

| 어디 | 컬럼 | 타입 | 색을 정하는 것 |
|---|---|---|---|
| [62](../../../../documents/screen/menu/requirements.md) §5.4 `API_CATALOG` | 매핑 메뉴 | **`number`** | **값이 `0` 인가** |
| [64](../../../../documents/screen/log/access/requirements.md) §4.3 `LOGIN_LOG` | 결과 | `code` | **묶음** — 코드 열넷을 색 셋으로 |
| [64](../../../../documents/screen/log/access/requirements.md) §3.2.2 · §5.2 로그 2종 | 상태 | **`number`** | **범위** — 2xx · 4xx · 5xx |

**셋이 같은 방향으로 벗어났으면 규약이 좁은 것이다.** 코드마다 색을 주는 것은
값이 적고 각각이 독립일 때만 성립하는데, 위 셋은 **값이 많거나(14) 연속이거나(HTTP 상태)
경계가 하나(0인가)** 다.

```ts
{ field:'statCd',    type:'code',   renderer:'badge' }                      // ① 코드가 정한다
{ field:'httpStat',  type:'number', renderer:'badge', tone: HTTP_TONE }     // ② 묶음이 정한다
```

| 축 | 누가 색을 정하나 | 선언 |
|---|---|---|
| **① 코드** | `SYS_CODE` 행이 자기 색을 갖는다 | **없다** — 기본값 |
| **② 묶음** | **화면이 값→색 맵을 선언한다** | `tone` |

**`tone` 은 함수가 아니라 맵이다.**

| 형태 | 언제 |
|---|---|
| `{ '값': '색' }` | 열거값 — `{ SUCCESS:'ok', LOGOUT:'muted' }` |
| `[{ max, tone }, …]` | **범위** — `[{max:399,tone:'none'},{max:499,tone:'warn'},{max:599,tone:'err'}]` |

- **색 이름은 닫혀 있다** — `none` · `ok` · `warn` · `err` · `muted` **다섯**.
  Hex 를 받지 않는다: 색은 [51](./main-shell.md) §9.7 의 테마 토큰에서 오며([53](./grid-standard.md) §8.4)
  화면이 직접 정하면 **다크·색 톤에서 절반만 따라온다**
- **`none` 이 기본값이고, 그것이 규칙이다** — 맵에 없는 값은 **칠하지 않는다.**
  [53](./grid-standard.md) §8.1 의 *"편집 가능은 칠하지 않는다"* 와 같은 판단이며, **정상이 압도적인
  목록에서는 칠하지 않는 것이 기본**이고 칠한 것만 눈에 남는다([64](../../../../documents/screen/log/access/requirements.md) §3.2.2 의 `2xx`)
- **함수를 열지 않는 이유는 §5.4 본문과 같다.** 맵이면 **선언을 읽어 색을 미리 알 수 있고**,
  판을 바꿔도 그대로 옮겨진다 — 함수는 그리드 내부를 알기 시작한다
- **`tone` 은 표시만 바꾼다.** 정렬 · 필터 · 검증 · 엑셀은 **원본 값**을 본다(아래)

> **`code` 타입에도 `tone` 을 쓸 수 있다** — [64](../../../../documents/screen/log/access/requirements.md) §4.3 이 그 경우다. 코드가 열넷인데
> 색이 셋이면 **`SYS_CODE` 에 색을 열넷 넣는 것이 오히려 어긋난다** — 색은 *운영자가
> 훑는 방식*이지 코드의 속성이 아니다. **`tone` 이 있으면 그것이 이긴다.**

#### 값은 원본 그대로다

| 무엇 | 무엇을 보나 |
|---|---|
| 표시 | **렌더러가 그린 것** |
| 정렬(§3) · 필터(§4) · 검증([56](./grid-edit-validation.md) §3) | **원본 값** |
| 엑셀(`⤓`) · 복사 | **원본 값**([53](./grid-standard.md) §2.2) |
| 편집 | **`editor` 가 한다** — 렌더러와 다른 축(§5 · [56](./grid-edit-validation.md)) |

**배지로 그렸다고 필터가 배지 텍스트를 보면 안 된다.** 표시와 값이 갈라지는 순간
*"화면에 보이는 것으로 걸렀는데 결과가 다르다"* 가 생긴다 — [54](./grid-column-contract.md) §4.4 가 `set` 필터
목록을 **코드값에서 모으고 이름만 붙이는** 것과 같은 규칙이다.

> **`sparkline` 은 AG Grid Enterprise 다.** Community 에서는 **자체 구현**이며(§7.2),
> 값이 배열이라 **정렬·필터·편집의 대상이 아니다** — 셋 다 끈다(§3 · §4.3).
> 배열을 한 컬럼에 담는 것은 §5.3 이 기각한 `object` 와 같은 모양이므로, **서버가 그 컬럼을
> 별도 필드로 내려주는 것**을 전제한다. §8 미결.

### 5.5 긴 텍스트(`nclob`) — 셀에서 보지 않는다

`nclob` 컬럼은 **수천 자가 들어올 수 있다**([22](../../backend/_study/db-portability.md) — `@Nationalized` + `LONG32NVARCHAR`).
공지 본문 · 요청 전문 · 스택트레이스가 그것이며 [64](../../../../documents/screen/log/access/requirements.md)(로그 3종) · [65](../../../../documents/screen/batch/schedule/requirements.md)(배치 오류)에서 실물이 나왔다.
공지 본문은 **`richText` 가 아니라 `largeText` 로 섰다**(2026-08-31 · [66](../../../../documents/screen/notice/requirements.md) §4.3) —
`CONTENT_TYPE_CD` 의 기본이 `TEXT` 라([47](../../../knowledge/sys/notification.md) §9) **에디터 없이 화면이 선다.**

> **정정(2026-08-31) — `textModal` 로 섰다고 적었다가 고쳤다.** 66 §4.3 이 처음 이 표를 보고
> `textModal` 을 골랐는데 **그 어휘에는 구현이 없다**(아래 표에 <b>`구현` 열</b>이 그래서 생겼다 —
> 그전에는 `판` 열의 *자체* 가 그것을 겸했고, 그 칸은 <i>"아직 안 만들었다"</i> 로 읽히지
> 않았다). 실물은 **셀 위 팝업**이며 **글자 수가 없다** — 그 둘이 감수한 것이다.
> 요청함의 `REQ_CONTENT` 뷰어도 같다(66 §5.2).
>
> **`textModal` 이 섰다**(2026-09-02 — [68](../../../playbook/INDEX.md) §9.7). `richText` 만 <i>쓰는 화면이 없는 어휘</i>로
> 남으며, 그것은 라이브러리 결정이 사용 프로젝트의 것이기 때문이다([60](../../../../documents/screen/_standalone/README.md) §11).

**타입은 `text` 그대로다.** 값이 문자열이라는 사실은 길이와 무관하며, 달라지는 것은
**어떻게 입력하고 어떻게 보여주는가**뿐이다 — 타입이 아니라 `editor` 로 가른다.

| `editor` | 어디서 | 무엇 | 판 | **구현** | 쓰는 화면 |
|---|---|---|---|---|---|
| `text` | 셀 안 | 한 줄 | 내장 | **있다** | 거의 전부 |
| **`largeText`** | **셀 위 팝업** | textarea. **글자 수가 없다** | **내장** (`agLargeTextCellEditor`) | **있다** | 공지 본문([66](../../../../documents/screen/notice/requirements.md) §4.3) · `BATCH_DESC` · `PARAM_JSON`([65](../../../../documents/screen/batch/schedule/requirements.md) §3.5.1) · 요청 내용·처리 메모(`viewer` · [66](../../../../documents/screen/notice/requirements.md) §5.2) |
| **`textModal`** | **화면 중앙 모달** | 큰 textarea + **글자 수** | 자체 | **있다**(2026-09-02) | 샘플 ①의 `RMK`([48](../../../playbook/INDEX.md) §3.1 · [68](../../../playbook/INDEX.md) §9.7) |
| **`richText`** | 〃 | **리치 에디터** | 자체 — **라이브러리 미정**([60](../../../../documents/screen/_standalone/README.md) §11) | **없다** — §7.2 열한째 | **없다** |

> **글자 수 상한은 `maxLength` 로 선언한다**(2026-09-02 — 구현). §5.6 이 *"형식·개수는
> 검증이지 선언이 아니다"* 로 그은 선을 이 값이 넘지 않는 것은, 그 절이 제시한 기준이
> **표시에 나타나는가**이기 때문이다 — 이 값은 창 아래 `n / 상한` 으로 **그려지며**,
> 없으면 `showCount` 가 센 수만 보여 *얼마나 남았는지* 를 말하지 못한다. **그 카운터가
> `largeText` 와 갈리는 유일한 지점**이라, 선언을 빠뜨리면 이 에디터의 존재 이유가 함께
> 사라진다. 업무 규칙(*"채널이 A 면 200자"*)은 여전히 `validate` 다.
>
> **`viewer: 'textModal'` 은 열지 않았다.** 위 *읽기 전용이어도 열린다* 는 이 에디터에도
> 그대로여서(고칠 수 없으면 확인 버튼을 감추고 읽기 모드로 연다) **읽기 전용 축이
> 따로 필요해지는 화면이 아직 없다** — 요구하는 화면이 오면 그때 연다(§5 의 주의).

> **`구현` 열이 이 표에서 가장 중요한 칸이다**(2026-08-31 추가). 그전에는 `판` 열의
> **`자체`** 가 그 일을 겸했는데, 그것이 <b>*"우리가 만든다"* 로 읽히고 *"아직 안 만들었다"*
> 로는 읽히지 않았다</b> — [66](../../../../documents/screen/notice/requirements.md) §4.3 이 이 표를 보고 `textModal` 을 골랐고([65](../../../../documents/screen/batch/schedule/requirements.md) §3.5.1 도
> 같이), **구현에 가서야** 그 값이 없다는 것이 드러났다.
>
> **조용히 무시되지는 않는다.** `EditorType` 은 유니온이라 없는 값은 **컴파일이 막는다** —
> 설계 개요 §4 의 *"어휘에 있는데 어댑터가 모르면 조용히 무시된다"* 는 **타입 목록에 미구현을
> 넣지 않은 이유**이고(§5 의 주의), 그 정책 덕분에 여기서는 타입이 문지기다.
>
> **그래서 새는 곳이 코드가 아니라 문서다.** 순서가 이렇게 된다 — 설계가 그 이름으로
> 결정을 적고, 구현이 <b>다른 이름으로 서고</b>, **결정 문서는 그대로 남는다.** 이번에
> 실제로 일어난 일이며 여섯 문서에 번졌다. `구현` 열은 **고를 때** 그것을 막는다.
>
> **`쓰는 화면` 열도 같은 목적이다.** 비어 있으면 <i>어휘에만 있는 것</i>이며, 그 값을
> 고르는 화면은 **그 에디터를 함께 만들어야** 한다.

#### 셀은 한 줄로 자른다

| 자리 | 무엇 |
|---|---|
| 셀 | **한 줄로 자르고 말줄임(`…`)** — 행 높이를 늘리지 않는다 |
| 툴팁 | 앞부분 미리보기 |
| 전체 | **에디터를 열어야 본다** |

**행 높이는 전역 설정이다**([51](./main-shell.md) §9) — 긴 텍스트 한 컬럼 때문에 그리드 전체가 늘어나면
다른 컬럼을 읽을 수 없다.

#### 읽기 전용이어도 열린다

**`editable: false` 가 *"못 본다"* 를 뜻하지 않는다.** 긴 텍스트는 **열어야만 볼 수 있으므로**
읽기 전용 컬럼도 에디터를 **읽기 모드**로 연다.

| | 편집 가능 | 읽기 전용 |
|---|---|---|
| 여는 방법 | 더블 클릭 | **더블 클릭** — 같다 |
| 안에서 | 고치고 확인 | **읽고 닫기**(복사는 된다) |

이것이 [56](./grid-edit-validation.md) §2.1 의 거부 메시지가 나오지 않는 유일한 읽기 전용 컬럼이다 — **거부할 것이
아니라 보여줄 것**이기 때문이다.

#### 정렬은 끈다 — 벤더가 막는다

**`sortable: false` 를 권장이 아니라 규칙으로 둔다.** Oracle 은 `CLOB` 을 `ORDER BY` ·
`GROUP BY` 에 쓸 수 없다 — **4벤더 무수정 기동**([22](../../backend/_study/db-portability.md))이 깨진다.

| | |
|---|---|
| 정렬 | **끈다** — 벤더 제약 |
| 필터 | **`text`(부분 일치).** 결과 내 필터라 로드된 값에서 거르므로 벤더와 무관하다(§4.1) |
| `set` 필터 | **쓰지 않는다** — 값이 길어 체크박스 목록이 되지 않는다 |
| 엑셀 | 셀 문자 상한을 넘으면 **잘린다.** 잘렸음을 알리거나 컬럼을 빼는 것은 화면의 판단 |

### 5.6 `list` — 배열을 담는 컬럼 (커스텀 4번째)

창고 시스템에서 **바코드를 여러 번 스캔해 그 묶음을 한 번에 보내야** 하는 경우가 있다.
시리얼·로트·검사 결과도 같은 모양이다.

#### §5.3 의 "한 컬럼 = 한 스칼라" 는 **DB 컬럼**에 대한 것이다

두 가지를 갈라야 한다. 앞 절이 이것을 뭉개서 썼다.

| | 배열이 되나 |
|---|---|
| **DB 컬럼** | **안 된다** — 배열·JSON 컬럼 타입은 벤더 종속이다([22](../../backend/_study/db-portability.md)). 저장은 **자식 테이블 행들**이거나 서버가 정한 직렬화다 |
| **그리드 셀의 값** | **된다** — 화면이 모아서 **API 로 보내는 형태**다 |

**배열은 전송 형태이지 저장 형태가 아니다.** 서버가 그것을 어떻게 저장하는지는
**화면이 모른다** — `40`~`47` 과 [22](../../backend/_study/db-portability.md) 의 몫이다.

#### 항목은 스칼라일 수도, 객체일 수도 있다

```ts
['8801234567890', '8809876543210']                       // 스칼라 배열
[{ barcode:'8801234567890', qty:3, lot:'A-24' }, …]      // 객체 배열
```

**객체 배열이면 `display` 가 필요하다** — 항목 하나를 무엇으로 보여줄지 그리드가 알 수 없다.
없으면 §5.3 이 지적한 `[object Object]` 가 그대로 나온다.

```ts
{ field:'barcodes', type:'list', renderer:'tags',
  display: (item) => `${item.barcode} (${item.qty})` }
```

| 키 | 필수 | 무엇 |
|---|---|---|
| `type: 'list'` | **Y** | 값이 배열이다 |
| **`display`** | **객체 배열이면 Y** | 항목 하나 → 표시 문자열. 스칼라 배열이면 생략(값 그대로) |
| `renderer` | N | **`tags`** 가 기본(§5.4) |
| `editor` | N | 아래 — **없어도 된다** |

#### 형식·개수·유일성을 키로 두지 않는다

`unique` · `pattern` · `max` 같은 키를 두지 않는다. **그것은 전부 검증이며 [56](./grid-edit-validation.md) §3 에 이미
자리가 있다.**

| | 어디에 | 왜 |
|---|---|---|
| `required`(§5.1) | **선언** | **헤더가 `*` 를 그리려면 알아야 한다** — 표시에 나타난다 |
| 유일성 · 형식 · 개수 | **`validate`**([56](./grid-edit-validation.md) §3.2) | **표시에 나타나지 않는다.** 그리고 행 전체·다른 컬럼을 함께 봐야 하는 경우가 곧 생긴다 |

키로 빼면 **같은 성격의 규칙이 두 곳**에 생기고, *"창고가 A 면 최대 50개"* 같은 조합이
필요해질 때마다 키를 늘리게 된다. `validate` 는 **배열 전체와 행을 함께 받으므로**([56](./grid-edit-validation.md) §3.2)
그런 조합이 처음부터 표현된다.

> **개수 상한의 실물이 생겼다**(2026-09-02 — 샘플의 태그가 **20** · [48](../../../playbook/INDEX.md) §8). 재 보니
> **층은 편집 어휘가 정한다** — 배열이 셀 값인 화면(①)은 **컬럼 층**이 배열을 세고, 같은
> 데이터를 행으로 편집하는 화면(⑤)은 **그리드 층**이 행을 센다. [48](../../../playbook/INDEX.md) §8 의 초안은
> *그리드 층* 하나로 적었는데, 그러면 ①에서 *어느 셀의 문제인가* 에 답할 자리를 잃는다
> ([56](./grid-edit-validation.md) §3.3).
>
> **이 절의 규칙이 실기동에서 값을 했다.** 컴포넌트가 개수를 재지 않으므로 창은 몇 개가
> 오든 같은 크기로 서야 했고([68](../../../playbook/INDEX.md) §9.6 — 내부 스크롤), 그 덕에 **화면 해상도가 업무
> 규칙이 되는 길**이 막혔다. 반대로 컴포넌트에 `max` 를 두었다면 상한은 *창에 들어오는
> 만큼* 이 되었을 것이다.

#### 값을 만드는 방법은 화면이 정한다

**`list` 의 값이 셀 편집기에서만 오는 것은 아니다.**

| 경로 | 어떻게 |
|---|---|
| **셀 편집기** | `editor: 'listModal'` — 더블 클릭하면 모달이 열려 **현재 목록을 보여주고 추가 입력을 받는다.** 적용을 누르면 셀에 반영 |
| **화면의 다른 그리드** | 하단 그리드에서 행을 쌓고, 화면이 그것을 추려 **마스터 행의 필드에 넣는다** — 실물은 [63](../../../../documents/screen/code/requirements.md) §3.2(언어별 메시지)다 |
| 스캐너 · 외부 입력 | 화면이 받아 넣는다 |

**모달의 내용은 어휘로 닫지 않는다** — 레지스트리에서 `key` 로 고른다(§6.3 의 팝업과 같은
방식). 바코드 스캔 모달과 검사 항목 모달은 생긴 것이 전혀 다르고, 그 다름을 옵션으로
표현하려 하면 키가 끝없이 늘어난다.

```ts
{ field:'barcodes', type:'list', editor:'listModal',
  listModal: { key:'BARCODE_SCAN' } }
```

> **`key` 가 가리키는 것은 <i>항목을 고르는 팝업</i>이다**(2026-09-02 — 구현 · [68](../../../playbook/INDEX.md) §9.6).
> 이 절의 초안은 **모달 자체**를 레지스트리에서 고르라고 적었고 근거는 *"바코드 스캔 창과
> 검사 항목 창은 생긴 것이 전혀 다르다"* 였는데, 갈아 보니 **다른 것은 고르는 창**이고
> *고른 것을 쌓고 · 순서를 바꾸고 · 빼는* 부분은 **어느 배열에서나 같았다.**
>
> 그래서 **바깥 껍데기는 하나**(`ListModalCellEditor`)이고 레지스트리가 정하는 것은
> **항목을 고르는 팝업**이며, 그 레지스트리는 §6.3 의 것과 **같은 한 벌**이다. 껍데기까지
> 화면이 만들면 [68](../../../playbook/INDEX.md) §9.6 이 요구한 **순서 변경**이 창마다 다른 모양으로 다시 만들어지고,
> 그 순서는 자식 테이블의 `SORT_NO` 라 **값의 일부**다([48](../../../playbook/INDEX.md) §4.1).
>
> **타이핑을 받지 않는 것도 같은 이유다.** 자유 입력을 열면 어느 코드에도 걸리지 않는
> 태그가 자식 테이블에 남는다 — §6.1 이 없애려던 불일치와 같은 종류다.

> **화면이 넣는 값도 셀 편집과 같은 취급이다.** 행 상태가 **수정(`✎`)** 이 되고([53](./grid-standard.md) §3.2),
> 검증을 받고, 저장에 실린다. **다른 경로로 들어왔다고 규약을 비껴가지 않는다** —
> [56](./grid-edit-validation.md) §2.3 의 후작업이 바꾼 값과 같은 자리다.

#### 계약

| 항목 | |
|---|---|
| 표시 | `tags` 렌더러 + `display`. 개수와 앞 몇 개 |
| **정렬 · 필터** | **둘 다 끈다** — 배열은 비교 대상이 아니다 |
| 검증 | `validate` 가 **배열을 받는다**([56](./grid-edit-validation.md) §3.2) |
| 엑셀 | **구분자로 이어 붙인다** — `display` 를 쓴다. 상한은 §5.5 와 같다 |
| 전송 | **배열 그대로** 페이로드에 실린다([55](./grid-api-contract.md) §8 의 대상 행 안에) |

> **`sparkline`(§5.4)의 값 문제가 여기서 닫힌다.** 숫자 배열도 `list` 타입이며 정렬·필터를
> 끄는 규칙이 같다 — 다른 것은 렌더러뿐이다.

> **타입이 12종에서 13종이 된다** — 커스텀이 `ynFlag` · `code` · `popupRef` · **`list`**
> 넷이다([24](./frontend-stack.md) §6.1). **AG Grid 내장 9종은 그대로**이며 늘어난 것은 우리 커스텀이다.

### 5.7 `richSelect` — 타이핑은 필터이지 입력이 아니다

`select` 는 항목이 열 개를 넘으면 못 쓴다. `richSelect` 는 **목록을 좁혀 가며 고르는**
에디터이며 Community 에서는 `<SearchSelect>` 자체 구현이다(§7.1 · [24](./frontend-stack.md) §7).

**고르는 것이지 쓰는 것이 아니다** — 이 한 줄이 아래 넷을 정한다.

| 동작 | 규칙 |
|---|---|
| **타이핑** | **필터**다. 목록이 즉시 좁아진다. 그 문자열이 값이 되지는 **않는다** |
| **후보가 하나로 좁혀지면** | **자동 확정**한다 — 남은 하나를 다시 고르게 하는 것은 헛수고다 |
| **고르지 않고 벗어나면** | **편집 전 값으로 되돌린다.** 타이핑한 문자열은 버린다 |
| **비우려면** | 목록의 **`(없음)`** 을 고른다 — `nullable` 을 선언한 컬럼에만 나온다 |

> **취소는 *비우기* 가 아니라 *되돌리기* 다.** 편집을 취소했는데 값이 사라지면 **취소가
> 데이터를 바꾼 것**이 된다. 비우는 것은 **고르는 행위**여야 하며 그래서 `(없음)` 이
> 목록에 있다.

> **자유 입력을 남기지 않는 것이 이 에디터의 존재 이유다.** 남기면 목록에 없는 값이 저장되고
> *"저장은 되는데 동작하지 않는"* 상태가 만들어진다 — [62](../../../../documents/screen/menu/requirements.md) §4.3 의 URL 칸이 그 사례다.
> 목록 밖의 값이 필요하면 그 컬럼은 `richSelect` 가 아니라 `text` 다.

#### 옵션은 어디서 오나 — `options` 를 선언한다

| 원천 | 선언 | 예 |
|---|---|---|
| **공통코드** | `type: 'code'` + `codeGrp` | 상태 · 구분([43](../../../knowledge/sys/code.md) §4) |
| **화면이 아는 목록** | **`options`** — 배열 또는 함수 | [62](../../../../documents/screen/menu/requirements.md) §4.3 의 **프론트 라우트 맵** |
| **소스가 갖는 고정 목록** | **`options`** — `{value, label}[]` | **액션 4종** — `<ActionSelect>`([43](../../../knowledge/sys/code.md) §4.3.1) |

```ts
{
  field:  'menuUrl',
  type:   'text',
  editor: 'richSelect',
  options: (row) => routeMap.keys()          // 함수면 행마다 다시 계산한다
              .filter(u => !usedByOther(u, row)),
  nullable: true,                            // 목록에 (없음) 이 나온다
}
```

- **함수 형태를 두는 이유** — *다른 행이 이미 쓰는 값을 빼는* 요구가 실제로 있다([62](../../../../documents/screen/menu/requirements.md) §4.3).
  배열만 받으면 화면이 행마다 컬럼을 다시 만들어야 한다
- **`options` 는 `code` 타입과 배타다.** 둘 다 있으면 같은 사실의 원천이 둘이 된다 —
  선언 시점에 거부한다
- **`filterOptions`(§4.4)와 다른 것이다.** 그쪽은 **`set` 필터의 목록**이고 여기는
  **에디터의 후보**다. 이름이 비슷해 헷갈리는 자리라 못 박는다

#### 항목은 문자열이거나 `{value, label}` 이고, **셀도 라벨을 그린다**

| 항목 형태 | 뜻 |
|---|---|
| `'…'` 문자열 | **값과 라벨이 같다** — 라우트 URL 이 그 경우다 |
| `{ value, label }` | 라벨이 값과 다르다. `label` 은 **메시지 키를 푼 결과**를 넣는다 |

**`options` 를 선언한 컬럼은 읽기 전용 셀에도 라벨이 나온다.** `code` 타입이 *"표시는
코드명, 저장은 코드값"* 인 것과 **같은 규칙**이다(§5).

> **2026-09-02 — 섰다.** `shared/grid/SearchSelectCellEditor` 이며 선언은 위 그대로
> `editor: 'richSelect'` 다([68](../../../playbook/INDEX.md) §9.5). **판의 이름을 어휘에 남긴 것이 결정**이다 —
> Enterprise 를 사면 어댑터가 `agRichSelectCellEditor` 로 바꿔 달면 되고, **화면 소스는
> 한 글자도 바뀌지 않는다**([ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md)).
>
> **자동 확정은 부분 일치라 안전하다.** 검색어를 늘리면 후보는 **줄기만 하므로**, 지금
> 하나면 더 쳐도 그 하나이거나 0건이다 — 사용자가 고를 것이 남아 있는데 가로채는 경로가
> 없다. 다만 **빈 검색어에는 하지 않는다**: 후보가 원래 하나뿐인 컬럼이면 창이 열리자마자
> 값이 확정되어 *더블클릭했더니 값이 바뀌었다* 가 된다.
>
> **아직 안 연 것 둘.** `nullable`(목록의 `(없음)`)과 **함수 형태의 `options`** 는 요구하는
> 화면이 오지 않았다 — 샘플이 여는 자리는 `CHNL_CD` 이고 그 컬럼은 `NOT NULL` 이며
> 후보도 행마다 갈리지 않는다([48](../../../playbook/INDEX.md) §3.1). *쓰이지 않는 후보를 미리 열지 않는다* 는
> [57](./search-form-contract.md) §3.4 의 규칙을 여기서도 그대로 따른다.

> **이 한 줄이 없으면 편집할 때만 한글이고 평소에는 `READ` 가 나온다.** 실제로 그렇게
> 되어 있었다 — 권한 화면의 **헤더**는 *조회·저장·내보내기·실행* 인데 API 목록의
> 액션 **셀**은 `READ` 였다([62](../../../../documents/screen/menu/requirements.md) §4.2 · §5.3). 원천이 둘이었고, 이제 `action.{ACTION_CD}`
> 하나를 **헤더와 셀이 함께 읽는다**([43](../../../knowledge/sys/code.md) §4.3.1).

## 6. 팝업 참조 컬럼 (`popupRef`) — 한 번 골라 여러 칸을 채운다

### 6.1 무엇을 푸는가

상품 아이디와 상품명이 각각 컬럼일 때, 둘을 **따로 입력받으면 불일치가 저장된다.**
아이디는 `P-001` 인데 이름은 다른 상품인 행이 만들어지고, 그것을 막을 제약이 화면에 없다.

**한 번 고르면 딸려 오는 칸이 함께 채워져야 한다.**

### 6.2 선언

```ts
{
  field: 'productId',
  type:  'popupRef',
  popup: {
    key:   'PRODUCT',                       // 팝업 레지스트리의 키 — §6.3
    param: (row) => ({ whCd: row.whCd }),   // 팝업에 넘길 조회 조건 (선택)
    apply: (row, picked) => picked          // 선택 행 → 이 행에 머지할 부분 객체
      ? { productId: picked.productId,
          productNm: picked.productNm,
          unitPrice: picked.unitPrice }
      : { productId: null, productNm: null, unitPrice: null },
  },
}
```

| 키 | 하는 일 | 필수 |
|---|---|---|
| `key` | 어느 팝업을 여는가 | **Y** |
| `param` | 팝업의 조회 조건을 **현재 행에서** 만든다 — 창고가 정해졌으면 그 창고의 상품만 | N |
| **`apply`** | 선택 행을 받아 **이 행에 머지할 부분 객체**를 반환한다 | **Y** |

### 6.3 세 가지를 지킨다

| 규칙 | 왜 |
|---|---|
| **`apply` 는 부분 객체를 반환한다** | 여러 컬럼을 한 번에 채우는 것이 **기본**이고 하나만 채우는 것이 특수한 경우다. 반환값을 컴포넌트가 행에 머지하므로 화면 코드가 그리드 API 를 만지지 않는다 |
| **`picked === null` 은 지우는 것이다** | 값을 비웠는데 상품명이 남으면 **그것이 곧 불일치**다. 채울 때와 지울 때가 대칭이어야 한다 |
| **딸려 온 컬럼은 `editable: false`** | 상품명만 손으로 고칠 수 있으면 §6.1 의 문제가 그대로 돌아온다 |

- `apply` 가 머지한 값에도 **후작업이 이어서 돈다**([56](./grid-edit-validation.md) §2.3) — 단가가 들어왔으면 금액이 계산된다
- **팝업은 화면마다 만들지 않고 등록된 것을 쓴다.** `key` 로 고르며, 팝업 자신도 그리드라
  [53](./grid-standard.md) §2 의 크롬을 갖는다(조회 조건 + 목록)
- **단일 선택이다.** 셀 하나에 값 하나이므로 여러 행을 고르는 것은 셀 편집이 아니라
  **행 추가**이며 다른 기능이다 — 필요하면 ①의 화면 고유 버튼으로 둔다

> **2026-09-02 — 섰다.** `shared/popup` 이 레지스트리와 창 하나(`PopupHost`)를 갖고
> `shared/grid/PopupCellEditor` 가 셀에서 그것을 연다([68](../../../playbook/INDEX.md) §9.4). §8 의 미결
> (*"화면 코드에서 선언할지 공통 목록을 둘지"*)은 **네임스페이스 있는 공통 레지스트리**로
> 닫혔다 — `sample.customer` · `sys.user`.
>
> **팝업은 컴포넌트가 아니라 선언이다.** 위 두 번째 줄(*"팝업 자신도 그리드"*)이 그
> 이유이며, 컴포넌트로 두면 그 크롬이 팝업마다 갈린다.
>
> **닫히는 방법이 셋이다** — 고름 · **지움** · 취소. 위 §6.3 의 *`picked === null` 은
> 지우는 것* 은 **지움**에만 해당하며, 취소를 거기 묶으면 **`Esc` 가 셀을 비운다**:
> 고르러 열었다가 마음을 바꾼 사람이 원래 값을 잃는다. 그래서 지우기는 **팝업 안의
> 버튼**이고, 지금 값이 있는 칸에서만 나온다.
>
> **머지 뒤의 순서는 셀 편집과 같은 코드를 탄다**(`commitPatch`) — 편집 가능 판정 →
> `afterEdit` → 검증. 흉내 내면 **흉내가 한 걸음 모자란 날**이 오고, 그때 팝업으로 채운
> 행만 금액이 비어 저장까지 그대로 간다.

### 7.2 자체 구현 열둘

[ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) 은 *"자체 구현이 필요한 것은 Set Filter 와 검색 콤보 둘"* 이라고 적었다.
**요건이 구체화되면서 열둘이 됐다** — 그 ADR 의 「결과」를 이 목록으로 갱신한다.

| # | 무엇 | 어디 |
|---|---|---|
| 1 | `<SetFilter>` — 체크박스 목록 + 전체 선택 | §4.3 |
| 2 | `<SearchSelect>` — `richSelect` 대체 | §5 |
| 3 | **`popupRef` 에디터 + 팝업 레지스트리** | §6 |
| 4 | **날짜 필터** — 범위 두 칸 · 정밀도 셋 · **AntD 달력**(검색 폼과 같은 것) | §4.5 |
| 5 | `<GridColumnSetting>` — 표시·순서(드래그)·좌우 고정·페이지 사이즈. **목록은 `전체 − 시스템 − hidden`**(§2.1) | [53](./grid-standard.md) §5 |
| 6 | **행 상태 · 삭제 컬럼 · 일괄 저장** | [53](./grid-standard.md) §3 |
| 7 | **검증 프레임워크** — 두 시점 · **세 층**(컬럼 공통 · API 별 컬럼 · API 별 그리드) · 실패 표시 | [56](./grid-edit-validation.md) §3 |
| 8 | **편집 전 판단과 거부 메시지** | [56](./grid-edit-validation.md) §2.1 |
| 9 | **`switch` 에디터** — `ynFlag` 는 체크박스가 아니다 | §5.2 |
| 10 | **셀 렌더러 일곱** — `badge`(+`tone` 맵 · §5.4.1) · `tags` · `link` · `progress` · **`duration`** · `icon` · **`sparkline`**(Enterprise) | §5.4 |
| 11 | **긴 텍스트 에디터** — `textModal` · `richText`(라이브러리 미정) | §5.5 |
| 12 | **`listModal`** — 배열 편집. **항목을 고르는 팝업**을 레지스트리에서 고른다(§5.6 의 구현 노트) | §5.6 |

> **열둘 중 열이 다 섰고 둘이 반씩 남았다**(2026-09-02). 반쪽 둘은 **10 의 `sparkline`**
> (Enterprise 이며 쓰는 화면이 없다 — [48](../../../playbook/INDEX.md) §3.1)과 **11 의 `richText`**(라이브러리가
> 사용 프로젝트의 결정이다 — [60](../../../../documents/screen/_standalone/README.md) §11)이고, **둘 다 의도적으로 열지 않은 것**이다.
> 1~4 · 9 · 11 의 `textModal` · 12 는 [68](../../../playbook/INDEX.md) §9.15 의 1~4단계에서, 5~8 은 그 전에 섰다.

> **Enterprise 를 사도 5·6·7·8·9·11·12 는 자체 구현이 남는다.** Tool Panel 은 우리의 저장 정책
> (순서·표시·고정은 DB, 너비는 `localStorage`)을 갖지 않고, 나머지 셋은 AG Grid 에 대응이
> 없다. **판을 바꿔 없어지는 것은 1~4 와 10 의 `sparkline` 뿐**이며 이것이 [ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md) 이 어댑터 경계를 둔
> 이유다 — 화면은 어느 쪽이든 같은 선언을 쓴다.

## 8. 미결 사항

| 항목 | 성격 | 범위 | 게이트 |
|---|---|---|---|
| **AG Grid 자체 정렬을 어떻게 끄나**(§3) — 서버가 정렬해 준 행을 그리드가 다시 정렬하면 **tie-breaker · 콜레이션 · 표시값**에서 어긋난다. Client-Side Row Model 에서 비교자를 무력화할지, **Infinite Row Model** 로 갈지(커스텀 푸터와 양립하는지) | 검증 | 템플릿 | **Phase 6** |
| **AG Grid 36.1 의 컬럼 교체 옵션 실물**(§2.2) — 컬럼 배열을 갈아 끼울 때 순서·너비를 보존하는 옵션(`maintainColumnOrder` 계열)의 실제 이름과 동작. **폴백: `applyColumnState` 로 직접 복원한다** | 검증 | 템플릿 | 스파이크 (Phase 6 이전) |
| **동적 컬럼의 개수 상한**(§2.2) — 정의가 늘면 그리드가 옆으로 자란다. 좌측 고정([53](./grid-standard.md) §4)으로 버티지만 상한을 정하지 않았다 | 실측 | 템플릿 | Phase 6 |
| **Community 의 컬럼 메뉴·컬럼 이동 지원 범위**(§7.1) — 버전에 따라 갈린다([24](./frontend-stack.md) §6.1 이 적은 판 기준으로 확인). **폴백: 둘 다 자체 구현하고 그리드 설정 창을 유일한 경로로 둔다**(순서는 어차피 창에서 바꾼다 — [53](./grid-standard.md) §5) | 검증 | 템플릿 | 스파이크 (Phase 6 이전) |
| **필터 상태를 개인화에 저장할지**(§4.2) — 지금은 세션 중에만 산다. 저장하면 다음 진입 때 **이유 모를 필터**가 걸려 있게 되므로 두지 않는 쪽에 가깝다 | 결정 | 템플릿 | Phase 6 |
| **필터로 숨겨진 행의 취급**(§4.2 · [53](./grid-standard.md) §3.1) — 편집 상태가 있는 행이 필터에 가려질 때 저장·검증에서 어떻게 알릴지. 초안은 [53](./grid-standard.md) §3.1 과 [56](./grid-edit-validation.md) §3.3 | 결정 | 템플릿 | Phase 6 |
| **다중 정렬의 기본값**(§3) — 화면이 켜는 것으로 뒀다. 전 화면 기본 on 이 나은지 | 결정 | 템플릿 | Phase 6 |
| **팝업 레지스트리의 등록 방식**(§6.3) — 화면 코드에서 선언할지, 공통 팝업 목록을 둘지. 업무 팝업은 사용 프로젝트가 늘린다 | 결정 | 템플릿 | Phase 6 (공통 컴포넌트) |
| **필수 표시를 `*` 로 할지**(§5.1) — 라벨 앞인지 뒤인지, 색을 줄지. 다국어에서 자리가 갈릴 수 있다 | 결정 | 템플릿 | Phase 6 |
| ~~**`precision: 'month'` 컬럼의 DB 형태**(§4.5)~~ → **해소(2026-09-01)** — **`VARCHAR(6)`**([48](../../../playbook/INDEX.md) §4.2 의 `DLVR_YM`). `date` 의 1일로 두면 **있지도 않은 일자가 값에 섞이고**(`2026-08-01` 이 *8월* 인지 *8월 1일* 인지 컬럼이 말하지 않는다), 문자열 정렬이 곧 시간 순서다 | 결정 | 템플릿 | ~~Phase 6~~ |
| **`richText` 의 에디터 라이브러리**(§5.5) — [20](../../stack.md) 스택 표에 없다. [60](../../../../documents/screen/_standalone/README.md) §11 이 공지(NOTI-01)에서 이미 물은 것과 **같은 결정**이며 한 번만 고른다 | 결정 | 템플릿 | **`D`**(설계 개요 §4) — 쓰는 화면이 공지 본문뿐이라 **Phase 6 공통 컴포넌트도 만들지 않는다** |
| ~~**`list` 를 서버가 어떻게 저장하나**(§5.6)~~ → **해소(2026-09-01)** — **자식 테이블이다**([48](../../../playbook/INDEX.md) §4.1 의 `SMPL_ORDER_TAG`). 근거 셋: **벤더 중립**(직렬화는 `JSON` 타입이나 구분자를 부르고 둘 다 4벤더에서 샌다) · **조회 조건이 성립한다**(`EXISTS` 한 줄 대 `LIKE '%…%'`) · **`list` 는 화면의 어휘이지 저장의 어휘가 아니다**. 순수 스칼라 + 조회 대상 아님 + 개수 한둘이면 문자열이 나으며, 그때는 **셋을 다 부정할 수 있어야** 한다 | 결정 | 템플릿 | ~~Phase 8~~ |
| **엑셀 셀 문자 상한 초과 처리**(§5.5) — 잘렸음을 알릴지, 긴 텍스트 컬럼을 엑셀에서 뺄지 | 결정 | 템플릿 | Phase 6 |
| **값이 손에 없는 긴 텍스트**(§5.5) — 목록이 `nclob` 을 싣지 못하면 *한 줄로 자르고 툴팁에 미리보기* 가 성립하지 않는다. [64](../../../../documents/screen/log/access/requirements.md) §2.4 가 **파생 컬럼 + `link` 렌더러 + `getDetail`** 로 풀었다. **그 규약을 여기로 올릴지** | 결정 | 템플릿 | Phase 5 완료 시점 |
| **한 행에 `textModal` 대상이 둘일 때**(§5.5) — 이 절은 *컬럼 하나에 모달 하나* 를 전제한다. [64](../../../../documents/screen/log/access/requirements.md) §5.5 가 **모달 하나 + 탭 둘**(전문 · 스택)로 풀었다 — 링크 컬럼을 둘 두면 사용자가 매번 판단한다 | 결정 | 템플릿 | Phase 5 완료 시점 |
| **`renderer` 일곱이 충분한가**(§5.4) — **모수는 `62`~`65` 가 아니라 업무 화면이다**([57](./search-form-contract.md) §1.1). Phase 8 샘플이 그 대리다(`66`·`67` 은 `D` — 설계 개요 §4). **첫 사례가 나왔고 구현됐다**(2026-08-30) — [65](../../../../documents/screen/batch/schedule/requirements.md) §4.4 가 `duration` 을 요구했고 여섯이 일곱이 됐으며 넷이 실물이다. 부족하면 더 늘리되 **함수는 열지 않는다** | 결정 | 템플릿 | Phase 5 완료 시점 |
