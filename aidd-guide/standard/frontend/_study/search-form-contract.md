## 1. 범위 — **필드 하나**를 선언하는 자리

[72](../../backend/_study/api-conventions.md) 가 *요청 하나* 를 정했다. 여기는 **그 요청을 만드는 폼의 칸 하나**를 정한다.

### 1.1 **`60`~`65` 는 요구의 전부가 아니다**

이 저장소는 **업무 도메인을 가리지 않는 베이스**다(설계 원칙). 지금 있는 화면 여섯은
**시스템 관리 화면**이며 개발자가 필요를 미리 다 안다 — 그 표본에서 *"이런 기능은
필요 없더라"* 를 결론으로 뽑으면 **템플릿을 쓰는 프로젝트의 업무 화면을 미리 좁힌다.**

| 그래서 | |
|---|---|
| **사례가 없다**는 것은 | *"열지 않는다"* 의 근거가 **아니다.** 지금 화면에 그 요구가 없었다는 사실일 뿐이다 |
| **닫는 근거는 셋뿐**이다 | ① 열면 **틀린 결과**가 나온다 · ② 열면 **운영이 깨진다**(성능·보안) · ③ **다른 수단이 이미 그것을 덮는다** |
| 목업도 마찬가지다 | 22장은 **지금까지 그린 것**이지 앞으로 필요한 전부가 아니다 |

**§6 의 표는 계약을 *검증* 하는 자리이지 *한정* 하는 자리가 아니다.**

### 1.2 셋의 분담 — [72](../../backend/_study/api-conventions.md) §1.1 의 반대편

| | [72](../../backend/_study/api-conventions.md) | **`57`**(여기) | Phase 6 |
|---|---|---|---|
| 관점 | 서버와 주고받는 사람 | **조회조건을 선언하는 사람** | 컴포넌트를 만드는 사람 |
| 단위 | 요청 하나 | **필드 하나** | `<SearchForm>` 하나 |
| 답 | 어떤 연산자가 존재하나 | **이 칸은 그중 무엇을 쓰나** | props · 렌더링 |

**`72` 가 먼저였고 그것이 끝났다.** 연산자 열셋([72](../../backend/_study/api-conventions.md) §3.3) · 봉투 넷(§3.1) ·
`params`(§3.1.1) · 페이징 모드(§3.8)가 전부 확정됐으므로 **여기서 발명할 와이어가 없다.**

### 1.3 이 문서가 닫는 미결

|---|---|---|

| **저장된 조건의 직렬화 · 공유 · 개수 상한 · 기본 조건** | [53](./grid-standard.md) §9 · [51](./main-shell.md) §5.1 | **§5** |
| **[54](./grid-column-contract.md) §5.1 의 *조건부 필수는 함수다* 어휘를 재사용할지** | 설계 개요 §4 | **§3.7 — 재사용한다** |

## 2. 검색 폼이 있는 화면과 없는 화면

[72](../../backend/_study/api-conventions.md) §3.0 이 조회를 둘로 갈랐다. **그 선이 곧 폼의 유무다.**

| | 검색 폼이 **있다** | 검색 폼이 **없다** |
|---|---|---|
| 조회 | **동적형** — 봉투([72](../../backend/_study/api-conventions.md) §3.1) | **고정형** — 전용 `record` |
| 어디 | **마스터 그리드**가 있는 화면 | 디테일 탭 · 코드 상세 · 트리 |
| 페이징 | `offset` · `cursor` | 대개 `all`([72](../../backend/_study/api-conventions.md) §3.8) |
| 정렬 | 서버 — 헤더 클릭이 재조회 | 클라이언트 |

- **화면에 폼은 하나뿐이다**([53](./grid-standard.md) §1.1) — 마스터 그리드의 것이며([53](./grid-standard.md) §2.4)
  디테일은 마스터의 선택에 종속되므로 자기 조건을 갖지 않는다([53](./grid-standard.md) §6.1)
- **자리는 마스터 그리드 위**, 컨트롤 둘(저장된 조건 · 접기 토글)은 **브레드크럼 줄의
  오른쪽**이다([51](./main-shell.md) §5.1) — 폼을 숨기는 버튼이 폼 안에 있으면 되돌릴 수 없다

### 2.1 폼처럼 생겼지만 폼이 아닌 것 — 트리의 *찾아가기*

[62](../../../../documents/screen/menu/requirements.md) §4.10 이 **거르지 않고 찾아간다**고 정했다. 조건에 맞는 노드만 남기면
부모가 사라져 트리가 아니게 되기 때문이다.

| | 검색 폼 | 트리의 찾아가기 |
|---|---|---|
| 하는 일 | **서버 조회** | **강조 + 경로 펼치기 + 스크롤** |
| 결과 | 행 집합이 바뀐다 | **행 집합이 그대로다** |
| 이 문서 | **대상이다** | **대상이 아니다** |

**같은 자리에 있지만 다른 물건이다.** `<SearchForm>` 을 재사용하더라도 **`72` 의 봉투를
만들지 않으므로** 여기의 계약이 적용되지 않는다 — 그 화면은 `n / m` 과 `‹ 이전 · 다음 ›`
을 폼 오른쪽에 갖는다(〃).

## 3. 필드 선언

### 3.1 키를 넷으로 묶는다

```ts
{ field: 'creDtm', type: 'dateTime', op: 'between',      // ① 무엇을 묻나
  label: 'log.field.period', span: 8,                    // ② 어떻게 보이나
  defaultValue: { relative: -7, unit: 'day' },
  required: true, maxRange: { days: 31 } }               // ③ 어떻게 검증하나
                                                          // ④ 어떻게 나가나 — 기본값이라 생략
```

| 묶음 | 키 | 필수 |
|---|---|---|
| **① 무엇을 묻나** | `field` · `type` · **`op` · `ops`** | **`field` · `type`** — 나머지는 타입이 기본을 준다(§3.4) |
| **② 어떻게 보이나** | `label` · `span` · `options` · `codeGroup` | `label` |
| **③ 어떻게 검증하나** | `required` · `maxRange` | — |
| **④ 어떻게 나가나** | `to` · `paramKey` · `scale` | — |

**키를 늘리기 전에 파생을 먼저 본다** — 필요해 보이는 것의 상당수는 **조건의 번역**이며
서버가 갖는다([72](../../backend/_study/api-conventions.md) §3.5). 그래도 남으면 **늘린다** — §1.1 이 그 이유다.

### 3.2 서버가 주는 것과 화면이 적는 것을 가른다

[72](../../backend/_study/api-conventions.md) §4.1 이 *"`57` 의 프론트 타입도 이 스펙에서 생성한다"* 고 적었다.
**그러면 화면이 적을 것이 줄고, 적은 것이 스펙과 어긋나면 빌드가 깨진다.**

| **생성된다** — `QuerySpec` 에서 | **화면이 적는다** |
|---|---|
| `field` 가 **존재하는가** | `field` 를 **고르는 것** |
| 자바 타입 → **허용 `type` 의 범위** | `type` 을 **그중에서 고르는 것** |
| `nullable`(§3.5) · `sortable` | `op` · `label` · 기본값 · 필수 · 폭 · 순서 · `to` |

**타입을 생성이 정하지 않고 *제한* 만 하는 이유** — `String` 컬럼 하나가 `text` 일 수도
`code` 일 수도 `ynFlag` 일 수도 있다. **그것은 화면의 판단**이며 서버가 알 수 없다.
다만 `OffsetDateTime` 필드에 `type: 'number'` 를 적으면 **생성물이 그것을 막는다.**

### 3.3 `type` 은 [54](./grid-column-contract.md) §5 의 어휘를 **그대로** 쓴다 — 새로 만들지 않는다

| `type` | 컨트롤 | 쓰는 곳 |
|---|---|---|
| `text` | 한 줄 입력 | 로그인 ID · 요청 URI · IP · 추적 ID |
| `number` | 숫자 입력 | 역할 만료 예정 N일 · 소요 시간 |
| `date` · `dateTime` | AntD 달력 | 등록일 · 일시 |
| **`ynFlag`** | **3-state 세그먼트** — `전체` · `Y` · `N` | 사용 여부 · 시스템 여부 |
| **`code`** | `CodeSelect`([10](../../../knowledge/features.md) MASTER-03) | 메뉴 · 결과 코드 |
| **`select`** | 콤보 — `options` 가 정한다(§3.5) | 상태 묶음 · 접두사 · 변경 여부 |
| **`richSelect`** | `<SearchSelect>`([ADR-0018](../../../records/adr/0018-grid-edition-agnostic-vocabulary.md)) | 배치 선택 |

- **어휘를 [54](./grid-column-contract.md) 에서 가져오는 이유** — 같은 컬럼이 그리드에도 폼에도 나타난다.
  둘이 다른 이름을 쓰면 **화면 하나가 어휘 둘을 쓰게 되고**, `code` 의 표시 규칙([54](./grid-column-contract.md) §5.4)
  같은 것이 두 곳에 생긴다
- **`ynFlag` 는 폼에서 스위치가 아니다.** [54](./grid-column-contract.md) §5.2 가 그리드에서 스위치로 정했지만
  **조회조건에는 *전체* 가 있어야 한다** — 스위치는 2-state 라 *묻지 않음* 을 표현할 수 없다
- **`list` 는 조회조건에 쓸 수 없다** — 배열 컬럼이라 *"이 값을 포함하는 행"* 이
  컬럼 조건이 아니다. 필요하면 **파생**이다([72](../../backend/_study/api-conventions.md) §3.5)
- **`bigint` · `popupRef` 는 지금 사례가 없을 뿐 막지 않는다**(§1.1) — `bigint` 는
  `text` 처럼 다루고 와이어에서 문자열이며([24](./frontend-stack.md) §6.1), `popupRef` 는 **골라서 값을
  채우는 컨트롤**이라 조회조건에서도 같은 모양이다([54](./grid-column-contract.md) §6)
- **컨트롤의 모양은 `type` × `op` 가 함께 정한다**(§3.5) — 범위·다중을 위한 별도 타입을
  만들지 않는다

> **2026-09-02 — `popupRef` 가 섰다**([68](../../../playbook/INDEX.md) §9.14). 위 줄이 *"사례가 없을 뿐 막지
> 않는다"* 라고 적어 둔 둘 중 하나이며, 쓰는 화면이 왔다.
>
> **그리드와 같은 레지스트리를 쓴다**([54](./grid-column-contract.md) §6) — 두 벌을 두면 같은 고객 팝업이
> 그리드에서는 다섯 컬럼이고 폼에서는 셋인 날이 온다. **선언의 모양은 갈린다**:
> 그리드의 `apply` 는 여러 칸을 채우지만 폼에서 나가는 것은 **조건 하나**라
> (`popupValue`) 채울 칸이 없다.
>
> **연산자가 넷이다** — `eq`·`ne`·`isNull`·`isNotNull`. 값이 *고른 키* 라 조각 일치가
> 뜻이 없고(사용자는 치는 것이 아니라 고른다), `isNull` 둘은 **팝업으로 표현할 방법이
> 없는 질문**이라 연다(*고객이 지정되지 않은 주문*).
>
> **표시값이 조건과 함께 저장된다**(`SavedCondValue.text` · §5.1) — 키만 저장하면 다시
> 열었을 때 **빈 칸**이고, 조건은 걸려 있는데 무엇으로 걸렀는지가 화면 어디에도 없다.

### 3.4 `op` — **사용자가 고른다.** 고정은 화면이 선언하는 예외다

**연산자 선택은 검색 폼의 핵심 기능이다.** [60](../../../../documents/screen/_standalone/README.md) §2.2 가 후보 여덟을 적고 넘겼을 때
*"화면이 고르는가 사용자가 고르는가"* 가 열려 있었다. **사용자가 고른다.**

| | |
|---|---|
| **여기는 템플릿이다** | `60`~`65` 는 **시스템 화면**이라 개발자가 필요를 다 안다. 그 위에 업무 화면을 얹는 프로젝트는 ***이 컬럼을 포함으로 찾고 싶다*** 를 매번 만나며, 고정이면 **선언을 고쳐 재배포**해야 한다 |
| **서버는 이미 열려 있다** | [72](../../backend/_study/api-conventions.md) §3.4 가 *"연산자가 타입을 제한한다 — 필드마다 선언하지 않는다"* 로 닫았다. **열셋을 다 받는다.** 좁힌 것은 폼뿐이었다 |
| **화이트리스트가 이미 막는다** | 연산자를 바꿔도 **필드·타입 판정은 그대로**다([72](../../backend/_study/api-conventions.md) §4). 열어서 생기는 위험은 **성능뿐**이고 그것은 아래가 막는다 |

> **폼이 지금 낼 수 있는 것은 여덟이다**(2026-08-29 — 구현) — `eq` · `ne` · **`in`** ·
> `startsWith` · `contains` · `endsWith` · `isNull` · `isNotNull`. **`in` 은 콤보에만
> 난다**: 컨트롤이 *다중 선택* 이라야 값 여럿을 받을 수 있고(§3.5) 텍스트 칸에는 그
> 컨트롤이 없다 — 텍스트의 `in` 은 태그 입력이 필요하며 그것을 요구하는 화면이 아직 없다.
> **`between` 과 부등호 넷은 달력·숫자 범위 컨트롤이 함께 와야 한다** — 그것을 처음
> 요구하는 화면은 [64](../../../../documents/screen/log/access/requirements.md)(기간 조건)다. **서버는 열셋을 다 받는다.**

#### 선언은 둘 — `op` 와 `ops`

```ts
{ field: 'userNm',     type: 'text' }                          // 기본 — 타입이 허용하는 전부에서 고른다
{ field: 'userNm',     type: 'text', op: 'contains' }          // 처음 선택된 것만 지정
{ field: 'requestUri', type: 'text', op: 'startsWith',
                                     ops: ['startsWith'] }     // 고정 — 셀렉터가 사라진다
{ field: 'userId',     type: 'text', ops: ['eq','startsWith'] } // 후보를 좁힌다
```

| 키 | 생략하면 | |
|---|---|---|
| `op` | **타입의 기본**(§3.6 의 표) | 처음 선택된 연산자 |
| `ops` | **타입이 허용하는 전부**([72](../../backend/_study/api-conventions.md) §3.4) | 고를 수 있는 후보 |

**셀렉터는 후보가 둘 이상일 때만 나타난다.** 그래서 `ops: ['startsWith']` 가 곧 고정이며
**`fixed` 같은 플래그를 따로 두지 않는다** — 규칙이 하나면 읽을 것도 하나다.

#### 목록의 **순서는 고정이다** (2026-08-30)

**화면이 적은 순서가 아니다.** 조회조건 둘이 나란히 있는데 한쪽은 *포함* 이 첫째고
다른 쪽은 셋째면 **손이 자리를 기억하지 못한다** — 실물에서 실제로 갈려 있었다.

| # | 묶음 | 연산자 |
|---|---|---|
| 1~3 | **같음 계열** | `eq` 같음 · `ne` 같지 않음 · **`in` 여럿 중 하나** |
| 4~6 | **문자열 계열** | `startsWith` 시작 · `contains` 포함 · `endsWith` 끝 |
| 7~8 | **있음/없음** | `isNotNull` 값 있음 · `isNull` 값 없음 |
| 9~13 | **크기 계열** | **`between` 범위**(구현) · **`gte` 이상**(구현) · **`lte` 이하**(구현) · `gt` 초과 · `lt` 미만 |

자주 쓰는 것에서 드문 것으로 가고, 묶음 안에서는 **넓은 것에서 좁은 것**이다.
**목록에 없는 연산자는 맨 뒤로 간다** — 크기 계열이 올 때 앞으로 튀어나오지 않는다.

> **크기 계열은 요구하는 화면이 하나씩 연다**(2026-08-30). `between` 을 `dateRange` 가
> 가져왔고 **`gte` 를 [65](../../../../documents/screen/batch/schedule/requirements.md) §4.7 의 *소요 시간 이상* 이 가져왔다**. 남은 둘은 아직
> 열지 않았다 — **쓰이지 않는 후보를 미리 열면** 드롭다운이 길어지고, 그 길이는 매 화면의
> 매 조건이 치른다. 기호는 `≥` 이고 라벨은 `search.op.gte` 다.
>
> **`lte` 는 [61](../../../../documents/screen/user/requirements.md) §3.3 의 기간 칸 둘이 가져왔다**(2026-08-31). 기호는 `≤` 이고
> 라벨은 `search.op.lte` 다. 기간에서 **한쪽만 아는 조건**이 실제로 흔하다 — *"이 날짜
> 이후로 한 번도 안 들어온 계정"* 이 그것이며, 범위로 표현하려면 반대쪽 끝에 **사람이 아무
> 값이나** 넣어야 하고 그 값이 곧 조건이 되어 **묻지 않은 것을 거른다**.
>
> 남은 둘(`gt` · `lt`)은 날짜에서 *초과* · *미만* 이 **경계 하루를 두고 사람이 잘못 읽기
> 쉬운** 조건이라, 요구가 오면 그 화면과 함께 판단한다.

- **순서와 기본값은 다른 축이다.** 순서의 첫째를 기본으로 삼으면 **텍스트 칸의 기본이
  완전 일치**가 되는데, 사람이 검색창에 치는 것은 대개 조각이다 — 기본값은 §3.5 의 표가
  정한다(`text` → `contains`)
- **`ops` 로 좁혀 그 기본이 빠지면 남은 것 중 첫째**로 간다. 고를 수 없는 연산자가
  골라져 있는 상태를 만들지 않는다

> **`in` 의 이름이 `포함` 이면 안 된다**(2026-08-30 — 고침). `contains` 도 `포함` 이라
> **한 드롭다운에 같은 이름이 둘**이었다. 둘은 전혀 다르다 — `contains` 는 *문자열의
> 일부* 이고 `in` 은 *고른 값들 중 하나* 다. **`여럿 중 하나`** 로 둔다.

#### 고정하는 자리 — **인덱스를 아는 화면**

[64](../../../../documents/screen/log/access/requirements.md) §3.3 이 요청 URI 를 **앞 일치로 좁힌 판단**이 여기서 산다.

| 화면 | 필드 | `ops` | 왜 |
|---|---|---|---|
| [64](../../../../documents/screen/log/access/requirements.md) §3.3 | 요청 URI | `['startsWith']` | 부분 일치를 열면 **인덱스도 없는 컬럼에 앞뒤 와일드카드** — 전체 스캔이다 |
| 〃 | 사용자 · IP | `['eq']` | 기간 인덱스로 좁힌 뒤 거르는 구조다. 부분 일치를 열면 **기간을 좁히는 대신 부분 일치로 찾으려 한다** |
| [64](../../../../documents/screen/log/access/requirements.md) §4.6 | IP | `['eq']` | 대역 검색은 인덱스가 없어 **완전 일치와 비용이 같은데 결과만 넓어진다**(〃) |

**고정은 성능이 근거일 때만 한다.** *"이 필드는 완전 일치가 자연스럽다"* 는 근거가
아니다 — 그것은 `op` 기본값으로 표현하면 되고, 사용자가 바꾸고 싶으면 바꾸면 된다.

#### 연산자를 바꾸면 **컨트롤이 바뀐다**

`type × op` 가 컨트롤을 정하므로(§3.3) 선택이 바뀌면 칸의 모양도 바뀐다.

| 바뀜 | 값 |
|---|---|
| `eq` → `in` | **옮긴다** — 스칼라가 1원소 배열이 된다 |
| `in` → `eq` | **첫 원소만 남긴다.** 단 **콤보(`select`·`code`)는 비운다** — 아래 |
| 스칼라 ↔ `between` | **옮긴다** — 한쪽 칸에 넣고 반대쪽은 빈다(단측이다) |
| 그 밖 | **비운다** |

**옮길 수 있으면 옮기고 아니면 비운다.** 조용히 잘못된 값을 남기는 것보다 낫다.

> **콤보에서 `in` → `eq` 는 *전체* 로 간다**(2026-08-29 — 구현). 콤보의 빈 값은 **값이
> 아니라 *묻지 않음*** 이며(§3.3 의 `ynFlag` 와 같은 축이다), 첫 원소를 남기면
> **사용자가 고른 적 없는 조건 하나가 조용히 걸린 채** 조회가 돈다 — `NORMAL`·`LOCKED`
> 를 고르고 있다가 연산자만 바꿨더니 `NORMAL` 만 나오는 화면이 그것이다. 텍스트 칸에는
> *전체* 가 없어 이 문제가 없지만 **규칙이 둘이면 읽을 것도 둘**이라 한쪽으로 모았다.

- **`ynFlag` 에는 셀렉터가 없다** — 3-state 세그먼트가 값 집합을 통째로 다루므로
  후보가 실질 하나다(§3.3)
- **`op` 는 `to: 'params'` 인 필드에 없다**(§3.8) — 연산자가 없는 값이다
- **연산자 라벨도 메시지 키다**([ADR-0023](../../../records/adr/0023-message-key-sync-from-source.md)) — 열셋이 전역 상수이므로 화면마다 적지 않는다

### 3.5 `op` × `type` 이 컨트롤을 정한다

| `op` | 컨트롤 | 예 |
|---|---|---|
| `eq` | 한 칸 | 추적 ID · IP |
| `startsWith` · `contains` | 한 칸 — **와일드카드를 사용자가 쓰지 않는다**([72](../../backend/_study/api-conventions.md) §3.3) | 로그인 ID · 이름 |
| **`between`** | **칸 둘** — 달력이면 범위 선택기. **한쪽만 채우면 단측**(〃) | 일시 · 등록일 |
| **`in`** | **다중 선택** | 계정 상태 · 메뉴 · 결과 |
| `gt` · `gte` · `lt` · `lte` | 한 칸 + 부등호 라벨 | 역할 만료 예정 · 소요 시간 이상 |

**타입마다 허용 연산자와 기본이 있다** — [72](../../backend/_study/api-conventions.md) §3.4 를 그대로 받는다.

| `type` | 허용(`ops` 의 기본값) | `op` 의 기본값 |
|---|---|---|
| `text` | `eq`·`ne`·`in` · `startsWith`·`contains`·`endsWith` · `isNull`·`isNotNull` | **`contains`** |
| `number` · `date` · `dateTime` | `eq`·`ne`·`in` · `between`·`gt`·`gte`·`lt`·`lte` · `isNull`·`isNotNull` | **`between`** |

> **`dateRange` 칸에 정밀도가 생겼다**(2026-09-02 — [68](../../../playbook/INDEX.md) §3.3 이 요구했다). `precision`
> 이 없으면 지금까지와 같은 `second` 이고, `month` 는 **년월 달력**이며 값도 `202608`
> 문자열로 나간다([48](../../../playbook/INDEX.md) §4.2), `day` 는 시각을 묻지 않는다.
>
> **와이어가 갈리는 것이 요점이다.** 년월 칸이 ISO 시각을 보내면 서버의 `VARCHAR(6)`
> 비교가 **언제나 빗나가고**, 그 조건은 *걸었는데 0건* 이 된다 — 조회가 실패하지 않으므로
> 사용자에게는 **그런 데이터가 없는 것**으로 보인다.

> **`dateRange` 칸이 타입에서 받는 후보는 `between` 하나다**(2026-08-31 — 구현). 위 표는
> *타입이 표현할 수 있는 것* 이고 폼이 실제로 내는 기본은 그 하나다 — 한쪽이 열린 범위는
> **기간 상한 검사를 그대로 통과하는 무제한 조회**이고(그 검사는 두 끝의 차를 본다),
> 기간이 **부하의 상한인 화면**([64](../../../../documents/screen/log/access/requirements.md) §2.2)에서 그것은 문을 열어 두는 것이다.
>
> **여는 것이 선언이다.** 기간이 *창* 이 아니라 *거르개* 인 칸은 화면이 `ops` 로 연다 —
> [61](../../../../documents/screen/user/requirements.md) §3.3 의 *최종 로그인* · *등록일* 이 `['between','gte','lte']` 다. 기본이 닫는
> 쪽이면 새 이력 화면이 빠뜨렸을 때 **덜 위험한 쪽**으로 떨어진다([23](../../backend/_study/security-design.md) §4 와 같은 방향).
>
> **`gte` · `lte` 를 고르면 값 칸이 달력 하나가 된다.** 범위 칸을 그대로 두고 한쪽을 비우게
> 하면 *비운 것* 과 *아직 안 고른 것* 이 같은 모양이 되어, 조회가 되는지 안 되는지를 눌러
> 봐야 안다. 범위에서 옮길 때 **두 끝을 남기지 않는다** — 하나만 남기면 사용자가 고른 적
> 없는 조건이 조용히 걸린다(§3.4 의 다중 → 단일 규칙과 같다).
| `code` · `select` · `richSelect` | `eq`·`ne`·`in` · `isNull`·`isNotNull` | **`eq`** |
| `ynFlag` | `eq` | **`eq`** — 셀렉터 없음 |

- **`isNull` · `isNotNull` 을 고르면 값 칸이 사라진다**([72](../../backend/_study/api-conventions.md) §3.3) — 값을 받지 않는
  연산자이며, 남겨 두면 *"값을 넣었는데 안 걸린다"* 가 된다
- **`nullable` 이 아닌 필드에는 그 둘이 없다** — 생성물이 안다(§3.2). 있어 봐야 전건이거나 0건이다

**`nullable` 인 필드의 `in` 컨트롤에는 `(없음)` 항목이 붙는다.** [64](../../../../documents/screen/log/access/requirements.md) §3.2.1 의
*메뉴 없음* 체크박스가 그것이며, **체크박스를 따로 두지 않는다** — [72](../../backend/_study/api-conventions.md) §3.6 이
*"`in` 배열에 `null` 을 넣는다"* 로 닫았으므로 **컨트롤도 하나여야 한다.**

#### `options` 의 원천 **셋**

| 원천 | 선언 | 예 |
|---|---|---|
| **정적** | `options: [...]` | `변경 여부` — `변경됨`·`기본값`([63](../../../../documents/screen/code/requirements.md) §4.6) |
| **공통 코드** | `type: 'code'` + `codeGroup` | 결과 코드([64](../../../../documents/screen/log/access/requirements.md) §4.6) |
| **서버 도출** | `options: 'derived'` | **접두사** — 전 키에서 뽑는다([63](../../../../documents/screen/code/requirements.md) §4.6) |

**셋째가 필요한 이유** — [43](../../../knowledge/sys/code.md) §6.1 이 `CFG_GRP_CD` 를 두지 않으며 *"새로 관리할 것도,
어긋날 것도 없다"* 고 한 그 도출이다. **목록을 관리하지 않는 콤보**가 실제로 있다.
목록은 **조회 응답이 함께 싣는다** — 별도 API 를 만들면 조건과 목록이 어긋난다.

### 3.6 기본값 — 성격이 **셋**이고, 셋 다 초기화의 대상이다

| 성격 | 선언 | 예 |
|---|---|---|
| **정적** | `defaultValue: 'ALL'` | 사용 여부 = 전체([62](../../../../documents/screen/menu/requirements.md) §3.3) |
| **상대 날짜** | `defaultValue: { relative: -7, unit: 'day' }` | 최근 7일([64](../../../../documents/screen/log/access/requirements.md) §4.6) |
| **집합** | `defaultValue: ['NORMAL','LOCKED','DORMANT']` | 계정 상태([61](../../../../documents/screen/user/requirements.md) §3.3) |

- **초기화 버튼은 *빈칸* 이 아니라 *기본값* 으로 되돌린다.** 비우면 [61](../../../../documents/screen/user/requirements.md) §3.3 의
  *"기본이 사용중인 이유 — 전체가 기본이면 목록이 퇴사자로 채워진다"* 가 무너진다
- **상대 날짜는 브라우저가 계산해 오프셋 포함 ISO 로 보낸다**([72](../../backend/_study/api-conventions.md) §2.5) —
  서버가 *"최근 7일"* 을 해석하지 않는다. 해석하면 **경계 판단이 두 곳**에 생긴다
- **상대 표현은 저장된 조건에서 다시 쓰인다**(§5.2) — 그것이 이 형태를 두는 진짜 이유다

> **넷째 성격이 하나 있다 — *비워 둔다*** (2026-08-30 — 구현). 기간 칸은 적지 않으면
> 시스템 기본 기간으로 **채워지는데**, 그것은 **기간이 부하의 상한인 화면**의 규약이다
> ([64](../../../../documents/screen/log/access/requirements.md) §2.2). [61](../../../../documents/screen/user/requirements.md) §3.3 의 *최종 로그인* · *등록일* 은 그런 칸이 아니라 **선택
> 필터**이며, 미리 채우면 **한 번도 로그인하지 않은 계정이 첫 조회에서 통째로 빠진다** —
> 그리고 그 계정들이야말로 사용자 관리에서 찾을 일이 많다.
>
> 그래서 `defaultValue: ''` 가 *비워 둔다* 를 뜻한다. **새 키를 만들지 않은 것**은 이미
> *기본값이 무엇인가* 를 말하는 자리가 여기이기 때문이며, `undefined`(적지 않음)와
> `''`(비운다)를 가르는 것이 그 뜻에 맞는다.
>
> **집합 기본값도 이때 실물이 됐다.** 위 표는 처음부터 배열을 적어 두었는데 폼은 문자열
> 하나만 받고 있었다 — `'NORMAL,LOCKED,DORMANT'` 를 주면 **원소 하나짜리 배열**이 만들어져
> 서버가 없는 계정 상태로 읽고 400 을 냈다(실물). 선언은 문서대로였고 **구현이 따라가지
> 않았던 자리**다.

### 3.7 필수와 조건부 필수 — [54](./grid-column-contract.md) §5.1 의 어휘를 **재사용한다**

설계 개요 §4 가 *"[54](./grid-column-contract.md) §5.1 의 **조건부 필수는 함수다** 어휘를 재사용할지"* 를 첫 결정으로
남겼다. **재사용한다.**

```ts
required: true                              // 기간은 필수 (64 §2.2)
required: (v) => v.traceId == null          // 추적 ID 를 넣으면 기간이 선택이 된다
```

| | [54](./grid-column-contract.md) §5.1 (그리드) | **여기** (폼) |
|---|---|---|
| 함수가 받는 것 | **행** — `(row)` | **폼 값 전체** — `(values)` |
| `*` 표시 | 헤더. 함수면 **조건임을 나타낸다** | 라벨. 〃 |
| 순서 | 필수 검사가 먼저 | 〃 |

**대상만 다르고 규칙이 같다.** 다른 어휘를 만들면 개발자가 *"그리드는 `row`, 폼은 무엇"* 을
매번 확인하게 된다.

- **서버도 본다.** 조건부 필수는 **폼과 서버 둘 다** 검증한다([56](./grid-edit-validation.md) §3.4 · [72](../../backend/_study/api-conventions.md) §3.6) —
  프로토콜에는 나타나지 않는다. *조건이 안 올 뿐* 이다
- **`maxRange` 는 범위 상한이다.** [64](../../../../documents/screen/log/access/requirements.md) §2.2 의 31일 · 92일이며 **2층**이다 —
  `SYS_CONFIG` 기본값을 **화면이 덮는다**([53](./grid-standard.md) §2.3 의 3층에서 개인 층이 빠진 모양).
  개인 층이 없는 이유는 **상한이 성능 보호 장치**이고 사용자가 풀 것이 아니기 때문이다

### 3.8 `to` — `conditions` 인가 `params` 인가 ([72](../../backend/_study/api-conventions.md) §3.1.1)

```ts
{ field: 'roleCd',   type: 'code', op: 'eq' }                      // 기본 — conditions
{ field: 'roleAsOf', type: 'date', to: 'params' }                  // paramKey 는 field 와 같다
{ field: 'expired',  type: 'ynFlag', to: 'params',
  paramKey: 'includeExpired' }                                      // 다르면 적는다
```

| | |
|---|---|
| 기본 | **`conditions`** — 적지 않으면 이쪽이다 |
| `params` 로 뺄 때 | **`op` 를 적지 않는다** — 연산자가 없는 값이다. 적으면 400 이 아니라 **선언 오류**다 |
| `paramKey` | 생략하면 `field` 와 같다 |

**언제 빼는지는 [72](../../backend/_study/api-conventions.md) §3.1.1 의 표가 정한다** — *파생은 값 하나가 들어가고 조각
하나가 나온다. 그 관계가 깨지면 `params`.*

### 3.9 `scale` — 화면 단위와 저장 단위가 다를 때

```ts
{ field: 'elapsedMs', type: 'number', op: 'gte', scale: 1000 }   // 입력 초 → 저장 ms
```

[65](../../../../documents/screen/batch/schedule/requirements.md) §4.7 의 **소요 시간**이 지금의 사례이며, 단위가 갈리는 컬럼은 업무 화면에서 흔하다(§1.1). [72](../../backend/_study/api-conventions.md) §3.6 이 *"와이어는 언제나
저장 단위. 변환은 화면이 한다"* 로 닫았으므로 **선언이 여기 있어야 한다.**

- **함수가 아니라 배수인 이유** — 비선형 변환이 필요해지면 그것은 단위가 아니라
  **파생 조건**이며 서버가 갖는다([72](../../backend/_study/api-conventions.md) §3.5)
- **저장된 조건에는 화면 단위로 남는다**(§5.2) — 사용자가 입력한 값 그대로다. 곱하는 것은
  **나가는 순간**이며, 폼의 상태에 곱해 두면 다시 열 때 **또 곱해진다**

> **구현됐다**(2026-08-30 — [65](../../../../documents/screen/batch/schedule/requirements.md) §4.7 의 *소요 시간 이상*). 숫자로 읽히지 않는 값에는
> **손대지 않는다** — 조용히 버리면 *조건을 넣었는데 안 걸렸다* 가 되고, 그 목록은 거르지
> 않은 것을 거른 것으로 읽힌다. 타입 강제는 서버의 화이트리스트가 한다([72](../../backend/_study/api-conventions.md) §4.1).
> **배열(`in`)에는 걸리지 않는다** — 단위가 갈리는 칸은 크기 비교이지 목록 고르기가 아니다.

### 3.10 폭과 배치 — **고정 폭 흐름**

| | |
|---|---|
| 칸 하나 | **연산자 `44px` + 값 `300px`** — 왼쪽 정렬로 흘려 놓는다 |
| 값 칸의 폭 | **`300px` 고정.** `span` 이 아니다 |
| 줄바꿈 | **자동.** 남는 폭이 모자라면 다음 줄로 내려간다 |
| **가로 스크롤** | **없다.** 조회조건은 전부 보여야 한다 |
| 라벨 | **칸 위** — 왼쪽에 두면 라벨 길이가 제각각인 다국어에서 격자가 흔들린다([63](../../../../documents/screen/code/requirements.md) §3) |
| 라벨의 글자 | **본문 크기 · 본문 색**이며 굵기만 반 단계 올린다. **흐리게 두지 않는다** |
| 버튼(§4.4) | **오른쪽에 나란히** — 칸 영역과 좌우로 갈린다. 칸이 두 줄 세 줄이 되어도 자리가 변하지 않는다 |

> **24칸 격자(`span`)를 버렸다**(2026-08-29 — 구현). AntD Grid 의 `span` 은 **화면 폭에
> 비례**하므로 같은 `span: 6` 이 27인치에서 400px, 노트북에서 240px 이 된다 — 칸의 폭이
> 줄마다·기기마다 달라져 **두 줄이 되는 순간 아래윗줄이 어긋난다.** 고정 픽셀은
> 폭이 어떻든 칸이 같은 자리에서 시작하고, 넘치면 줄만 하나 늘어난다.

- **`newLine` 같은 강제 개행 키를 두지 않는다** — 폭이 고정이라 줄은 화면 폭이 정한다
- **가로 스크롤 뒤에 숨은 칸은 접힌 칸보다 나쁘다** — 접힘에는 최소한 *조건 n개* 표시가
  붙지만(§3.11) 스크롤에는 아무 표시도 없다
- **버튼을 마지막 칸 뒤에 붙이지 않는다** — 줄이 늘 때마다 버튼이 옮겨 다닌다
- **버튼을 칸 *위* 에 한 줄로 두지도 않는다**(2026-08-30 실물) — 칸 전체가 그 높이만큼
  내려앉는다. **좌우로 가른다**: 왼쪽이 칸, 오른쪽이 버튼이며 버튼은 라벨 줄만큼 내려
  **첫 줄의 칸과 눈높이가 같다**
- **라벨을 흐리게 두지 않는다**(〃) — 지금 무엇으로 찾고 있는지가 그 줄에만 적혀 있다.
  못 읽으면 **조건을 잘못 넣고도 모른다**
- **연산자와 값은 붙은 하나로 보여야 한다**(〃) — 바깥 모서리만 둥글고 **맞닿는 쪽은
  각지다**. 스플릿 버튼과 같은 모양이며, 둘 다 둥글면 **따로 놓인 컨트롤 둘**로 읽힌다

### 3.11 접기 — 토글은 [51](./main-shell.md) §5.1, **접히는 단위는 화면이 정한다**

```ts
collapsedRows: 1      // 첫 줄만 남기고 접는다. 생략하면 0 — 전부 접힌다
```

| | |
|---|---|
| 기본 | **`0` — 전부 접는다.** 지금 화면들은 두 줄이라 부분 접기가 값을 하지 않는다 |
| **긴 폼** | **`collapsedRows: n`** — 업무 화면의 조회조건이 스무 칸이 되면 *"자주 쓰는 첫 줄만"* 이 정상 동작이다(§1.1) |

- **접힌 채로 조회하면 접기 전 조건으로 나간다**([51](./main-shell.md) §5.1) — 접기는 표시다
- **감춰진 칸에 조건이 걸려 있으면 브레드크럼 줄에 표시한다**(〃). 부분 접기여도
  규칙이 같다 — **표시의 기준은 *접힌 줄* 이 아니라 *보이지 않는 칸에 값이 있나* 다**
- **접힘 상태의 저장처는 `localStorage`** 이고 **탭마다 다르다**(〃)

## 4. 폼이 하는 일과 하지 않는 일

### 4.1 검증은 폼이 한다 — 그리드는 값을 요청할 뿐이다

[55](./grid-api-contract.md) §5 가 흐름을 정했다. **폼이 실패하면 조회가 일어나지 않는다.**

| 순서 | |
|---|---|
| ① | 그리드가 폼에 파라미터를 요청 |
| ② | **폼이 검증** — 필수(§3.7) · `maxRange` · 타입 |
| ③ | 실패면 **폼이 오류를 표시하고 조회하지 않는다** |
| ④ | 성공이면 **봉투를 만들어 넘긴다**([72](../../backend/_study/api-conventions.md) §3.1) |

- **오류 표시는 칸 아래**다 — [56](./grid-edit-validation.md) §3.3 의 셀 오류와 같은 어휘
- **서버가 400 을 주면 `fields` 배열이 칸에 다시 붙는다**([72](../../backend/_study/api-conventions.md) §2.3) — 폼이 놓친
  것(관계 검증 등)이 그 경로로 온다

### 4.2 빈 칸은 **보내지 않는다**

[72](../../backend/_study/api-conventions.md) §3.1 이 *"화면이 비운 칸은 배열에서 빠진다"* 로 닫았다.

- **`value: null` 을 보내지 않는다** — *"NULL 인 것을 찾아라"* 와 섞이면 안 된다(§3.4 의 `(없음)`)
- **Oracle 은 `'' = NULL`** 이다([22](../../backend/_study/db-portability.md) §4.5) — 빈 문자열을 보내면 벤더마다 다르게 해석된다
- **`between` 은 한쪽만 채워도 보낸다** — 단측 조건이다([72](../../backend/_study/api-conventions.md) §3.3)

### 4.3 정렬 필드는 **없다**

[54](./grid-column-contract.md) §3 이 닫았다 — *"정렬 UI 를 검색 폼에 두지 않는다. 정렬 기준은 언제나
컬럼이므로 컬럼 위가 맞는 자리다 — 폼에는 컬럼이 없다."*

**그래서 폼은 `sorts` 를 채우지 않는다.** 봉투 넷 중 폼이 만드는 것은
**`conditions` 와 `params` 둘**이고, `sorts` 는 헤더가, `page` 는 그리드 푸터가 만든다.

### 4.4 버튼은 **초기화 하나**

[53](./grid-standard.md) §2.4 가 정했다 — 조회는 그리드 ①이 갖는다.

| | |
|---|---|
| 조회 · 검색 | **없다** |
| **초기화** | **있다** — 기본값으로 되돌리고(§3.6) **컬럼 필터도 함께 지운다**([54](./grid-column-contract.md) §4.2) |
| **`Enter`** | **조회가 돈다**([53](./grid-standard.md) §2.4) — 폼을 채우고 손을 옮기지 않는 것이 가장 흔한 동선이다 |

## 5. 저장된 조회조건 (UX-07) — **직렬화**

[51](./main-shell.md) §5.1 이 *"상세 스펙은 아직 없다"* 로 남긴 자리다. 컨트롤(`[조건 ▾]`)의
자리와 제스처는 그쪽이 갖고, **여기는 저장되는 것의 모양**을 정한다.

### 5.1 저장하는 것은 **와이어가 아니라 폼 값**이다

```jsonc
// SYS_USER_SEARCH_COND.COND_JSON
{ "userId":    { "op": "startsWith", "value": "kim" },   // 사용자가 연산자를 바꿨다
  "status":    { "value": ["NORMAL","LOCKED"] },         // 기본 연산자 — op 를 안 적는다
  "createdAt": { "value": ["2026-08-01","2026-08-15"] } }
```

**연산자도 사용자 입력이다**(§3.4) — 고를 수 있는 필드에서 고른 것은 **값과 함께
저장해야 한다.** 고정된 필드(`ops` 가 하나)는 저장할 것이 없다.

| | |
|---|---|
| **왜 와이어가 아닌가** | 봉투는 **파생물**이다. `to` · `paramKey` · `scale` 은 **선언에 있으므로** 함께 저장하면 미러링이고, 선언을 고쳤을 때 **저장된 쪽이 낡은 형태를 되살린다** |
| **왜 폼 값인가** | 폼이 그것을 채우고 **다시 직렬화한다.** 필드가 사라지면 **그 키만 버리면 된다** — 봉투를 저장했다면 사라진 `field` 가 조건으로 남아 400 이 난다 |
| **`op` 만 예외인 이유** | 다른 셋은 **선언이 정하지만** `op` 는 **사용자가 고른다**(§3.4). 사용자가 고른 것은 선언에 없으므로 **저장하지 않으면 복원되지 않는다** |

**[72](../../backend/_study/api-conventions.md) §4.1 의 *원본이 하나* 가 여기에도 적용된다** — 저장은 **사용자가 입력한 것**만
담고, 그것을 요청으로 바꾸는 규칙은 **선언 한 곳**에 있다.

### 5.2 **기본값과 같은 칸은 저장하지 않는다**

이것이 §3.6 의 상대 날짜를 살리는 장치다.

| 저장 시점 | 저장되나 |
|---|---|
| 기간이 **최근 7일**(기본값 그대로) | **저장 안 함** |
| 기간을 **8/1~8/15 로 바꿈** | **저장함** — 절대값 |
| 연산자가 **기본 그대로** | **`op` 를 안 적는다** |
| 연산자를 **바꿈** | **`op` 를 적는다** |

**그래서 *최근 7일* 로 저장한 조건은 열 때마다 최근 7일이 된다.** 절대값으로 굳으면
**내일 열었을 때 어제 것이 나오고**, 그것이 저장된 조건의 가장 흔한 배신이다.

- 저장 크기도 준다 — 대부분의 칸이 기본값이다
- **단위는 화면 단위로 남는다**(§3.9) — `scale` 은 와이어로 나갈 때만 걸린다

### 5.3 화면 선언이 바뀌면 — **조용히 버린다**

| 바뀐 것 | 복원할 때 |
|---|---|
| 필드가 **없어졌다** | **그 키를 버린다.** 알리지 않는다 — 사용자가 할 수 있는 일이 없다 |
| `type` 이 **바뀌었다** | 값이 새 타입에 맞으면 쓰고, **아니면 버린다** |
| 저장된 `op` 가 **`ops` 에서 빠졌다** | **기본 연산자로 되돌린다.** 값은 §3.4 의 이동 규칙을 탄다 |
| 필드가 **추가됐다** | **기본값**이 들어간다(§5.2 의 뒷면이다) |
| 전부 버려졌다 | **기본값 폼**이 된다 — 저장 항목은 남긴다. 사용자가 지울지 정한다 |

**실패가 조용한 쪽인 이유** — 여기는 [40](../../../knowledge/sys/INDEX.md) §7 의 *실패가 시끄러운 쪽을 택한다* 와
방향이 다르다. **개인 편의 기능**이며, 배포마다 *"저장한 조건 3개가 무효입니다"* 를
띄우면 **고칠 수 없는 경고**가 반복된다.

### 5.4 항목의 속성 — 넷

| | |
|---|---|
| **이름** | 사용자가 붙인다. 화면 안에서 **중복 불가** |
| **기본 조건** | **하나만.** 지정하면 **화면 진입 시 그 조건으로 폼이 채워진다** — 없으면 §3.6 의 기본값 |
| **개수 상한** | `SYS_CONFIG` — §8 |
| **공유** | **두지 않는다** — 아래 |

**공유를 두지 않는 이유** — 공유하면 *"남의 조건을 내가 고칠 수 있나"* 가 따라오고,
그것은 소유권·권한이라 **화면 하나가 아니라 관리 기능**이 된다. [51](./main-shell.md) §5.1 이
*"저장된 조건은 DB 다 — **나는 이 화면을 이렇게 조회한다** 는 사람의 속성"* 이라고 적은
그대로이며, **사람의 속성은 공유 대상이 아니다.**

### 5.5 [40](../../../knowledge/sys/INDEX.md) · [41](../../../knowledge/sys/user-role.md) 에 내는 요구

[40](../../../knowledge/sys/INDEX.md) §7 과 [41](../../../knowledge/sys/user-role.md) §9 가 *"`57` 이 직렬화 형태를 정해야 한다"* 로 미뤄 둔 것이다.

| 컬럼 | | 비고 |
|---|---|---|
| `USER_ID` · `MENU_CD` · `COND_NM` | **PK 셋** | 화면 안에서 이름 중복 불가(§5.4)가 곧 PK 다 |
| **`COND_JSON`** | **`nclob`** | 값 맵(§5.1). **정렬·검색 대상이 아니므로** `nclob` 제약([54](./grid-column-contract.md) §5.5)에 걸리지 않는다 |
| `DFLT_YN` | `CHAR(1)` | 기본 조건 — **사용자·메뉴당 하나**(§5.4) |
| `SORT_NO` | `NUMBER` | 드롭다운 순서 |

- **`MENU_CD` 가 PK 에 있다** — 조건은 **화면에 매인다.** 화면이 다르면 필드가 다르다
- **FK 를 `SYS_MENU` 에 건다** — 메뉴가 사라지면 조건도 의미가 없다.
  다만 [41](../../../knowledge/sys/user-role.md) §8 의 *이력에는 걸지 않는다* 와 달리 여기는 **개인 설정이라 걸어도 안전**하다
- `DFLT_YN` 의 **하나뿐** 을 DB 로 강제하지 않는다 — 부분 유니크 인덱스는 벤더마다
  문법이 다르다([22](../../backend/_study/db-portability.md) §4). **저장 시 애플리케이션이 이전 것을 내린다**

> **섰다**(2026-08-30). 테이블은 `schema/007-user-search-cond.yaml`, API 셋은
> `/api/common/searchCond/{getList,save,delete}` 이며 **`common` 계층이다** — `MENU_CD` 를
> 받지만 **그 메뉴의 권한을 묻지 않는다.** 여기서 다루는 것은 *"나는 이 화면을 이렇게
> 조회한다"* 라는 **사람의 속성**이고([51](./main-shell.md) §5.1) 그 화면의 데이터가 아니다. `service` 로
> 두면 **메뉴마다 액션을 하나씩 더** 만들어야 하는데 그 액션은 업무 권한과 무관하다.
>
> **컨트롤의 자리는 폼 안 오른쪽 아래**다 — [51](./main-shell.md) §5.1 이 브레드크럼 줄로 정했던 것을
> 폼 안으로 옮겼고(2026-08-30), 오른쪽 위였던 것을 **아래로 내렸다**(2026-09-01 — 칸이 두 줄이
> 되면 버튼만 첫 줄에 남았다). 근거와 치르는 값은 그쪽에 적었다.
>
> **목록이 `condJson` 을 함께 싣는다.** 고를 때 서버를 다시 부르지 않으며, 그래도 되는
> 이유는 §5.2 가 조건을 작게 만들기 때문이다 — 따로 부르면 목록과 내용이 어긋나는
> 순간이 생긴다.

## 6. `60`~`65` 를 이 계약으로 다시 읽는다 — **검증이지 한정이 아니다**

**서른셋 전부가 표현된다.** 표현되지 않는 것이 있으면 계약이 틀린 것이다.
**반대로 여기 없는 것을 계약이 못 한다는 뜻은 아니다** — §1.1.

**`ops` 가 적힌 셋만 고정이고 나머지는 사용자가 고를 수 있다**(§3.4) — **셋 다 근거가 성능**이다.

### 6.1 이 표가 찾아낸 것 — **넷**

| 무엇 | 어디로 |
|---|---|
| **`options` 의 원천이 셋이다** — 서버 도출이 실제로 있다([63](../../../../documents/screen/code/requirements.md) §4.6) | §3.5 |
| **범위 상한이 필요하다** — [64](../../../../documents/screen/log/access/requirements.md) 의 31일 · 92일 | §3.7 `maxRange` |
| **단위 변환 선언이 필요하다** — [65](../../../../documents/screen/batch/schedule/requirements.md) 의 초 → ms | §3.9 `scale` |
| **한 칸이 두 컬럼을 거는 사례가 셋** — 파생으로 전부 덮인다 | [72](../../backend/_study/api-conventions.md) §3.5 |

**`params` 로 빼야 하는 사례는 `60`~`65` 에 없었다.** [72](../../backend/_study/api-conventions.md) §3.1.1 은 **`61` §3.3 의
보유 역할에 기준일·만료 포함이 붙을 때**를 대비한 것이며, 지금은 `roleCd` 하나라
파생으로 족하다 — **문이 열려 있을 뿐 아직 아무도 지나가지 않았다.**

### 6.2 이 표가 **말하지 않는 것**

| 여기 없다 | 그래서 |
|---|---|
| 연산자를 바꾸고 싶은 필드 | **시스템 화면이라 없을 뿐이다**(§1.1). 업무 화면의 *거래처명* · *상품코드* 는 다르다 |
| 조회조건 스무 칸짜리 폼 | 〃 — 그래서 `collapsedRows` 를 열어 뒀다(§3.11) |
| `params` · `bigint` · `popupRef` | 〃 — 계약은 이미 표현할 수 있다 |

**계약이 좁아야 하는 자리는 §1.1 의 셋뿐이다** — 틀린 결과 · 깨지는 운영 · 이미 덮인 것.
