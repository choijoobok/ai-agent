# 다국어 — `MSG` 키 · `label()` · 언어 추가

> **문구를 소스에 박지 않는다**(CLAUDE.md §5-6). 화면 문구는 `MSG` 키 + `label()`.
> **한글 문자열·JSX 텍스트·템플릿 리터럴은 ESLint 가 막는다.**

## 1. 키 하나가 도는 길

```
messageKeys.ts (MSG 상수)  ─→ generateMessageSeed ─→ SYS_MESSAGE_KEY
                                                          │
SYS_MESSAGE (값)  ←── MESSAGE_MGMT 화면에서 채운다 ───────┘
     │
     └─→ 공개 번들 API ─→ messageStore ─→ label('login.title')
```

- **`MSG` 상수가 곧 "프론트가 쓰는 키"** 다 — 그것이 `USE_SCOPE` 를 정한다.
- **키 시드는 생성물이다.** `messageKeys.ts` 를 고쳤으면 `./gradlew generateMessageSeed`
  를 돌려 **CSV 를 같은 커밋에** 담는다.
- **값은 시드에 없다** — 화면과 엑셀로 채운다.

## 2. `label()` — 훅이 아니라 함수다

```ts
label('login.title');
label('grid.selected', { count: 3 });     // {count} 자리를 채운다
```

- **훅이 아닌 이유**: **모달 콜백·토스트·스토어 안에서도** 불러야 한다. 그래서 스스로
  구독하지 않고, **컴포넌트는 언어가 바뀌어도 다시 그리지 않는다.**
- **언어 교체는 페이지를 다시 부른다**(`window.location.reload()`). 그래서 `label()` 의
  결과를 `useMemo` 로 붙들어도 낡지 않으며, **셸이 그것에 기대고 있다.**
  다시 그려서 바꾸는 날에는 **그 자리들이 함께 바뀌어야 한다.**

> **없으면 키를 그대로 낸다.** 빈 문자열이나 `—` 를 보여주면 **누락이 숨는다** —
> 화면에 `login.title` 이 보이면 **즉시 신고된다.**

> **자리표가 없으면 그대로 둔다.** 번역이 `{name}` 을 빠뜨렸을 때 빈 칸이 아니라
> **원문이 그대로** 보여야 무엇이 잘못됐는지 드러난다.

**서버도 같은 규칙이지만 마지막 수단은 각자 정한다** — 에러 응답의 마지막 수단은 키가
아니라 **폴백 문구**다([../backend/exception.md](../backend/exception.md)).

## 3. 그리드·검색 폼의 문구도 키다

- 컬럼의 `header` 는 **메시지 키**다 — 문자열이 아니다.
- 검색 필드의 `label` 도 같다.
- 코드값의 표시명은 **`SYS_MESSAGE` 의 `code.{그룹}.{값}`** 이다 — 그래서 **코드명을
  고친 저장은 `message` 캐시 버전도 올린다**([../backend/caching.md](../backend/caching.md)).

## 4. `locales/` 는 폴백이 아니다

번들 로드에 **실패했을 때** 쓰는 문구 몇 개만 있다. 이 키들은 **`MSG` 에도
`SYS_MESSAGE` 에도 없다** — **서버가 없을 때 쓰는 것이라 서버에 두면 뜻이 없다.**

## 5. 축이 넷이고 원본이 셋이다

| 축 | 뜻 | 원본 |
|---|---|---|
| **지원 목록** | 화면에 낼 수 있는 언어 전부 | `sys-config.message.supported` (`application.yml`) — **프론트에 사본 하나** |
| **언어의 이름** | *한국어* · *Korean* | `SYS_MESSAGE` 의 `code.LANG_CD.{언어}` |
| **번역이 빈 칸의 폴백** | `ja` 값이 없을 때 무엇을 보이나 | `message.default-lang` (`ko`) |
| **모르는 언어의 답** | 일본어 브라우저에 무엇을 주나 | `message.browser-fallback-lang` (`en`) |

> **뒤의 둘은 다른 것이다.** 앞엣것은 *"번역이 비었다"* 의 답이고 뒤엣것은 *"이 사람의
> 언어를 우리가 모른다"* 의 답이다. 언어를 추가할 때 이 둘은 **대개 그대로 둔다.**

**언어를 늘려도 번역을 전부 채울 필요는 없다** — 값이 없는 키는 `default-lang` 으로,
그것도 없으면 **키 문자열**이 보인다.

## 6. 언어를 추가할 때 — 다섯 자리를 함께 고친다

**한 줄만 고치면 되는 일처럼 보이는데 아니다.** 그중 둘은 **고치지 않아도 빌드가 통과한다.**

| 빠뜨린 곳 | 증상 | 왜 원인이 안 보이나 |
|---|---|---|
| 프론트의 `SUPPORTED_LANGS` | **새 언어를 골랐는데 새로고침하면 영어로 돌아온다** | 서버에는 정상 저장된다. **DB 를 봐도 맞다** |
| `code.LANG_CD.*` 시드 | 언어 콤보에 **`code.LANG_CD.ja`** 가 그대로 뜬다 | 이것은 **의도된 동작**이라 오류가 아니다 |
| 캐시 버전 | **새로 설치한 곳에서는 멀쩡하고** 이미 쓰던 브라우저에서만 안 보인다 | **개발 중에 잡히지 않는다** |

나머지 셋(`supported` · 정적 문구 · 번역 값)은 빠뜨리면 **기동이 죽거나 컴파일이 깨져서**
바로 드러난다 — **이 절이 실제로 지키는 것은 위 표의 셋이다.**

**순서가 규약이다.** 번역 값을 채우는 것은 `supported` 가 **배포된 뒤**에만 할 수 있다 —
저장 서비스가 목록에 없는 언어의 값을 거부한다.

> **`supported` 는 환경설정 화면에서 못 바꾼다.** `List` 라 설정 카탈로그에 실리지 않는다.
> `SYS_CONFIG` 에 SQL 로 행을 직접 넣으면 바인딩은 통과하지만 **비지원**이다.
