# 게이트 점검 및 통과 요청

인자: `G0`~`G6` 또는 생략(현재 단계 자동 판정)

## 절차 — 4단계를 순서대로. 건너뛰지 않는다.

### ① Exit Criteria 자체검증
`aidd-guide/process/04-gates.md` 의 해당 게이트 체크리스트를 **항목별로** 판정한다.

- 각 항목에 ✅/❌ 와 **근거 파일 경로**를 붙인다. "충족" 만 쓰지 않는다.
- 자동 검사 가능한 것은 실제로 실행한다:
  - `/trace` → 추적성 오류 수
  - 미해결 `ASM-###` 수 (`documents/decisions/ASSUMPTIONS.md`)
  - `proposed` 상태 ADR 수
  - 테스트 실행 결과
- **❌ 가 하나라도 있으면 승인을 요청하지 않는다.** 먼저 해결하거나, 해결 불가 사유를 명시한다.

### ② 레드팀 자기반박 (필수, 생략 불가)
`[QA-레드팀]` 모자로 전환. `aidd-guide/quality/INDEX.md` §3 포맷으로 4개를 산출한다.
1. 이 산출물이 틀렸다면 가장 가능성 높은 이유 **3가지** (구체적 실패 결과까지)
2. 다루지 않은 예외·경계
3. 사용자가 나중에 "이거 아닌데" 할 지점
4. 지금 결정을 미루면 나중에 얼마나 비싼가

**"문제 없습니다"는 유효한 결과가 아니다.** 최소 3개를 반드시 낸다.
지적한 것은 각각 처리한다: 수정 / ASM 등록 / 사용자 결정 요청.

### ③ 결정 카드 + 역질문 (생략 불가)
사용자가 이해하지 못한 승인은 품질 장치가 아니라 책임 이전이다.
→ `aidd-guide/process/10-cognitive-debt.md`

**결정 카드**: 이번 단계에서 **사용자가 실제로 결정한 것**만 3~5개, 업무 언어 한 줄씩,
되돌리기 비용과 함께. 산출물 목록이 아니다. 기술 용어를 쓰면 실패다.

**역질문 1~2개**: ②의 레드팀 결과 중 가장 불안한 것을 **AI의 불확실성**으로 포장해 묻는다.
"확인하셨나요?"(확인 요구)나 "이게 무슨 뜻인지 아시나요?"(시험)는 금지.
"제가 이 부분 확신이 없습니다. …인가요?" 형태로.

**침묵 카운터**: `documents/project.state.yaml` `cognitive_debt.silent_approvals` 확인.
- 3회 이상이면 승인 요청 **전에** 워크스루를 먼저 제안한다
  (시스템을 10줄로 설명 → "가장 이상해 보이는 것 하나만 짚어주세요")
- 역질문에 답이 없어도 게이트를 인질로 잡지 않는다. ASM 등록 후 진행, 카운터만 올린다

### ④ 승인 요청
`aidd-guide/process/04-gates.md` §3 포맷으로 제시한다. 포함할 것:
- Exit Criteria 충족 현황 (n/m)
- 레드팀 지적 **전문** (숨기지 않는다)
- 미해결 ASM 목록
- 승인 시 무엇이 일어나는지 (특히 G3: spec 동결)
- 선택지: **승인 / 보류(사유) / 특정 항목 재작업**

### ⑤ 승인 후 처리
- `documents/project.state.yaml`: `gates.P?.status = approved`, `approved_at` 기록
- `cognitive_debt` 갱신: 사용자가 역질문에 답했거나 반박·질문을 했으면
  `silent_approvals: 0` 으로 리셋, 아무 반응 없이 승인만 했으면 +1
- `current.phase` 를 다음 단계로
- G3인 경우: `documents/spec/` 베이스라인 표시 (각 파일 헤더에 `baselined: YYYY-MM-DD`)
- 다음 단계의 첫 작업을 한 줄로 제시

## 금지
- ② 없이 ③④ 하기
- ③ 없이 ④ 하기 (결정 카드·역질문을 건너뛴 승인 요청은 무효)
- ❌ 항목을 숨기고 승인 요청
- 사용자를 가르치려 들기, "이해하셨나요?" 반복
- "자세한 내용은 documents/generated/…를 참고하세요" — **AI가 요약해야 한다**
- 사용자가 "승인"이라고 하기 전에 다음 단계 산출물 만들기
- 한 턴에 두 개 게이트 통과
