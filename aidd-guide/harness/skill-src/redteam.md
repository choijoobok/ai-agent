# 레드팀 자기반박

AI의 최대 실패 모드는 **자기 산출물에 대한 무비판**이다. 이 스킬은 그것을 절차로 강제한다.

## 태도
작성자가 아니라 **인수 심사자**다. "잘 만들었다"를 찾는 게 아니라 **"어디서 터질까"** 를 찾는다.
회사에 손해를 끼치는 방향으로 이 시스템이 실패하는 경로를 상상한다.

## 산출 (4개 전부 필수)

### 1) 이 산출물이 틀렸다면, 가장 가능성 높은 이유 3가지
추상적 우려 금지. **무엇이 어떻게 잘못되어 어떤 결과가 나오는지** 구체적으로.
- ❌ "확장성이 부족할 수 있습니다"
- ✅ "재고 차감을 출고확정 시점으로 잡았는데 현장은 피킹 시점을 기대할 수 있습니다.
     그러면 피킹~확정 사이에 같은 재고가 이중 할당되어 재고가 마이너스가 됩니다."

### 2) 다루지 않은 예외·경계
각 UC/기능에 대해 훑는다: 0건/최대값/음수 · 동시 처리 · 부재중 승인자 · 취소·되돌리기
· 마감 기간 소급 · 권한 경계 · 외부 시스템 무응답 · 중복 요청 · 부분 실패

### 3) 사용자가 나중에 "이거 아닌데" 할 지점
업무 현장의 상식과 어긋나는 곳. 특히 **범위 밖으로 뺀 것 중 현업이 당연히 있다고 볼 것.**
(엑셀 업로드/다운로드, 인쇄, 일괄 처리, 조회 조건, 즐겨찾기 등이 자주 걸린다)

### 4) 지금 결정을 미루면 나중에 얼마나 비싼가
미결정 항목별로 되돌리기 비용을 산정한다.

## 규칙
- **"문제 없습니다"는 유효한 결과가 아니다.** 3개를 못 찾았으면 아직 안 들여다본 것이다.
- 찾은 것은 반드시 처리한다: 수정 / `ASM-###` 등록 / 사용자 결정 요청 중 하나.
- 결과를 게이트 승인 요청에 **그대로 포함**한다. 숨기지 않는다.

## 대상별 추가 렌즈

| 대상 | 렌즈 |
|---|---|
| 요구사항 | 모순 쌍, 검증 불가 문장, 출처 없는 항목, Must 과다 |
| 아키텍처 | 운영 인력으로 감당 가능한가, 단일 장애점, 되돌리기 비용 |
| ERD | 정규화 위반의 근거, 권한 범위 컬럼 누락, 이력 없이 지워지는 데이터, 상태 전이 누락 |
| API | 예외 흐름 미매핑, 멱등성 없는 확정 액션, 권한 검사 누락 |
| 화면 | 오류 표시 없음, 빈 상태 없음, 중복 제출 가능 |
| 코드 | 트랜잭션 경계, N+1, 예외 삼킴, 클라이언트 검증만 존재 |
