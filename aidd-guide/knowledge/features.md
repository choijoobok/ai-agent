## 등급 정의

| 등급 | 의미 | 처리 |
|---|---|---|
| **M** (Must) | 템플릿 필수. Phase 8 이 CRUD 기본 패턴·샘플로 길을 내고, **Phase 10 기능 전개에서 전부 구현** — 설계 개요 §4 | 구현 |
| **S** (Should) | 대부분의 프로젝트가 필요. 구현하되 후순위 | 구현(후순위) |

> **공통 코드 참조(MASTER-10) 의 3형태** — `SYS_CODE_REF(GRP_CD, DTL_CD, REF_CD, REF_VAL)`,
> PK 는 앞 3컬럼.
>
> | 용도 | `REF_CD` | `REF_VAL` | 행 수 |
> |---|---|---|---|
> | **단일 부모** 필터 (대-중-소분류) | 부모 그룹명 | 부모 코드값 | 1 |
> | **다중 부모** 필터 (한 코드가 두 부모에 속함) | `IS_{부모값}` | `Y` | N |
> | **부가 속성** (색상·정렬가중치 등) | 속성명 | 임의 값 | 1 |
>
> - PK 를 3컬럼으로 유지해 **부가 속성의 유니크를 보장**한다. `REF_VAL` 을 PK 에 넣으면
>   같은 속성에 `Y`/`N` 이 공존해 **조용한 비결정 동작**이 된다.
> - 다중 부모를 플래그로 표현하는 대가는 `REF_CD` 오타뿐이고, 이는 콤보가 비어
>   **즉시 드러난다.** 실패가 시끄러운 쪽을 택한다.
> - `REF_CD` 는 공통코드(`CODE_REF_KEY`)로 **화이트리스트** 관리 → 입력 단계에서 오타 차단.
> - **2026-08-28 개정([ADR-0025](../records/adr/0025-reference-code-definition-and-dynamic-columns.md))** — 테이블이 **둘**이 된다. *"이 그룹이 어떤 참조 코드를
>   쓰는가"* 를 담는 **정의 테이블 `SYS_CODE_GRP_REF`** 를 신설하고 `SYS_CODE_REF` 가 그것을
>   FK 로 참조한다. 화면은 정의 하나를 **상세 코드 그리드의 컬럼 하나**로 낸다 —
>   `USE_YN` 은 없어지고 **빈 셀이 *값 없음* 이다**([43](./sys/code.md) §5 · [63](../../documents/screen/code/requirements.md) §2.4).
>   **다중 부모 플래그는 정의를 먼저 추가**해야 한다.
> - 한 필터 축에 다중 부모가 **하나라도 있으면 그 축 전체를 플래그** 방식으로 통일한다.
>   두 형태가 섞이면 프론트가 양쪽을 다 조회해야 한다.
> - 단일 부모 형태는 `REF_VAL` 이 부모 그룹의 유효 `DTL_CD` 인지 **검증 가능**하다.
>
> **계층 순회는 캐시 메모리에서 한다.** 공통코드는 전량 캐시(MASTER-02)되므로
> 재귀 SQL 이 필요 없다 — 재귀 CTE 의 벤더 문법 차이도 등장하지 않는다.
> **별도 마스터 테이블로 분리하는 판정 기준** — 깊이가 아니다.
>
> | 신호 | 조치 |
> |---|---|
> | 건수가 많아 **전량 캐시 전제가 깨진다** | 별도 마스터 |
> | 코드마다 **고유 속성**이 필요하다 (세율·배송권역) | 별도 마스터 — 참조 코드로 되지만 타입 안전성이 없다 |
> | **자체 라이프사이클** (승인·이력·유효기간) | 별도 마스터 |

## D-1. 개인정보 (PII) — **Phase 12 로 미룸**

> **이 그룹 전체와 LOG-04 는 설계 개요 에서 처음부터 다시 설계한다(2026-08-26).**

| ID | 기능 | 등급 | 비고 |
|---|---|---|---|

| NOTI-03 | **알림 발송 채널** (메일/SMS/웹훅/푸시 추상화) | **M** | `support` 어댑터. **outbox 기반**. 아래 주석 |

| NOTI-06 | **사용자 → 관리자 요청함** (권한 신청 · 잠금 해제 요청 등) | S | **방향과 상태가 NOTI-02 와 다르다** — 아래 주석 |

> **NOTI 그룹은 성격이 둘로 갈린다.**
>
> | 성격 | 항목 | 처리 |
> |---|---|---|
> | **발송 인프라** (기술 어댑터) | NOTI-03 · NOTI-04 | 템플릿 유지 |
> | **업무 화면** (공지함·알림함) | NOTI-01 · NOTI-02 · NOTI-05 | **`module-notice` 분리** |
>
> 발송 인프라는 뺄 수 없다 — **AUTH-07**(비밀번호 초기화 메일)과 **BATCH-06**(배치 실패 알림)이
> 이미 의존하고, [21-backend-architecture](../standard/backend/_study/architecture.md) 가 `support` 모듈에
> 이미 배치해뒀다. 인터페이스만 스텁으로 두면 첫 사용자가 시그니처를 정하게 되어
> 템플릿이 표준을 제공하지 못한다.
>
> **발송은 outbox 로 한다.** 업무 트랜잭션 안에서 보내면 롤백돼도 메일은 나가고,
> 커밋 후에 보내면 프로세스가 죽을 때 알림이 사라진다. 업무 트랜잭션에서 알림 행을
> INSERT 하고 릴레이가 발송하면 로컬 ACID 만으로 at-least-once 가 된다 —
> XA 를 제외하며 채택한 대안(설계 원칙 §2)의
> **첫 실사용처**다. 즉시성이 필요하면 `AFTER_COMMIT` 이벤트로 릴레이를 깨우고 보장은 테이블이 맡는다.
>
> 업무 화면은 없어도 백오피스가 완전히 동작한다. NOTI-01 은 **리치 텍스트 에디터**에
> 의존하는데, 에디터는 리포트·차트와 같은 이유로 범위에서 제외했다.

### 인앱 알림함의 위상을 다시 봐야 한다 (NOTI-02 · NOTI-06)

**상세 설계는 Phase 4 로 미룬다.** 다만 미루기 전에 두 가지를 기록해 둔다.

#### 1. "업무 화면" 이라는 분류가 흔들린다

위 표는 NOTI-02 를 *"없어도 백오피스가 동작하는 업무 화면"* 으로 묶어 `module-notice` 에
분리했다. **메일을 쓸 수 없는 배포를 전제하면 그 판단이 성립하지 않는다.**

발송 채널이 메일뿐인데 메일 연동이 없으면 아래가 전부 **도달하지 못한다.**

| 보내는 것 | 근거 |
|---|---|
| 관리자 비밀번호 초기화 통지 | AUTH-07 — [23](../standard/backend/_study/security-design.md) |
| 배치 실패 알림 | BATCH-06 |
| **권한 만료 예정 통보** | AUTHZ-08 — [23](../standard/backend/_study/security-design.md) §4. 유효 권한이 공집합이 되면 로그인이 막힌다 |
| 비밀번호 만료 예고 | AUTH-05 (`expire-notice-days`) |

**인앱 알림함은 로그인만 되면 반드시 도달한다** — 서버가 DB 에 행을 쓰고 화면이 읽는 것이
전부이므로 외부 의존이 없다. 이 성질이 다른 어떤 채널에도 없다.

> **AUTH-07 관리자 발급과 같은 구조의 판단이다.** 그때도 *"편의 기능이면 기본 OFF 가 맞지만
> 유일한 복구 경로면 기본 ON 이어야 한다"* 로 S → M 승격했다. 여기도 같다 —
> **`module-notice` 에서 분리하면 삭제 가능한 모듈이 유일한 도달 경로를 들고 나간다.**
>
> → **권고: NOTI-02 를 M 으로 올리고 코어에 둔다.** 공지사항(NOTI-01, 리치 에디터 의존)만
> 분리 모듈로 남긴다. 확정은 Phase 4 (§미결).

#### 2. NOTI-06 은 NOTI-02 의 반대 방향이며 상태를 갖는다

*"사용자가 관리자에게"* 는 알림이 아니라 **요청**이다 — 받는 쪽이 무언가를 해야 하고,
했는지 여부가 남아야 한다. NOTI-02(읽음/안읽음)와 데이터 모델이 다르다.

경계를 미리 못박는다. **결재선·워크플로를 만들지 않는다**(설계 원칙 §2).
상태는 **접수 · 처리 · 반려** 셋에서 닫고 단계·결재자 지정을 두지 않는다. 그 이상이 필요하면
신청 메뉴와 승인 메뉴를 분리해 권한으로 표현한다 — 이미 정한 방식이다.

#### 이미 정해져 있어 다시 정하지 않는 것

| 항목 | 이미 정해진 것 |
|---|---|
| 헤더의 자리 | [24](../standard/frontend/_study/frontend-stack.md) §3 앱 셸에 `알림` 이 있다 |
| 배지 갱신 방법 | **폴링.** NOTI-05(SSE/WebSocket)는 H 이고 SYS-13 이 폴링으로 통일했다 |
| 비활성 브라우저 탭 | `refetchInterval` 중지 — [24](../standard/frontend/_study/frontend-stack.md) §4 |
| 목록을 탭이 아니라 **모달**로 | 알림 목록에 작업 탭을 소모할 이유가 없다(UX-02) |
| 발송 경로 | **outbox 를 그대로 쓴다.** 인앱은 채널 하나가 늘어나는 것이며 별도 경로가 아니다 |

**알림에서 화면으로 가는 링크**가 필요하다. `MENU_CD` + 파라미터를 담아 두면 클릭이 곧 메뉴
진입이 되고, [42](./sys/menu.md) §8 의 메뉴 선택 API 에 `entryType = NOTIFICATION`
하나가 추가된다. 다만 **권한이 없으면 링크를 보여주지 않는다** — 알림이 권한을 주지는 않는다.

미결 3건은 이 문서 마지막 **남은 리뷰 포인트** 표에 넣었다.

### 샘플은 회귀 테스트 픽스처이기도 하다

샘플 테이블에 숫자·날짜·`CHAR(1)` Y/N·시퀀스·긴 문자열을 고루 넣으면
**4종 DB CI 의 실증 케이스**가 된다 → [22-db-portability](../standard/backend/_study/db-portability.md)

그래서 "넣을까 뺄까" 가 아니라 **격리 방법**이 문제다.

| 주체 | 샘플 처리 |
|---|---|
| **템플릿 저장소** | 항상 유지 — CI 가 이것으로 이식성을 검증한다 |
| **템플릿 사용자** | 복사 후 **삭제** |

### 격리 규약

| 축 | 규약 |
|---|---|
| 테이블 | 접두사 **`SMPL_`** (공통 테이블은 `SYS_`) |
| Liquibase | **별도 changelog** — master 에서 include 한 줄 제거로 탈락 |
| 백엔드 | 별도 패키지. **공통 코드가 샘플을 역참조 금지** (ArchUnit 강제) |
| 프론트 | 별도 디렉터리 (`pages/sample/`) |
| 메뉴·권한 시드 | **별도 changelog** — 코드와 함께 빠지도록 |
| 스위치 | `app.sample.enabled` — 지우기 전에 끌 수 있게 |

스위치를 두는 이유는 사용자가 초기에 **살아 있는 참조**로 쓰고 배포 전에 지우기 때문이다.
삭제 전 단계가 필요하다.

### 삭제는 **체크리스트가 아니라 제거 changelog** 다 (2026-09-01 개정)

이 자리는 오래 체크리스트였다. **체크리스트로는 안 된다** — 항목 대부분이 *사람이
소유한 시드* 라 `include` 를 지워도 **기존 DB 에 그대로 남고**([48](../playbook/INDEX.md) §7.1),
빠뜨리면 조용하다. 설계 원칙 P1 이 요구하는 것은 장치다.

| 절차 | |
|---|---|
| 1 | 백엔드 샘플 패키지 · 프론트 `features/sample/` · `SCREENS` 의 여섯 줄([68](../playbook/INDEX.md) §10.2) · **`menu/menu-tree.yaml` 의 일곱 줄**([ADR-0028](../records/adr/0028-menu-seed-upsert-and-orphan.md)) 삭제 |
| 2 | **`008-init-message-key.csv` 에서 `sample.` 줄 제거** — 유일하게 손이 가는 자리([48](../playbook/INDEX.md) §7.5) |
| 3 | `./gradlew generateApiSeed generateMessageSeed` |
| 4 | master 의 include 를 **`999-sample-remove.yaml`** 로 바꿔 끼운다 |
| 5 | 기동 — changelog 가 메뉴 · 권한 · 코드 · 메시지 · 채번 · 개인화 · 테이블을 순서대로 지운다 |
| 6 | `./gradlew reportSampleResidue` — **남았는지 기계가 센다**([48](../playbook/INDEX.md) §7.6) |

**자동으로 사라지는 것은 `SYS_API` · `SYS_MENU_API` 둘뿐**이고([ADR-0022](../records/adr/0022-generated-seed-full-sync.md) 의 전건 동기화)
나머지 아홉은 남는다 — 그 목록과 근거는 [48](../playbook/INDEX.md) §7.1 이 갖는다.
**개인화 넷**(`SYS_USER_GRID_PREF` · `_SEARCH_COND` · `_FAVORITE` · `_MENU_STAT`)은
이전 체크리스트에 **아예 없었다**.

권한·메뉴 데이터가 남으면 트리에 죽은 메뉴가 뜬다.

| 조회 화이트리스트 | **소스의 스펙 객체에서 도출.** 프론트 선언을 서버가 미러링하지 않는다 — [72](../standard/backend/_study/api-conventions.md) §4.1 |
| 분산 락 | **안전망(만료)과 쿨다운(최소 재실행 간격)을 별도 필드로 분리.** 불린 하나로 만료의 의미를 바꾸지 않는다 |
| 상호 배제 수단 | **기본은 비관적 락**(해제=커밋). 외부 락은 잠글 행이 없거나 트랜잭션 경계를 넘을 때만 |
| 글로벌 트랜잭션 | **제외.** XA 전제조건이 벤더별로 달라 DB 중립성과 충돌. 대안은 읽기전용 보조 DB / Outbox |
| 메뉴 권한 판정 | **경로 결합 없음.** 리프 단독 판정, 권한은 URL 있는 메뉴에만. 폴더 일괄 부여는 화면에서 |
| 서버측 인가 | **메뉴↔API 매핑 데이터가 단일 원본**, 액션은 4종(조회/저장/출력/실행)에서 닫는다 — 일괄 저장(UX-14)에서 등록/수정/삭제는 API 경계에서 구분 불가. 판정은 인가 인터셉터 한 곳, 매핑 없는 API 는 403 (deny by default). **기동 검증은 두지 않는다.** ~~코드 어노테이션도 두지 않는다~~ → **개정(2026-08-26, [ADR-0020](../records/adr/0020-path-prefix-action-and-seed-generation.md))**: 액션은 **경로 접두**가 정하고 `@ApiActionType` 이 예외를 선언한다. 둘 다 **시드 생성 입력**이며 런타임 판정에 참여하지 않으므로 판정 원본은 여전히 데이터 하나다 |
| 알림 | **발송 인프라(NOTI-03/04)는 유지, 업무 화면(공지·알림함)은 분리.** 발송은 outbox |
| 샘플 화면 | **전용 메뉴·테이블로 제공.** `SMPL_` 격리 + 삭제 체크리스트. 저장소에서는 CI 픽스처로 유지. **메뉴 여섯**([68](../playbook/INDEX.md)) · **테이블 셋**([48](../playbook/INDEX.md)) |
| 코드 계층 | **참조 코드로 흡수.** 자기참조 컬럼을 두지 않는다. 종속 콤보·대중소분류·부가속성이 한 메커니즘 |
| 사용 이력 메뉴 문맥 | **전 요청에 `X-Menu-Code` 부착** (공통 API 포함) — 메뉴 활용도 측정 근거. 기록 전용, 인가 불사용 |
| PII 대상 컬럼 | **템플릿은 확정하지 않는다.** `SYS_PII_DEF` 관리 화면에서 사용 프로젝트가 테이블·컬럼을 직접 지정 |
| 2FA | **자체 제공하지 않는다.** AUTH-11 은 H(훅) 유지 — 필요한 프로젝트가 직접 추가 |
| API 경로 체계 | **`/api/{public,common,service}/**` 계층 프리픽스, 버전 프리픽스 없음** — 단일 배포라 구버전 클라이언트가 없다. 외부 연동이 생기면 `/api/ext/**` |
| 업무 API 경로 규약 | **고정 경로 완전 일치** — 경로 변수·와일드카드 금지, 식별자·조회조건은 body. 매핑 겹침이 구조적으로 소멸, 매칭은 해시 조회 |
| 암호화 키 보관 | **키 파일 기본** (컨테이너 secret 마운트 호환), 환경변수는 개발용 |
| `SYS_USER` 개인정보 | **평문 보관.** 사내 직원 명부이며 고유식별정보가 아니다 — 이름·회사 메일. **휴대폰 컬럼 없음**(SMS 발송 수단 부재). PII Vault 는 업무 테이블용으로 유지 |
| UI 설정 저장 위치 | **기기·화면 속성은 localStorage, 사람 속성은 DB.** 언어만 DB — 서버가 메일·알림 언어를 알아야 한다 |
| 보존·파기 정책 | **단일 원본 문서로 통합**([32](./retention.md)). 보존에는 **상한과 하한**이 있고, 개인정보 접근 이력만 하한 — **파기 배치에서 구조적 제외**. 만료 청소(dedup·락·vault 고아)는 보존이 아니라 별도 성격 |
