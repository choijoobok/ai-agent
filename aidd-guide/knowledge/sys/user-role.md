# 계정 · 역할 — `SYS_USER` · `SYS_ROLE` · 부여

> 표 여섯: `SYS_USER` · `SYS_USER_PWD_HIST` · `SYS_USER_PWD_RESET` ·
> `SYS_USER_IP_ALLOW` · `SYS_ROLE` · `SYS_USER_ROLE`.
>
> **인증 체인이 어떻게 도는가**는 [standard/backend/security.md](../../standard/backend/security.md)
> 가 갖는다. 여기는 **그 판정이 읽는 데이터**다.

## 1. `SYS_USER` — PK 가 자연키다

`USER_ID`(로그인 ID)가 PK 다. 업무에서 부여되고 사실상 불변이며, **이력 표가 이미
`USER_ID` 를 값으로 보관한다** — 대리키를 두면 이력에 숫자를 남기고 조회할 때마다
조인해야 한다.

**이름·이메일을 암호화하지 않는다.** 사내 직원 명부이고, 참조키를 담으면 **이름 정렬과
LIKE 검색이 불가능해져** 사용자 목록의 가장 흔한 요구가 막힌다.

### 계정을 못 쓰게 만드는 것이 넷이고 **축이 다르다**

| 컬럼 | 누가 | 성격 |
|---|---|---|
| `USE_YN` | **관리자** | 손으로 내리고 손으로 올린다 |
| `VALID_FROM_DT` · `VALID_TO_DT` | 관리자 | **예정된 것** — 미리 넣어 둔다 |
| `LOCK_YN` · `LOCK_DTM` · `LOGIN_FAIL_CNT` | **시스템** | 일시적 — 로그인 실패 |
| `DORMANT_YN` | **배치** | 장기 미접속 |

**서로 덮지 않는다.** 잠금을 풀어도 여전히 미사용일 수 있고 그것이 정상이다. 이 규칙을
**엔티티 메서드의 경계가 집행한다** — `unlock()` 은 잠금 셋만, `releaseDormant()` 는
휴면 하나만 쓴다.

| 메서드 | 표면 |
|---|---|
| `changeProfile` | 본인이 고치는 것 **둘**(이름·이메일) |
| `changeLocale` | 언어 — **서버가 알아야 해서** 여기 있다(메일·알림을 어느 언어로 보내나) |
| `changePassword` | 해시 + `PWD_CHG_DTM` + **`PWD_INIT_YN` 을 내린다** |
| `changeByAdmin` | 관리자 축 **둘만**(`USE_YN` · 사용 기간) |
| `unlock` | `LOCK_YN` · `LOCK_DTM` · **`LOGIN_FAIL_CNT`** |
| `releaseDormant` | `DORMANT_YN` 하나 |
| 임시 비밀번호 발급 | 해시 + **`PWD_INIT_YN` 을 세운다** |

- **`PWD_INIT_YN` 을 함께 내리지 않으면 같은 화면에 갇힌다.** 임시 비밀번호로 들어온
  사람이 바꿔도 강제 변경으로 계속 돌아간다.
- **`unlock` 에서 `LOGIN_FAIL_CNT` 를 0 으로 두지 않으면 다음 한 번의 실패로 다시 잠긴다** —
  임계값에 이미 닿아 있다.
- **휴면 해제에 잠금이 같이 풀리지 않는다.** 함께 풀면 *실패 5회 → 해제 → 다시 5회* 가
  무한 반복된다.
- **관리자는 비밀번호 값을 정하지 않는다.** 발급만 한다.

## 2. `SYS_USER_PWD_HIST` — 재사용 금지가 유일한 존재 이유

| 컬럼 | |
|---|---|
| `USER_ID` + `CHG_SEQ` | PK. **`CHG_SEQ` 는 사용자 안에서만 단조 증가한다** |
| `PWD` | 과거 해시 — `SYS_USER.PWD` 에서 **그대로 옮겨 온다**(다시 해시하지 않는다) |
| `REG_ID` · `REG_DTM` | 감사 **둘뿐** |

- **`USER_ID` 는 주체, `REG_ID` 는 행위자다.** 둘이 갈리는 **유일한 표**이며, 본인 변경이면
  같고 관리자 임시 발급이면 다르다 — **그 구분이 여기 말고는 남지 않는다.**
- **감사 넷을 상속하지 않는다.** 이력은 수정되지 않으므로 `MOD_*` 는 언제나 NULL 이다.
- **전역 시퀀스를 쓰지 않는다.** 비교가 언제나 *이 사람의 최근 N건* 이라 전역 번호에 쓸
  데가 없다. 동시 변경은 **PK 충돌로 드러난다** — 조용히 덮어쓰는 것보다 낫다.

## 3. `SYS_USER_PWD_RESET` — **이력이 아니라 지금 유효한 토큰 하나**

| 컬럼 | |
|---|---|
| `USER_ID` | PK. **단독 PK 인 것이 이 표의 전부다** — 재요청이 옛 행을 덮어쓴다 |
| `TOKEN_HASH` | BCrypt. `SYS_USER.PWD` 와 같은 인코더가 만든다 — 알고리즘을 옮기는 날 둘이 함께 옮겨진다 |
| `ISSUE_DTM` | **재발송 쿨다운의 기준**. 만료 시각에서 역산하지 않는다 |
| `EXPIRE_DTM` | 계산이 아니라 **값**이다 — 발급 시점의 정책으로 굳힌다 |
| `TRY_CNT` · `USED_YN` | 시도 횟수 · 사용 표시 |

- **청소 배치가 없다. 없는 것이 맞다** — 사용자당 한 행이라 늘어날 상한이 계정 수이고,
  다음 발급이 옛 행을 밀어낸다. [retention.md](../retention.md) 의 어느 표에도 없는 이유다.
- **발급 이력을 여기 쌓지 않는다.** 그 자리는 로그인 이력이 이미 갖는다 — 쌓으면
  **토큰 해시가 계정마다 여러 줄 남고**, 지켜야 할 것이 느는 쪽이다.
- **메일 주소 컬럼이 없다.** 서버가 `SYS_USER.EMAIL` 에서 찾는다 — 복사해 두면 발급
  시점과 발송 시점의 주소가 갈리고, **입력받지 않는 값을 저장할 자리**가 생긴다.
- **쓴 토큰을 지우지 않고 표시한다.** 지우면 *쓴 적 없음* 과 구분되지 않아 같은 코드로
  두 번 바꾸는 경로가 재요청 쿨다운을 지나지 않는다.
- **해시가 절대적 방어가 아니다.** 6자리는 100만 조합이라 방어가 셋이다 —
  해시 · 만료 · 시도 한도. 평문으로 두면 셋 중 하나가 통째로 사라진다.

## 4. `SYS_USER_IP_ALLOW` — **행이 없으면 제한 없음이다**

**그 해석이 이 표의 전부다.** 빈 화이트리스트를 전면 차단으로 읽으면 **운영 사고가 관리자
계정에서** 난다 — 이 기능을 쓰는 계정이 정확히 그것이다.

| 컬럼 | |
|---|---|
| `USER_ID` + **`IP_CIDR`** | PK. 같은 대역을 두 번 넣을 수 없다 — 대리키를 두면 하나만 껐을 때 **껐는데 들어와진다** |
| `USE_YN` | *지금 손으로 끄고 켜는 것* |
| `VALID_FROM_DT` · `VALID_TO_DT` | *미리 정해 두는 것* — 파견·출장·외부 감사 |

- **둘의 AND 가 판정이다.** 기간이 없으면 끝난 계약의 IP 를 **사람이 기억해서** 지워야 한다.
- **`NULL` 이 제한 없음이라 기간을 뒤늦게 더할 수 있었다** — 기존 행의 뜻이 그대로다.
- **`LocalDate` 다.** 시각을 두면 *오늘 몇 시부터* 가 브라우저 시계로 흘러간다.
- **고칠 수 있는 것은 사용 여부와 기간뿐이다.** 대역을 바꾸는 것은 **다른 사실**이라 지우고
  다시 넣는다. 기간 연장은 **같은 사실의 수정**이다.
- **이 행을 읽는 검사는 아직 없다.** 값을 관리하는 화면이 먼저 섰다 —
  **검사가 먼저 서면 아무도 값을 넣을 수 없어 전원이 잠긴다.**

## 5. `SYS_ROLE` — 역할 자체에는 기간이 없다

역할은 **조직의 구조물**이며 *언제부터 언제까지 존재하는 역할* 이라는 개념이 없다.
기간은 **부여**의 것이다.

**`SORT_NO` 를 두지 않는다.** 소비처가 관리 화면의 정렬 하나였는데 그 그리드는 헤더 정렬을
이미 갖는다. **컬럼이 있으면 우선순위로 읽히고, 합집합에 우선순위는 없다.**

## 6. `SYS_USER_ROLE` — 회수는 삭제가 아니라 종료일이다

| 컬럼 | |
|---|---|
| `USER_ID` + `ROLE_ID` | PK |
| `VALID_FROM_DT` · `VALID_TO_DT` | **`NULL` 이 무제한** |

- **필수로 하면 `9999-12-31` 을 채우는 관행이 생긴다.** 그 값은 *무기한* 을 뜻하지만
  **아무 제약도 그것을 보증하지 않는다.**
- **즉시 회수는 어제 날짜다** — 오늘은 포함되므로 오늘로 두면 오늘까지 유효하다.
- **행을 지우지 않는 이유**는 *누가 언제까지 무슨 역할을 가졌는지* 가 남아야 하기
  때문이다. 변경 이력 표를 두지 않았으므로 **이 컬럼이 그 기록을 대신한다.**
- **역할이 비활성화되어도 이 행은 남긴다.** 다시 켜면 원래 부여가 살아나야 한다.

### 두지 않는 것 셋

| 없는 것 | 왜 |
|---|---|
| **주 역할 플래그** | 합집합이라 대표 역할이 판정에 쓰이지 않는다. 컬럼을 두면 **우선순위로 오해된다** |
| **`USE_YN`** | 기간이 *예정된 종료* 를, `VALID_TO_DT` 가 *즉시 중단* 을 맡는다 — 더하면 **축이 셋**이 된다 |
| **부여 사유** | 계약직에게 계약 기간만큼 주는 것은 정상 운영이다. 전부에 사유를 강제하면 **아무도 쓰지 않는다** |

> **개인 예외 권한은 반대다** — 기간 **필수** + 사유 **필수**. [menu.md §5](./menu.md).
