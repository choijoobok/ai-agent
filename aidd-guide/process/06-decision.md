# 의사결정 정책 — 누가 무엇을 결정하는가

## 1. 결정 분류표

AI는 모든 선택 앞에서 **되돌리기 비용**을 먼저 판정한다.

| 등급 | 정의 | 처리 |
|---|---|---|
| **High** | 되돌리려면 이미 만든 것의 30% 이상을 다시 만들어야 함 | **ADR 작성 + 사용자 승인 필수** |
| **Medium** | 되돌리기 가능하나 여러 산출물 수정 필요 | ADR 작성, 사용자에게 통지(승인 불필요) |
| **Low** | 국소적, 언제든 변경 가능 | AI가 결정, 기록 불필요 |

### High 결정 목록 (사용자 승인 없이 확정 금지)

- 시스템 목적과 성공 기준, 범위 경계
- **업무 규칙** — 계산식, 승인 단계, 상태 전이, 예외 처리 정책
- 데이터베이스 종류 (RDB/NoSQL, 벤더)
- 인증·인가 방식, 권한 모델
- 배포 형태 (온프레미스/클라우드/하이브리드), 운영 주체
- 주 언어·프레임워크
- 멀티테넌시 여부, 다국어 여부, 감사로그 범위
- 개인정보 수집 항목과 보존 기간
- 외부 시스템 연동 대상과 데이터 소유권
- 기존 데이터 이행 범위
- **아키텍처 스타일** (모놀리식/모듈러 모놀리식/마이크로서비스)

### Medium 예시
캐시 도입, 큐 도입, ORM 선택, API 스타일(REST/GraphQL), 테이블 정규화 수준, 프론트엔드 상태관리 라이브러리

### Low 예시
디렉터리 구조, 명명 규칙, 유틸 함수 설계, 로그 포맷, 테스트 픽스처 방식

## 2. ADR (Architecture Decision Record)

`documents/decisions/ADR-###-슬러그.md`. 템플릿은 [`aidd-guide/artifact/template/01-adr.md`](../artifact/template/01-adr.md).

**작성 원칙**
- **대안을 최소 2개** 적는다. 대안 없는 ADR은 결정이 아니라 통보다.
- **포기한 것(trade-off)** 을 반드시 적는다. 나중에 "왜 이거 안 됐지?"의 답이 된다.
- **되돌리기 방법과 비용**을 적는다. 미래의 AI가 이 결정을 뒤집을 때 필요하다.
- 결정을 뒤집을 때는 기존 ADR을 **수정하지 않는다**. 새 ADR을 만들고 기존 것을 `superseded_by` 로 표시한다.

**상태**: `proposed` → `accepted` / `rejected` → `superseded`
`proposed` 상태의 ADR이 있으면 해당 게이트를 통과할 수 없다.

## 3. 가정 원장 (Assumption Ledger)

사용자 답변을 기다리다 멈추지 않기 위한 장치다. **진행하되 흔적을 남긴다.**

`documents/decisions/ASSUMPTIONS.md`:

| ID | 가정 내용 | 근거 | 영향 산출물 | 확인 기한 | 상태 |
|---|---|---|---|---|---|
| ASM-007 | 개인정보 컬럼 판정 주체는 보안담당 | 개인정보처리방침상 관리 주체 | FEAT-003, SCR-002 | G3 이전 | 미확인 |
| ASM-008 | 동시 접속 최대 50명 | 사용자 300명 × 통상 15% | NFR-002, 인프라 사이징 | G2 이전 | 확인됨 → REQ-031 |

**규칙**
- 가정으로 만든 산출물 안에는 `[ASM-007]` 을 인라인 표시한다.
- **각 가정에는 확인 기한(게이트)을 붙인다.** 기한 게이트에서 미확인 가정이 있으면 게이트가 열리지 않는다.
- 확인되면 상태를 갱신하고 정식 REQ/ADR로 승격한다. **행을 지우지 않는다** (이력 보존).
- 가정이 틀린 것으로 밝혀지면 즉시 변경 영향 분석 → CR.

## 4. 사용자가 "알아서 해줘"라고 할 때

이것은 흔하고, 위험하다. 처리 절차:

1. **Low/Medium 이면 그냥 결정**하고 한 줄로 통지한다.
2. **High 이면 그냥 결정하지 않는다.** 대신 부담을 낮춘 형태로 다시 묻는다:
   - 선택지를 2개로 줄인다
   - 업무 언어로 번역한다 ("PostgreSQL vs MySQL" → "둘 다 됩니다. 사내에 운영 경험 있는 쪽이 어디인가요?")
   - "지금 안 정하면 언제까지 미룰 수 있는지"를 알려준다
3. 그래도 답이 없으면 **권장안으로 `ASM-###` 등록 + 해당 게이트에서 재확인**.
4. **절대로 조용히 결정하고 넘어가지 않는다.**

## 5. AI가 사용자 결정에 반대할 때

사용자가 명백히 문제 있는 선택을 하면:
1. **한 번은 반대한다.** 근거는 사실 기반으로 2~3문장. (예상되는 구체적 실패 시나리오)
2. 사용자가 재확인하면 **그대로 진행한다.** 설득을 반복하지 않는다.
3. ADR에 `사용자 결정 (AI 권고와 상이)` 로 표시하고, AI 권고 내용과 예상 리스크를 함께 남긴다.
4. 그 리스크가 실제로 나타나면 조용히 넘어가지 않고 ADR을 인용해 보고한다.
