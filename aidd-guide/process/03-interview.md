# 질문 규약 — 사용자에게 무엇을 어떻게 묻는가

AI-SDLC에서 실패는 대부분 "AI가 안 물어봐서" 또는 "너무 많이 물어봐서" 생긴다.
전자는 잘못된 시스템을, 후자는 포기한 사용자를 만든다. 질문은 **설계된 자원**이다.

## 1. 질문 배치 포맷 (반드시 이 형식)

```markdown
## [P2] 아키텍처 결정 — 질문 4개 (예상 소요 5분)

> 전부 기본값으로 진행하려면 "기본값" 한 마디만 주세요.

### Q1. [필수] 사용자 인증을 어떻게 처리할까요?
- **배경**: 사내 임직원 300명 + 외부 위탁 인력 50명 계정이 섞여 있습니다.
- **선택지**
  - (A) 사내 SSO(SAML) 연동 + 위탁 인력은 별도 로컬 계정  ← **권장**
  - (B) 전부 자체 계정 관리
  - (C) 전부 외부 IdP(Auth0 등)
- **권장 이유**: 임직원 계정 관리 부담이 없고, 퇴사자 접근 차단이 자동입니다.
- **영향**: ADR-004 / documents/spec/50-api/_index.yaml 인증 / SCR-001 로그인 / 사용자 관리 기능 3개
- **되돌리기 비용**: 높음 (구현 후 변경 시 인증 관련 전면 재작업)

### Q2. [기본값 가능] 데이터 보관 기간은?
- **권장(기본값)**: 거래 데이터 5년, 로그 1년, 삭제는 soft delete 후 배치 물리 삭제
- **영향**: ERD 공통 컬럼, 배치 기능 1개
- **되돌리기 비용**: 낮음
```

## 2. 규칙

| 규칙 | 내용 |
|---|---|
| **개수 상한** | 한 배치 최대 7개. 넘으면 우선순위로 자르고 나머지는 다음 배치. |
| **권장안 필수** | 권장안 없는 질문은 금지. "어떻게 할까요?"만 던지는 것은 책임 전가다. |
| **[필수] 남발 금지** | `되돌리기 비용 = 높음` 인 것만 `[필수]`. 한 배치에 3개를 넘지 않게. |
| **영향 범위 명시** | 답이 바뀌면 다시 만들어야 하는 산출물 ID를 적는다. 사용자가 무게를 가늠할 수 있어야 한다. |
| **소요 시간 표기** | 배치 상단에 예상 소요 시간. 사용자가 지금 답할지 미룰지 판단하게 한다. |
| **업무 용어로** | 기술 용어를 쓸 때는 업무 영향으로 번역해 준다. "SAML 연동" → "퇴사하면 자동으로 접근이 막힙니다". |
| **답 없으면 진행** | 무응답은 곧 "권장안 채택"이다. `ASM-###` 으로 기록하고 진행한다. 단 `[필수]`는 게이트에서 다시 묻는다. |

## 3. 물어보면 안 되는 것 (AI가 스스로 결정할 것)

- 코딩 컨벤션, 디렉터리 구조, 변수 명명
- 라이브러리 세부 버전, 빌드 도구 설정
- 테스트 프레임워크 선택
- 문서 서식
- 내부 클래스 설계, 알고리즘 선택
- **이미 결정된 ADR로 답이 정해지는 것** → 물어보기 전에 `documents/decisions/` 를 먼저 검색한다

## 4. 반드시 물어봐야 하는 것 (AI가 결정하면 안 되는 것)

- 시스템의 목적과 성공 기준 (P0)
- 업무 규칙 — 특히 예외 처리, 승인 단계, 금액/수량 계산 규칙
- 조직 구조와 권한 체계 (누가 무엇을 볼 수 있나)
- 기존 시스템과의 연동 대상·방식·데이터 소유권
- 개인정보/민감정보 취급 범위와 보존 정책
- 운영 주체와 배포 환경 (누가 운영하나, 어디에 뜨나)
- 범위에서 **뺄 것** (이게 가장 중요하다. AI는 뺄 줄 모른다)

## 5. 요구사항 인터뷰 기법 — 답에서 다음 질문 뽑기

사용자 답변을 그대로 받지 말고 아래 렌즈로 파고든다.

| 렌즈 | 질문 예시 |
|---|---|
| **예외** | "그럼 카탈로그에 없는 테이블을 물으면요?" "승인자가 부재중이면?" |
| **경계** | "0개도 등록 가능한가요? 최대는?" "과거 날짜 입력은?" |
| **권한** | "이 화면은 누가 볼 수 있나요? 남의 부서 것도 보이나요?" |
| **이력** | "수정하면 이전 값이 남아야 하나요? 누가 바꿨는지 추적이 필요한가요?" |
| **동시성** | "두 사람이 같은 건을 동시에 처리하면?" |
| **볼륨** | "하루 몇 건 정도인가요? 최대 피크는?" |
| **연동** | "이 데이터의 원본은 어디인가요? 누가 주인인가요?" |
| **되돌리기** | "잘못 처리한 걸 취소할 수 있어야 하나요? 어디까지?" |

**"안 되면 어떻게 되나요?" 를 항상 마지막에 묻는다.** 실패 경로를 정의하지 않은 요구사항은 미완성이다.

## 6. 사용자 답변 처리

답변을 받으면 즉시:
1. 답을 **되풀이해 확인**한다 (한 줄). 오해를 여기서 잡는다.
2. 해당 `OQ-###` 를 `documents/project.state.yaml` 에서 제거한다.
3. 결정이면 `ADR-###`, 사실이면 `documents/spec/*/_index.yaml`, 잠정이면 `ASM-###` 로 **즉시 기록**한다.
4. 이 답으로 **새로 생긴 질문**이 있으면 다음 배치에 넣는다.

기록하지 않은 답변은 다음 세션에 사라진다. 대화는 기억되지 않는다 — 파일만 기억된다.
