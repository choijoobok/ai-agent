# P0 착수 — "무엇을, 왜, 어디까지"

> 목표: 만들 것의 **경계**를 정한다. 여기서 경계를 못 그으면 끝까지 못 긋는다.
> 산출물: `documents/spec/00-charter.yaml`, `documents/spec/01-actors.yaml`, `documents/spec/02-constraints.yaml`
> 소요: 사용자 대화 1~2회

## 1. 첫 응답 규칙

사용자가 "○○ 시스템 만들어줘"라고 했을 때 **바로 만들지 않는다.**
아래 순서로 응답한다.

1. 이해한 것을 **한 문단으로 되풀이**한다 (오해를 여기서 잡는다).
2. **비슷한 시스템의 통상 구성**을 3~5줄로 제시한다 → 사용자가 "이건 필요없고 저건 필요하고"로 답하기 쉬워진다.
   (백지에서 요구사항을 뽑게 하면 사용자는 못 한다. **틀을 주고 깎게 한다.**)
3. **질문 배치 1**을 던진다 (아래 질문 은행 참조).

## 2. 질문 은행 — P0

### 필수 7문 (첫 배치)

| # | 질문 | 왜 묻는가 | 없으면 |
|---|---|---|---|
| 1 | 이 시스템이 없어서 지금 **누가 무엇 때문에 불편**한가요? | 목적. 기능 목록이 아니라 문제를 잡는다 | 기능만 늘어나는 시스템 |
| 2 | 이게 잘 만들어졌다는 걸 **6개월 뒤 무엇으로 판단**하시겠어요? | 성공 기준 | 인수 기준이 없어 끝나지 않음 |
| 3 | **누가 씁니까?** 유형별로, 대략 몇 명씩? | 액터, 권한, 사이징 | 권한 모델 붕괴 |
| 4 | 지금은 이 업무를 **어떻게** 하고 계신가요? (엑셀? 기존 시스템? 수기?) | As-Is, 이행 범위 | 데이터 이행 누락 |
| 5 | **이번에는 안 할 것**을 정해 주세요. 나중에 해도 되는 건? | 범위 밖 ★ | 무한 확장 |
| 6 | **언제까지** 필요하고, **누가 운영**하나요? | 기한·트랙·아키텍처 상한 | 운영 불가능한 시스템 |
| 7 | 반드시 지켜야 할 **제약**이 있나요? (사내 표준 기술, 망분리, 규제, 기존 DB 등) | 제약 | 뒤늦은 전면 재설계 |

### 5번이 가장 중요하다
사용자는 "다 필요해요"라고 답한다. 그때 이렇게 되묻는다:
> "전부 만들면 A개월입니다. 절반 기간에 먼저 쓸 수 있게 한다면 **무엇부터** 있어야 할까요?"

### 후속 질문 (답에 따라)
- 기존 시스템이 있다 → 대체인가 병행인가? 데이터를 가져오나? 얼마나?
- 외부 사용자가 있다 → 인터넷 노출? 보안 요구는?
- 여러 조직이 쓴다 → 조직 간 데이터가 보이나? 격리 수준은?
- 돈이 오간다 → 정산 주기, 감사 요구, 증빙 보관

## 2-A. 기대치 정렬 (질문 배치 직후, 헌장 확정 전 — 필수)

사용자가 묻기를 기다리지 않는다. **AI가 먼저** 진행 속도에 대해 말한다.
전문은 `aidd-guide/process/11-verification-cost.md` §2. 요지는 세 줄이다.

- P0~P3은 **돌아가는 게 하나도 안 나온다.** 답답할 것이다
- P4 구현은 **빠르다.** 앞에서 정한 것 덕분이다
- P5 검증에서 **다시 느려진다.** AI 코드는 논리 오류가 사람 코드보다 75% 많다(2026 관측치)

그리고 반드시 이 말을 붙인다.

> AI를 쓴다고 총 기간이 줄지는 않을 수 있습니다. 줄어드는 건 사람이 문서를 쓰는 시간이고,
> 늘어나는 건 확인하는 시간입니다. 지금 말씀드리는 이유는, 중간에 "절차를 줄이자"고
> 판단하실 때 **무엇을 줄여도 되고 무엇은 안 되는지**를 미리 합의해 두기 위해서입니다.

이어서 **우선순위 하나만** 받는다. 이게 나중에 압박이 왔을 때의 협상 기준이 된다.

> **[필수] 속도와 품질 중 어느 쪽에 무게를 두시겠습니까?**
> - `quality` — 절차를 지킨다. 후반 사고가 적다 ← 권장 (엔터프라이즈 기본)
> - `speed` — 지금부터 `12-verification-cost.md` §4의 '줄일 수 있는 것'을 미리 적용한다
> - `balanced` — 기본으로 가되 지연 시 §4 표로 협상한다

```yaml
purpose: "업무 시스템 여럿에 흩어진 데이터를 자연어로 한 번에 조회해, 화면을 번갈아 열고 손으로 대조하는 일을 없앤다"
problem:
  - "한 건을 확인하려고 시스템 셋을 열고 엑셀에 붙여 맞춘다 — 건당 20분"
  - "테이블 뜻을 아는 사람이 부서마다 한둘이라 조회 요청이 그 사람에게 몰린다"
success_criteria:            # 측정 가능하게. 최대 3개.
  - id: SC-01
    metric: "자연어 조회 성공률 — 사람 손을 거치지 않고 끝난 비율"

    target: "80% 이상"
  - id: SC-02
    metric: "시스템 경계를 넘는 조회 1건의 소요 시간"

  - "스키마 카탈로그 등록/검수"

    reason: "3차 범위"
track: standard              # lite | standard | full
deadline: "2026-12-31"
operator: "정보시스템팀 (2명)"

expectations:                # §2-A 기대치 정렬 결과. 비어 있으면 G0 미충족.
```

## 4. P0 흔한 실패와 방어

| 실패 | 방어 |
|---|---|
| 사용자가 기능 목록부터 말한다 | "그 기능이 해결하려는 문제가 무엇인가요?"로 한 단계 위로 올린다 |
| 범위 밖이 비어 있다 | 게이트를 열지 않는다. "안 할 것"을 최소 3개 받아낸다 |
| 성공 기준이 "편해진다" | 숫자로 바꾼다. "지금 몇 분 걸리나요? 몇 분이면 되나요?" |
| 액터가 "직원들" | 유형별로 쪼갠다. 하는 일이 다르면 다른 액터다 |
| 기한만 있고 우선순위가 없다 | "기한을 못 맞추면 무엇을 뺄까요?"를 지금 묻는다 |
| "AI 쓰니까 금방 되겠죠" | §2-A 기대치 정렬을 반드시 한다. 안 하면 P3에서 절차가 깎인다 |
