# P5 검증 — 통합·시나리오·비기능

> 목표: 개별 기능이 아니라 **업무 흐름 전체**와 **비기능 목표**를 검증한다.
> 산출물: `documents/generated/71-테스트결과서.md`, `documents/generated/72-결함대장.md`, `documents/generated/90-추적성매트릭스.md`

## 1. P4 테스트와 무엇이 다른가

| | P4 (슬라이스) | P5 (검증) |
|---|---|---|
| 단위 | FEAT 하나 | 업무 프로세스 전체 (PRC-##) |
| 데이터 | 픽스처 | 실제에 가까운 볼륨·이력 |
| 관점 | "이 기능이 되는가" | "이걸로 일할 수 있는가" |
| 비기능 | 안 봄 | 측정 |

## 2. 검증 유형

### ① 시나리오 테스트 (프로세스 관통)
`documents/spec/11-processes.yaml` 의 각 PRC를 처음부터 끝까지 한 흐름으로 실행한다.

```yaml
- id: TS-01
  process: PRC-01
  title: 조회 요청 처리 전체 (질의→계획→SQL 검증→실행→결과)
  actors_sequence: [ACT-001, ACT-001, ACT-003, ACT-001]
  steps: [...]
  verify:
    - "권한 밖 테이블이 계획에 섞이면 실행 전에 막힌다"
    - "개인정보 컬럼이 마스킹되어 나온다"
    - "각 단계 이력이 감사로그에 기록"
    - "토큰 사용량이 쿼터에 반영된다"
```

**액터 전환이 있는 시나리오를 반드시 포함한다.** 권한·상태 전이 버그가 여기서 나온다.

### ② 데이터 정합성 검증
- 동시 질의 후 토큰 쿼터 합계가 맞는가
- 트랜잭션 중단 시 부분 반영이 없는가
- 참조 무결성 위반 데이터가 생길 수 있는가
- soft delete 데이터가 조회/집계에서 제외되는가

### ③ 권한 매트릭스 전수 검증
`documents/spec/22-authz.yaml` 의 역할 × 기능 조합을 전부 시도한다.
**"권한 없는 사용자가 API를 직접 호출"** 을 반드시 포함한다 (화면 우회).

### ④ 비기능 측정
모든 `NFR-###` 의 `measurement:` 를 실제로 실행하고 **실측값을 기록**한다.

| NFR | 목표 | 실측 | 조건 | 판정 |
|---|---|---|---|---|
| NFR-002 | p95 ≤ 2000ms | 1,340ms | 대상 100만행, 동시 20 | ✅ |
| NFR-005 | 동시 50명 | 50명 / 오류율 0.2% | 30분 지속 | ✅ |

목표 미달 시: 튜닝 → 재측정, 또는 목표 조정(사용자 승인 + ADR).

### ⑤ 예외·장애 주입
- 외부 시스템 응답 없음 / 타임아웃 / 오류 응답
- DB 연결 끊김 후 복구
- 동시 수정 충돌
- 잘못된 형식의 대량 입력

## 3. 결함 처리 루프

```
발견 → DEF-### 등록(심각도·원인분류) → 원인이 설계/요구사항이면 spec 먼저 수정(CR)
     → 코드 수정 → 재현 TC 추가 → 회귀 테스트 → 상태 갱신
```
