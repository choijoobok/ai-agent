# P6 인도 — 배포·운영·매뉴얼·인수

> 목표: 사용자가 **AI 없이도 운영할 수 있는 상태**로 넘긴다.
> 산출물: `documents/generated/80-운영런북.md`, `documents/generated/81-사용자매뉴얼.md`, `documents/generated/82-데이터이행.md`, `documents/generated/99-인수확인서.md`

## 1. 배포

- 배포 절차를 **재현 가능하게** 문서화한다. 수동 단계도 빠짐없이.
- 환경별 설정 차이를 표로 정리 (개발/스테이징/운영)
- 롤백 절차를 **실제로 한 번 해 본다.** 문서만 있는 롤백은 없는 것이다.
- 초기 데이터(공통코드, 관리자 계정, 권한) 투입 스크립트

## 2. 운영 런북 (`documents/generated/80-운영런북.md`)

운영 인력이 새벽에 전화받고 읽을 문서다. 짧고 절차적으로.

```markdown
## 1. 시스템 구성 한눈에
(C4 Level 2 다이어그램 + 서버/포트/계정 위치)

## 2. 일상 점검
| 주기 | 항목 | 확인 방법 | 정상 기준 |
|---|---|---|---|
| 매일 | 배치 실행 결과 | 관리>배치이력 | 실패 0건 |

## 3. 장애 대응
### 증상: 로그인이 안 됨
1. SSO 연동 상태 확인 → ...
2. ...
### 증상: 토큰 쿼터가 실제 사용량과 맞지 않음
1. 조회 이력으로 마지막 정상 시점 확인 → ...

## 4. 백업과 복구
- 백업: 매일 03:00, 보관 30일, 위치 ...
- 복구 절차: (단계별)
- **복구 검증 방법**: (복구가 됐는지 확인하는 쿼리)

## 5. 모니터링 지표와 임계값
## 6. 정기 작업 (월/분기)
## 7. 에스컬레이션 연락처
```

## 3. 사용자 매뉴얼 (`documents/generated/81-사용자매뉴얼.md`)

**메뉴 구조 순서**로, **역할별**로 쓴다. `documents/spec/31-features.yaml` 의 menu 트리에서 생성.

```markdown
# 사용자 매뉴얼

## 시작하기 (전 역할 공통)
로그인 / 화면 구성 / 권한별로 보이는 메뉴

## 현업 담당자용
### 1. 자연어로 조회하기
**언제 사용하나요**: 시스템 여럿에 걸친 데이터를 한 번에 확인할 때
**절차**
1. 채팅 창에 묻고 싶은 것을 그대로 씁니다
2. ...
**이럴 때는**
- 계획이 엉뚱한 테이블을 짚은 경우 → `아니오` 를 누르고 조건을 덧붙입니다
- 권한 밖 데이터가 필요한 경우 → 접근 요청을 남깁니다 (즉시 열리지 않습니다)
**자주 묻는 것**
- Q. 숫자가 이상해요 → 결과 아래 `쓰인 조회 보기` 로 어떤 조건이 걸렸는지 확인하고, 그래도 이상하면 신고합니다
```

**규칙**
- 기능 설명이 아니라 **업무 상황 기준**으로 목차를 짠다 ("자연어로 조회하기", not "채팅 화면")
- 각 절차에 **오류 상황 대응**을 붙인다
- 화면 캡처는 P6에서 실제 화면으로 (Mermaid로 대체 불가한 유일한 문서)

## 4. 데이터 이행 (해당 시)

- 원천 데이터 목록과 건수
- 매핑 규칙 (원천 컬럼 → 대상 ENT 속성)
- 정제 규칙 (누락·중복·형식 오류 처리)
- **검증 방법**: 건수 대사, 금액/수량 합계 대사, 표본 상세 대사
- 리허설 1회 이상 + 결과 기록
- 실패 시 롤백 계획

## 6. 프로젝트 회고 (선택이지만 권장)

`documents/generated/98-회고.md` — 다음 프로젝트에서 이 프레임워크를 개선하기 위한 기록.
- 어느 게이트에서 가장 많이 되돌아갔나
- 어떤 질문을 P0에 했어야 했나
- 결함 원인분류 분포 (요구사항누락이 많으면 P1 강화, 설계결함이 많으면 P3 강화)
- 이 프로젝트에서 추가하고 싶은 체크리스트 항목
- **슬라이스별 `verification_load` 추이** — 다음 프로젝트의 견적 근거가 된다
- **반복된 spec 결함 유형 / 미검증 규칙 유형** — P3 체크리스트와 TC 작성 기준에 반영
- **실제로 줄인 절차와 그 결과** (`charter.expectations.reduced_scope`) — 문제가 됐는가, 안 됐는가

**회고 결과는 [`process/`](../process/01-overview.md) 와 [`phase/`](P0-inception.md) 에 반영한다.** 프레임워크가 프로젝트마다 자란다.
