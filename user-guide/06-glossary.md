# 06. 용어 사전 — 대화를 위한

> **왜 있나.** AI 가 `ASM-004` · `G2` · `DTO` 처럼 기호로만 말하면 사용자는 그것이 무엇인지
> 알 수 없다. [`CLAUDE.md` §5-13](../CLAUDE.md) 이 그 화법을 금지하고, **이 파일이 그때 펴 보는
> 사전**이다. AI 가 대화에서 괄호로 붙이는 풀이의 출처가 여기다.
>
> **여기 없는 것 — 업무 도메인 용어.** 세션·턴·스텝·워크플로우처럼 *이 시스템이 다루는 개념*
> 44개는 [`documents/spec/03-glossary.yaml`](../documents/spec/03-glossary.yaml) 이 정본이다.
> 그것은 **만들 물건의 말**이고, 여기는 **만드는 동안 오가는 말**이다.
>
> **모르는 말을 만나면 AI 에게 물어보고, 그 답을 여기에 더하게 한다.** 사전이 자라야
> 다음 대화가 짧아진다.

## 1. 문서 ID 접두 — 무엇의 약자이고 어디에 있나

**왜 ID 를 붙이나.** 요구사항 하나가 *어느 화면 어느 테스트로 실현됐는지* 기계가 따라갈 수
있어야 하기 때문이다. 그래야 "이 요구사항은 구현이 안 됐다" 를 사람이 세지 않고 검사가 잡는다.
이것을 **추적성**이라 하고 `node .claude/hooks/trace-check.mjs --all` 이 검사한다.

### 1.1 추적성 사슬 — 요구사항에서 테스트까지

```
REQ ──→ UC ──→ FEAT ──┬──→ ENT   (테이블)
                       ├──→ API   (서버 호출구)
                       └──→ SCR   (화면)
                              └──→ TC (테스트)
```

| 접두 | 무엇의 약자 | 한국어 | 무슨 뜻인가 | 만드는 단계 |
|---|---|---|---|---|
| `REQ` | **Req**uirement | 요구사항 | *무엇을 할 수 있어야 하는가* 한 줄 | P1 |
| `NFR` | **N**on-**F**unctional **R**equirement | 비기능 요구사항 | *무엇을* 이 아니라 **얼마나 빠르고·안전하고·견디는가**. 응답 3초 이내 같은 것 | P2 |
| `UC` | **U**se **C**ase | 유즈케이스 | 사용자와 시스템이 주고받는 **한 편의 이야기**. 정상 흐름과 예외 흐름을 갖는다 | P3 |
| `FEAT` | **Feat**ure | 기능 | 요구사항을 실제로 실현하는 **메뉴 단위의 덩어리** | P3 |
| `ENT` | **Ent**ity | 엔티티 | DB 테이블 하나에 대응하는 개념 | P3 |
| `API` | **A**pplication **P**rogramming **I**nterface | 서버 호출구 | 화면이 서버에 무엇을 요청하는 창구 하나 | P3 |
| `SCR` | **Scr**een | 화면 | 주소 하나에 대응하는 화면 | P3 |
| `TC` | **T**est **C**ase | 테스트 케이스 | *이렇게 하면 이렇게 되어야 한다* 한 건. **되면 안 되는 것**도 포함한다 | P3~ |
| `DEF` | **Def**ect | 결함 | 검증에서 발견된 버그 | P4~ |

### 1.5 화면 문서 안의 두 글자 접두 — 전역이 아니다

`AL-14` · `MS-03` · `CF-07` · `BH-02` · `UA-11` · `S1-05` 처럼 **화면마다 자기 약자**를 쓴다
(`AL`=접근 로그, `MS`=메시지, `CF`=설정, `BH`=배치 이력, `UA`=사용자 권한, `S1`~`S6`=샘플 여섯).

**전역 목록을 만들지 않는다.** 그 화면의 요건서 안에서만 뜻이 있는 번호이고, 화면이 늘 때마다
사전을 고쳐야 하는 것은 유지되지 않는다. **뜻이 궁금하면 그 화면의 `requirements.md` 를 보면 된다.**

## 2. 단계와 게이트 — `P` 와 `G`

**`P` 는 구간이고 `G` 는 그 구간을 끝내는 관문이다.** `P2` 를 끝내려면 `G2` 를 통과해야 하고,
통과 조건은 **사용자의 명시 승인**이다. AI 혼자 넘지 못한다.

| 구간 | 이름 | 무엇을 하나 | 끝내는 관문 |
|---|---|---|---|
| `P0` | **착수** | 무엇을 · 왜 · 어디까지 만드나 (헌장) | `G0` 착수 게이트 |
| `P1` | **발견** | 업무 프로세스와 요구사항 | `G1` 요구사항 게이트 |
| `P2` | **아키텍처** | 되돌릴 수 없는 기술 선택 | `G2` 아키텍처 게이트 |
| `P3` | **설계** | 유즈케이스·ERD·API·화면·테스트 — **여기서 설계가 동결된다** | `G3` 설계 베이스라인 게이트 ★가장 중요★ |
| `P4` | **구현** | 수직 슬라이스를 반복해 만든다 | `G4` 슬라이스 미니게이트 (슬라이스마다) |
| `P5` | **검증** | 통합·시나리오·비기능 시험 | `G5` 검증 게이트 |
| `P6` | **인도** | 배포·런북·매뉴얼·인수 | `G6` 인도 게이트 |

- **`G3` 가 가장 중요한 이유**: 여기를 넘으면 설계가 **베이스라인**(동결된 기준선)이 되고,
  이후 바꾸려면 그냥 고치는 게 아니라 **변경 요청**(`CR`) 절차를 밟는다. 넘기 전에는 자유롭고
  넘은 뒤에는 비싸다.
- **`T1`~`T12`** 는 단계가 아니라 **추적성 검사 규칙 번호**다. 예: `T5`= 모든 기능은 테스트
  케이스를 최소 하나 갖는다. → [`aidd-guide/process/05-traceability.md`](../aidd-guide/process/05-traceability.md)

## 3. 이 프로젝트에서 정의해 쓰는 말

**IT 업계 일반 용어가 아니라 여기서 뜻을 정해 쓰는 말**이다. 다른 프로젝트에서 같은 단어가
다른 뜻일 수 있다.

| 말 | 무슨 뜻인가 |
|---|---|
| **게이트** | 단계를 끝내는 관문. **Exit Criteria**(끝내기 조건) 를 전부 충족하고 사용자가 승인해야 열린다 |
| **Exit Criteria** | *이것이 다 되어야 이 단계가 끝난 것이다* 하는 조건 목록. AI 가 항목별로 자체 판정한 뒤 승인을 요청한다 |
| **베이스라인** | **동결된 기준선.** 여기 담긴 것을 바꾸려면 변경 요청 절차를 밟는다. `G3` 에서 설계가 베이스라인이 된다 |
| **레드팀** | AI 가 **자기가 만든 것을 적으로 공격하는** 절차. 게이트마다 필수이며 *문제 없습니다* 는 유효한 결과가 아니다 — 실패 시나리오를 최소 3개 낸다 |
| **결정 카드** | 게이트에서 사용자에게 내미는 **업무 언어 3~5줄** — *당신이 실제로 결정한 것은 이것이고 되돌리기 비용은 이만큼이다* |
| **역질문** | AI 가 **자기가 확신 없는 것**을 사용자에게 되묻는 것. 게이트마다 1~2개. 답을 못 받고 승인되면 **인지 부채**로 기록된다 |
| **인지 부채** | 사용자가 **이해하지 못한 채 승인한 양**. 쌓이면 나중에 *이건 아닌데* 가 한꺼번에 터진다 |
| **`@defer <기한>`** | *지금 정하지 않고 미룬다* 는 **표시**. 기한은 날짜가 아니라 **단계**다 — 기한 칸에 `P4` 를 적으면 *구현 단계에 가서 정한다* 는 뜻이다. 미룬 것의 **목록을 따로 만들지 않고** 그 결정이 사는 문장 옆에 붙이며, `/pm-status` 가 긁어 모은다 — 목록을 만들면 정본이 둘이 되어 한쪽만 닫혔을 때 어느 쪽이 참인지 알 수 없다. **기한을 모르면 `?`** 를 쓴다: 아는 척한 기한보다 낫고, *기한 없음* 칸으로 모여 눈에 띈다 |
| **되돌리기 비용** | 이 결정을 나중에 뒤집으려면 얼마나 드나. 높음/중간/낮음으로 적어 **지금 신중할 것과 나중에 고쳐도 될 것**을 가른다 |
| **정본 / 파생** | **정본**은 사람이 손으로 쓰는 원본, **파생**은 정본에서 기계가 다시 만들 수 있는 것. 파생은 형상 관리에 넣지 않는다 — 넣으면 정본 한 줄 고칠 때 파생물이 변경 내역을 덮는다 |
| **SSOT** | **S**ingle **S**ource **O**f **T**ruth — *유일한 진실.* 한 사실은 한 곳에서만 정의하고 나머지는 링크한다. 이 프로젝트의 산출물 SSOT 는 `documents/spec/` 이다 |
| **문서 셋** | 화면 하나에 딸리는 문서 묶음 — **요건서**(AI 가 읽음) · **메뉴얼**(사용자가 읽음) · **목업**(설계자가 봄) |
| **요건서** | `requirements.md`. *무엇을* 만 적고 *어떻게* 는 적지 않는다 — 어떻게는 개발 표준과 AI 의 몫이다 |
| **목업** | `mockup.html`. 화면 배치를 그린 **그림**. 요건서에서 생성하는 파생물이라 **저장소에 없는 것이 정상**이고, 볼 필요가 있을 때 만든다 |
| **시드** | 앱이 처음 뜰 때 DB 에 들어가야 하는 **기초 데이터** — 메뉴 목록·권한·화면 문구 등. 대부분 소스에서 자동 생성한다 |
| **슬라이스** | **수직 슬라이스.** 화면 하나를 DB부터 API·화면·테스트까지 **끝까지 관통해** 하나 완성하는 구현 단위. 층별로 나눠 만들지 않는다 |
| **훅** | 특정 시점에 자동으로 끼어드는 검사 프로그램. **차단**하는 것과 **경고**만 하는 것이 있다 |
| **스킬** | AI 가 정해진 절차를 따르게 하는 지시서. `/phase-gate` 처럼 슬래시로 부른다 |
| **산출물 지도 · 문서 예산** | *어떤 문서를 어디에 만들 수 있는가* 의 허용 목록. 지도에 없는 자리에 문서를 만들면 훅이 막는다 — **문서가 문서를 낳는 것**을 끊기 위해서다 |
| **문맥 비용 / 이해 비용** | AI 가 한 번에 읽어야 하는 양(문맥) 과 사람이 파악해야 하는 양(이해). **줄이는 방법이 같아서** 이 프로젝트는 둘을 한 목표로 다룬다 |
| **폐쇄망** | 인터넷이 끊긴 고객사 내부망. **AI 를 쓸 수 없는 환경**이라 사람이 직접 코딩해야 하고, 그래서 짧고 읽히는 소스가 기능보다 앞선다 |
| **J 커브** | AI 개발의 속도 곡선 — **처음이 느리고 중간이 빠르고 끝이 다시 느리다.** 설계 확정까지 돌아가는 화면이 없고, 구현에서 빠르게 쌓이고, 검증에서 다시 느려진다 |
| **트랙** | 산출물을 얼마나 갖출지의 등급 — `lite` · `standard` · `full`. 이 프로젝트는 `full` 이다 |

## 4. IT 업계에서 통용되는 말

### 4.1 개발 일반

| 말 | 무엇의 약자 | 무슨 뜻인가 |
|---|---|---|
| **저장소 · repo** | **repo**sitory | 소스 코드와 그 변경 이력이 담긴 보관소 |
| **커밋** | commit | **변경 한 묶음을 이력에 확정하는 것.** *왜 그렇게 고쳤나* 가 여기 남는다 |
| **푸시 · 풀** | push / pull | 내 컴퓨터의 이력을 서버로 올리기 / 서버 것을 내려받기 |
| **브랜치** | branch | 이력의 갈래. 본류를 건드리지 않고 따로 작업하는 자리 |
| **머지** | merge | 갈래를 본류에 합치기 |
| **diff** | difference | **무엇이 바뀌었는지 줄 단위로 보여 주는 것** |
| **PR** | **P**ull **R**equest | *내 갈래를 본류에 합쳐 달라* 는 요청. 합치기 전에 검토와 검사를 거친다 |
| **CLI** | **C**ommand **L**ine **I**nterface | 글자를 쳐서 쓰는 프로그램 (창과 버튼이 아니라) |
| **IDE** | **I**ntegrated **D**evelopment **E**nvironment | 코드를 쓰는 통합 편집기 |
| **린트 · 린터** | lint | **쓰기 규칙 검사기.** 돌아가는지가 아니라 *약속대로 썼는지* 를 본다 |
| **리팩터** | refactoring | **동작을 바꾸지 않고 구조만 정리하는 것** |
| **CI / CD** | **C**ontinuous **I**ntegration / **D**elivery | 올릴 때마다 자동으로 빌드·검사하는 것 / 그것을 자동으로 배포까지 잇는 것 |
| **레거시** | legacy | **이미 돌고 있는 옛 시스템.** 나쁘다는 뜻이 아니라 *이미 있어서 맞춰야 하는 것* 이다 |

### 4.2 백엔드 — 서버 쪽

| 말 | 무엇의 약자 | 무슨 뜻인가 |
|---|---|---|
| **JDK / JVM** | **J**ava **D**evelopment **K**it / **V**irtual **M**achine | 자바 개발 도구 / 자바가 돌아가는 실행 엔진 |
| **JAR** | **J**ava **AR**chive | 자바 프로그램을 하나로 묶은 실행 파일. 이 프로젝트는 **화면까지 담아 JAR 하나로 배포**한다 |
| **Spring Boot** | — | 자바 서버를 만드는 가장 널리 쓰는 뼈대 |
| **ORM / JPA** | **O**bject-**R**elational **M**apping | **DB 테이블을 프로그램의 객체처럼 다루게 해 주는 것.** JPA 는 자바의 표준 규격 |
| **QueryDSL** | — | 복잡한 조회를 **글자 조합이 아니라 코드로** 쓰게 해 주는 도구. 오타를 컴파일이 잡는다 |
| **DTO** | **D**ata **T**ransfer **O**bject | **계층 사이로 데이터를 실어 나르는 그릇.** DB 모양 그대로 화면에 내보내지 않기 위해 쓴다 |
| **엔드포인트** | endpoint | 서버가 열어 둔 **호출 주소 하나** (`/api/admin/user/search` 같은 것) |
| **트랜잭션** | transaction | **전부 되거나 전부 안 되거나** 를 보장하는 처리 묶음. 중간에 실패하면 앞의 것도 되돌린다 |
| **필터 · 인터셉터** | filter / interceptor | 요청이 실제 처리에 닿기 **전후에 끼어드는 공통 처리** (로그인 확인·로그 남기기 등) |
| **스택** | stack | 이 시스템을 만드는 데 쓴 **기술 묶음 전체** |

### 4.5 인증 · 보안

### 4.7 AI · 이 제품이 다루는 기술

| 말 | 무엇의 약자 | 무슨 뜻인가 |
|---|---|---|
| **LLM** | **L**arge **L**anguage **M**odel | 대규모 언어 모델 — 이 제품이 자연어를 이해하는 데 쓰는 엔진 |
| **토큰** | token | 모델이 글을 세는 단위. **요금과 한도가 이걸로 매겨진다** |
| **컨텍스트** | context | 모델이 **한 번에 볼 수 있는 분량.** 넘치면 앞의 것을 잊는다 |

| **임베딩** | embedding | 글의 의미를 숫자 배열로 바꾼 것. **뜻이 비슷하면 숫자도 가깝다** — 그래서 검색에 쓴다 |

| **오케스트레이션** | orchestration | 그 여러 단계와 도구 호출을 **순서대로 엮어 관리하는 것** |
| **환각 · 할루시네이션** | hallucination | 모델이 **모르는 것을 아는 것처럼 지어내는 것.** 이 제품이 *절제*(모르면 모른다고 답하기)를 성공 기준에 둔 이유다 |

## 5. 이 사전을 고치는 법

- **AI 가 모르는 말을 썼으면 물어본다.** 답을 받으면 **여기에 더하게 한다** — 다음에 또 묻지
  않으려고 사전이 있다.
- **업무 도메인 용어는 여기 적지 않는다.** `documents/spec/03-glossary.yaml` 이 정본이고,
  거기 것을 여기 옮겨 적으면 **두 사실이 되어 갈린다**([`CLAUDE.md` §4-3](../CLAUDE.md)).
- **화면별 두 글자 접두도 적지 않는다**(§1.5). 화면이 늘 때마다 고쳐야 하는 목록은 유지되지 않는다.
