# ADR-010 — 논리 spec 문서를 폴더형 spec-set으로 관리한다

| 항목 | 내용 |
|---|---|
| 결정 일자 | **2026-09-15** — 사용자 승인 |
| 상태 | **accepted** |
| 적용 범위 | `documents/spec/`의 17개 논리 문서와 이를 읽거나 인용하는 가이드·생성·검증 도구 |
| 관련 결정 | ADR-006, ADR-007 |

## 1. 맥락

현재 17개 논리 spec 문서는 각각 하나의 YAML 파일이다. 용어·요구사항·기능처럼 큰 문서는 다음
세션에서 필요한 범위만 읽기 어렵고, 병행 편집 때 충돌 범위도 넓다. 파일을 임의로 나누면
무엇이 한 문서인지와 조각 순서가 불명확해져 SSOT가 갈린다.

## 2. 고려한 대안

### 대안 A — 논리 문서별 폴더형 spec-set을 표준으로 둔다 — 사용자 선택

- 내용: `documents/spec/{이름}/_index.yaml`에 `meta`와 순서 있는 `parts`를 두고,
  `NNN-이름.yaml` 조각에 본문을 둔다. 호출자는 물리 파일 대신 논리 이름 또는 인덱스만 쓴다.
- 장점: 큰 문서를 최상위 책임 단위로 좁혀 읽고 고칠 수 있으며, 인덱스가 문서 경계·조각 순서·누락을
  기계로 판정한다.
- 단점: 파일 수가 늘고, 단일 파일을 직접 여는 습관과 외부 참조를 한 번 이행해야 한다.
- 비용/난이도: 중간. 로더·가이드·생성기·검증과 17개 정본을 함께 대조한다.

### 대안 B — 기존 단일 YAML을 유지한다

- 장점: 경로와 도구를 바꾸지 않는다.
- 단점: 큰 문서의 부분 탐색·수정 비용과 광범위한 충돌이 계속된다.
- 왜 선택하지 않았나: 사용자가 승인한 모듈별·크기별 관리 목적을 달성하지 못한다.

### 대안 C — 단일 YAML을 정본으로 두고 읽기 전용 분할본만 생성한다

- 장점: 기존 정본 경로를 보존하면서 탐색용 파일을 얻는다.
- 단점: 수정은 다시 단일 파일에서 해야 하며, 파생본과 정본의 경계를 새로 관리해야 한다.
- 왜 선택하지 않았나: 사용자가 원하는 관리 단위가 파생 뷰에 머물러 편집 충돌을 해결하지 못한다.

## 3. 결정

**17개 논리 spec 문서는 폴더형 spec-set을 정식 저장 형태로 사용한다.** `_index.yaml`은
`meta`와 `spec_set.version: 1`, 명시적 `parts`만 가지며, 각 조각은 하나의 최상위 본문 키를
중복 없이 정의한다. 기존 단일 YAML은 이관 호환 입력으로만 허용하고 정식 이관 뒤에는 함께 두지 않는다.

## 4. 근거

1. 문서의 정체성은 파일명이 아니라 논리 이름과 ID 연결에 있다. 인덱스가 그 경계를 명시해야
   도구·생성기·사람이 같은 문서를 읽는다.
2. 조각 순서와 완전성을 로더가 검사하면, 부분 파일의 누락·중복·조용한 값 덮어쓰기를 즉시 막을 수 있다.
3. 기존 YAML의 설명 주석은 검증·생성 입력이 아니므로 그 설명이 걸리는 항목의 명시적
   `note`·`rationale` 필드로 승격한다. **이관 메모를 `meta.source_commentary`에 모으는
   방식은 2026-09-15에 철회했다** — 줄번호가 가리키던 원본 파일이 사라져 처음부터 무효였고,
   `meta`가 그대로 고객 제출 문서에 실렸다. `meta`는 문서 수준 사실만 갖는다.

## 5. 포기한 것

- 하나의 파일만 복사하거나 링크하면 되는 단순한 경로 관례.
- 조각 순서를 파일 시스템 정렬에 맡기는 느슨함.

## 6. 되돌리기

- 되돌릴 수 있는가: 가능하나 중간.
- 되돌리는 방법: 각 `_index.yaml`의 `parts` 순서로 본문을 병합해 단일 YAML을 복원하고, 논리
  로더·가이드·생성기 참조를 단일 경로로 함께 되돌린다.
- 예상 비용: 17개 문서의 병합 검증, 문서 도구·가이드 참조·검증 규칙 재대조 1회.
- 되돌려야 한다는 신호: 인덱스·조각 병합이 단일 문서 의미를 재현하지 못하거나, 검증 도구가
  논리 이름을 경로 누락 없이 처리할 수 없는 경우.

## 7. 영향

- 산출물: `aidd-guide/artifact/spec-schema.md`, 산출물 지도·단계 가이드·템플릿·개발자 안내,
  `documents/spec/` 17개 논리 문서.
- 도구: `spec-set` 로더, `doc-gen`, 추적성·하네스 검사.
- 후속으로 정해야 할 것: 새 논리 문서나 조각 분할 기준을 추가할 때는 spec-schema의 규칙과
  해당 문서의 `_index.yaml`을 같은 변경에서 갱신한다.
