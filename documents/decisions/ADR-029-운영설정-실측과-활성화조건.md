## 1. 문제와 범위

REQ-032의 의도 확인 만료와 NFR-005의 저장 조회 유량/개수 제한은 실측 후 정하기로 했다.
일부 산출물에는 실제 값 확정까지 P2에서 수행하도록 남아 있으나, 제품 계측 소스는 소유 작업흐름 G3 승인 뒤에 작성한다.
그 결과 측정되지 않은 숫자를 만들어 P2를 닫거나, 구현에 필요한 설계를 승인하지 못하는 문제가 생긴다.

이번 결정은 위 실측 대상의 **측정 시점과 완료 조건**에 한정한다. ARCH-033의 사용자 승인 초기 운영값,
REQ-026의 승인 대기/실행 기한, 데이터 보존·권한·승인 규칙을 바꾸지 않는다.
제품 계약은 [ARCH-033.measurement_required](../spec/20-architecture/017-runtime-setting-proposals.yaml)에 둔다.

## 2. 대안

| 대안 | 장점 | 대가·위험 |
|---|---|---|
| A. P2에서 측정 계약 확정, G3 승인 뒤 구현·시험으로 수치 확정, 운영 활성화 전 검수 | 기존 실측 원칙과 설계 후 구현 순서를 함께 지킴 | 시험값이 운영 기본값으로 섞이지 않도록 활성화 차단·검수 필요 |
| B. P2를 유지하고 독립 실험을 먼저 마련해 수치 확정 | 값의 근거를 설계 승인 전에 확보 | 실제 제품/운영 경로를 대신하지 못할 수 있고 독립 실험의 범위·자료·환경을 추가로 정해야 함 |
| C. 근거 없이 초기 숫자를 제품 기본값으로 확정 | 문서를 빨리 채울 수 있음 | 실측 후 정한다는 기존 결정과 다르고 정상 업무 차단·부하 위험의 근거가 없음 |

## 3. 결정 — A

2026-10-27 사용자가 “측정 계약 먼저, 구현 후 수치 확정 (권장)”을 선택해 승인했다.
이 승인은 측정 순서와 운영 활성화 조건에 대한 결정이며 단계 게이트 통과나 제품 소스 구현 승인은 아니다.

P2는 측정 항목·원천·후보 입력·판정 기준·설정 적용 경계를 정하고 P3는 그 시험과 미설정 동작을 설계한다.
소유 작업흐름 G3 승인 뒤 합성 자료와 명시적인 시험 후보값으로 측정한다.
최초 운영 활성화 전에는 측정 근거에 따라 유한한 보호 설정과 허용 범위를 확정하고 계약 시험을 통과해야 한다.

미정 값은 0이나 무제한으로 처리하지 않는다. 검증된 설정이 없는 기능은 운영 활성화하지 않는다.
시험 후보값이 제품 기본값·고객 운영값으로 자동 승격되지 않도록 구분한다.
소유 G4/G5에서 수치 반영·측정 근거·경계 시험·미설정 차단을 점검하며, 고객 실제 부하는 파일럿에서 별도 검수한다.

## 4. 포기한 것·되돌리기 비용

P2에서 최종 운영 숫자까지 모두 채우는 형식을 포기한다. 대신 측정 책임과 운영 활성화 조건은 미룰 수 없다.
비용은 중간이다. 기한을 되돌리면 실험 일정·게이트 근거를 다시 맞춰야 하지만 신규 저장소나 기술 스택을 바꾸는 결정은 아니다.
동일한 의미를 여러 원장에 복사하지 않고 REQ-032·NFR-005의 후속 기한과 ARCH-033의 측정 계약을 함께 맞춘다.

## 5. 확인 조건

- 제품 설정이 미정인데 운영 기능이 활성화되면 실패다.
- 시험 전용 값을 확정 기본값으로 표시하거나 실측하지 않은 성능을 주장하면 실패다.
- 실제 측정값·환경·표본 수·정상 사용 차단/부하 반례를 재현할 수 있어야 한다.
- P2에서는 측정 계약을 확인하고, 수치 실측과 운영 활성화 검수는 소유 작업흐름의 후속 게이트에서 확인한다. 측정 순서 승인만으로 단계 상태를 변경하지 않는다.
