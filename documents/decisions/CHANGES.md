## CR-026 — 설정 값·버전과 승인 처리의 일관성 (설계 방향 승인)

**문제**: 현재 ConfigLookup은 작업 안의 값을 고정하지만 값과 결합된 설정 버전을 제공하지 않는다.
ConfigService의 다중 행 저장은 한 트랜잭션이지만 기대 버전 검사가 없고, SYS_CACHE_VERSION은 업무 승인과 설정 저장의 경합을 통제하지 않는다.
현재 소스 근거는 ARCH-029.system_current가 갖는다. REQ-601의 혼합 세트와 전결 판정을 현행 조회만으로 보장할 수 없다.

**A 지금 설계에 반영(선택)**: 기존 system 설정 원천을 유지하며 다음 공개 계약을 추가한다. 구현은 영향 설계·화면 승인과 계약 시험을 갖춘 뒤 별도 진행한다.

2. 설정 저장/기본값 복원은 기대 버전을 검사하고 전체 후보의 범위·상호 제약을 검증한다. 동시 저장에서 오래된 편집본은 충돌로 응답한다.
3. admin의 신규 접수/전결은 system 공개 계약을 통해 해당 업무의 값·버전을 검증하고 요청/후보·이력·유효값 반영과 함께 성공하거나 실패한다.
4. 같은 DB와 트랜잭션을 공유하는 경로는 system 소유 서비스가 경합 제어에 참여한다. admin은 system Entity/Repository를 직접 읽지 않는다. 잠금을 외부 모델·업무 API 호출 동안 유지하지 않는다.

6. 기존 접수 건의 모드 유지, 설정 읽기 실패와 미구성 구분, 설정 변경 사유·변경 전후 값·버전 기록은 REQ-601·614를 따른다.

**읽기 장애 경로(A 승인에 포함)**: REQ-601의 읽기 실패 시 true를 요청 접수 차단으로 확대하지 않는다.
요청/감사 저장과 현재 권한·참조 검증이 가능한 경우에는 혼합 세트 전체를 책임자 승인이 필요한 요청으로 접수한다. 전결·유효본 반영은 하지 않는다.

**직접 영향**: REQ-506, UC-506·FEAT-506, API-558·560, SCR-515와 설정 화면 요건/목업, TC-5061~5065 중 관련 계약, ARCH-029·031.

오래된 설정으로 반영하거나 일부 전결·부분 커밋하면 실패다. 단순 값 조회 시험만으로 완료하지 않는다.

## CR-027 — 공통 인증 주체와 Portal 이용 자격 (설계 방향 승인)

**문제**: 현재 로그인은 로컬 계정·필수 비밀번호 기반이다. 빈 메뉴 권한 로그인 거부 옵션만으로 외부 인증 주체 연결과 Portal 이용 자격 검사를 제공할 수 없다.
현재 소스와 격차의 정본은 ARCH-050.portal_account_contract다. admin에 별도 비밀번호·인증 엔진을 만들면 공통 인증 원칙을 위반한다.

**A 지금 설계에 반영(선택)**: 아래 경계를 system·integration의 영향 설계에 포함한다. 특정 외부 인증 프로토콜·고객사 연동을 임의 확정하지 않는다.

1. 안정된 Hub 주체와 인증 수단을 구분하고, 외부 원천과 그 원천이 검증한 주체 식별자를 공통 계정에 명시적으로 연결한다. 이메일·표시명 일치로 자동 병합하지 않는다.
2. 로컬 인증의 비밀번호 정책은 유지하고 외부 전용 계정에 가짜 비밀번호를 만들지 않는다. 저장 구조·외부/로컬 전환·중복/충돌·최초 연결과 회수는 P3에서 명세한다.
3. Portal 이용자에게 필요한 실제 메뉴·액션 권한은 system의 기존 유효 권한 모델로 부여한다. 고정 역할명 우회나 전역 빈 권한 허용으로 해결하지 않는다.
4. 관리자 계정 관리와 Portal 사용자 관리 두 화면은 같은 공통 계정을 참조한다. admin은 등록/활성·그룹·쿼터 등급·대상 신원 매핑을 그 공통 Hub 주체에 연결한다. 자체 계정의 생성·초기화·잠금 해제는 현재 관리자 권한을 검증한 system 공개 명령을 사용한다. 외부 인증의 신원·프로필은 원천에서 관리하고 Hub는 검증된 주체 연결과 읽기 전용 참조를 제공한다.
5. 인증 원천의 비활성화는 전체 인증/세션, Portal 이용 자격 회수는 Portal 업무 접근에 적용한다. 관리자로서의 별도 유효 권한을 함께 제거하지 않는다.
6. 그룹·매핑·이용 자격의 회수는 agent의 다음 접근·실행 검사에서도 확인한다. system 세션 권한 갱신만으로 admin 정책 최신성을 보장하지 않는다.
7. 계정 생성과 이용자 등록의 부분 실패·재요청은 안정된 요청/주체로 대조한다. 미완료 Portal 등록을 활성 이용자로 노출하거나 재시도로 계정을 복제하지 않는다.

**B 후속으로 미룸**: 현행 로컬 인증은 유지하고 Portal 전용 계정·외부 원천 연결의 관련 설계/구현을 보류한다. 뒤 단계에서 계정·세션 계약 재작업이 필요하다.
**C 안 함**: 현행 관리자 계정 경계만 유지한다. REQ-616·ARCH-050의 공통 계정 재사용·외부 인증 요구를 축소하는 별도 범위 결정이 필요하다.

**직접 영향**: REQ-501, UC-501·FEAT-501, ENT-501 및 외부 주체 연결 구조, ARCH-050, REQ-616·609, admin FEAT-005.
**간접 검토**: API-501~523·ENT-502~505·SCR-501~503·505~506·TC-5011~5016, FEAT-502·503의 유효 권한, SLICE-517의 자기 정보 경계.

**재작업**: system SLICE-501·504 보강과 integration 주체/권한 계약, admin 소비자 설계. SLICE-502·503·505·517은 권한·자기 정보 회귀 대상이다. 기능 수 증가 0개 예상이며 추정이다.
**검증**: 로컬/외부 주체 중복·충돌, 외부 원천 변경, 권한 없는 계정 명령, 등록 부분 실패/재시도, 관리자와 Portal 겸임자의 한쪽 자격 회수, 대기 중 퇴직/그룹/매핑 회수.
이메일 자동 병합·재요청 계정 중복·Portal 회수 후 다음 호출 성공·Portal 회수로 관리자 권한까지 삭제되면 실패다.
**배포/복구**: 기존 로컬 계정·비밀번호를 보존하고 외부 주체 연결을 일괄 추정하지 않는다. 비밀번호 필수 제약 변경·세션 전환·외부 연결 롤백 시 로그인 차단 범위와 운영 안내는 P3에서 명세한다.
**현재 처리**: 2026-10-27 사용자가 공통 계정 하나를 두 관리 화면에서 참조하는 방향에 동의했다. REQ-501·616, ARCH-050, UC-501·FEAT-501과 TC-5017~5019의 미구현 계약 시험을 반영했다. SLICE-501·504는 상세 설계 재작업(todo)이며 관련 권한 기능은 회귀 검토 대상이다. 기존 소스·물리 저장 구조를 변경하지 않았고 특정 외부 인증 프로토콜·계정 자동 이행은 확정하지 않았다.
