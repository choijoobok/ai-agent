# ADR-017 — 기준정보별 참조 검증과 변경 전 스냅샷 이력

superseded_by: [ADR-023](ADR-023-업무별-관리승인-설정과-전결.md) — 승인 대상/절차 설정의 범위만 후속 변경하며 참조 검증·변경 전 스냅샷 결정은 유지한다.

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-10-01 · accepted · 사용자 명시 결정 |
| 등급 | High — 기준정보 수명주기와 변경 이력 저장 원칙 |

## 1. 맥락

참조나 과거 사용이 있다는 이유로 모든 기준정보의 삭제를 일괄 금지하는 안은 대상별 특성을 반영하지 못한다.
사용자는 그룹·쿼터 등급·태그 등 조회 가능한 참조·이력을 비활성화와 삭제 전에 검증하고,
그 외에는 삭제할 수 있도록 요구했다. 변경 이력은 변경 직전 최종 데이터의 스냅샷이다.

## 2. 대안

- **A — 항목별 검증 + 변경 전 스냅샷(선택):** 현재 데이터와 과거 데이터를 분리하며 참조 영향에 맞게 허용·차단한다.
- **B — 이력이 있으면 항상 삭제 금지:** 단순하지만 불필요하게 삭제를 제한하고 비활성화 영향도 놓친다.
- **C — 변경 필드 차이만 기록:** 저장량은 줄지만 과거 상태를 조립해야 하므로 사용자 요구와 다르다.

## 3. 결정

삭제·비활성화 전 항목별로 확인 가능한 참조·이력을 검증하고, 기존 개별 규칙을 적용한다.
일괄 금지하지 않되 유효 참조나 기존 정책을 깨뜨리는 변경은 차단한다. 검증 제약이 없는 항목은 삭제 가능하다.
변경 직전 최종 데이터를 별도 이력 테이블에 스냅샷으로 남긴 뒤 변경 데이터를 현재 테이블에 저장한다.
두 쓰기는 같은 트랜잭션으로 처리한다. 승인된 삭제도 삭제 직전 상태를 이력에 남긴다.
비밀값·개인정보의 기존 저장 통제는 이력에도 적용한다. 정본은 REQ-601이다.

## 4. 근거와 포기한 것

스냅샷으로 당시 최종 상태를 직접 확인할 수 있다. 대신 변경량이 작아도 전체 스냅샷의 저장 비용이 든다.
초기 등록은 현재 데이터로 시작하고 이후 첫 변경·삭제 때 이전 상태가 이력으로 넘어간다.
기존 지식 세트 승인·쿼터 월 잠금과 system 구현을 일괄 이력 구조로 재작성하지 않는다.

## 5. 되돌리기

이력 저장 방식 변경은 과거 상태 조회·감사·동시 갱신 계약을 재검증해야 한다.
기존 자료의 변환 여부와 보존 정책을 별도로 정하며 운영 이력을 임의로 삭제하지 않는다.

## 6. 영향·후속

REQ-601 및 이를 참조하는 REQ-602~616 · PRC-13.
기준정보별 이력 테이블 구성·식별키·조회 가능한 참조 목록·보관 기간은 P2/P3에서 정한다.
사용자 결정은 기존 일괄 삭제 금지 권고와 다르며, 위험은 검증 누락이다. 항목별 삭제·비활성화 시험으로 확인한다.
