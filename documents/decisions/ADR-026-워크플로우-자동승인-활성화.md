# ADR-026 — 워크플로우 액션의 자동 승인은 사용자 요청과 관리자 검토로 활성화한다

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-10-26 · accepted · 사용자 업무 방향 결정 |
| 등급 | High — 반복 업무 실행의 승인 주체·범위 |
| 적용 차수 | RM-P3. RM-P1 일반 실행의 사용자 승인 정책은 유지한다 |
| 정본 | [REQ-404·405](../spec/10-requirements/008-derived.yaml) |
| 승인 근거 | 사용자는 자연어 지시·작업 순서로 설정하는 자동 스케줄 배치와 대화창 수동 실행을 요구했다. 각 액션의 자동 승인은 워크플로우 작성 후 사용자가 활성화를 요청하고 관리자가 검토해 활성화 승인하는 절차를 선택했다 |

## 1. 맥락

REQ-026·105는 일반 업무 실행마다 실제 값을 확인한 사용자 승인을 요구한다.
이 방식만으로는 사용자가 사전에 설정한 자동 스케줄 배치를 무인 수행할 수 없다.
반면 작성자가 자동 승인 스위치만 켜거나 모델이 판단해 승인하면 잘못된 계획을 반복 실행할 수 있다.
지식·카탈로그·API의 업무 의미가 바뀌어도 실행 오류가 나지 않을 수 있으므로 실행 정의의 의존 계약과 승인 범위를 함께 다뤄야 한다.

## 2. 고려한 대안

| 대안 | 장점 | 단점·비용 | 판단 |
|---|---|---|---|
| A. 모든 회차·액션마다 사용자 카드 승인 | 현재 실제 값을 사람이 확인 | 무인 배치라는 사용자 목적을 충족하지 못함 | 대화창 수동 실행 경로로 유지 |
| B. 작성자가 자동 승인 설정을 켜거나 모델이 자동 허용 | 설정과 실행이 간단함 | 독립된 관리 검토 근거·범위 통제가 없고 계획 변경이 반복 오처리로 이어짐 | 제외 |
| C. 사용자 요청 → 관리자 검토 → 특정 버전/액션의 자동 승인 활성화 | 검토한 반복 업무를 무인 수행하면서 범위를 한정할 수 있음 | 요청 스냅샷·입력 규칙·변경/해제와 실행별 검사·감사가 필요 | 사용자 선택 |

## 3. 결정

RM-P3 워크플로우는 자연어로 만든 실행 정의를 예약 배치와 대화창 수동 실행에 사용한다.
액션별 자동 승인은 사용자 활성화 요청과 관리자의 위험·적합성 검토 및 명시적 활성화 승인 뒤에만 효력을 갖는다.
작성·일정 활성·자동 승인 활성화·실제 호출을 구분한다.

사용자가 선택한 업무 방향을 이 ADR로 기록한다. 카드에 보완한 유효 조건·경합·상세 검증안의 전체 확정과 소유 작업흐름의 설계/구현 게이트 승인을 대신하지 않는다.

## 4. 근거와 통제 경계

제품 사실은 REQ-404·405에 둔다. 관리자 승인 범위와 실행 시의 실제 값 검증을 분리하면 날짜·주문·수량처럼 실행마다 달라지는 값도 통제 아래 처리할 수 있다.
자동 승인 활성화는 현재 실행자의 권한이나 대상 시스템의 멱등성을 새로 부여하지 않는다.
결과 불명 후속 실행에 대한 REQ-105의 수동 확인·새 승인 규칙도 그대로 유지한다.

대화창 수동 실행은 기존 실제 값 승인 카드를 사용한다. 일반 관리 대상의 승인 미사용/저장자 전결(ADR-023)은 워크플로우 자동 승인 활성화의 필수 검토를 생략할 근거가 아니다.
승인 자격을 유효 권한으로 판단하는 ADR-019와 원값 보호의 ADR-025는 유지하며 자동 경로의 저장/검사 계약은 후속 설계에서 연결한다.

## 5. 포기한 것과 위험

- 워크플로우 전체 또는 API 전체에 대한 무제한 승인 면제와 자동 최신 계획 치환은 제공하지 않는다.
- 의미 변경·승인 해제와 호출 사이의 경합, 동적 값 허용 범위의 부정확한 정의가 주요 위험이다.
- 원천 시스템이 업무 의미 변경을 통지하지 않으면 Hub 단독으로 완전한 탐지를 보장할 수 없다.
- 자동화 편의와 함께 관리자 검토·변경 영향 확인·실행별 검사 비용을 부담한다.

## 6. 되돌리기

활성화 효력을 해제하고 미전송 후속 액션을 기존 수동 승인 또는 보류 경로로 전환할 수 있다.
이미 전송/완료된 외부 업무를 되돌린다는 뜻은 아니다. 구현 전 문서 조정 비용은 중간이며 구현 후 승인 상태·예약 실행·감사·화면·경합 시험을 함께 수정해야 한다.
검토 범위를 확인할 수 없거나 현재 조건을 강제하지 못하는 경우 자동 승인 대상 축소 또는 수동 실행 전환을 검토한다.

## 7. 영향과 후속

REQ-404·405 신설과 REQ-005·026·105·107·114·207의 적용 범위 연결, FEAT-039·118·119·212·213, SCR-038·106, IN-04·RM-P3·AUTHZ-014·PRC-03·13을 대조한다.
기존 RM-P1 상세 시퀀스는 수동 경로로 범위를 명시하고 RM-P3 자동 경로의 상세도는 해당 차수 설계에서 연결한다.
후속 설계는 요청/승인 스냅샷·현재 조건/유효 기간·업무 한도·의존 버전·정지/해제·자동 승인과 전송 경합·감사/원값 임시 보관을 구체화한다.
현재 소스·게이트와 REQ-615의 평가 기능 유예는 변경하지 않는다.
