# ADR-002 — 최신 안정 버전 계열을 따라간다 (Spring Boot 4 · Spring AI 2.0)

| 항목 | 내용 |
|---|---|
| 결정 일자 | 2026-08 (프레임워크 조사 시점) · **이관 2026-09-07** |
| 상태 | 확정 |
| 근거 자료 | [프레임워크 조사](../research/agent-frameworks.md) §3.4 · [오케스트레이션 PoC](../research/orchestration-poc.md) §6.1 |
| 반영 위치 | `CON-007` |

## 1. 맥락

**프레임워크 검토보다 먼저 갈라야 하는 길이었다.** Spring Boot 3 계열을 유지하면 Spring AI 는
1.1.x 라인이고, Boot 4 계열이면 2.0 라인이다. 그리고 프레임워크마다 Boot 4 대응 시점이
달라서 — 조사 시점에 Embabel 1.0 은 Boot 3.5 계열을 대상으로 했다 — **버전 선택이 후보군을
먼저 좁힌다.** 그래서 오케스트레이션 결정([`ADR-001`](ADR-001-오케스트레이션-프레임워크.md))과 별개 항목으로 먼저 확정했다.

이 제품은 **고객사 서버에 직접 구축하고 고객사별로 수년 개별 유지보수한다**(CON-014).
따라서 버전 선택은 *지금 무엇이 편한가* 가 아니라 *몇 년 뒤에 무엇이 지원되는가* 의 문제다.

## 2. 고려한 대안

### 대안 A — 최신 안정 버전 계열 (Boot 4 · Spring AI 2.0) — **채택**
- 장점: 지원 수명이 가장 길다. 구축형 제품의 유지보수 기간과 방향이 같다.
- 단점: 프레임워크의 Boot 4 대응을 기다려야 하는 후보가 생긴다(조사 시점 Embabel).
  QueryDSL·JPA 등 기존 스택의 Boot 4 대응도 함께 확인해야 한다.

### 대안 B — Boot 3 계열 유지 (Spring AI 1.1.x)
- 장점: 조사 시점에 후보군이 더 넓었다. 생태계 성숙도가 높다.
- 왜 선택하지 않았나: **고객사에 넘긴 뒤 수년을 사는 제품이다.** 착수 시점에 이미 한 세대
  뒤에서 시작하면 그 격차가 유지보수 기간 내내 커진다. 구축형은 우리가 나중에 일괄
  업그레이드해 줄 수 없다 — 고객사 간 버전이 갈리는 것을 전제하는 구조다(CON-014).

## 3. 결정

**Spring Boot 최신 안정 버전 계열을 따라간다** — 현재 4.x, 따라서 Spring AI 2.0 계열이다.

## 4. 근거

**LangGraph4j·LangChain4j 는 Spring 버전 종속이 상대적으로 약하다**(Java 17 기준). 즉 이 축의
위험은 오케스트레이션 후보 쪽에서는 낮았고, 실제로 **Boot 4 / Spring AI 2.0 / LangGraph4j
1.8.25 조합이 PoC 에서 그대로 동작했다**(§6.1). 위험이 실측으로 낮게 확인됐으므로 수명이
긴 쪽을 택하는 것이 남는 판단이었다.

## 5. 포기한 것

- **후보군의 일부를 포기했다** — 조사 시점에 Boot 3.5 계열을 대상으로 하던 프레임워크
  (Embabel)는 이 노선에서 자동으로 밀려난다. 다만 그 후보는 다른 이유로도 배제됐다(ADR-001).
- **생태계 성숙도를 포기했다.** 최신 계열은 예제와 사례가 적고, 폐쇄망에서 참고 자료 없이
  문제를 풀어야 하는 상황이 늘어난다.

## 6. 되돌리기

- 되돌릴 수 있는가: **초기에는 가능하다.** 구현이 쌓이기 전이면 버전 하향은 의존성과 API
  변경 대응 수준이다.
- 예상 비용: Spring AI 2.0 → 1.1.x 의 API 차이 대응 + JPA/QueryDSL 재정렬. 구현 착수 후에는
  비용이 급격히 오른다.
- 되돌려야 한다는 신호: ① 필요한 라이브러리의 Boot 4 대응이 장기간 오지 않는다
  ② 고객사 인프라가 요구하는 JDK 를 Boot 4 가 지원하지 않는다.

## 7. 영향

- 산출물: `CON-007` · `CON-005`(Spring AI 추상화의 경계).
- 후속으로 정해야 할 것: **라이선스·공급망 검토가 미확정으로 남아 있다** — Spring AI·LangChain4j·
  Embabel·Spring AI Alibaba 는 Apache 2.0, LangGraph4j 는 MIT 이며 **전이 의존성까지의 확인은
  남아 있다**(프레임워크 조사 §5.1 의 6번). @defer G2 전이 의존성 라이선스를 확인한다
