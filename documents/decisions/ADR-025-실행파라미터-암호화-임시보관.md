# ADR-025 — 실행 파라미터 원값을 전용 임시 테이블에 암호화해 보관한다

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-10-19 · accepted · 사용자 명시 승인 |
| 등급 | High — 승인한 값의 동일성과 개인정보 저장 예외 |
| 적용 범위 | REQ-005의 실행 파라미터 준비·승인·실행·삭제, REQ-105·107·109·111·PRN-07 |
| 대체 결정 | ADR-014의 모든 저장 사본 마스킹 원칙 중 실행에 필요한 파라미터 원값의 전용 임시 보관에만 예외를 둔다. 감사·로그·증거·일반 재개 상태와 조회 결과/API 응답 사본의 마스킹은 유지한다 |
| 승인 근거 | 사용자가 전용 테이블의 승인 전 저장·승인 후 호출·사용 후 삭제 방안을 확인하고, 암호화·수명·예외 조건을 포함한 정리 내용을 요구사항에 반영·확정하도록 요청했다 |

## 1. 맥락

REQ-005는 모든 실행 파라미터를 확보하고 사용자가 실제 값을 확인·최종 승인한 뒤 그 값 그대로 호출하도록 한다. ADR-014의 마스킹된 재개 상태만으로는 승인 후 다른 인스턴스가 배송지·계좌 등 원값을 복원할 수 없다. 다시 조회하면 승인한 값을 변경할 위험이 있다.

로그인 세션에 원값을 두면 세션 만료·로그아웃에 서버 처리가 종속돼 REQ-016과 맞지 않는다. 사용자 활동에 따른 세션 수명과 승인 대기·실행 기한도 다르다.

## 2. 고려한 대안

| 대안 | 장점 | 단점·비용 | 판단 |
|---|---|---|---|
| A. 마스킹된 상태만 저장하고 승인 후 재조회 | 기존 저장 원칙 유지 | 승인한 원값의 유지·다중 인스턴스 인계와 승인 후 값 채움 금지를 함께 충족하지 못함 | 제외 |
| B. Redis 또는 Spring Session JDBC의 로그인 세션에 원값 저장 | 기존 공유 세션 인프라 활용 | 로그인 수명·접근 갱신·로그아웃과 실행 수명이 결합되며 승인 건별 통제는 별도로 필요 | 제외 |
| C. 기존 AI 전용 공용 DB의 전용 임시 테이블 | 승인 건별 버전·기한·삭제와 다중 인스턴스 참조를 기존 DB에서 관리 | 복호화 가능한 민감값의 단기 저장, 키·접근·삭제/복구 관리가 필요 | 선택 |

## 3. 결정

실행 파라미터 원값은 전용 임시 테이블에 암호화해 보관하고, 승인 카드와 실제 호출이 같은 버전을 사용한 뒤 실행 목적이 끝나면 삭제한다.

제품 규칙의 정본은 [REQ-005](../spec/10-requirements/001-03-processing-intervention.yaml)의 `execution_parameter_storage`다. 로그인 세션과 독립적인 수명, 부분 입력·최종 승인본 구분, 현재 권한·승인/점유 검사, 거절·만료·허용 재시도·삭제 실패 처리를 그곳에서 정의한다. 임시본 존재를 실행 허가로 사용하지 않으며 외부 업무의 exactly-once 실행을 보장한다고 해석하지 않는다.

## 4. 근거

승인한 값을 저장본에서 다시 읽으면 원천 데이터 변경이나 인스턴스 교체에도 승인 대상이 바뀌지 않는다. 기존 공용 DB를 사용하므로 세션 저장소나 추가 운영 구성요소가 필요하지 않다. 원값 접근을 실행 목적에 한정하고, 감사 자료는 계속 마스킹해 보존 목적과 실행 목적을 분리한다.

## 5. 포기한 것

모든 저장소에 복원 가능한 업무 원값이 전혀 없다는 원칙은 이 제한된 범위에서 포기한다. 암호화만으로 삭제·접근 통제가 대체되지는 않는다. 키 관리·삭제 재처리·백업/복구 시 만료본 차단이 필요하다. 삭제된 원값은 과거 실행의 재현이나 조사 목적으로 되살리지 않으며 감사에는 기존 마스킹 사본과 메타데이터를 남긴다.

## 6. 되돌리기

현재 agent 상세 설계·구현 전이므로 관련 요구사항과 시퀀스의 보관/승인 흐름을 함께 재설계할 수 있다. 구현 후에는 전용 테이블·키·승인 계약·정리 작업과 백업 정책을 변경해야 하며 이미 삭제한 원값은 복구할 수 없다. 실행용 원값의 단기 암호화 저장도 금지하는 고객 제약이 확인되면 승인한 값의 유지·다중 인스턴스 처리 대안을 사용자와 재결정한다.

## 7. 영향과 후속

- REQ-005는 사용자 요청으로 전체 보완본을 confirmed로 확정한다. REQ-105·107·109·111과 PRN-07은 이 결정의 제한된 저장 예외와 실행/감사 경계를 참조한다.
- ARCH-070, 실행/대기 시퀀스, 관련 프로세스·기능과 생성 문서를 맞춘다. 기존 ADR-014는 본문을 보존하고 부분 대체 관계만 표시한다.
- P3에서 물리 테이블·암호화/키 관리·상태와 원값 버전의 결합·삭제와 실행의 경합·백업/복구 계약 및 실제 시험을 설계한다.
- 이번 확정은 REQ-005와 원값 보관 정책의 확정이며, 다른 요구사항 카드 전체의 신규 승인·REQ-010 최종 확정·단계 게이트 전이·소스 구현 승인은 별도다.
