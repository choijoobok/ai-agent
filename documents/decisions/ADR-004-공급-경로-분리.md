# ADR-004 — 「공급사」를 모델 제작사와 공급 경로로 가르고, 게이트웨이 경유를 지원 대상에 넣는다

| 항목 | 내용 |
|---|---|
| 결정 일자 | 2026-09-08 (사용자 결정) |
| 상태 | accepted |
| 근거 자료 | **조사가 앞선 것이 아니라 설계 검토에서 드러났다.** 게이트웨이별 과금 세부는 조사 대상이다(§7) |
| 반영 위치 | `TRM-086`~`TRM-089` · `PRN-05` · `CON-035` · `ACT-007` · `NFR-010` · `FEAT-016` · `REQ-107` |

## 1. 맥락

비용 산정의 키가 **`공급사 · 모델 · effort`** 였다(`NFR-010` · `FEAT-016` · `SCR-016`).
그런데 **「공급사」가 무엇인지 정의된 적이 없다** — `03-glossary.yaml` 에 항목이 없고,
문서마다 뜻이 갈려 있었다:

- `ACT-007` 의 제약은 *약관과 정보보호 인증을 보유한 공급사만 선정 대상* 이라 한다 → **모델 제작사**
- `NFR-010` 의 단가 키는 값을 청구하는 곳을 가리킨다 → **과금 주체**

같은 모델을 여러 경로로 살 수 있으면 이 둘이 갈라진다. Amazon Bedrock 으로 Claude 를 쓰면
**심사 대상은 Anthropic 과 AWS 둘, 청구는 AWS, 모델은 Claude** 다. 한 낱말로 표현되지 않는다.

**지금이 가장 싼 시점이다** — `40-domain.yaml` 이 비어 있어 단가 엔티티가 아직 없다. P3 에서
그것을 만드는 순간 키가 굳고, `G3` 뒤에는 변경 요청 절차를 탄다.

## 2. 고려한 대안

### 대안 A — 「공급사」를 셋으로 가르고 게이트웨이를 경로로 다룬다 — **채택**
- 내용: `모델 제작사` · `공급 경로` · `모델` 로 나눈다. 단가·엔드포인트·인증은 **경로**에 붙고,
  데이터 정책 심사는 **제작사와 경로 둘 다** 를 대상으로 한다.
- 장점: 같은 모델을 여러 경로로 쓰는 것이 표현된다. 리전·과금 모드가 경로의 속성으로 자연히
  들어간다. `PRN-05`(공급사 교체 가능)의 추상화 경계는 오히려 선명해진다 — 도메인은 여전히
  우리 인터페이스만 본다.
- 단점: 용어가 늘고, 이미 쓴 문서에서 「공급사」를 어느 쪽으로 읽을지 다시 정해야 한다.
- 비용/난이도: 문서 여섯. **구현이 없으므로 코드 재작업 0.**

### 대안 B — 「공급사」 한 낱말을 유지하고 값에 `Bedrock` 을 나란히 넣는다
- 내용: 공급사 목록에 `Anthropic` 옆에 `Bedrock` 을 둔다.
- 왜 선택하지 않았나: **단가표는 성립하지만 나머지가 무너진다.** `ACT-007` 의 심사 제약이
  Bedrock 한 줄로 끝나 Anthropic 의 약관을 아무도 안 보게 되고, 리전을 표현할 자리가 없어
  `Bedrock-us-east-1` 같은 문자열 우회가 생긴다 — 그 순간 역할별 모델 지정과 집계가
  **문자열을 파싱**하게 된다. 파싱하는 규칙은 검사할 수 없다.

### 대안 C — 게이트웨이를 지원하지 않는다 (직접 API 만)
- 왜 선택하지 않았나: 고객사 구축형이며 클라우드 계약이 이미 있는 곳이 흔하다. 나중에 넣으면
  단가 키를 바꾸는 변경 요청이 되고, 그때는 엔티티가 이미 서 있다.

## 3. 결정

**「공급사」를 `모델 제작사` · `공급 경로` · `모델` 셋으로 가르고, 단가·엔드포인트·인증을 공급
경로에 붙인다. 게이트웨이 경유를 지원 대상에 넣는다.**

## 4. 근거

- **되돌리기 비용이 지금 가장 낮다** — 엔티티가 없다.
- **대안 B 의 단순함은 가짜다** — 문자열 우회가 곧 파싱을 부르고, 파싱하는 규칙은 어겨도
  아무 일이 일어나지 않는다(정책형 실패).
- **팀이 운영할 수 있는가** — 경로를 늘리는 일이 화면에서 행을 더하는 일이 된다.

## 5. 포기한 것

- **「공급사」라는 짧은 말**을 못 쓴다. 문서에서 매번 제작사인지 경로인지 골라야 한다.
- **경로별 세부를 다 지원하지 않는다** — 시간당 과금(Provisioned Throughput)은 **범위 밖** 으로
  두고 `NFR-010` 의 과금 모드에 **자리만 남긴다.** 지금 만들면 쓰지 않을 것을 만든다.

## 6. 되돌리기

- 되돌릴 수 있는가: **예** — 구현 전이다.
- 방법: 용어 셋을 하나로 접고 `NFR-010` 의 키를 되돌린다.
- 예상 비용: 문서 여섯. **P3 에서 ENT 를 만든 뒤에는 테이블 마이그레이션이 붙는다.**

## 7. 남은 것

@defer P2 **게이트웨이별 과금 구조를 조사한다** — 리전별 단가 · 프롬프트 캐시 과금의 지원 범위 ·
배치 할인 · 교차 리전 추론. **지어내지 않았다.** 조사 자리는 `documents/research/` 다.
