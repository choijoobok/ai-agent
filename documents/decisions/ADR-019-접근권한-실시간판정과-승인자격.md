# ADR-019 — 접근 권한은 매 접근 시점에 판정하고 승인 자격은 유효 권한으로 정한다

## 1. 맥락

REQ-108은 같은 턴에서 최초 판정한 권한을 유지해 회수 뒤에도 해당 턴이 실행될 수 있도록 정의돼 있었다.
사용자는 스텝별 지식 검색·쿼리 수행 시 실시간으로 권한을 적용하는 의도를 확인했다.
또한 별도 승인 메뉴에서 역할상 권한이 있으면 요청자와 동일인도 승인할 수 있도록 결정했다.

## 2. 대안

- A — 내용 버전과 권한 분리(선택): 내용 일관성을 유지하면서 접근은 현재 권한으로 판정한다. 권한 조회·문맥 출처 관리 비용이 생긴다.
- B — 권한까지 턴 끝까지 고정: 구현과 재현은 단순하지만 회수된 권한으로 후속 접근할 수 있다.
- C — 내용과 권한 모두 매번 최신으로 교체: 권한은 현재화되지만 프롬프트·카탈로그 내용이 턴 중 달라질 수 있어 선택하지 않는다.

승인 자격은 별도 승인 권한 보유를 기준으로 한다. 요청자와 승인자를 반드시 다른 사람으로 제한하는 대안은 선택하지 않았다.

## 3. 결정

권한은 실제 검색·모델 입력·조회·실행·결과 제공 시점에 현재 유효값으로 확인한다.
내용 버전 고정은 권한 검사 생략 근거가 아니다. 정본은 REQ-108이다.
승인 권한이 있으면 요청자 자신도 승인할 수 있으나 요청·승인 단계와 이력은 생략하지 않는다. 정본은 REQ-609다.

## 4. 근거와 포기한 것

권한 회수를 턴 종료나 장기 대기 기준 시간까지 미루지 않는다.
이전 스텝 결과·지식·모델 문맥을 재사용하는 경로에도 현재 권한을 적용해야 한다.
이미 외부로 전송한 데이터·호출이나 완료된 업무를 소급 취소·복구한다는 보장은 하지 않는다.
동일인 승인 허용으로 강제적인 상호 견제는 포기하고 역할·메뉴 액션 권한과 단계별 이력으로 운영한다.

## 5. 되돌리기

권한 판정 경계·캐시·내용 버전·문맥 재사용·승인 API와 시험을 함께 재검증해야 하므로 구현 후 비용이 높다.
권한 검사 비용이나 동일인 승인 오남용이 나타나면 근거를 확인해 변경 요청으로 재검토한다.

## 6. 영향·후속

REQ-103·108·609·616, PRN-06, TRM-158, ARCH-060, AUTHZ-001, PRC-13, SCR-037.
다중 인스턴스 변경 전파, 검사와 호출 사이 경합, 혼합·요약된 문맥의 권한 출처 추적은 P2/P3에서 설계한다.

## 7. 사용자 결정 (AI 권고와 상이)

AI는 요청자 본인 승인 금지를 권고했지만 사용자는 지식 변경 승인과 동일하게 권한이 있으면 동일인 처리를 허용했다.
예상 위험은 한 사람이 잘못된 신원 부여를 요청하고 승인하는 것이며, 증상은 동일인의 반복적인 오인 부여·승인이다.
임의로 자기 승인 금지를 구현하지 않고 요청·승인 내용과 처리자를 추적한다.
