# ADR-024 — 조회 결과에 유한 보존 기간을 필수 적용한다

| 항목 | 내용 |
|---|---|
| 일자·상태 | 2026-10-14 · accepted · 사용자 명시 승인 |
| 등급 | High — 결과 재참조·화면 복원·감사 증거의 수명 |
| 적용 범위 | REQ-107·109·110·115·614와 과거 결과 참조·재접속 |
| 대체 결정 | ADR-015의 선택적 미보존과 ADR-016의 미보존 결과 종료/중단 삭제 및 기본 3개월을 대체한다. 공용 DB·마스킹·감사 분리 원칙은 유지한다 |

## 1. 맥락

이전 결정은 업무 데이터의 무기한 복제·노출과 저장량을 줄이면서 조사 근거를 확보하려는 목적이었다. 진행 중에는 다중 인스턴스를 위해 결과 사본을 공용 DB에 저장하고, 미보존 대상은 턴 종료 때 삭제하도록 했다. 이 방식은 완료 직후의 최종 폴링, 브라우저 재접속과 과거 결과 요약·검증 요청에서 이미 사라진 결과를 필요로 하는 문제를 만든다(REQ-002·019·027·040).

사용자는 미보존 설정을 없애고 짧은 유한 기간을 적용하되 오류·품질 신고·추적 감사 조사 중 필요한 자료만 삭제에서 보호하는 권장안을 승인했다. 턴/스텝 현재 상태와 시작·변경·종료 사실을 언제 저장하는지도 요구사항에 함께 명시하도록 요청했다.

## 2. 고려한 대안

| 대안 | 장점 | 단점·비용 | 판단 |
|---|---|---|---|
| A. 미보존 선택과 종료 시 삭제 유지 | 종료 뒤 결과 저장량을 줄임 | 최종 폴링·재접속·후속 가공마다 결과 부재 처리와 별도 전달 보장이 필요 | 제외 |
| B. 모든 안전한 결과 사본에 짧은 유한 기한 적용 | 동일 결과 참조로 화면 복원·후속 가공·조사를 연결, 수명 규칙 단순화 | 전체 대상의 저장량·파기 처리량과 조사 보호를 관리해야 함 | 선택 |
| C. 장기 또는 무기한 보존 | 오래된 결과 재사용 범위 확대 | 데이터 복제·노출·백업/파기 비용 증가, 최소 보관 목적 약화 | 제외 |

## 3. 결정

조회 결과 마스킹 사본은 수신 시각부터 양의 유한 기간 동안 보존하며 기본값을 7일로 정하고, 턴 종료 시 삭제 대신 만료 후 일일 파기와 필요한 조사 자료의 삭제 유예를 적용한다.

제품 규칙의 정본은 [REQ-107](../spec/10-requirements/003-security.yaml)의 `retention_policy`와 `history_storage`다.

- 기간은 전역 및 데이터소스·대상 시스템별 YAML로 정하며 관리자 화면은 읽기 전용이다. 미보존·0·음수·무기한 값을 허용하지 않는다.
- 수신 당시 확정한 원래 만료 시각을 조회·재접속·복사·재가공·재시도로 연장하지 않는다. 기간 변경은 새 결과부터 적용한다.
- 완료·실패·중단 시 실행용 체크포인트를 무효화·정리해도 별도 결과 사본을 함께 삭제하지 않는다. 과거 결과 사용은 현재 권한과 필요한 LLM 전송 동의를 다시 확인한다.
- 오류·품질·추적 감사 조사에 필요한 자료만 담당자·사유·대상·시각을 기록해 보호한다. 만료 후 일반 사용은 차단하며 마지막 보호 해제 후 원래 기한으로 파기한다.
- ADR-014의 마스킹과 비밀 제외를 유지한다. 안전한 마스킹 사본을 만들 수 없는 경우 값 없이 메타데이터·지문을 남기는 보안 예외는 미보존 설정이 아니다.
- 감사 메타데이터·실제 모델 전송분·원 질의·모델 응답에는 각각의 보관 정책을 적용한다. 전체 결과를 감사 사본으로 복제해 원문 기한을 우회하지 않는다.
- 턴 접수·스텝 시작부터 기록을 만들고 현재 상태를 갱신한다. 상태 전이·판정/보정·재시도·인계·중단의 사실은 불변 사건으로 추가한다. 현재 상태 갱신과 해당 전이 이력은 함께 확정한다.

## 4. 근거

같은 결과 사본을 기한 내 참조하면 원천 변경에 영향받지 않고 당시 응답을 표시·검토할 수 있다. 짧은 기한과 마스킹은 원래의 저장 최소화 목적을 유지한다. 현재 상태와 변경 이력을 구분하면 완료 이전 장애도 추적하면서 폴링·실행 제어에 필요한 최신 상태를 제공할 수 있다.

## 5. 포기한 것

고객별 미보존 선택은 제공하지 않는다. 7일이 지난 일반 결과의 재표시·재가공은 보장하지 않으며 조사 보호가 이를 연장하지 않는다. 가려진 개인정보와 이미 파기한 전체 결과는 복원하지 못한다. 모든 결과의 단기 저장과 상태 전이 기록으로 쓰기·저장·파기 부하가 증가한다.

## 6. 되돌리기

설정만 바꿔 미보존을 되살릴 수는 없다. 즉시 삭제를 다시 요구하면 최종 폴링·재접속·과거 결과 가공·조사 증거의 사용자 안내와 저장 계약을 함께 변경해야 한다. 이미 파기한 데이터를 되돌릴 수 없다. 절대적 저장 금지라는 고객 제약이 확인되거나 단기 보존량/파기 처리량이 운영 허용치를 넘는다면 관련 요구사항과 화면 계약을 재검토한다.

## 7. 영향과 후속

- REQ-107이 기록 시점·불변 사건·보존/조사 보호의 정본을 갖고, REQ-109는 실행 상태 정리, REQ-110·115는 신고/조사 업무에 연결한다.
- REQ-002·006·019·040·614, PRN-07·CON-025, 관련 기능·프로세스·ARCH-070과 설계 참고 시퀀스를 맞춘다.
- P3에서 물리 테이블·키·버전/점유 조건·원자적 상태/사건 저장·실패 후 대조, 만료와 읽기/보호/파기의 경합·배치 재처리·보호 재검토 계약을 설계한다. REQ-107의 검증 사례를 사용한다.
- 본 결정은 보존 정책 변경 승인이다. 아직 검토 중인 요구사항 카드 전체 확정, REQ-010 최종 확정, 게이트 전이와 구현 승인은 포함하지 않는다.
