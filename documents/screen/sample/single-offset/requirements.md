# 요건 정의서 — 샘플 · 단일 그리드(오프셋)

## 개요

- **무엇을 하는 화면인가**: 샘플 주문(`SMPL_ORDER`)을 **컬럼 서른으로 전부 펼쳐** 등록·수정하고, 확정과 일괄 재계산을 실행한다.
- **프로세스상 위치**: (선행) 없음 — 샘플 데이터는 시드가 넣는다 → **이 화면** → (후행) 없음. **업무 흐름이 아니라 어휘의 전시장이다.**
- **이 데이터를 누가 쓰나**: 샘플 여섯이 같은 두 테이블(`SMPL_ORDER` · `SMPL_ORDER_ITEM`)을 나눠 본다.
- **바꾸면 어디가 흔들리나**: **여기서 컬럼을 하나 줄이면 템플릿에서 그 어휘의 예가 사라진다.**

> **참조 구현이지 업무 화면이 아니다.** 샘플 여섯은 *새 화면을 만들 때 베껴 갈 실물* 이며, 걷어낼 때는 여섯이 함께 사라진다 — `screenRegistry.ts` 의 샘플 줄과 `menu-tree.yaml` 의 `SMPL_ROOT` 이하, 그리고 `SMPL_` 접두의 테이블·시드가 그 대상이다.

> **어휘의 본진이다.** 커버리지 표에서 **열둘**이 이 화면에만 있다 — 에디터 셋 · 뷰어 · 숨김 두 층 · 파라미터 모달 · 진행률 · 큰 정수 · 우측 컨트롤이 전부 여기다.

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).


## 2. 조회조건 — **열둘**

**폼의 컨트롤이 전부 나오는 유일한 화면**이다. `gt`·`lt` 연산자, 태그 입력, 팝업 필드 넷이 여기서 처음 쓰인다 — *쓰이지 않는 후보를 미리 열지 않는다* 는 규칙의 문을 **요구하는 화면이 와서** 연다.

| 조건 | 대상 | 입력방식 | 특징 |
|---|---|---|---|
| 주문번호 | `ORD_NO` | 텍스트 | `contains` 기본 |
| 고객 | `CUST_ID`/`CUST_NM` | **팝업 검색** | 고른 결과가 두 칸으로 들어온다 |
| 주문 상태 | `ORD_STAT_CD` | 셀렉트(다중) | **코드그룹 `SMPL_ORD_STAT`** |
| 주문일 | `ORD_DT` | 날짜(기간) | `precision: day` |
| 납기월 | `DLVR_YM` | 날짜 | **`precision: month`** — `202608` 문자열 |
| 금액 | `ORD_AMT` | 숫자 | **`gt` · `lt`** 가 여기서 처음 쓰인다 |
| 태그 | `TAG_LIST` | **태그 입력** | 목록 항목을 조건으로 |
| 소요시간 | `PROC_MS` | 숫자(**초**) | **초로 받아 밀리초로 보낸다** |
| 그 밖 | — | — | 채널 · 우선순위 · 고객등급 · 긴급 여부 |

- **화면 층이 시스템 값을 좁힐 수는 있어도 넓힐 수는 없다.**

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 |
|---|---|
| `SMPL_ORDER` | 메인 — **컬럼 스물여섯** |
| `SMPL_ORDER_TAG` | `TAG_LIST` 목록 컬럼 |
| `SYS_CODE` | 코드명 |

- **커서형 화면과 같은 테이블을 읽는다** — 테이블을 하나 더 만들면 **모드가 데이터의 성질처럼** 읽힌다. **모드는 엔드포인트가 정한다.**
- **마스터-디테일 화면의 조회 경로를 재사용하지 않는다.** 같은 테이블·같은 페이징 모드지만 **투영이 다르다** — 여기를 거기에 맞추면 서른 중 스물하나가 빈 칸이 되고, 거기를 여기에 맞추면 **그 화면이 그리지도 않는 큰 텍스트 셋을 페이지마다 나른다.**

### 3-2. 고정 조건 · 기본 정렬

- 페이징: **offset**(총 건수를 센다).

## 4. 컬럼 — **서른**

- **행 식별키**: `ORD_ID` — **문자열이다.** `bigint` 어휘가 뜻을 가지려면 API 가 문자열로 내려야 한다 — 자바스크립트의 수는 상한을 넘기면 **조용히 정밀도를 잃고**, 그 손실은 화면이 아니라 **저장 요청이 다른 행을 가리키는 것**으로 드러난다.
- **`PROC_MS` 만 숫자다** — 규칙이 *`bigint` 는 문자열* 이 아니라 **정밀도를 잃을 수 있으면 문자열**이기 때문이다. 소요 시간은 그 근처에 갈 수 없다.
- **`itemCnt` 가 없다** — 이 화면에는 마스터 삭제 게이트가 없다. 삭제 컬럼은 있지만 **조건 없이 열리며**, 품목이 있는 주문을 지우려 하면 **서버가 사유를 담아 거절한다.** 게이트는 마스터-디테일 셋의 어휘다.
- **숨김이 두 층이다** — `visible:false`(설정에서 켤 수 있다)와 `hidden`(켤 수 없다). `LOCK_YN` 이 후자이며 **그리지 않고 편집 판정만 읽는다.**

### 4-2. 편집 가능 판단 — **전이표를 그대로 편다**

```
LOCK_YN 이 먼저다  →  잠긴 것은 상태와 무관하게 닫힌다
신규 행은 언제나 열린다  →  아직 상태가 없다
그 밖에는 ORD_STAT_CD 가 정한다 (RCV → CFM → SHP → DON)
```

- **상태는 *일이 어디까지 갔나* 이고 잠금은 *운영이 잠갔나* 다** — 축이 다르다.

### 4-3 ~ 4-6

- 재계산 · 팝업 매핑(고객 · 태그) · 행 추가 기본값 · 비노출 컬럼이 전부 있다 — 어휘의 전시가 목적이라 **한 화면이 다 갖는다.**

## 5. 버튼 · 액션

| 버튼 | 액션 | 자리 | 특징 |
|---|---|---|---|
| 조회 · 저장 · 행 추가 · 행 삭제 | `R` `S` | 공통 | — |
| **표시 범위**(전체 / 내 것) | — | **좌 컨트롤** | **조회조건이 아니다** |
| **확정** | **`X`** | 우 컨트롤 | 고른 행. **진행률 없음** — 응답이 곧 끝이다 |
| **일괄 재계산** | **`X`** | 우 컨트롤 | **전체 대상. 파라미터 모달 + 진행률** |

- **실행 둘이 갈리는 것이 이 화면의 핵심 시연이다.** 둘 다 `X` 인데 **사용자 경험이 다르다** — 앞은 고른 행 몇의 상태를 바꾸고 응답이 곧 끝이며, 뒤는 **인자를 받고 작업 번호를 받아 진행률을 훑는다.** 화면에서 어떻게 보이는지는 **여기가 유일한 실물**이다.
- **화면이 폴링 코드를 쓰지 않는다** — 선언 한 줄이면 그리드가 처리한다. 화면마다 주기·중단 조건·실패 처리가 갈리면 **같은 기능이 화면 수만큼** 생긴다.
- **엑셀 선언이 없다** — 이 화면이 그리는 표가 곧 내려받을 표라 **프론트가 만든다.** 왕복이 0 인 것을 왕복 하나로 만들 이유가 없다. `EXPORT` 권한은 **메뉴가 선언한다.**

## 6. 규칙 — 저장 · 실행

- **상태 전이**: `RCV` 접수 → `CFM` 확정 → `SHP` 출고 → `DON` 완료.
- **삭제**: 게이트 없이 열리고 **서버가 사유를 담아 거절한다**(품목이 있으면).
- 검증은 서버가 최종 판정한다.

## 7. API

| 용도 | 키 | 경로 | 액션 |
|---|---|---|---|
| 목록 | `getOrderOffsetList` | `/service/sample/getOrderOffsetList` | R |
| 고객 팝업 후보 | `getCustomerList` | `…/getCustomerList` | R |

- **팝업의 조회는 부르는 화면의 것이다** — 팝업 등록은 공용 파일에 있어도 **인가는 여는 쪽**이 갖는다.
- **태그 후보의 이름이 긴 이유가 있다.** `getTagList` 는 탭 화면의 것이고(한 주문의 태그 **행들**) **같은 경로 공간을 나눠 쓰므로**, 짧은 이름을 쓰면 **기동이 매핑 충돌로 죽는다.**
- **`export*` 가 하나도 없다.**

- 코드그룹: `SMPL_ORD_STAT` · `SMPL_UOM` · `SMPL_ITEM_STAT` 등 — **전부 `SMPL_` 접두**다.

- **모듈 노드도 `SMPL_` 접두다** — `SAMPLE` 이면 **제거 changelog 의 조건에 걸리지 않는다.**
- 샘플 데이터는 별도 changelog 가 넣는다.

| `S1-30` | 팝업으로 채운 뒤 | `afterEdit` → 검증이 **같은 순서로** 돈다 — 경로가 달라도 규약을 비껴가지 않는다 |
| `S1-31` | 채널 셀에서 `온라인` 타이핑 | **목록이 걸러진다.** 없는 값은 만들어지지 않는다 |
| `S1-32` | 태그 셀 더블클릭 → 순서 변경 → 적용 | `SORT_NO` 가 바뀌고 셀의 태그 순서가 따라간다 |
| `S1-33` | 오류 컬럼 더블클릭 | **읽기 모드**로 열린다 — 거부 메시지가 나오지 않는 유일한 읽기 전용 컬럼 |
| `S1-34` | 오류 컬럼 정렬 | **끈다** — `nclob` 은 벤더가 막는다 |
| `S1-35` | 확정 버튼 — 접수 행이 없는 선택 | **비활성 + `hint`** *"접수 상태만 확정할 수 있습니다"* |
| `S1-36` | 확정 → 확인 → 성공 | **토스트** + 즉시 재조회. 모달을 띄우지 않는다 |
| `S1-37` | 확정 응답 전에 버튼 재클릭 | **아무 일도 없다** — 응답 전에는 다시 실행하지 않는다 |
| `S1-38` | 일괄 재계산 클릭 | **검증이 먼저** 돈다. 통과해야 파라미터 모달이 뜬다 |
| `S1-39` | 파라미터 모달에서 실행 | **확인 모달이 또 뜨지 않는다** — 이 모달이 확인을 겸한다 |
| `S1-40` | 실행 직후 | 응답이 `{jobId}` 이고 **즉시** 돌아온다. 진행률 모달이 뜬다 |
| `S1-41` | 진행률 모달을 **닫는다** | **작업은 계속 돈다.** 취소가 아니다 |
| `S1-42` | 폴링 중 **세션 만료** | 재인증 모달 → 인증 후 **폴링이 재개된다** |
| `S1-43` | 남의 `jobId` 로 폴링 | **404** — 403 이 아니다. 있다는 사실도 알리지 않는다 |
| `S1-44` | 10만 건 작업 | `UPDATE` 가 **100회 안팎** — 1% 또는 1초 중 늦은 쪽으로 flush |
| `S1-45` | `TOT_CNT` 가 `NULL` | **불확정 막대**. 퍼센트를 지어내지 않는다 |
| `S1-46` | 작업 실패 | 모달이 **`FAIL` 로 멈추고** `ERR_MSG` 와 **어디까지 됐는지**를 보인다 |
| `S1-47` | 작업 완료 | **완료 뒤에** 재조회한다 — 도는 중에 읽지 않는다 |
| `S1-48` | 그리드 설정 창 | `SRC_SYS_CD` 는 **있고 꺼져 있다**. `LOCK_YN` 은 **없다** |
| `S1-49` | `LOCK_YN` 을 API 응답에서 뺀다 | **`USE_YN` 의 `editable` 판정이 깨진다** — `hidden` 컬럼도 데이터는 온다 **(되면 안 되는 것)** |
| `S1-50` | `S` 권한 없는 사용자 | 저장·행 추가가 **없고** 셀이 열리지 않는다. `<Permission>` 을 손으로 두르지 않았는데도 |
| `S1-51` | `X` 권한 없는 사용자 | 확정·일괄 재계산이 **없다** |
| `S1-52` | `app.sample.enabled=false` | 메뉴가 트리에 **없고** API 가 404. **데이터는 남는다** |
