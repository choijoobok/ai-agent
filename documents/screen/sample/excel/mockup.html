5. 주석

  1. 1하단 디테일 탭과 같은 탭이다 — 셸 표준의 미결을 이 화면이 닫는다. 처음 답은 세그먼티드 컨트롤이었고 실물에서 뒤집혔다(2026-09-02): 채운 배경으로 활성을 말하니 일반 버튼 두 개로 읽혔다 — 화면을 갈아 끼우는 컨트롤이 누르면 뭔가 실행되는 버튼 과 같은 모양이면 지금 어디에 있는지를 말하는 표시로 읽히지 않는다. 셸 탭바와는 여전히 갈린다: 닫기 × 가 없고(셸 탭은 항목마다 단다) 자리가 브레드크럼 아래다 — 셸 탭바는 위다. 나머지 둘(층이 다르다 · 하단 탭과 갈린다)은 모양이 아니라 자리가 말한다.
  2. 2대상이 SMPL_ORDER_ITEM 인 것이 규약의 결과다. 엑셀 업로드 전용 탭 결정이 CODE_MGMT(2단계)와 MESSAGE_MGMT(list 컬럼)를 둘 다 기각한 그 기준으로 보면 SMPL_ORDER 도 같은 이유로 기각된다 — TAG_LIST 가 있다. 평면이어야 한다.
  3. 3양식이 갈릴 수 없다 — 두 탭의 컬럼 배열이 같은 것이고, ②의 전체 다운로드 가 곧 양식이다. 양식 파일을 따로 배포하면 컬럼이 바뀔 때 양식만 옛것으로 남는다.
  4. 4조회 버튼이 없다 — 디테일 그리드와 갈리는 자리다. 그리드 표준이 "디테일도 ①에 조회를 갖는다" 로 닫았지만 업로드 탭은 디테일이 아니다: 행이 서버 조회가 아니라 파일에서 오므로 부를 곳이 없고, 눌리면 읽어들인 412행이 통째로 날아간다 — list 디테일에 api 를 선언하지 않는 것과 같은 이유다. 기존 행과의 대조는 파일을 읽은 직후 업무 탭과 같은 조회 API 를 한 번 불러서 한다 — 이것이 이 패턴이 요구하는 유일한 추가 동작이며 새 API 가 아니다.
  5. 5동일 행은 상태가 없다. 그리드 표준이 변경 행만 보낸다 이므로 저장 대상에서 자동으로 빠진다 — 따로 거르는 코드가 없다.
  6. 6엑셀은 삭제 수단이 아니다. 파일에서 줄을 지운 것과 지워라 를 구별할 방법이 없다.
  7. 7오류는 배너와 셀 둘 다. 412행에서 배너만 있으면 찾을 수 없고, 셀만 있으면 스크롤 밖의 오류를 못 본다. 파일 내 중복은 그리드 층 검증이다 — 행 하나만 봐서는 알 수 없다.
  8. 8양식이 다르면 읽지 않는다. 되는 만큼만 읽으면 빠진 컬럼이 조용히 기본값이 되고, 그것이 그대로 저장된다.
  9. 9상한을 넘으면 자르지 않고 거절한다 — 엑셀 세 갈래 결정이 엑셀 상한에서 쓴 것과 같은 수법이다. 조용히 자르면 전량 올렸다 가 거짓말이 된다.
  10. 10세그먼트 전환은 묻고 하단 탭 전환은 묻지 않는다. 기준은 잃는가 하나다 — 화면 전체가 갈리면 읽어들인 412행이 사라진다.
  11. 11권한이 이미 걸러 준다. 업로드 API 가 없고 저장이 업무 탭과 같은 하나이므로, READ 권한자가 업로드 창을 여는 경로가 애초에 존재하지 않는다. 엑셀 업로드 전용 탭 결정이 사라지는 것 으로 적은 항목이다.

7. 이 목업으로 확인할 것

이 화면이 정한 것
  • 화면 안 최상단 탭은 하단 디테일 탭과 같은 모양이다(주석 1) — 셸 표준의 미결을 닫는다. 세그먼티드로 정했다가 실물에서 뒤집었다(2026-09-02): 채운 배경은 지금 어디 가 아니라 누르면 실행 으로 읽혔다. 셸 탭바와 갈리는 것은 닫기 없음 과 자리가 맡는다.
  • SMPL-04(탭 안 레이아웃 중첩)를 없앤다 — 엑셀 업로드 전용 탭 결정이 마스터-디테일에 업로드를 붙이는 것을 금지하므로 그 조합이 성립하지 않는다. 중첩은 ⑤가 이미 보인다.
  • 대상이 디테일 테이블인 것이 규약의 결과다(주석 2) — 마스터를 골랐다면 엑셀 업로드 전용 탭 결정이 스스로 기각한 모양을 샘플이 되풀이하는 셈이 된다.
  • ORD_NO 복제가 이 화면 때문이다 — 정규화를 깨는 유일한 자리이며 왜 깼는지가 여기에 있다.
아직 답이 없는 것
  • 엑셀의 code 컬럼 — 사람이 코드값(EA)을 쓰나 코드명(개)을 쓰나. 명으로 받으면 역매핑이 유일하지 않을 수 있고, 값으로 받으면 사람이 코드표를 봐야 한다. 둘 다 받고 값을 우선하는 안이 있으나 정하지 않았다.
  • ui.excel.max-rows 의 실제 값 — 5,000 은 초안이다. 프론트 파싱 + 한 트랜잭션이 어디서 무너지는지 재 보지 않았다.
  • 대조 파생 컬럼의 문구 — 수량 50→80 처럼 무엇이 달라졌는지까지 적을지, 변경 만 적을지. 컬럼이 여럿 바뀌면 칸이 길어진다.
