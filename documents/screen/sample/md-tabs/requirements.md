# 요건 정의서 — 샘플 · 마스터-디테일(복수 탭)

## 개요

- **무엇을 하는 화면인가**: 상하 분할 화면에 **탭을 얹었다** — 아래가 **품목**과 **태그** 두 탭이다.
- **프로세스상 위치**: 없음 — **어휘의 전시**다.
- **이 데이터를 누가 쓰나**: 샘플 여섯이 같은 테이블을 나눠 본다.
- **바꾸면 어디가 흔들리나**: **하단 디테일 탭의 유일한 실물**이다.

> **상하 화면에 탭을 얹은 것이지 그것을 베낀 것이 아니다.** 마스터는 그 화면의 아홉이고 조회조건도 같다 — **갈리는 것은 하단**이며, 그래서 이 파일이 갖는 것은 **마스터와 스플리터뿐이고 탭 둘은 별도 컴포넌트가 갖는다**: 한 파일에 컨트롤러 셋을 두면 ***어느 미저장 상태가 누구의 것인가* 를 읽는 사람이 세야 한다.**

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 1. 화면 구성

```
[조회조건 — 넷. 상하 화면과 같다]
[그리드: 주문 — 컬럼 아홉]
[━━ 스플리터(상하) ━━]
[탭 둘: 품목 · 태그]      ← 각자 저장 버튼을 갖는다
```

- **저장 단위가 셋이다** — 마스터 · 품목 · 태그. 상하 화면이 둘이었던 자리에서 하나가 는다. **묶지 않는 이유는 그대로다**: 묶으면 *태그만 고쳤는데 주문도 갱신됨* 이 되어 **감사 컬럼이 거짓말을 한다.**
- **마스터 컬럼이 아홉이다** — 상하 화면과 **같은 표이므로 같은 키를 쓴다.** 여기에 새 키를 만들면 **같은 컬럼이 두 화면에서 다른 이름으로 보이는 날이 온다** — **폴더가 가르는 것은 인가 경계이지 표의 정의가 아니다.**
- **탭은 조회조건을 갖지 않는다** — 대상이 마스터의 선택이며 그것은 **구조**다.

### 1-1. 마스터-디테일 연동 — **미저장 경고를 한 번만 묻는다**

- **마스터의 선택을 바꿀 때 탭 둘 중 하나라도 미저장이면 묻는다.** **탭마다 물으면 사용자는 같은 물음에 두 번 답하면서도 무엇을 잃는지는 여전히 모른다.**
- **탭을 오가는 것으로는 묻지 않는다** — **표시가 바뀔 뿐 데이터를 버리지 않는다.**
- 탭은 **처음 열 때 조회된다**(지연 로딩).

## 2. 조회조건 — **넷. 상하 화면과 같다**

| 조건 | 대상 | 입력방식 | 기본값 |
|---|---|---|---|
| 주문번호 | `ORD_NO` | 텍스트(`contains`) | — |
| 고객명 | `CUST_NM` | 텍스트(`contains`) | — |
| 주문 상태 | `ORD_STAT_CD` | 셀렉트(다중) | `RCV`·`CFM` |
| 주문일 | `ORD_DT` | 날짜(기간) | 기본 30일 · 상한 366일 |

---

## 3. 조회 — 테이블과 범위

| 테이블 | 역할 |
|---|---|
| `SMPL_ORDER` | 마스터 |
| `SMPL_ORDER_ITEM` | 품목 탭 |
| **`SMPL_ORDER_TAG`** | **태그 탭** — 여기서 **행으로** 읽는다 |

- **태그의 성격이 화면마다 다르다.** 오프셋 화면은 태그를 **주문 응답에 실린 목록 컬럼**으로 나르고(그 화면은 태그를 따로 묻지 않는다), **여기서는 탭이 스스로 조회하고 스스로 저장한다** — 그것이 **지연 로딩과 탭별 독립 편집 상태의 전제**다.

---

## 4. 컬럼

### 4-1. 마스터 — 아홉

상하 화면과 **같은 키**를 쓴다.

### 4-1a. 품목 탭

상하 화면과 같은 표.

### 4-1b. 태그 탭

`TAG_NM` · `TAG_TYPE_CD`.

- **저장 갈래가 오프셋 화면과 다르다.** 저쪽은 **전량 교체**이고 여기는 **행마다 상태를 싣는다.**

### 4-2. 편집 가능 판단

- 상하 화면과 같은 전이표(**잠금이 먼저**, 신규 행은 언제나 열림).

## 7. API — **새 경로가 둘뿐이다**

| 용도 | 키 | 비고 |
|---|---|---|
| 마스터 목록 | `getOrderList` | **상하 화면의 것** |
| 품목 목록 | `getItemList` | 〃 |
| 마스터 저장 | `saveOrders` | 〃 |
| 품목 저장 | `saveItems` | 〃 |
| **태그 목록** | `getTagList` | **이 화면이 여는 첫 경로** |
| **태그 저장** | `saveTags` | 〃 — **행마다 상태를 싣는다** |

- **마스터와 품목 탭은 상하 화면의 것을 그대로 부른다** — **같은 표에 경로를 새로 열면 어느 쪽이 진짜인지를 다음 사람이 물어야 한다.**
- **같은 URL 을 두 화면이 선언하는 것이 정상이다**(좌우 화면이 먼저 그렇게 했다). **적지 않으면 이 화면에서만 403 이 난다.**
- **고객 팝업이 없다.** 좌우 화면은 선언했지만 **이 화면의 마스터는 상하 화면의 아홉이고 그 컬럼에서 고객명은 평범한 텍스트다** — **부르지 않는 경로를 적으면 *선언 = 사용* 이 깨지고, 그 화면에 없는 권한이 역할에 붙는다.**
- **태그 후보 경로의 이름이 오프셋 화면과 갈린다** — 저쪽은 `getTagCandidateList`(후보), 여기는 `getTagList`(한 주문의 행들). **같은 경로 공간을 나눠 쓰므로 이름이 겹치면 기동이 매핑 충돌로 죽는다.**
