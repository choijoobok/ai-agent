# 요청함 처리

> 사용자가 낸 **요청을 처리하거나 반려합니다.** 결과는 **요청한 사람에게 알림으로** 갑니다.

**메뉴 위치** 시스템 › 공지 › 요청함 처리

[요청함 처리 화면 — 오래 기다린 요청이 위에 옵니다](./mockup.html#main)

---

## 1. 먼저 알아 둘 것

- **목록이 비어 있으면 좋은 소식입니다.** 처리할 요청이 없다는 뜻입니다.
- **오래된 요청이 위에 옵니다.** 다른 목록과 반대인데, **가장 오래 기다린 사람이 먼저 보여야** 하기 때문입니다.
- **처리하거나 반려하면 되돌릴 수 없습니다.** 잘못 처리하면 사용자가 요청을 **다시 내야** 합니다.
- **여기서 처리를 눌러도 실제로 권한이 생기거나 계정이 풀리지는 않습니다.** 두 단계입니다.

| 어떤 요청인가 | **먼저 조치할 곳** | 그다음 |
|---|---|---|
| 권한을 달라 | [역할별 권한] 또는 [개인 예외 권한] | 여기서 `[처리]` |
| 잠긴 계정을 풀어 달라 | [사용자 관리]의 `[잠금 해제]` | 여기서 `[처리]` |
| 기타 | 내용에 따라 | 여기서 `[처리]` 또는 `[반려]` |

- **반려하려면 사유가 필수입니다.** 그 문장이 **그대로 요청자에게 갑니다.**

---

## 2. 찾기

1. 조회조건에 값을 넣고 `[조회]`.

**자주 쓰는 조건**

| 이렇게 찾고 싶다 | 이렇게 넣습니다 |
|---|---|
| **처리할 것만** | 그냥 조회합니다 — **기본이 *접수* 입니다** |
| 지난 처리 내역 | `상태`에서 *처리* · *반려* 를 고릅니다 |
| **급한 것부터** | `유형`에서 *잠금 해제* 를 고릅니다 |
| 특정 사람의 요청 | `요청자`에 이름을 넣습니다 |

- **`상태` 는 처음부터 *접수* 하나만 골라져 있습니다.** 전체를 기본으로 두면 **처리된 것이 대기 중인 것을 덮기** 때문입니다.
- **`요청 기간` 은 비어 있습니다.** 기간을 걸면 **가장 오래 기다린 요청이 조회에서 사라집니다** — 그것이 정확히 봐야 할 줄입니다.
- **요청 내용이 잘려 보이면 칸을 두 번 눌러** 펼쳐 읽습니다. 고칠 수는 없습니다.
- `요청 ID` · `요청자 ID` 칸은 숨어 있습니다 — 그리드 설정(`[⚙]`)에서 켭니다.

**유형 셋**

| 유형 | 무슨 요청인가 | 색 |
|---|---|---|
| *권한 신청* | 메뉴나 기능을 쓸 권한을 달라 | 보통 |
| **잠금 해제** | **계정이 잠겨 못 들어온다** | **주의색** |
| *기타* | 그 밖 | 회색 |

> **잠금 해제만 색이 다릅니다.** 권한 신청은 하루 늦어도 일이 되지만, **잠긴 계정은 그동안 아무것도 못 하기** 때문입니다.

---

## 3. 하기

### 3-1. 처리하기

1. **먼저 실제 조치를 합니다** — 권한을 주거나 계정을 풉니다(§1 의 표).
2. 이 화면에서 그 줄을 고릅니다. **여러 줄을 한 번에** 고를 수 있습니다.
3. `[처리]` 를 누릅니다.
4. 창이 **알림이 요청자에게 간다**는 것을 알려 줍니다.
5. 필요하면 **메모**를 씁니다 — **선택입니다.**
6. 확인합니다.

- 처리한 줄은 **목록에서 사라집니다.** 기본 조건이 *접수* 이기 때문이며, **그것이 처리됐다는 가장 분명한 신호**입니다.
- 다시 보려면 `상태`에서 *처리* 를 고르십시오.

### 3-2. 반려하기

[반려는 사유가 필수입니다](./mockup.html#reject)

1. 줄을 고르고 `[반려]`.
2. **사유를 씁니다. 필수입니다.**
3. 확인합니다.

> **사유는 그대로 요청자에게 갑니다.** 사유 없는 반려는 요청자가 **같은 요청을 또 내게** 만듭니다. *왜 안 되는지* 와 *어떻게 하면 되는지* 를 적으십시오.

- 창을 열 때마다 **사유 칸이 비어 있습니다** — 앞서 쓴 사유가 남아 있으면 **다음 사람에게 딸려 가기** 때문입니다.

### 3-3. 버튼이 눌리지 않을 때

**고른 줄 중에 이미 처리된 것이 하나라도 있으면 두 버튼이 모두 잠깁니다.**

- 버튼에 마우스를 올리면 **왜인지 알려 줍니다.**
- **가능한 것만 골라 실행하지 않습니다** — 일부만 처리하면 **알림이 일부에게만 가고** 사용자는 무엇이 처리됐는지 모릅니다.
- *접수* 인 줄만 다시 고르십시오. `상태`를 *접수* 로 걸고 조회하면 섞일 일이 없습니다.

### 3-4. 못 쓰는 계정의 요청

요청자 이름 옆에 **`(미사용)`** 이 붙어 있으면 **지금 로그인할 수 없는 계정**입니다.

- **처리를 막지는 않습니다** — 요청은 계정이 살아 있을 때 낸 것이고, 계정을 다시 켤 수도 있습니다.
- 창을 열 때도 그 사실을 알려 줍니다.
- 계정을 확인하려면 [사용자 관리]로 갑니다.

### 3-5. 엑셀

이 화면에는 **엑셀이 없습니다.**

## 4. 안 될 때

| 이런 일이 생기면 | 이유 | 어떻게 하나 |
|---|---|---|
| **두 버튼이 다 잠겨 있습니다** | 고른 줄이 없거나, **이미 처리된 것이 섞여 있습니다** | 버튼에 마우스를 올려 확인합니다 |
| *반려 사유는 필수입니다.* | 사유를 비웠습니다 | 이유를 씁니다 — **요청자에게 갑니다** |
| *이미 처리된 요청이 선택에 있습니다.* | 다른 사람이 그 사이에 처리했습니다 | 다시 조회하고 남은 것만 고릅니다 |
| *없는 요청입니다.* | 그 요청이 사라졌습니다 | 다시 조회합니다 |
| **잘못 처리했습니다** | **되돌릴 수 없습니다** | 사용자에게 알리고 **요청을 다시 내게** 합니다 |
| 목록이 비어 있습니다 | **처리할 요청이 없습니다** | 정상입니다 |
| 처리했는데 사용자가 여전히 못 씁니다 | **실제 조치를 안 했습니다** | 이 화면은 판정만 기록합니다 — §1 의 표대로 조치하십시오 |
| 오래된 요청이 안 보입니다 | 기간 조건이 걸려 있습니다 | `요청 기간`을 비웁니다 |
| 처리한 줄이 사라졌습니다 | **정상입니다** | `상태`에서 *처리* 를 고르면 다시 보입니다 |
| 요청 내용 칸이 안 고쳐집니다 | 이 화면은 **고치는 화면이 아닙니다** | 두 번 눌러 읽기만 합니다 |
| 요청 유형을 늘리고 싶습니다 | 화면에서 할 수 없습니다 | 개발 담당자에게 요청합니다 |

## 5. 다른 메뉴와의 관계

**먼저 해야 하는 것**

| 어떤 요청이면 | 어디서 조치하나 |
|---|---|
| 권한 신청 | **[역할별 권한]**(여러 명에게 해당) · **[개인 예외 권한]**(그 사람만) |
| 잠금 해제 | **[사용자 관리]** 의 `[잠금 해제]` |

**여기서 저장하면 바뀌는 곳**

| 어디가 | 어떻게 |
|---|---|
| **요청자의 알림** | 처리 결과와 메모가 알림으로 갑니다 |
| 요청 상태 | *접수* → *처리* 또는 *반려* 로 바뀌고 **되돌아가지 않습니다** |

**같이 보는 화면**

| 무엇이 궁금한가 | 어디로 |
|---|---|
| 이 계정이 왜 못 들어오나 | **[로그인 이력]** · **[사용자 관리]** |
| 이 사람이 지금 무엇을 할 수 있나 | **[사용자 관리]** 의 [유효 권한] 탭 |
| 권한을 어디서 주나 | **[역할별 권한]** · **[개인 예외 권한]** |

## 6. 자주 묻는 것

- **처리를 누르면 권한이 생기나요** — 아닙니다. **먼저 권한을 주고 나서** 처리를 누르십시오.
- **여러 건을 한 번에 처리할 수 있나요** — 됩니다. 다만 **전부 *접수* 상태여야** 합니다.
- **처리 메모는 꼭 써야 하나요** — 처리는 선택, **반려는 필수**입니다.
- **처리한 뒤 취소하고 싶습니다** — 되돌릴 수 없습니다. 사용자에게 요청을 다시 내게 하십시오.
- **목록이 계속 비어 있습니다** — 요청이 안 들어오는 것입니다. 정상입니다.
- **왜 오래된 것이 위에 있나요** — 대기열이기 때문입니다. 오래 기다린 사람이 먼저 처리되어야 합니다.
