# 요건 정의서 — 월별 개인 쿼터 기준

## 개요

- **무엇을 하는 화면인가**: 월별 계획 가능 금액과 보정 단가로 총 풀을 산정하고 등급별 가중치·활성 인원으로 개인 기본 한도를 확정한다.
- **프로세스상 위치**: SCR-016 월 계획 단가 + SCR-023 대조 수동 보정 근거 → 년월 행 추가·저장(단가 고정) → 쿼터 배분 실행 → 대상 월 개인 한도 적용·신규 일할 배정
- **이 데이터를 누가 쓰나**: 권한 있는 관리자와 연결 업무의 담당자가 현재 적용값 또는 업무 처리 근거로 사용한다.
- **바꾸면 어디가 흔들리나**: 소유 기능의 요청·권한·참조 및 이력/감사 연결을 함께 확인한다.

> 미구현 화면 초안이며 사용자 화면 합의·제품 구현·G3(설계 승인 게이트) 승인이 아니다. [화면 정본](../../../../spec/60-screens/_index.yaml)과 [기능 정본](../../../../spec/31-features/002-admin.yaml)을 따른다. 표시 예시는 실제 데이터·물리명·운영 기본값이 아니다.

## 1. 화면 구성

상단 조회조건 → 월별 개인 쿼터 기준 목록 → 등급별 배분 · 사용자 배정 · 수동 보정 근거 · 산정·처리 근거 순서다. 제목·건수는 왼쪽, 작업 버튼은 상단·그리드 툴바·모달 하단에서 우측 정렬한다. 초기 화면의 모든 탭은 실제 전환하며 같은 상위 대상의 입력·선택·추가/제거 행을 유지한다.

목록 연동: 년월
대상 편집 조건: 배분 여부=N
선택 무관 버튼: 행 추가
저장 후 실행 버튼: 쿼터 배분 실행
행 추가 탭: 월별 개인 쿼터 기준 목록
행 제거 보호: 보존 사유
상태별 버튼: 허용 목록

### 탭 · 선택 변경 규칙

- 년월은 화면의 업무 식별값이며 월당 한 건이다. 내부 참조/자기 기준본·원 명령 식별자는 비표시로 보존하고 새 물리 키를 확정하지 않는다.
- 행 추가는 조회조건 년월과 저장된 같은 월 단가를 검사한다. 추가만으로 단가를 잠그거나 저장하지 않는다. 단가가 없거나 미완료·조회 실패면 행 추가 금지. 추가 후 저장 전에 단가가 바뀌면 재조회·검토하며 조용히 새 값으로 바꾸지 않는다.
- 최초 저장 성공과 단가 고정은 함께 처리한다. 이후 재저장은 원 잠금 단가/스냅샷·상한을 그대로 두고 금액·환산율·보정만 검증하며 실적을 재집계하지 않는다. 저장된 월 기준은 삭제/년월 변경하지 않으며 배분 전 금액·환산율·보정/사유만 수정한다. 잠긴 단가는 교체·해제하지 않는다.
- 배분 실행 전에는 현재 등급/인원으로 미리 보기만 하며 사용자 배정은 생성하지 않는다. 실행 시점에 고정한 기준의 개인 한도는 대상 월부터 적용한다.
- SCR-055는 원 화면 읽기 전용 상속이다. 별도 이력 목업·이력 탭을 복제하지 않는다.

| 소유 저장/명령 | 물리명 미정 — 소유 논리 집합 | 선택 월 계획 입력·저장/고정 USD 단가/수동 환산율·보정·고정 인원/가중치·확정 근거. 사용자 사용량은 직접 수정 대상 아님 | 검증·현재 권한·자기 기준본과 실제 결과를 함께 확인. 일부만 반영하지 않음 |

### 6-3. 상태 전이

미저장 → 월 기준 저장·단가 고정(배분 전) → 쿼터 배분 실행(대상 월 적용). 월말까지 실행하지 않으면 직전 실행/승계확정 기준으로 자동 승계한다. 원 저장 제안과 실제 적용 승계 기준을 구분하며, 저장한 단가를 승계값으로 몰래 사용하지 않는다. 같은 월 새 단가 없음은 자동 승계를 막지 않는다. 활성0명은 월 기준만 확정하고 개인 기준은 미산정으로 남긴다. 저장 시점에는 승급 적용 월·인원·개인 한도를 고정하지 않는다. 경합 공개/물리 계약은 후속이다.

## 8. 시드 · 데이터 전제

- 코드그룹·메시지 키·물리 테이블·필드·신규 API 경로는 미정이다. A 담당 공통 정본 확정 후 연결하며 이번 작업에서 시드·제품 소스를 변경하지 않는다.
- 메뉴/경로는 §0의 등록된 설계값만 사용한다. 연결 대상 메뉴·본문·증거·반출은 현재 유효 권한을 각각 검사한다.
- 초기 운영값·조회 상한·보존 기간은 미정. 기존 정본의 확정 계약을 소비하고 목업 예시로 운영 기본값을 정하지 않는다.
