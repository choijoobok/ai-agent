# 요건 정의서 — 외부 모델 등록

## 개요

- **무엇을 하는 화면인가**: 공급사 - 모델 - effort 지원 조합을 한 행씩 등록하고 외부 모델 식별값 하나로 식별한다. 각 표시명과 실제 호출 코드를 구분한다. 실제 전송값과 화면 표시값을 구분해 유효한 조합을 만든다.
- **프로세스상 위치**: 배포 연결/어댑터 준비 → **공급사·모델·effort 등록** → SCR-062 모델 용도·우선순위 설정 → 실행 시 코드 해석.
- **이 데이터를 누가 쓰나**: 용도 설정은 등록 모델/effort를 콤보로 선택한다. Portal은 등록된 유효 텍스트 조합 전체를 사용자 주 추론 선택지로 제공한다.
- **바꾸면 어디가 흔들리나**: 모델 용도 참조·최초 기본값·사용자 선택지·호출/계량 근거. 표시명 변경과 호출 코드 변경은 영향이 다르다.

## 1. 화면 구성

조회조건 → 외부 모델 조합 단일 그리드다. 한 행은 공급사·호출 경로·모델·effort의 유효한 조합이며 외부 모델 식별값 하나를 갖는다.
개발 가이드의 공통 그리드 크롬을 사용한다. 조회조건에는 초기화만, 조회·행 추가·저장·업무 버튼은 그리드 상단 우측에 둔다. 편집 그리드의 상태·삭제 컬럼은 저장 전 변경을 표시한다.
상태별 버튼: 허용 목록
행 추가 탭: 외부 모델 조합
행 제거 보호: 사용 용도

### 그리드 선택

| 그리드 선택 | 선택 방식 |
|---|---|
| 외부 모델 조합 | 다중 |

번호 → 행 선택 체크박스 → 상태(편집 가능) → 업무 컬럼 → 삭제(삭제 가능) 순이다. 번호·선택·상태는 왼쪽, 삭제는 맨 오른쪽에 고정한다.
체크박스는 행 선택용이며 행 클릭으로 선택을 갈아치우지 않는다. 저장은 체크한 행만이 아니라 같은 저장 단위의 전체 변경 행을 대상으로 한다.

### 1-1. 연동·편집 단위

없음. 표시명/코드·지원 여부·현재 사용 용도를 한 행에서 확인한다. 조회 필터 밖의 조합을 삭제로 보지 않으며 전체 편집본과 입력을 유지한다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

공급사·모델·지원 effort의 안정 참조와 등록 리비전, 배포 연결 참조 및 현재 용도 사용처를 조회한다. 물리 테이블·결합 키는 미정이다.
API/개발 CLI·연결별 모델/effort 코드가 다르면 해당 호출 경로별로 구분한다. 공급사 코드 입력만으로 미지원 어댑터가 생기지 않는다.

### 3-2. 고정 조건 · 기본 정렬

공급사명/코드, 모델명/호출 코드, 모델별 effort명 순이다. 텍스트 생성/임베딩과 활성·비활성을 구분한다.
등록 정보의 삭제 가능 여부는 현재 용도 참조를 서버에서 검사하며 화면의 사용처 목록만 믿지 않는다.

## 5. 버튼 · 액션

| 버튼 | 액션 | 사용 조건 | 저장/실행 단위 | 동작 |
|---|---|---|---|---|
| 조회 | READ | 현재 조회 권한·저장 처리 중 아님 | 없음 | 미저장 변경 확인 후 적용본/현재 사용처 조회 |
| 수정 | SAVE | 변경 권한·전체 편집본 확보 | 편집본 | 등록 조합 편집 시작 |
| 행 추가 | SAVE | 편집 중 | 새 조합 한 행 | 상태 신규(C), 식별값은 실제 저장 시 부여 |
| 저장 | SAVE | 현재 권한·지원/참조/기준본 검사 통과 | 등록 편집본 전체 | 추가/수정/삭제 상태를 한 번 검증·원자 저장 |
| 편집 취소 | SAVE | 편집 중·저장 처리 중 아님 | 편집본 | 임시 변경만 취소 |
| 엑셀 다운로드 | EXPORT | 별도 반출 권한 | 표시 열/허용 범위 | 숨은 코드·비밀 자동 포함 없음 |

삭제는 별도 툴바 버튼이 아니라 행의 삭제 컬럼이다. 기존 행은 삭제 상태(D)로 표시하고 저장 때 반영, 신규 행은 즉시 편집본에서 제거한다. 참조 중 조합의 삭제는 잠그고 이유를 표시한다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

- 공급사→모델→지원 effort의 실제 조합만 등록한다. 등록명과 코드를 분리하며 대소문자·별칭·숫자 단계 등을 임의 정규화/변환하지 않는다. 값 전송 시 코드 필수, 미전송 시 코드 비움이다.
- 모델 용도에서 참조 중이면 외부 모델 조합 행 삭제를 차단한다. 사용 용도는 해당 외부 모델 식별값을 참조하는 모든 현재 용도를 합해 확인한다. 참조가 미사용/보완 필요여도 남아 있으면 사용 중이다. 용도에서 참조하는 외부 모델 조합을 우회 제거할 수 없다. 사용처를 확인하지 못하면 삭제 가능으로 처리하지 않는다.
- 표시명 변경은 안정 참조를 유지한다. 현재 용도에서 쓰는 호출 모델 코드·effort 코드·전송 방식·연결 교체는 참조 해소 전 거부하고 새 조합 등록 후 용도 이동을 안내한다. 과거 실행/이력의 코드를 덮어쓰지 않는다.
- 긴급 미사용은 허용하되 해당 모델/effort를 신규 선택/호출에서 제외하고 용도 설정에 무효·보완 필요를 알린다. 다른 모델로 자동 치환하거나 참조를 자동 삭제하지 않는다.
- 삭제 저장과 용도 저장이 경합하면 현재 전체 참조를 일관되게 검사한다. 먼저 생성된 참조를 무시한 삭제나 삭제된 모델/effort를 참조하는 설정은 모두 허용하지 않는다. 삭제 확인 뒤 화면에 남은 오래된 참조로 호출하지 않는다.
- 자기 기준 리비전·현재 변경 권한·실제 연결/어댑터 지원을 서버에서 재검사한다. 코드만 등록해 실제 지원 확인이 끝난 것으로 보지 않는다. 실제 호출·동의/쿼터 집행은 실행 소유 기능이다.
- 시작된 작업은 당시 등록/용도 버전과 실제 전송 코드·전송 여부를 고정 기록한다. 현재 권한·참조/연결·동의 검사는 호출 당시 다시 수행한다. 등록/용도 변경으로 기존 작업을 다른 코드로 호출하지 않는다.
- 접속 주소·API 키·비밀번호는 REQ-403의 배포 설정을 참조한다. 등록으로 전송 동의 범위를 확대하지 않는다(REQ-106). 보조 판정만 기존 자동 대체 범위를 유지한다.

### 6-2. 영향 테이블

물리명은 미정. 외부 모델 등록 편집본의 전체 적용본과 이력을 원자 반영한다. 용도 참조는 읽고 검증하며 이 화면에서 편집하지 않는다.

### 6-3. 상태 전이

적용본 → 편집 → 검증 성공 저장/취소. 참조 중 삭제·코드 오류·충돌은 미적용/입력 보존, 결과 불명은 원 명령 결과 확인이다.
변경 이력 SCR-051은 이 단일 그리드를 읽기 전용 상속한다. 독립 이력 요건/목업을 복제하지 않는다.

## 7. API

등록·지원 근거·현재 용도 사용처 조회 및 전체 저장의 공개 계약은 화면/업무 흐름 합의 후 상세 설계한다. URL·DTO·물리명은 확정하지 않는다.

## 8. 시드 · 데이터 전제

배포 연결·어댑터 지원 근거가 선행한다. 화면의 모든 demo 코드는 설명용이며 실제 공급사 지원값이나 초기 운영값이 아니다. 제품 sources/·DB·시드 변경 없음.
