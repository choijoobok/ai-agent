# 요건 정의서 — 지식 검토 작업

## 개요

- **무엇을 하는 화면인가**: 오류가 없어도 외부 스키마·기준정보·업무 규칙의 변경 통지에서 예방적 영향 검토를 시작하고 판단·조치 근거를 남긴다.
- **프로세스상 위치**: 변경 통지/관측 → 예방 검토 작업 → 소유 자산 전용 변경 요청/직접 조치 → 실제 반영 확인 후 완료. 사후 조사에서 이미 진단한 변경은 필수 경유 아님
- **이 데이터를 누가 쓰나**: 권한 있는 관리자와 연결 업무의 담당자가 현재 적용값 또는 업무 처리 근거로 사용한다.
- **바꾸면 어디가 흔들리나**: 소유 기능의 요청·권한·참조 및 이력/감사 연결을 함께 확인한다.

> 미구현 화면 초안이며 사용자 화면 합의·제품 구현·G3(설계 승인 게이트) 승인이 아니다. [화면 정본](../../../../spec/60-screens/_index.yaml)과 [기능 정본](../../../../spec/31-features/002-admin.yaml)을 따른다. 표시 예시는 실제 데이터·물리명·운영 기본값이 아니다.

## 1. 화면 구성

상단 조회조건 → 지식 검토 작업 목록 → 영향 자산 · 판단 근거 · 조치 연결 · 검토 기록 순서다. 제목·건수는 왼쪽, 작업 버튼은 상단·그리드 툴바·모달 하단에서 우측 정렬한다. 초기 화면의 모든 탭은 실제 전환하며 같은 상위 대상의 입력·선택·추가/제거 행을 유지한다.

### 1-3. 마스터-디테일·이력 경계

- 선택 변경·조회·이탈 때 미저장 변경을 확인하고 취소하면 선택·입력을 보존한다. 결과 불명에는 새 명령 없이 원 처리 결과를 확인한다.
- 업무 원장·로그의 자체 기록을 조회한다. 이 화면 자체를 관리 구성 이력으로 복제하지 않는다.
- 선택 검토 작업의 원 통지·영향 자산·판단·조치 연결과 단계별 근거

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 역할 | 결합 기준 |
|---|---|---|
| 미정 — 논리: 지식 검토 작업 | 소유 업무 기록/원장 | 안정 식별자 + 해당 조회 문맥. 물리 테이블·컬럼·조인/API는 소유 상세 설계 후속 |

### 3-2. 고정 조건 · 기본 정렬

- 항상 현재 메뉴·액션과 대상 열람 범위를 서버에서 검사한다. 선택한 업무 기록의 당시 내용과 현재 관측을 구분한다.
- 기본 정렬·페이지 방식·조회 기간/상한·보존 기간·대량 반출 한도는 소유 계약 미정이다. 운영값을 추정하지 않는다.
- 빈 결과·권한 제외·조회 실패·미확인을 구분한다. 명령과 연계 조회의 권한을 자동 승계하지 않는다.

현재 변경 권한과 허용 상태가 모두 맞을 때만 소유 입력을 편집한다. 제출본·처리 완료본은 잠금. 저장/판정/결과 불명 중 입력과 원 키를 보존하고 새 명령을 잠근다.

### 값 변경 후 연쇄 · 재계산

참조 선택은 안정 ID와 표시명을 함께 유지한다. 검색 문자열은 선택값을 바꾸지 않는다. 다른 대상 선택 시 기존 상세를 섞지 않는다. 외부 리비전 상승에 따른 자동 매핑/내용 동기화는 없다.

- 코드그룹·메시지 키·물리 테이블·필드·신규 API 경로는 미정이다. A 담당 공통 정본 확정 후 연결하며 이번 작업에서 시드·제품 소스를 변경하지 않는다.

- 초기 운영값·조회 상한·보존 기간은 미정. 기존 정본의 확정 계약을 소비하고 목업 예시로 운영 기본값을 정하지 않는다.
