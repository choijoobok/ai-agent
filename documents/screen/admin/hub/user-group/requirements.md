# 요건 정의서 — 사용자 그룹

## 개요

- **무엇을 하는 화면인가**: 그룹 정의를 관리하고 선택 그룹의 사용자·지식·스키마 카탈로그·API·커스텀 도구 매핑을 다섯 탭에서 확인·편집한다.
- **프로세스상 위치**: 그룹 선택 → 탭의 현재 매핑/제약 확인 → 활성 스위치·사유 편집 → 해당 소유 업무의 저장/승인 처리 → 현재 적용본 재조회.
- **이 데이터를 누가 쓰나**: 사용자 접근·자산 권한 관리 담당자가 그룹 관점에서 현재 허용 범위와 변경 후보를 확인한다.
- **바꾸면 어디가 흔들리나**: 소속 부여/회수와 각 자산 후보·승인·이력. 정본은 REQ-605.mapping_workbench와 각 소유 계약이다.

## 1. 화면 구성

조회조건 → 상단 사용자 그룹 목록 → 상하 스플리터 → 사용자·지식·스키마 카탈로그·API·커스텀 도구 다섯 탭이다.
각 탭은 현재 활성 매핑과 현재 조회 권한 안의 비활성/미매핑 후보를 구분해 표시한다. 스위치 값은 저장 전 편집본이며 현재 접근·승인 상태와 별도다. 지식 탭에는 인증 예제도 자산 종류로 구분하고, 커스텀 도구 탭에는 등록 업무 도구를 내부 빈/API 기반 유형으로 구분한다.
제목·건수는 왼쪽, 작업 버튼은 오른쪽이다. 스위치는 한 번 눌러 변경하고 사유는 셀에서 입력한다. 새 대상 등록/계약·컬럼 예외 편집은 원 소유 화면의 업무다.

목록 연동: 그룹 식별자
대상 편집 조건: 대상 선택됨=Y
상태별 버튼: 허용 목록

행 클릭으로 선택하고 선택 체크박스는 두지 않는다. 탭의 저장/승인 요청은 선택 행만이 아니라 선택 그룹·해당 탭의 전체 변경 후보를 대상으로 하며 다른 그룹/탭의 미저장 변경을 포함하지 않는다.

### 1-1. 마스터-디테일 연동

- 안정 그룹 식별자로 다섯 탭을 함께 조회한다. 그룹명 변경으로 매핑을 다시 식별하지 않는다.
- 그룹/탭을 왕복해도 각 편집본·입력·선택을 유지한다. 재조회·이탈은 미저장 변경 확인 후 처리한다. 아직 저장되지 않은 신규 그룹은 매핑 편집을 잠근다.
- 원천의 일부 목록·열람 제한·조회 실패를 빈 전체 매핑으로 간주하지 않는다. 화면에 보이지 않은 다른 그룹/자산 매핑을 삭제하거나 후보에서 누락하지 않는다.

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

그룹 정의와 각 원 소유의 현재 사용자 소속·지식/인증 예제·테이블·업무 API·도구 그룹 매핑을 안정 참조로 역조회한다. 실제 테이블·결합·페이징 계약은 후속이다. 조회자는 그룹 화면과 각 원천의 현재 열람 범위를 함께 만족해야 한다.

### 3-2. 고정 조건 · 기본 정렬

선택 그룹의 활성 매핑을 우선 표시하고 비활성/미매핑 후보·진행 요청은 구분한다. 현재 접근은 현재 적용본에서만 판정하고 편집값/승인 대기를 합치지 않는다. 그룹 하나만으로 다른 소속 그룹·사용자 대상 매핑·컬럼/행·계약·노출·원 시스템 권한까지 확정했다고 표시하지 않는다.

## 6. 규칙 — 저장 · 실행

### 6-1. 검증

정본은 [REQ-605.mapping_workbench](../../../../spec/10-requirements/011-reference-integration.yaml)와 관련 요구사항 표의 소유 계약이다.

- 그룹 정의 저장과 다섯 매핑 처리 단위를 구분한다. 저장 직전 현재 그룹·대상·소유 변경 권한·전체 후보·자기 기준본을 서버에서 재검사한다. 미저장 다른 그룹/탭을 자동 합치지 않는다.
- 사용자 ON은 새 부여/재부여 후보이고 현재 설정에 따라 승인 또는 전결, OFF는 별도 승인 없는 회수다. 마지막 활성 그룹 회수는 이용자 비활성화를 함께 처리하며 취소/제거의 지연 승인으로 소속을 부활시키지 않는다.
- 지식·예제·카탈로그·API·도구는 다른 그룹·본문/계약·컬럼 예외 등 원 소유 구성을 보존한 전체 후보/세트로 처리한다. 승인 사용 시 기존 유효본을 유지하고 미사용 전결도 전체 검증·스냅샷·일괄 반영을 유지한다. 진행 중 제출본은 직접 변경하지 않는다.
- 접근 상태는 현재 적용본을 보여준다. 그룹 포함만으로 사용자 대상 신원·컬럼 HIDE/MASK·행 스코프·API 입력/원 시스템 권한·도구 노출/지식 연결/유효 계약이 모두 충족됐다고 표시하지 않는다. API 기반 도구도 API와 도구 양쪽 권한을 검사하고 서로의 매핑을 자동 변경하지 않는다.
- 그룹 생성으로 소속·자산 권한·system 역할·쿼터를 자동 부여하지 않는다. 사용 중 삭제와 참조 조회 실패는 삭제를 차단한다. 미상 매핑은 꺼짐으로 만들지 않는다.

### 6-2. 영향 테이블

새 물리 플래그를 정하지 않는다. 그룹 정의는 원 그룹 정본, 소속은 REQ-609, 자산 후보/요청/적용 이력은 각 소유 정본이 쓴다. 그룹 화면에 원 자산 사본이나 별도 승인 원장을 만들지 않는다. 선택 탭에서 묶은 처리도 소유 승인 계약의 원자성·중복 방지를 유지한다.

### 6-3. 상태 전이

현재 적용본 조회 → 스위치·사유 로컬 편집 → 소유 검증 → 전결/무승인 회수 적용 또는 승인 요청 대기 → 승인 성공 후 현재 적용본 갱신.
검증 실패·충돌은 입력 보존, 결과 불명은 원 명령 결과 확인이다. 그룹 정의의 변경 이력은 원 그룹 정의를, 매핑 변경은 해당 소유의 부여/후보·적용 이력을 참조한다. 다른 소유의 현재 매핑을 그룹 정의의 과거 값으로 둔갑시키지 않는다.

## 7. API

그룹 관점의 매핑 조회·후보 전달은 기존 소유 기능을 재사용하는 진입 계약으로 상세화한다. URL·DTO·물리명은 화면/전체 업무 흐름 합의 후다. 실제 접근 판정·실행을 목업 저장이 대신하지 않는다.

## 8. 시드 · 데이터 전제

메뉴·메시지·권한 시드와 제품 소스는 이번 화면 검토에서 구현하지 않는다. 기존 그룹·대상 안정 식별자와 현재 적용본·권한·승인 설정을 조회할 수 있어야 한다. 예시 데이터는 모두 가상이다.
