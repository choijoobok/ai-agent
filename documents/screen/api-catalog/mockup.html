총 1건 — 더블 클릭하면 메뉴 트리를 그 메뉴로 연다 5
  1. 1매핑 상태 가 진단의 입구다. 미매핑만 골라 보는 것이 이 화면에서 가장 자주 하는 일인데, 컬럼 필터로 두면 현재 페이지 안에서만 걸린다 — 전량을 물어야 하므로 서버 조건이다.
  2. 2쓰는 버튼이 없다. 전 컬럼이 읽기 전용이라 editable 을 하나도 선언하지 않고, 그래서 상태 컬럼 · 삭제 컬럼 · 저장 버튼 · 행 추가가 전부 없다 (§4). ⤓ 는 있다 — 조회 전용은 쓰기 에 관한 말이지 내보내기 에 관한 말이 아니다. 항목은 둘(현재 페이지 · 전체)이며 — 페이징이 있어 메뉴 트리와 다르다. ⚙ 도 있다 — 개인화이지 데이터가 아니다.
  3. 3미매핑은 대개 결함이다. SYS_MENU_API 에 행이 없으면 아무도 그 API 를 호출할 수 없다 — 유효 권한의 원소가 (MENU_CD, ACTION_CD) 쌍인데 메뉴가 없으니 쌍이 만들어지지 않는다. 프론트가 부르지 않는 API 가 컨트롤러에 남아 있다는 뜻이며, 배포 예정 화면의 API 가 먼저 들어온 정상 경우가 있어 막지는 않는다.
  4. 4탭이 아니라 pane 하나다 — 메뉴·권한 화면 설계가 역할 화면에서 내린 것과 같은 판단이며 탭 하나짜리 탭바는 누를 곳이 없는 크롬이다. 메뉴 경로를 전체로 낸다 — 메뉴명만으로는 어느 것인지 모른다.
  5. 5더블 클릭이 셋째 갈래로 넘겨준다(화면 2). MENU_TREE 를 그 메뉴로 열고 (UX-02 멀티탭), 거기 매핑된 역할 탭에서 ROLE_AUTH_MGMT로 이어진다.
  6. 감사 4컬럼이 목록에 없다 — 기본 숨김이다(visible: false). 시드가 전건 삭제 후 전건 삽입이라 모든 행의 값이 매번 같이 다시 쓰인다 — 등록일 이라고 부르면 거짓말이라 라벨이 최종 시드 반영이다.
  7. 액션 셀이 조회 · 저장 · 내보내기 · 실행 으로 나온다 — READ 가 아니다. 권한 화면의 액션 4열 헤더와 같은 메시지 키(action.{ACTION_CD})를 읽는다 . 공통코드가 아니다 — 이 넷은 헤더로도 쓰여 소스에 박혀 있고, 잠가 두면(SYS_YN) 관리자에게 남는 것이 없다. 값은 소스, 라벨만 데이터다.
  8. 기본 정렬은 API_URL 이다. PK 라 tie-breaker 가 필요 없다 — 역할 목록이 ROLE_NM, ROLE_ID 로 두 컬럼이 필요했던 것과 다르다.

2. 이 화면의 존재 이유 — 403 은 세 갈래로 갈린다

  • 운영자가 403 을 받는다 → 로그(64)에서 URL 하나를 얻는다 → 여기서 찾는다
  • 목록에 없다 → 미등록 — 컨트롤러 + 시드 재생성. 화면 3
  • 있는데 매핑 메뉴 0 → 미매핑 — 프론트 endpoints.ts + 시드 재생성. 화면 4
  • 있고 매핑 메뉴가 있다 → 권한 문제 — 역할 권한 또는 개인 예외
세 갈래가 이 화면의 설계를 전부 정한다 — 마스터가 첫째와 둘째를 답하고, 하단 pane 이 셋째로 넘겨준다(화면 1 주석 5)
상태무엇이 없나증상고치는 곳
미등록SYS_API 에 행403. 이 화면에서 찾을 수 없다 컨트롤러 + ./gradlew generateApiSeed
미매핑SYS_MENU_API 에 행403. 배지가 보인다 프론트 endpoints.ts + 시드 재생성
권한 문제사람의 권한403. API 는 정상이다 역할 권한 · 개인 예외
  1. 인가 데이터 모델이 미등록과 미매핑을 가른 이유가 여기서 값을 한다 — "둘 다 403 이지만 고치는 곳이 다르므로 구분해 기록한다". 그 구분을 사람이 확인하는 자리가 이 화면이다.
  2. 미등록은 이 화면이 보여줄 수 없다 — 없는 행을 목록에 낼 방법이 없다. 그래서 검색 결과 0건의 빈 상태가 곧 진단이 된다(화면 3). "조회 결과가 없습니다" 로 끝내면 세 갈래 중 하나가 사라진다.

5. 왜 조회 전용인가 — 여기서 고친 것은 다음 배포에서 사라진다

사실어디그래서
ACTION_CD 는 코드가 결정한다 — 경로 접두 또는 @ApiActionType —위 넷 중 하나만으로도 조회 전용이 된다.
편집 수단을 두면 "고쳤는데 원래대로 돌아왔다" 가 배포마다 반복되고, 그것은 기능이 아니라 고장으로 읽힌다
매핑은 프론트 endpoints.ts 에서 나온다〃
시드는 전건 삭제 후 전건 삽입이다—
매핑 행 추가가 곧 접근 범위 확장이라 코드 리뷰를 거쳐야 한다—
API 명·설명은 @Operation 이 준다 — 컨트롤러에 쓴 한 문장이다— 고칠 곳은 코드다. summary 누락은 ArchUnit 이 빌드에서 깬다 — 그래서 이 화면에 이름 없는 행 이 없다
  1. EXPORT 는 있다(메뉴 목록의 액션 열이 R E). 넷은 쓰기 를 막는 근거이지 내보내기 를 막는 근거가 아니다. 시드 파일에 있는 것은 SYS_API 네 컬럼과 매핑 행뿐이고, 이 화면이 계산하는 매핑 메뉴 수와 접근 가능 인원은 어디에도 없다. 가장 쓸모 있는 조합은 매핑 상태 = 미매핑 으로 조회한 뒤 전체 — 결함 목록이 그대로 파일이 된다.
  2. 62 의 넷 중 처음으로 R 만 있는 화면이다 — §2·§3 은 R S, §4 는 R S E 였다.
  3. 조회 전용이라고 그리드 설정까지 없어지는 것은 아니다 — 컬럼 표시·순서·고정은 개인화이며 데이터와 무관하다. 트리가 그 창을 갖지 않는 것과는 이유가 다르다.

7. 테스트 케이스 — 주석의 주장을 전부 덮는다

주석은 "왜 이렇게 그렸는가" 를 말하고, 여기는 "그것이 지켜졌는가" 를 묻는다. 근거가 빈 케이스는 지어낸 것이다 — 문서 절이나 이 파일의 화면 번호를 가리킨다. 되면 안 되는 것도 함께 넣는다.

8. 이 목업으로 확인할 것

이 화면이 규약에 되돌려 준 것
  • 메뉴 목록이 남긴 기본정보 탭 정리가 끝났다 — ROLE_MGMT · MENU_TREE 에 이어 마지막 하나다. AUTHZ-14 의 "API명·설명·액션 팝업" 도 팝업이 아니라 컬럼이 됐다.
  • 인가 데이터 모델의 미등록·미매핑 구분이 화면을 얻었다 — 그 절이 "고치는 곳이 다르므로 구분해 기록한다" 고 적은 것을 사람이 확인하는 자리가 생겼다.
  • 조회 전용 화면의 모양이 처음 정해졌다 — 상태·삭제 컬럼도 저장 버튼도 행 추가도 없지만 ⤓ 와 ⚙ 는 남는다. 하나는 쓰기가 아니고 하나는 개인화다. 64 의 로그 3종이 이 모양을 그대로 따랐고, 대용량이라 셋을 더했다 — 총 건수 생략 · nclob 미적재 · 추적 ID.
아직 답이 없는 것
  • 미매핑을 CI 경고로 올릴지 — 배포 예정 화면의 API 가 먼저 들어오는 정상 경로가 있어 오탐이 난다.
  • SYS_API 가 수백 건이 됐을 때 — 전량 페이징으로 버티는지. 매핑 상태 를 서버 조건으로 둔 것이 그 대비다.
  • 403 로그에서 이 화면으로 바로 넘어가는 링크를 둘지 — 닫혔다(2026-08-28). 둔다 — 에러 로그의 요청 URI 셀 더블 클릭이며, 아래 하단 행 더블 클릭 → MENU_TREE 와 같은 어휘다. 403 은 사용 이력과 에러 로그 양쪽에 남고, ERR_CD 가 세 갈래를 그대로 나른다.
목업 규약 — 정적 HTML, 프레임워크 없음, 픽셀 충실도는 목표가 아니다. 결정은 requirements.md 가 갖고 이 파일은 확인용이다 — 여기에만 있고 요건서에 없는 정보는 유실된 것으로 친다.
