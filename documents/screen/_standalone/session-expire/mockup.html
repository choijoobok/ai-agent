1. 예고 상태

셸 위 모달 · 유휴 타임아웃 임박
세션이 곧 만료됩니다 ✕ 없음 1

1:47 후 자동으로 로그아웃됩니다. 2

  1. 1닫기(✕)를 두지 않는다. 닫으면 사용자는 연장했다고 착각하고 작업을 계속하다 잃는다. 출구는 연장과 로그아웃 둘뿐이다.
  2. 2남은 시간은 클라이언트 카운트다운이다. 서버에 매초 물을 수 없다 — 그러면 그 요청 자체가 세션을 연장한다.
  3. "계속 사용" → POST /api/common/auth/heartbeat. 자동 연장은 두지 않는다 — 자리를 비운 화면이 무한히 살아 있으면 유휴 타임아웃의 목적이 사라진다.
  4. 미응답으로 만료되면 로그아웃 네 경로 중 만료 로 수렴한다 — authStore 비우기 · 탭 정리 · 로그인 화면 전환이 같은 함수다.

2. 만료된 뒤 — 재인증 모달. 탭을 비우지 않는다

로그인 화면으로 되돌리지 않는다. 자리를 잠깐 비운 것과 업무를 끝낸 것은 다르므로, 탭과 입력값을 그대로 두고 셸 위에 재인증 모달을 띄운다.

셸 위 모달 · 401 수신 · 배경 블러
세션이 만료되었습니다 ✕ 없음 5

비밀번호를 입력하면 작업을 이어서 할 수 있습니다.

authStore(메모리)에서 채운다 — 6
다른 계정으로 로그인 7
  1. 5닫기(✕)를 두지 않는다. 출구는 재인증 · 다른 계정 · (불가 시) 로그아웃 셋뿐이다. 닫을 수 있으면 만료된 화면을 계속 보게 된다.
  2. 6로그인 ID 를 바꿀 수 없다. ID 가 다르면 탭을 유지할 수 없다 — 열린 탭은 이전 사용자의 유효 권한으로 열린 화면이고 새 사용자가 그 권한을 갖는다는 보장이 없다. ID 를 고정하면 이 모달의 의미가 "같은 사람의 세션 복구" 로 좁혀지고 탭 유지가 정당해진다. 값은 authStore 에 남아 있다(만료가 비우지 않는다).
  3. 7"다른 계정으로" 는 정식 로그아웃이다 — 탭·캐시를 정리하고 로그인 화면으로 간다.
  4. 성공하면 모달만 닫는다. 그리고 새 menus·permissions 로 탭 정리를 한 번 돌린다 — 자리를 비운 사이 권한이 바뀌었을 수 있다.
  5. 401 을 받은 요청은 자동 재시도하지 않는다. 저장이었으면 재시도가 중복 실행이 되고, 중복 요청 방어(SYS-11)는 기본 꺼짐이다. 입력값이 남아 있으니 사용자가 다시 누르는 비용이 작다.
  6. 재인증이 불가능한 결과(잠김·비활성·기간 만료·권한 공집합)면 모달에서 사유를 보이고 정식 로그아웃으로 전환한다.
  7. 새로고침(F5) 후에는 이 모달이 뜨지 않는다. authStore 가 메모리라 ID 를 잃는데, 그 경우 유지할 탭도 없다 — 새로고침 시 탭을 복원하지 않기로 이미 정했으므로. 탭 스토어와 authStore 가 같은 메모리 수명을 가져 두 조건이 함께 움직인다. F5 후 401 은 로그인 화면이다.
  8. ID 를 localStorage 에 넣지 않는다. 모달을 채우려고 옮기면 화면 흐름이 경계한 "로그아웃 뒤에도 남는 이전 사용자 정보" 가 된다. 메모리는 탭을 닫으면 사라지므로 그 경계 안에 있다.

3. 배경 블러 — 가리는 것과 못 가리는 것

대상블러로비고
그리드 데이터 · 폼 입력값가려진다화면 흐름이 경계한 잔존 노출
탭 제목(메뉴명)남는다"무슨 업무를 하는지" 는 보인다
사이더 메뉴 트리가려진다블러 범위에 포함
  1. 완전한 방어는 OS 잠금의 몫이다. 백오피스가 그것을 대신할 수 없다. 그 이상이 필요한 배포는 유휴 타임아웃을 짧게 잡는 것이 답이다.

4. 테스트 케이스 — 주석의 주장을 전부 덮는다

주석은 "왜 이렇게 그렸는가" 를 말하고, 여기는 "그것이 지켜졌는가" 를 묻는다. 근거가 빈 케이스는 지어낸 것이다 — 문서 절이나 이 파일의 주석 번호를 가리킨다. 되면 안 되는 것도 함께 넣는다.

5. 이 목업으로 확인할 것

  • 예고를 몇 분 전에 띄우는가 — 세션 30분 기준. 목업은 2분 전을 가정했다
  • 여러 브라우저 탭에서 동시에 뜨는 문제 — 화면 흐름이 다중 탭을 다루므로 한 탭에서 연장하면 다른 탭의 모달도 닫혀야 한다. 탭 간 통신 수단(storage 이벤트 등) 필요
  • 미저장 변경이 있는 탭이 있을 때 만료 직전 경고를 더 강하게 할지
  • 재인증 모달의 브라우저 탭 간 동기화(§2) — 여러 브라우저 탭에 각각 뜬다. 한 곳에서 재인증하면 나머지가 닫혀야 한다. storage 이벤트 등 통신 수단 필요 (셸 표준 미결)
  • 블러 범위(§3) — 탭바까지 가릴지. 가리면 재인증 후 어디로 돌아가는지 알기 어렵고, 안 가리면 메뉴명이 노출된다
