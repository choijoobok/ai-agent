저장 버튼이 없다 — 즉시 반영한다 2
  1. 1언어만 서버다(SYS_USER.LOCALE_CD) — 메일·알림을 어느 언어로 보낼지 결정하는 것은 서버이고 localStorage 는 서버가 볼 수 없다. 바꾸면 메시지 번들을 그 언어로 교체하고 localStorage 도 함께 갱신한다 — 다음 로그인 화면이 그것으로 그려진다(화면 흐름의 1순위).
  2. 2저장 버튼을 두지 않는다. 나머지가 전부 localStorage 라 왕복이 없고, 테마·글꼴은 바꿔 보면서 고르는 것이라 저장 버튼이 오히려 방해다. 언어만 예외다 — 4.
  3. 4언어를 바꾸면 재로드한다. 번들을 새로 받아야 하고, 코드 라벨도 언어별이며, 이미 떠 있는 에러 메시지는 서버가 번역해 보낸 문자열이라 클라이언트가 다시 번역할 수 없다.
    순서는 ① 미저장 변경 확인 → ② 서버 저장 → ③ localStorage → ④ 재로드 다. 서버가 먼저인 이유는 저장이 실패했는데 localStorage 만 바뀌면 다음 로그인의 언어 판정이 어긋나기 때문이다.
    탭은 따로 닫지 않는다 — 새로고침 시 복원하지 않기로 이미 정했으므로 재로드가 탭 비우기를 함께 한다.
  4. 3그리드 폰트 크기는 기본 크기와 별개다 — 그리드는 한 화면에 행을 많이 넣어야 해서 본문보다 작게 쓰는 경우가 흔하다.
  5. UI 설정은 기기의 속성이다 — PC 마다 해상도·화면 비율이 달라 계정에 묶으면 다른 자리에서 로그인할 때마다 어긋난다.

3. 테스트 케이스 — 주석의 주장을 전부 덮는다

주석은 "왜 이렇게 그렸는가" 를 말하고, 여기는 "그것이 지켜졌는가" 를 묻는다. 근거가 빈 케이스는 지어낸 것이다 — 문서 절이나 이 파일의 주석 번호를 가리킨다. 되면 안 되는 것도 함께 넣는다.

4. 이 목업으로 확인할 것

  • 기본값 숫자 — 셸 표준 미결. 목업은 폰트 14 / 헤더 36 / 행 32 / 그리드 13 을 가정했다. 실측이 필요하다
  • "기본값으로" 버튼의 범위 — 그룹별인지 전체인지. 전체면 확인 모달이 필요하다
  • Primary Color 입력 방식 — 자유 입력인지 팔레트 선택인지. 자유 입력이면 명암비 검증이 필요하다(다크 모드에서 안 보이는 색이 나온다)
  • 언어 변경 시 재로드 안내를 어떻게 줄지(§1 4) — 확인 모달로 미리 알릴지, 미저장 변경이 없으면 조용히 재로드할지. 후자면 "갑자기 화면이 새로 떴다" 가 된다
  • 그리드 설정이 UX-06 그리드 컬럼 설정과 다른 것임을 화면에서 구분할지 — 여기는 높이·폰트(전역), UX-06 은 컬럼 순서·표시(화면별)다
