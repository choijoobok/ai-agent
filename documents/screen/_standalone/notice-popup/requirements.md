# 요건 정의서 — 공지 팝업

## 개요

- **무엇을 하는 화면인가**: 셸이 사용 가능해진 직후 **게시중 공지 1건**을 띄운다. 나머지가 있으면 *"N건 더 있음"* 으로 알리고 알림 모달의 공지 탭으로 보낸다.
- **프로세스상 위치**: (선행) 관리자가 `NOTICE_MGMT` 에서 공지를 게시한다 → **이 화면**(로그인 직후 자동) → (후행) 더 보려면 [알림 모달](../noti-inbox/requirements.md)의 공지 탭.
- **바꾸면 어디가 흔들리나**: *오늘 하루 보지 않기* 는 **`localStorage`** 라 기기를 바꾸면 다시 뜬다. **그것이 팝업의 목적에 맞다** — 취향이 아니라 **도달 보장 장치**다.

> **이 문서는 `docs/design/60-screen-auth.md` §9 에서 옮겼다**(2026-09-04 · 그 폴더는 폐지됐다).

> **문서 상태: 구현됨** — `features/notification/NoticePopupModal.tsx`.

## 5. 버튼 · 액션

| 버튼 | 무엇 |
|---|---|
| 닫기 | 이번만 닫는다 |
| 오늘 하루 보지 않기 | **다음 자정까지** — §6-2 |
| N건 더 있음 | 알림 모달의 **공지 탭**을 연다. **누르면 팝업이 닫힌다** |

> **누르면 팝업이 닫힌다.** 열어 둔 채 모달을 띄우면 목록을 다 보고 모달을 닫았을 때 **읽고 지나온 팝업이 다시 눈앞에 있다** — 그때 *오늘 하루 보지 않기* 체크도 함께 지켜진다.

---

## 6. 규칙 — 저장 · 실행

### 6-1. 표시 조건

| 항목 | 결론 |
|---|---|
| 여러 건 | **팝업은 1건**, 나머지는 알림 모달의 공지 탭. 그 탭이 이미 있으므로 **목록을 두 곳에 만들지 않는다** |
| 어느 건 | **목록 정렬의 첫 건** — 결정적이라 **매 로그인마다 달라지지 않는다** |
| *오늘 하루 보지 않기* | **`localStorage`** · **다음 자정까지** · **영구 숨김 없음** |
| 키 구조 | `notice.dismissed.{NOTICE_ID}` 에 만료 시각. **한 키에 목록을 담으면 다른 탭이 덮어쓴다** |
| 만료 키 청소 | **팝업이 뜰 때 지나간 것만** — 별도 청소 경로를 만들지 않는다 |

### 6-2. 서버에 두지 않는 이유

*안 보기* 는 **읽음의 약한 형태**이고, 읽음을 두지 않기로 해 놓고 안 보기만 서버에 두면 **같은 사실을 반쪽만 저장**하게 된다.

### 6-3. "N건 더 있음" 의 셈

**게시중 전건에서 하나를 뺀 수**다. 팝업 대상만 세지 않는 것은 링크가 여는 곳이 공지 탭이고 **그 탭은 게시중 전부를 보이기 때문**이다 — 2건이라고 해 놓고 5건이 있으면 **숫자가 거짓말**이 된다.

### 6-4. 셸 부팅을 막지 않는다

조회가 실패하면 **아무것도 열지 않고 끝난다.** 토스트조차 내지 않는 것은 **로그인할 때마다 뜨는 오류가 팝업보다 더 성가시기** 때문이며, 실패는 서버 로그에 남는다.

## 9. 테스트 케이스

> **요건이 지켜졌는지 묻는 표다.** 위의 절들이 *무엇을* 정했다면 여기는 *그것이 지켜졌는가* 다.
> **되면 안 되는 것**을 함께 담는다 — 그것이 빠지면 케이스가 그림 검사로 줄어든다.
>
> **목업(`mockup.html`)은 이 표와 위의 절들로부터 생성되는 파생물이다** — 케이스를 목업에서
> 고치지 않는다. 고칠 곳은 여기고, 고친 뒤 `/mockup` 이 목업을 다시 만든다.

### 케이스

| # | 조작 · 상황 | 기대 |
|---|---|---|
| `NP-01` | 로그인 직후 | **셸이 먼저 뜬다** — 팝업은 그 뒤다 |
| `NP-02` | 셸 부팅 중 공지 조회가 **실패** | **셸은 정상 동작**한다 — 차단하는 것은 메시지 번들뿐이다 **(되면 안 되는 것)** |
| `NP-03` | 공지 본문 영역 | **텍스트 그대로** 그린다 — `CONTENT_TYPE_CD` 가 `TEXT` 뿐이다. 리치 에디터는 **범위 밖** |
| `NP-04` | 알림 모달의 공지사항 탭과 대조 | **목록은 한 곳에만** 있어야 한다 — 팝업은 **도달 보장**, 목록은 그 탭 |
| `NP-05` | "오늘 하루 보지 않기" 체크 후 재로그인 | **다시 뜨지 않는다** — `localStorage` 에 **다음 자정까지** |
| `NP-06` | 체크하고 닫은 **다음 날** 로그인 | **다시 뜬다** — 영구 숨김은 없다 **(되면 안 되는 것)** |
| `NP-07` | 감춘 뒤 **다른 기기**로 로그인 | **뜬다** — 기기의 속성이며 그것이 도달 보장에 맞다 |
| `NP-08` | 게시중 공지가 **1건뿐**일 때 | **"N건 더 있음" 링크가 없다** — 0 을 적지 않는다 |
| `NP-09` | 팝업 기간은 지났고 게시 기간은 남은 공지 | **팝업은 안 뜨고 공지 탭에는 있다** — 축이 다르다 |
