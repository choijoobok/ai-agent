1. 기본 상태

/password/change
비밀번호를 변경해야 계속할 수 있습니다. 1
  • 9자 이상
  • 영대문자 · 영소문자 · 숫자 · 특수문자 중 3종 이상
  • 같은 문자 · 연속된 문자 4자 이상 금지
  • 아이디를 포함할 수 없습니다
  • 최근 3개 와 같은 비밀번호는 쓸 수 없습니다 — 서버에서 확인
로그아웃 4
  1. 1진입 사유에 따라 문구가 다르다 — §2. 사유를 알려주지 않으면 "왜 갑자기 비밀번호를 바꾸라는가" 가 문의로 온다.
  2. 2규칙과 숫자는 정책 API 에서 받는다. 화면 코드에 박지 않는다. 문구도 서버가 완성해 내려준 것이다.
  3. 3재사용 금지(회색)는 제출해야 알 수 있다. 프론트가 과거 해시를 가질 수 없으므로 원리상 서버 전용이다.
  4. 4로그아웃 외의 출구를 두지 않는다. 셸로 빠져나갈 링크가 있으면 이 화면을 통과하지 않고 들어가는 경로가 생긴다.

2. 진입 사유별 안내

진입 사유판정 근거안내 문구(초안)
관리자 초기화PWD_INIT_YN='Y' 발급된 임시 비밀번호입니다. 새 비밀번호를 설정하세요.
자기 재설정 직후PWD_INIT_YN='Y'〃
변경 주기 초과PWD_CHG_DTM + 90일 < now 비밀번호를 변경한 지 90일이 지났습니다.
  1. 둘 다 체인 #5 지만 조건이 독립이다 — PWD_INIT_YN 과 변경 주기는 서로를 대체하지 않는다.
  2. 로그인은 성공한 상태다. 비밀번호 만료는 실패 코드가 아니며 제한 세션으로 들어온다.

3. 테스트 케이스 — 주석의 주장을 전부 덮는다

주석은 "왜 이렇게 그렸는가" 를 말하고, 여기는 "그것이 지켜졌는가" 를 묻는다. 근거가 빈 케이스는 지어낸 것이다 — 문서 절이나 이 파일의 주석 번호를 가리킨다. 되면 안 되는 것도 함께 넣는다.

4. 이 목업으로 확인할 것

  • 변경 후 어디로 가는가 — 셸 직행인지, 로그인 화면으로 되돌려 재로그인시킬지. 세션을 재발급할 필요가 있는지와 함께 판단해야 한다
  • 현재 비밀번호 입력을 요구할지 — 관리자 초기화 경로에서는 사용자가 임시 비밀번호를 방금 입력해 들어왔다. 한 번 더 받는 것이 맞는지
  • 안내 배너를 SYS_MESSAGE 키로 둘 것 — 사유 3종에 각각 키가 필요하다
목업 규약 — 정적 HTML, 프레임워크 없음, 픽셀 충실도는 목표가 아니다. 결정은 requirements.md 가 갖고 이 파일은 확인용이다 — 여기에만 있고 요건서에 없는 정보는 유실된 것으로 친다.
