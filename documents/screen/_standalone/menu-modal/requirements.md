# 요건 정의서 — 메뉴 검색 · 즐겨찾기 모달

## 개요

- **무엇을 하는 화면인가**: 메뉴 이름으로 찾아 바로 열고, 자주 쓰는 메뉴를 즐겨찾기로 둔다. **같은 메뉴 선택 컴포넌트**를 쓴다.
- **프로세스상 위치**: (선행) `MENU_MGMT` 가 트리를 만들고 권한이 걸러진다 → **이 화면**(사용자가 고른다) → (후행) 선택이 `SYS_USER_MENU_STAT` 에 쌓여 사용 통계가 된다.
- **바꾸면 어디가 흔들리나**: 선택은 **경로 하나로 수렴한다** — 트리 클릭도, 검색도, 즐겨찾기도 같은 API 를 부르고 `entryType` 으로만 갈린다. 그래야 통계가 한 곳에서 나온다.

> **이 문서는 `docs/design/60-screen-auth.md` §10 에서 옮겼다**(2026-09-04 · 그 폴더는 폐지됐다).

> **문서 상태: 구현됨** — 셸의 헤더에서 연다.

---

## 0. 메타

| 항목 | 값 |
|---|---|
| 자리 | 헤더 → 모달 |
| 메뉴코드 | **없음** |
| 프론트 폴더 | `sources/frontend/src/layouts/ShellLayout/` — `MenuEntryModal.tsx`. 검색은 `shared/authz/menuSearch`, 즐겨찾기는 `shared/favorite/` 가 갖는다. **`features/menu/` 가 아니다** — 그쪽은 메뉴 트리 관리 화면(`/menu`)이다 |
| 화면 유형 | 모달 하나 — 검색과 즐겨찾기가 **같은 컴포넌트** |
| 처리 유형 | 조회 + 실행(선택) |
| 액션 권한 | **해당 없음** |

---

## 1. 화면 구성

- **검색 결과가 1건이면 바로 열고, 2건 이상이면 모달**을 띄운다.
- 즐겨찾기 목록은 **개수 상한이 없다** — 모달 목록이 스크롤될 뿐이다.

---

## 2. 조회조건

메뉴 이름 한 칸. **매칭은 번역된 메뉴명 포함 여부이며 클라이언트가 거른다** — 트리가 이미 내려와 있으므로 서버에 묻지 않는다.

---

## 3. 조회 — 테이블과 범위

### 3-1. 사용 테이블 · 결합

| 테이블 | 읽기 | 쓰기 |
|---|---|---|
| (메뉴 트리) | 셸이 이미 받아 둔 것 | — |
| `SYS_USER_FAVORITE` | 즐겨찾기 | 추가 · 삭제 |
| `SYS_USER_MENU_STAT` | — | 선택 기록 |

### 3-2. 고정 조건

**트리는 유효 권한으로 이미 걸러져 온다** — 이 화면이 권한을 다시 묻지 않는다.

---

## 4. 컬럼

메뉴명 · 경로(조상). 즐겨찾기는 별 표시.

---

## 5. 버튼 · 액션

| 조작 | API |
|---|---|
| 메뉴 선택 | `POST /api/common/menu/saveSelect { menuCd, entryType }` |
| 즐겨찾기 추가·삭제 | `/api/common/**` |

**선택이 경로 하나로 수렴한다** — 트리 클릭도 같은 API 다.

---

## 6. 규칙 — 저장 · 실행

### 6-1. `entryType` 이 진입 경로를 가른다

| 값 | 어디서 |
|---|---|
| `TREE` | 좌측 메뉴 트리 클릭 |
| `SEARCH` | 이 모달의 검색 |
| `FAVORITE` | 이 모달의 즐겨찾기 |

**같은 메뉴를 열어도 어디서 왔는지가 남는다** — 그것이 *검색이 실제로 쓰이나* 에 답한다.

### 6-2. 영향 테이블

`SYS_USER_MENU_STAT` 한 행. 즐겨찾기를 고치면 `SYS_USER_FAVORITE`.

---

## 7. API

`/api/common/**`. **인가 시드의 입력이 아니다.**

---

## 8. 시드 · 데이터 전제

메뉴 이름이 `menu.{MENU_CD}` 메시지 키로 있어야 검색이 걸린다 — 번역된 이름으로 찾기 때문이다.
