즐겨찾기 · 최근 · 자주 쓰는 메뉴는 탭으로 — §2
  1. 1결과 1건이면 모달을 띄우지 않고 바로 연다. 0건이면 빈 상태 (UX-11), 2건 이상이면 이 모달이다.
  2. 2매칭은 메뉴명 하나만 본다 — 경로는 표시용이다. 경로를 포함시키면 기준정보 를 쳤을 때 그 폴더 하위 전체가 걸려 결과가 폭발한다. 사용자 가 사용 이력 을 잡은 것은 메뉴명에 그 글자가 있기 때문이다.
  3. 3정규화는 공백 제거 + 소문자화, 판정은 포함이다. 초성 검색은 하지 않는다 — 한국어 전용 규칙이 되어 다국어 템플릿에 맞지 않는다.
  4. 4"일치 위치가 앞선 것 우선" 을 쓰지 않는다 — UX 로는 나을 수 있으나 결과 순서를 예측할 수 없게 된다.
  5. 서버 왕복이 없다 — 클라이언트 필터다. 프론트가 로그인 시 이미 유효 권한 메뉴 트리를 갖고 있고 번역도 프론트가 한다. 따라서 권한 필터를 검색 로직이 따로 걸지 않는다.
  6. 구조 노드는 결과에 넣지 않는다 — MENU_URL 이 없어 열 수 없다.

개수 상한 없음 — 많이 등록하면 목록이 스크롤될 뿐이다 6

즉시 저장 · 디바운스 · 마지막 상태만 전송
  1. 5두 화살표가 다른 것이다 — 행 우측 아이콘은 순서 변경, 키보드 위아래는 항목 선택 이동이다. 키보드로 순서를 바꾸려면 Alt + 위아래. 같은 목록 위에 함께 있어 구현할 때 헷갈리기 쉽다.
  2. 6모달은 크기를 조절할 수 있다므로 목록이 길어도 감당된다. 상한을 두면 "왜 더 못 넣나" 가 생긴다.
  3. 저장 버튼을 두지 않는다 — "순서 바꿨는데 안 됐다" 가 생긴다. 연타에 요청이 쏟아지지 않게 디바운스하고 마지막 상태만 보낸다.
  4. 즐겨찾기가 권한을 주지는 않는다. 권한을 잃으면 행은 남고 표시만 멈춘다 — 권한이 돌아오면 다시 나타난다.

3. 세 목록의 원본이 다르다

탭원본권한을 잃으면기능
즐겨찾기SYS_USER_FAVORITE행은 남고 표시만 멈춘다UX-03
최근 사용localStorage표시에서 걸러진다UX-03
자주 쓰는 메뉴SYS_USER_MENU_STAT표시에서 걸러진다UX-16
  1. 셋 다 같은 게이트를 지난다 — 유효 권한을 통과한 메뉴만 보여준다. 화면마다 다른 규칙을 쓰면 어디선가 권한 없는 메뉴가 새어 나온다.
  2. 자주 쓰는 메뉴는 월 버킷 · 이번 달 포함 3개월 창이고 메뉴 선택 행위만 센다 — 탭 클릭·버튼 클릭은 세지 않는다.

4. 선택은 API 하나로 수렴한다

POST /api/common/menu/select   { menuCd, entryType }

entryType = TREE · SEARCH · FAVORITE · RECENT · FREQUENT · DEEPLINK
            (+ NOTIFICATION NOTI-02 가 요청, 인가 데이터 모델 미반영)
  1. 메뉴 선택 UI 는 재사용하되 API 는 하나다. 이 모달의 어느 탭에서 골랐는지가 entryType 이고, 그것이 UX-16 집계와 이력의 입력이 된다.
  2. 구조 노드는 선택 대상이 아니다 — 어느 탭에도 나타나지 않는다.

5. 테스트 케이스 — 주석의 주장을 전부 덮는다

주석은 "왜 이렇게 그렸는가" 를 말하고, 여기는 "그것이 지켜졌는가" 를 묻는다. 근거가 빈 케이스는 지어낸 것이다 — 문서 절이나 이 파일의 주석 번호를 가리킨다. 되면 안 되는 것도 함께 넣는다.

6. 이 목업으로 확인할 것

  • 검색과 세 탭이 한 모달인지 두 모달인지 — 셸 표준이 "검색 결과 모드" 로 같은 모달의 모드 전환을 시사하지만, 목업에서는 §1 과 §2 를 따로 그렸다. 검색 입력이 탭 위에 상시 있는 형태가 자연스러운지 확인 필요
  • 모달을 여는 단축키 — 미결이다(Ctrl+W 충돌 건과 같은 표에서 함께 정한다). 커맨드 팔레트는 단축키가 없으면 값이 절반이다
  • 즐겨찾기 등록·해제를 어디서 하는가 — 이 모달에는 해제 버튼이 없다. 사이더 트리의 별 아이콘인지, 화면 안 버튼인지
  • "자주 쓰는 메뉴" 상위 N — 인가 데이터 모델이 릴리스 게이트로 미룬 실측 항목
목업 규약 — 정적 HTML, 프레임워크 없음, 픽셀 충실도는 목표가 아니다. 결정은 requirements.md 가 갖고 이 파일은 확인용이다 — 여기에만 있고 요건서에 없는 정보는 유실된 것으로 친다.
