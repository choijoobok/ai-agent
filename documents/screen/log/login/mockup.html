  1. 1결과 묶음 이 배지 셋과 같은 축이다(화면 2). 코드 열다섯을 하나씩 고르게 하면 "실패 전부" 를 고르는 데 열 번 클릭한다. 묶음을 고르면 서버가 코드 집합으로 번역한다 — 사용자 화면 설계의 계정 상태와 같은 파생 조건이며 72 프로토콜의 두 번째 사례다. 하나로 합치지 않는 이유: 한 콤보에 15+2 를 섞으면 목록에서 무엇이 묶음인지 알 수 없다.
  2. 2⤓ 와 ⚙ 만 남는다 — 메뉴·권한 화면 설계의 조회 전용 모양 그대로다. getDetail 도 없다 — nclob 컬럼이 없으므로 목록이 곧 전부다(사용자 화면 설계와 같은 이유).
  3. 3헤더가 사용자 아이디 다(2026-09-01 개정 — 이력 셋이 같은 이름을 쓴다). 값은 여전히 시도한 ID 이며 SYS_USER 에 없는 값이 들어온다 — 그 사실은 헤더 툴팁과 옆 칸의 배지가 말한다. 시도 ID 라는 이름으로 걱정을 표현하는 것보다 칸이 스스로 말하는 편이 낫다.
  4. 4이름이 비면 없는 계정 배지가 붙는다(화면 3). 글자와 색이 결과 칸의 FAIL_NO_USER 와 같은 공통코드 행에서 온다 — 한 행의 두 칸이 같은 사실을 두 글자로 말하면 사람이 둘을 다른 사실로 읽는다. 아이디가 없는 행에는 붙지 않는다: 입력조차 없었으면 없는 계정 이 아니라 계정을 말하지 않은 것이고, 왼쪽 칸이 이미 (입력 없음) 이라고 말한다.
  5. 5FAIL_NO_USER 와 FAIL_PWD 를 여기서는 구분해 보여준다. 로그 데이터 모델의 비대칭 — 이력의 목적은 진단이고 로그인 화면의 목적은 정보 노출 최소화다. 로그인 화면에서는 같은 메시지를 준다.
  6. 6없는 ID 로의 연속 시도가 침입 탐지의 근거다(FK 를 걸지 않은 이유). IP 를 복사해 그 IP 로 다시 조회하는 것이 이 화면의 두 번째 동선이다(화면 3).
  7. 7SESSION_EVICTED 가 회색인 것이 의도다. 사용자에게는 "갑자기 로그아웃됨" 이지만 시스템으로서는 정상 동작이다(보안 설계 동시 접속 제어). 빨강으로 두면 문의를 받은 운영자가 장애로 읽는다.

  1. 색은 tone 맵이 정한다. SYS_CODE 에 색을 열다섯 넣는 것이 오히려 어긋난다 — 색은 운영자가 훑는 방식이지 코드의 속성이 아니다. code 타입이어도 tone 이 있으면 그것이 이긴다.
  2. 색만 접고 값은 접지 않는다. 사용자 화면 설계가 계정 상태 넷을 파생 컬럼 하나로 접은 것과 같은 방향, 다른 수단이다 — 거기는 값을 접었고 여기는 색만 접는다. 값을 접으면 FAIL_NO_USER 와 FAIL_PWD 의 구분이 사라지는데 그 구분이 이 화면의 존재 이유다(화면 1 주석 4·5).
  3. SESSION_TIMEOUT 을 더했다(2026-08-28). 원래 13 중 세션 만료가 없었고 FAIL_EXPIRED 는 사용 기간 만료지 세션이 아니다. 401 을 에러 로그에 남기지 않기로 한 것과 한 결정이다(하트비트마다 쌓이면 에러 로그가 만료 로그가 된다) — "왜 로그아웃됐나" 에 답하는 화면인데 가장 흔한 답이 빠져 있었다. 기록 시점은 첫 401 — 만료 순간(스토어 이벤트)은 JDBC 와 Redis 에서 시각이 갈려 세션 스토어 선택형 결정 선택형과 충돌한다. 하트비트가 있어 실질적으로 만료 직후에 잡히고, 중복은 만료된 세션 쿠키 값으로 막는다. 브라우저를 닫고 영영 안 오면 기록이 없지만 그 경우엔 물어볼 사람도 없다.
  4. 화면 이름을 세션 이력 으로 바꾸지 않는다. MENU_CD 는 시드이고 메뉴명은 메시지 키다 — 바꾸면 로그인 실패를 찾는 사람이 메뉴에서 그것을 못 찾는다. 담는 것이 넓은 것보다 찾는 이름으로 있는 것이 낫다.

3. SYS_USER 를 leftJoin 한다 — 빈칸 대신 배지를 그린다 (2026-09-01 개정)

이 절은 뒤집혔다. 로그 화면 설계는 "조인하면 없는 ID 행에서 이름이 비고 그 빈칸이 조회가 덜 됐다 로 읽힌다" 를 이유로 이름을 붙이지 않았다. 그런데 문제는 조인이 아니라 빈칸이었으므로 답은 빈칸을 없애는 것이다 — 그 자리에 없는 계정 배지를 그린다.

배지의 글자와 색이 결과 칸에서 온다 — 같은 공통코드 행(code.LOGIN_RSLT_CD.FAIL_NO_USER)이라 한 행의 두 칸이 같은 말을 한다
무엇이 바뀌었나왜
leftJoin 으로 이름을 붙인다 join 이면 없는 계정의 시도가 통째로 사라진다 — 그것은 이 화면의 두 번째 용도(침입 시도 탐지)를 없애는 것이다. USER_ID 가 SYS_USER 의 PK 라 행이 늘지 않는다
빈칸에 없는 계정 배지 이 칸이 비는 것은 이 테이블에서 예외가 아니라 흔한 일이다. 글자와 색을 결과 컬럼의 FAIL_NO_USER 와 같은 공통코드 행에서 가져오므로, 관리 화면에서 이름을 고치면 두 칸이 함께 바뀐다
헤더가 사용자 아이디 · 사용자명 이다 이력 셋이 같은 이름을 쓴다. 값이 시도한 ID 라는 사실은 헤더 툴팁과 옆 칸의 배지가 말한다 — 시도 ID 라는 이름으로 걱정을 표현하는 것보다 칸이 스스로 말하는 편이 낫다
이름으로도 검색한다 옛 근거("퇴사자를 지우면 과거 이력이 검색되지 않는다")는 전제가 성립하지 않는다 — SYS_USER 는 물리 삭제를 하지 않는다(USER-02). 그래서 65 의 (삭제된 배치) 같은 고아가 여기에는 생기지 않는다
  1. 1배지가 붙는 조건은 아이디는 있는데 이름이 없다 이다. 지워진 계정의 예전 로그인도 같은 배지이며 그것이 맞다 — "지금 이 아이디로 들어올 계정이 없다" 가 두 경우에 다 참이다.
  2. 2아이디가 없는 행에는 배지를 붙이지 않는다. 입력조차 없었으면 없는 계정 이 아니라 계정을 말하지 않은 것이고, 왼쪽 칸이 이미 (입력 없음) 이라고 말한다. 그 판정이 ?? 가 아니라 || 인 것에 이유가 있다 — 오라클은 빈 문자열을 NULL 로 저장한다: ?? 로 두면 같은 행이 PostgreSQL 에서는 빈칸, 오라클에서는 (입력 없음) 이 된다.
  3. 3이름으로 물으면 이 행들이 빠진다 — 그 행에는 이름이 없기 때문이며 그것이 맞다: "홍길동의 로그인 실패" 를 묻는 사람이 찾는 것은 그 사람의 행이고, 없는 계정의 시도는 아이디나 결과 코드로 찾는다(§1 의 첫 동선).
  4. IP 를 완전 일치로 둔 것은 그대로다. 실패 행에서 IP 를 복사해 그 IP 로 다시 조회한다 — 대역 검색(LIKE '203.0.113.%')은 두지 않는다: 인덱스가 없어 기간으로만 좁혀지므로 완전 일치와 비용이 같은데 결과만 넓어진다. 사람 칸 둘이 그 예외다 — 부분 이름은 다른 답을 낸다.
  5. 읽는 테이블이 넷이 됐다 — SYS_LO_LOGIN · SYS_USER · SYS_CODE · SYS_CONFIG. SYS_USER 가 목록에 들어온 것이 이 개정이다.

  3. 기간 상한은 시스템 값 92 를 그대로 쓴다 — 화면이 덮지 않는다. 덮는 것은 사용 이력 하나(1 / 31)이며, 그 화면만 행마다 nclob 이 달려 있다.

6. 테스트 케이스 — 주석의 주장을 전부 덮는다

주석은 "왜 이렇게 그렸는가" 를 말하고, 여기는 "그것이 지켜졌는가" 를 묻는다. 근거가 빈 케이스는 지어낸 것이다. 되면 안 되는 것도 함께 넣는다.

7. 이 목업으로 확인할 것

이 화면이 규약에 되돌려 준 것
  • 로그 데이터 모델의 USER_AGENT 미결이 닫혔다 — 500 유지. 파싱하지 않고, 절단 표시를 값에 만들지 않는다.
  • LOGIN_RSLT_CD 가 15종이 됐다 — SESSION_TIMEOUT 신설. "왜 로그아웃됐나" 에 답하는 화면인데 가장 흔한 답이 없었다. 401 을 에러 로그에 남기지 않기로 한 것과 한 결정이며 함께 정했다.
  • 파생 조건의 두 번째 사례가 나왔다 — 결과 묶음. 사용자 화면 설계의 계정 상태에 이어, 72 프로토콜이 화면 값 ≠ SQL 컬럼을 어떻게 싣는지 정해야 한다.
아직 답이 없는 것
  • 보존 1년, 조회 창 92일 — 1년치를 봐야 하는 일이 실제로 있는지, 있으면 엑셀 네 번으로 버티는지.
  • 첫 401 로 잡는 것이 실제로 만료 직후인가 — 하트비트 주기에 달려 있다. 주기가 길면 만료 시각과 기록 시각이 벌어진다.
  • 침입 탐지를 화면이 어디까지 하나 — 지금은 실패만 + IP 로 사람이 읽는다. 연속 실패 집계·경고는 두지 않았다. 두면 임계값이 또 하나의 설정이 된다(AUTH-04 는 이미 있다).
