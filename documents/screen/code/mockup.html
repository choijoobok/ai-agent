오른쪽 세 컬럼은 선언되어 있지 않다 — ORDER_KIND 에 정의된 참조 코드 3개가 만든 것이고 헤더는 REF_NM 이다. 다른 그룹을 고르면 컬럼이 갈린다 3
  1. 1코드 조건이 그룹을 거른다. 마스터만 거르면 "이 코드값이 어느 그룹에 있더라" 에 답할 수 없다. 조건에 맞는 코드를 가진 그룹만 남고, 고르면 하단이 그 조건으로 미리 걸려 있다.
  2. 2코드명이 키 문자열로 보이면 아직 안 채운 것이다. 빈 문자열이나 — 를 보여주면 누락이 숨는다 — 원칙 P1 의 "실패가 시끄러운 쪽". 이 셀은 편집 가능하며 저장하면 SYS_MESSAGE 행이 생긴다(화면 2).
  3. 3참조값은 컬럼이고 정의는 모달이다. 빈 셀이 곧 안 채웠다 이므로 배지도 정렬 규칙도 두지 않는다. 정의를 만드는 버튼은 조회 왼쪽(ⓐ)이며 controls 다 — 서버를 부르지 않고 모달을 연다. 참조 건수 컬럼이 없어졌다 — 값이 보이므로 셀 수를 셀 이유가 없다.
  4. 4코드 0 건인 그룹만 지울 수 있다. 나머지 넷은 체크박스가 비활성이며 왜인지 말한다 — 화면 4.
  5. 일괄 저장이다(UX-14). 메뉴 트리와 다르다 — 순서 재작성도 락도 없어 그리드 표준의 즉시 저장 예외에 해당하지 않는다. 그래서 상태 컬럼과 저장 버튼이 있다.
  6. GRP_CD · DTL_CD 는 읽기 전용으로 보인다 — PK 라 신규 행에서만 열린다. 고치려면 지우고 다시 만든다.
  7. 정렬 컬럼의 뜻이 위아래가 다르다 — 그룹은 관리 화면 정렬, 코드는 콤보 정렬이다 . 같은 라벨이지만 보는 사람이 다르다.

2. 코드명은 여기서 입력한다 — 기준정보 데이터 모델의 미결을 닫는다

무엇어디로 가나
화면이 받는 것코드명 하나 — 지금 세션 언어의 값
서버가 쓰는 곳SYS_MESSAGE(code.ORDER_KIND.IN, ko, "입고")
DTL_NM저장 DTO 에 없다 — 서버가 PK 로 조립한다
다른 언어여기서 못 채운다 — message 화면으로 간다
  1. 기준정보 데이터 모델이 이미 이 방향을 적어 뒀다 — "등록 화면에서 명칭을 함께 받아 메시지 행까지 한 번에 쓰면 사용자가 느끼는 단계는 늘지 않는다". 그 문장의 화면 쪽 절반이 이것이다. 의도된 것은 누락이 드러나는 것이지 두 화면을 오가는 것이 아니다.
  2. 언어 컬럼을 여럿 두지 않는다. 지원 언어는 공통코드(LANG_CD)라 런타임에 늘어난다 — 컬럼으로 두면 언어를 켤 때마다 그리드가 옆으로 자라고 그리드 설정의 저장된 컬럼 목록이 어긋난다.
  3. 비우면 지운다. 코드명을 비운 채 저장하면 그 언어의 메시지 행을 삭제한다 — 빈 문자열을 넣으면 기준정보 데이터 모델의 폴백이 죽고 "이름이 없는 코드" 가 조용히 생긴다.

  2. 2미저장 편집이 있으면 ⓐ 버튼이 비활성이다. 정의가 바뀌면 컬럼이 바뀌고 재조회가 편집을 버린다 — "저장하지 않은 편집이 있어 열 수 없습니다". 누를 수 없는 것이 먼저 보이는 편이 낫다(그리드 API 계약과 같은 방향)이며, controls 가 그리드와 같은 상태를 보기 때문에 가능하다.
  3. 3REF_CD 는 CODE_REF_KEY 화이트리스트에서 고른다 — 소스가 그 값을 문자열로 참조하기 때문이며 정의 테이블이 그 통제를 대신하지 않는다. <CodeSelect codeGrp="CODE_REF_KEY"> 다.
  4. 4다중 부모 플래그는 정의를 먼저 추가해야 한다 — 이전에는 행만 넣으면 됐다. 대가이며, 얻는 것은 쓰이는 플래그의 목록이 명시되는 것이다.
  5. 5USE_YN 이 없다 — 정의에도, 값에도 없다. 셀 하나는 값 하나이고 스위치를 따로 두면 컬럼 수가 두 배가 된다. 끄는 것은 값을 비우는 것이며 비우면 행을 지운다 — 코드명이 이미 같은 규칙이다(화면 2).
  6. 그리드 표준이 기각한 등록/수정 모달 과 다른 것이다. 그쪽은 그리드가 이미 하는 일을 모달로 다시 하는 것이고, 이것은 다른 테이블의 행 집합이다. 판별 기준은 "모달을 닫았을 때 같은 행이 바깥에도 있는가" 이며 여기서는 없다.
  7. 조회가 둘이다 — getRefDefList(정의)와 getList(코드 + refs 맵). 병렬로 부르고 둘 다 도착한 뒤에 그린다 — 컬럼 없이 행을 그리면 값이 갈 자리가 없다.
  8. 그리드 설정(③)과 UX-13 시그니처에서 동적 컬럼이 빠진다. 빼지 않으면 그룹을 클릭할 때마다 저장된 설정이 폐기되고, 사용자가 겪는 것은 "설정이 저장되지 않는다" 이며 원인을 짐작할 수 없다.

4. 삭제 — 게이트는 하나고 나머지 둘은 확인이다

지우려는 것무엇이 걸리나왜
코드 그룹게이트 — 하단이 0 건인가FK 가 DELETE 를 거부한다
코드확인 — "참조값 3건이 함께 삭제됩니다"참조값은 그 행의 파생이다
참조 코드 정의확인 — "입력된 참조값 12건이…"〃. 값 → 정의 순서로 지우면 거부되지 않는다
비활성 사유를 말한다 1
  • ▸ ORDER_KIND 삭제 — 코드 2건이 있어 지울 수 없습니다 (게이트)
  • ▸ SHIP_STATUS 삭제 — 가능(코드 0). 정의가 남아 있어도 함께 지운다 2
  • ▸ OUT 삭제 — 가능. "참조값 3건이 함께 삭제됩니다" 를 묻는다 3
  • ▸ 미저장 신규 행 — 항상 가능. 즉시 제거된다
회색 체크박스만 두면 버그로 읽힌다 — 메뉴·권한 화면 설계가 드롭 불가에서 이유를 낸 것과 같은 방향이다
  1. 1게이트와 확인을 가르는 기준은 DB 가 거부하는가 다. 자식이 다른 화면에서 관리되는 남의 데이터면 게이트이고, 그 행의 파생이면 서비스가 자식부터 지우므로 거부되지 않아 확인이다 — 메시지 키 동기화 결정이 메시지 키에서 같은 판단을 했다.
  2. 2정의는 그룹과 함께 지운다. 하단이 0 건이면 값도 0 건이므로 안전하다.
  3. 3코드 삭제에 게이트를 두지 않는 것이 이 설계의 결과다. 참조를 매트릭스로 보면 정의를 쓰는 그룹의 코드는 전부 참조 1건 이상이라, 게이트를 두면 아무것도 지울 수 없다. 셀은 남의 데이터가 아니라 그 행의 일부다.
  4. 그룹은 다중 선택 삭제가 안 된다 — 하단은 선택된 한 행에 대해서만 조회되므로 나머지 그룹의 자식 유무를 모른다. 코드는 된다 — 게이트가 없다.
  5. 동시성으로 뚫릴 수 있다. 조회 뒤에 다른 사람이 코드를 추가하면 그룹 DELETE 가 FK 로 거부된다 — 그리드 표준이 "저장 시점에 나는 실패를 조회 시점에 알리는 일" 이라고 한 그대로다.

5. SYS_YN — 화면은 잠그기만 한다

SYS_YN='Y' 인 행에서화면근거
삭제 체크박스없다 — 비활성이 아니라 아예 없다—
USE_YN 스위치잠긴다 — 비활성도 삭제와 같은 효과다〃
SYS_YN 컬럼 자체읽기 전용 — 켜지도 끄지도 못한다—
그룹명 · 코드명 · 설명 · 정렬열려 있다기준정보 데이터 모델이 허용한 그대로
참조값(동적 컬럼)열려 있다 — 운영 데이터다SYS_YN 이 지키는 것은 코드의 존재다
표시행에 시스템 배지—
  1. 컬럼 자체가 읽기 전용인 것이 핵심이다. 켤 수 있게 하면 관리자가 아무 코드나 잠글 수 있고, 끌 수 있게 하면 보호가 한 번의 클릭으로 사라진다. 기준정보 데이터 모델이 저장 서비스에서 거부한다고 한 것을 화면은 입력 수단을 없애는 것으로 갚는다(원칙 P1).
  2. 그룹 'N' · 코드 'Y' 조합을 화면이 만들 수 없다 — 둘 다 읽기 전용이기 때문이다. 시드로 들어오는 것만 남고 그것은 changelog 검증이 잡는다.
  3. 액션 4종은 여기 없다 — 이전 판은 이 절의 대표 예시였는데 잠근다는 것 자체가 데이터가 아니라는 자백이라 공통코드에서 뺐다. 지금 SYS_YN='Y' 인 것은 CODE_REF_KEY · LANG_CD · 마스킹 규칙 류다.

6. 엑셀 — 다운로드만 있다

무엇이 화면에근거
다운로드(②)있다 — 항목 둘(현재 페이지 · 전체). 마스터에만 둔다 1—
업로드없다 — 전용 탭의 패턴이고 실물은 SMPL-05 다 2§5
미리보기 API없다 — saveExcelPreview · saveExcelImport 를 두지 않는다 3〃 §2 · §4
업로드 양식 파일없다 — 전체 다운로드가 곧 양식이다 4〃 기각 대안
  1. 1하단에는 다운로드가 없다. 하단은 마스터의 선택에 딸린 목록이라 파일 하나로 뜻이 서지 않는다 — "어느 그룹의 코드인가" 가 파일에서 사라진다.
  2. 2이 화면이 업로드에 맞지 않는 이유는 취향이 아니다. 단계가 둘이라(그룹 → 코드) 평면 엑셀 한 장에 담으려면 그룹 속성이 행마다 반복된다. 업로드 탭은 단일 그리드 화면을 전제로 한다.
  3. 3업로드 탭은 업무 탭의 save 를 그대로 부른다. 전용 API 를 두면 같은 테이블에 저장 경로가 둘이 되는데 그리드 표준이 등록/수정 모달을 없앤 이유가 정확히 그것이다. 신규·변경·동일은 rowState C · U · 없음이고 (동일은 그리드 표준이 보내지 않는다) 오류는 편집·검증 규약의 검증 표시다 — 미리보기가 그리드 자체다. 기준정보 데이터 모델이 정한 규약이 폐기가 아니라 흡수됐다.
  4. 4importExcel 접두 문제가 문제째로 사라졌다. 메뉴 목록이 "거기서 처음 나온다" 고 예고했고 이 목업의 이전 판이 saveExcelImport 로 답했었다 — 업로드 API 가 없으면 접두를 고를 일이 없다. 규칙은 접두 액션 · 시드 생성 결정에 그대로 있다.

9. 이 목업으로 확인할 것

이 화면이 닫은 것
  • 기준정보 데이터 모델의 "언어별 명칭을 함께 입력받을지" — 받는다(§2). 기준정보 데이터 모델이 이미 "등록 화면에서 명칭을 함께 받아 … 단계는 늘지 않는다" 고 적어 뒀다.
  • 그리드 표준의 삭제 게이트가 처음 실물이 됐다(§4) — 디테일 경로다. 그리고 게이트와 확인을 가르는 기준이 나왔다 — DB 가 거부하는가. 건수 컬럼 경로는 이 화면에서 실물을 얻지 않는다(메뉴·권한 화면 설계가 그것이다).
  • 참조가 매트릭스라는 것이 화면 모양으로 드러났다(§3) — 정의는 모달, 값은 동적 컬럼이다. 정의 테이블(SYS_CODE_GRP_REF)이 생기면서 컬럼 목록이 데이터의 우연이 아니게 됐다.
  • 컬럼 계약이 신설됐다 — 컬럼 선언이 데이터에서 오는 경우다. header 가 메시지 키가 아닌 유일한 자리이며 근거는 기준정보 데이터 모델의 기존 예외다.
  • UX-13 시그니처 공식이 개정됐다 — 동적 컬럼 이 빠진다. 안전장치가 연발되는 오작동이 되는 것을 막은 것이다.
  • 메뉴 목록이 예고한 importExcel 접두 문제(§6) — 문제째로 사라졌다. 엑셀 업로드 전용 탭 결정이 업로드를 전용 탭으로 빼고 업무 탭의 save 를 부르게 했다. 예고가 취소된 것이 아니라 다르게 갚혔다.
  • 모달 안 그리드가 처음 나왔다(§3) — 그리드 표준이 기각한 등록/수정 모달 과 판별 기준이 다르다는 것을 못 박았다. controls 의 button 첫 실물도 여기다(§7).
아직 답이 없는 것
  • 참조 코드 정의 개수의 실질 상한 — 컬럼이 옆으로 자란다. DTL_CD·코드명 좌측 고정으로 버티지만 몇 개까지인지 정하지 않았다.
  • AG Grid 36.1 의 컬럼 교체 옵션 실물 — 교체 시 순서·너비 보존 옵션의 실제 이름과 동작. 폴백: applyColumnState 로 직접 복원한다.
  • 업로드 탭의 실물 — 이 화면에는 없고 SMPL-05 가 담는다. 프론트 파싱이 감당하는 행 수의 상한이 아직 없다 — 넘으면 그것은 배치다.
  • 저장 하나가 두 테이블을 쓴다(§7) — SYS_CODE 와 SYS_MESSAGE. 한쪽만 실패하면 어떻게 되는지는 트랜잭션 경계 문제이며 21 이 답할 자리다.
