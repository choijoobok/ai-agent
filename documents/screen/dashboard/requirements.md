# 요건 정의서 — 대시보드

## 개요

- **무엇을 하는 화면인가**: 로그인 직후 보이는 첫 화면. **지금은 위젯이 들어올 자리만 있다** — 인사말과 *내가 쓸 수 있는 것* 의 수 둘을 낸다.
- **프로세스상 위치**: (선행) 로그인 → **이 화면**(첫 착지) → (후행) 사용자가 메뉴를 고른다.
- **이 데이터를 누가 쓰나**: 없다. **이 화면은 아무것도 만들지 않는다.**
- **바꾸면 어디가 흔들리나**: **업무 데이터 위젯을 두면 위젯 단위 권한이 따라온다** — 인가의 단위는 `(메뉴, 액션)` 이고 위젯은 그 단위가 아니다.

> **비어 있는 것이 결함이 아니다.** 이 저장소는 *업무 화면* 이 아니라 **업무 화면을 만드는 바탕**이고, **대시보드의 내용은 고객사가 정한다.**

> **목업이 소스보다 나중에 그려진 유일한 화면이다**(2026-09-03). 원래 목업이 없었고, **그 사실이 곧 이 화면의 성격이다.**

> **이 문서는 구현된 소스에서 역으로 작성했다**(2026-09-03).

## 4. 컬럼 — **위젯별 표시 항목**

| 위젯 | 라벨 키 | 값 키 | 무엇을 세나 |
|---|---|---|---|
| 인사말 | — | `MSG.DASHBOARD_GREETING`(`{name}`) | 로그인한 사람의 이름 |
| 사용 가능 메뉴 | `MSG.DASHBOARD_MENU_COUNT` | `MSG.DASHBOARD_MENU_COUNT_VALUE`(`{count}`) | 로그인 응답의 **메뉴 목록 길이** |
| 보유 권한 | `MSG.DASHBOARD_PERMISSION_COUNT` | `MSG.DASHBOARD_PERMISSION_COUNT_VALUE`(`{count}`) | 로그인 응답의 **권한 목록 길이** |

- **셋 다 로그인할 때 이미 받은 값이다** — 다시 세지 않는다.
- **그래서 권한이 바뀌어도 다시 로그인해야 숫자가 바뀐다.**
- 카드는 좁은 화면에서 세로로 쌓인다.

### 6-4. 왜 지금은 슬롯인가 — **넷이 걸려 있다**

| # | 무엇이 | 왜 |
|---|---|---|
| ① | **위젯 단위 권한이 없다** | 인가의 단위는 `(메뉴, 액션)` 이고 **위젯은 그 단위가 아니다.** 업무 데이터를 얹는 순간 *이 카드를 누가 보는가* 가 **새 질문**이 된다 |
| ② | **차트 라이브러리가 없다** | 들이는 결정을 아직 하지 않았다 |
| ③ | **고정 탭이라 항상 살아 있다** | 폴링이나 무거운 그리드를 두면 **그 비용을 모든 사용자가 로그인 내내** 낸다 |
| ④ | **무엇을 놓을지가 미결이다** | 업무를 모르면 정할 수 없다 — **고객사가 정한다** |

- **그래서 지금은 로그인 응답에 이미 있는 값 둘만 센다.** 서버 호출이 없으므로 **이 화면의 API 는 0개**이며, 그것이 API-메뉴 매핑 표에 `DASHBOARD` 행이 없는 이유다.

## 9. 테스트 케이스

> **요건이 지켜졌는지 묻는 표다.** 위의 절들이 *무엇을* 정했다면 여기는 *그것이 지켜졌는가* 다.
> **되면 안 되는 것**을 함께 담는다 — 그것이 빠지면 케이스가 그림 검사로 줄어든다.
>
> **목업(`mockup.html`)은 이 표와 위의 절들로부터 생성되는 파생물이다** — 케이스를 목업에서
> 고치지 않는다. 고칠 곳은 여기고, 고친 뒤 `/mockup` 이 목업을 다시 만든다.
