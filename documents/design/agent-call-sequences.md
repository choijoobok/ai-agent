# 모델·업무 도구·임베딩 호출 시퀀스

아래 ‘읽는 순서’의 번호는 여러 메시지를 업무 단계로 묶은 설명 번호이며, 그림의 화살표 자동 번호와는 다릅니다. 조건에 맞는 분기만 실행하고, 병행 경로는 동시에 진행됩니다.

[전체 연결](agent-request-sequences.md)의 호출 상세다. 각 그림은 현재 실행 자격을 가진 agent의 처리다.
전송 전 권한·점유 검사와 호출 사이의 경합을 없다고 가정하지 않는다. 실제 외부 호출을 AI DB 트랜잭션으로 롤백할 수 없다.
기록기 처리의 저장·실패·중복 계량 방지는 [DES-005](agent-history-sequences.md), 실행 자격 상실·중단은 [DES-003](agent-lifecycle-sequences.md)을 따른다.

2026-10-14 정책 보완: 업무 자료의 모델 입력은 REQ-106의 사용자 요청·동의 범위를 호출 전에 검사한다. 직접 입력은 안내된 제출, 기존 결과는 결과 버전·대상·목적에 대한 동의를 기록한다. 분류·임베딩·재주입에도 같은 범위를 적용한다. 관련 카드 재확정 후 REQ-010 보완에서 지식 불필요 분기와 동의 없음/거부/변경·선행 감사 실패의 상세 분기를 그림과 번호 설명에 함께 추가한다. 현재 그림만으로 그 경로의 상세 설계 완료를 뜻하지 않는다.

### S2 읽는 순서

1. 모델을 호출하기 전에 agent는 현재 시도·회차·점유가 유효한지, 중단 요청이 있는지, 스텝·회차 한도를 넘지 않았는지 확인합니다.
2. 이번 단계의 목적과 역할에 맞는 모델·허용 작업을 선택합니다. 필요한 내용 리비전과 현재 접근 권한을 확인하고, 규칙·기술 템플릿·동적 입력에 이번 응답의 형식 안내까지 합쳐 프롬프트를 만듭니다.
3. 문맥 한도, 외부 요청·동의 범위 여부, 마스킹과 오염 방지 경계를 검사합니다. 이어서 이번 호출에 적용할 쿼터 재검사 설정을 읽습니다. 활성화돼 있으면 현재 한도와 저장된 사용량을 비교하고, 비활성화돼 있으면 검사 생략 사유를 기록합니다.
4. 쿼터나 호출 전 검사에서 막히거나 필수 기록에 실패하면 모델을 호출하지 않습니다. 허용되면 호출 식별자, 모델·설정, 계약·규칙 버전과 입력 근거를 기록한 뒤 공통 구현체가 공급사 형식으로 변환해 전송합니다.
5. 독립 제어 경로가 호출 대기 중 점유를 갱신하고 중단·변경을 확인합니다. 청크가 없어도 제어해야 합니다. 변경은 S6와 REQ-007.model_change_contract에 따라 같은 실행 변경·공급자 자동 후속·Hub 종료 후 재요청을 구분합니다. 자동 후속은 사전 통제가 가능한 경로만 사용하고 중복 새 요청을 보내지 않습니다. 수신 이벤트는 실제 응답 실행 경계로 정규화하며 최초 전송의 선행 기록에 연결하거나 자동 후속 시작이 확인된 때 새 스텝을 만듭니다. 접수·콘텐츠 블록·청크마다 스텝을 추가하지 않습니다.
6. 개별 응답 실행의 완료·거절·오류가 확인되면 연결 종료와 무관하게 수신 경로와 독립적으로 결과·실제 사용량을 기록하고 후속 검증으로 전달합니다. 취소로 계량을 받지 못하면 NFR-010에 따라 추정 가능분과 미상을 구분합니다. 계량 수신 여부와 관계없이 결과를 지금 처리에 반영할 자격이 있는지 다시 확인합니다. 늦은 응답이나 무효 회차의 결과는 기록만 남기고 업무 상태에는 반영하지 않습니다. 점유를 잃은 경로는 공용 실행 상태를 쓰지 않고 해당 호출의 로컬 정리·감사·계량만 수행합니다.
7. 유효한 응답은 타입·필수값·허용 작업을 검증하고 판정 근거를 기록합니다. 검증 결과에 따라 도구 실행, 사용자 확인, 한도 내 보완 호출 또는 실패로 분기합니다. 동일 실행 변경은 저장된 적용 사건과 현재 조건 버전도 대조합니다. 자동 후속이 진행/대기 중이면 같은 변경을 다시 요청하지 않습니다. 다만 대기 해소에 필요한 유효한 도구 결과·승인 결과는 기존 통제와 새 실행 허용 검사를 거쳐 공급자 계약대로 제출합니다. 이는 같은 변경의 중복 요청과 구분하며 대기 자체가 무효/미승인 도구 실행을 허용하지 않습니다. Hub의 별도 추가 요청이 필요하면 처음 검사부터 반복하고, 종료 조건이면 반복을 끝냅니다.

현재 권한은 매 접근 시 판정하고 내용 리비전 고정으로 생략하지 않는다. 허용된 도구·인자도 서버가 다시 검증한다.
보조 판정 모델 호출도 질의를 발생시킨 사용자 사용량에 포함한다. 모델 거절·시간 초과·잘못된 응답은 정상 결과가 아니다.
공급 경로 오류 때 다른 모델로 자동 전환하지 않는다. 안전한 호출의 재시도·보완 상한과 중단 전이는 NFR-020·022 및 REQ-009에 연결한다.
루프의 차단·종료 분기는 루프 탈출을 뜻한다. 다음 반복에서 임의로 재개하지 않는다.
@defer P3 프롬프트 조합·구조화 출력·실행 분기가 같은 소스 계약을 참조하는 방식과 CLI 지원 차이를 계약 시험으로 확정한다.

### S3 읽는 순서

1. agent는 모델이 제안한 작업이 현재 단계에서 허용되고, 지식 후보와 등록된 도구 계약에 속하는지 확인합니다. 모델이 요청했다는 이유만으로 실행하지 않습니다.
2. 입력값이 부족하거나 후보가 여러 개면 허용된 조회·모델 재호출·사용자 확인으로 값을 확보합니다. 사용자 입력·조회 결과·기본값·시스템 매핑 등 출처와 무관하게 실제 호출에 쓸 모든 파라미터의 최종 값을 확보하고 agent가 등록 입력 계약으로 검증합니다. 미정 값·자리표시자·승인 후 채울 값이 있으면 최종 승인을 요청하거나 실행하지 않습니다.
3. 모든 값이 준비되면 현재 권한·대상 신원·데이터 범위·점유를 검사합니다. SQL이면 구문·카탈로그·읽기 전용·필터를, 조회 API나 조회 도구이면 등록 계약을 확인합니다. 실행 액션은 최종 대상·순서·전체 파라미터 버전을 고정하고 원값을 공용 DB의 전용 임시 테이블에 암호화해 저장합니다. 저장 성공이 확인된 같은 버전의 실제 값을 승인 카드에 제시합니다. 사용자의 최종 승인 조작을 agent가 검증하며 LLM의 승인 해석은 근거가 아닙니다. 호출 시 같은 임시본을 읽어 복호화·승인값 대조를 통과해야 하며, 부재·오류를 새 조회나 클라이언트 값으로 보충하지 않습니다. 변경된 값은 새 버전으로 전체 확인·최종 승인받고 선행 결과 의존 액션도 값 확보 뒤 개별 승인합니다(REQ-005·026, ADR-025).
4. 검증이나 승인이 부족하면 사유를 기록하고 추가 확인 경로로 갑니다. 통과하면 호출 근거를 기록하고 전송 직전에 점유·회차·중단·승인을 다시 확인합니다. 업무를 변경하는 액션일 때는 전송 방어 기록도 먼저 저장하며, 저장에 실패하면 호출하지 않습니다.
5. 등록 실행기가 검증된 입력으로 업무 DB나 API를 호출합니다. 조회 취소 수단은 해당 호출에 묶어 등록/해제하며, 동기 응답 대기 중에도 S6의 실행 서버 제어 경로가 취소를 요청할 수 있습니다. 이미 전송한 실행은 취소 불가를 안내하고 원 응답 또는 기존 타임아웃을 확인합니다. 반환된 결과·취소 근거·오류·타임아웃·응답 불명과 소요 시간을 별도 이력으로 남기고, 현재 실행 자격과 중단 반영을 다시 확인합니다.
6. 중단이 반영됐으면 새 업무 후속 처리를 시작하지 않고 S6의 호출별 결과 보고·필수 확인/정리로 연결합니다. 중단되지 않은 성공한 유효 결과는 현재 권한과 마스킹을 적용해 가공·저장합니다. 모델에 다시 보낼 필요가 있으면 외부 요청·동의 범위를 별도로 검사하고, 적용한 API/도구 공통 결과 가이드·지식 매핑별 설명·당시 버전을 결과와 연결합니다. 모델의 안내·질문과 구조화된 후속 작업 제안은 REQ-009.result_dialogue를 따릅니다.
7. 재작성 가능한 SQL 오류만 원인과 재작성 상한을 확인해 정제된 오류 정보로 모델 호출에 되돌립니다. 부분 실패·결과 불명·무효 결과는 이 분기의 자동 재전송 대상으로 삼지 않고, 기존 확인·부분 처리·종결 규칙을 따릅니다.
8. 실행 원값은 호출과 기존 명세상 필요한 후속 처리·허용 자동 재시도가 끝나면 삭제합니다. 중단·만료·회차/버전 무효화 시에도 사용을 차단하고 삭제하며, 거절 후 재승인은 최초 기한 안에서만 원값을 유지합니다. 삭제 실패·복구 후의 차단·재처리는 REQ-005를 따릅니다. 감사 이력·로그·일반 체크포인트에는 원값을 복제하지 않습니다.
9. 접수 성공이면 완료로 안내하지 않고, 가이드에 따라 선택적 결과 확인을 물을 수 있습니다. 응답이 필요한 경우 DES-003의 기존 사용자대기에서 유효한 선택만 이어갑니다. 결과 조회 선택은 원 실행 재전송이나 새 상태 변경 승인이 아니며, 후속 호출은 현재 후보·권한·계약·입력을 다시 검사하고 상태 변경이면 전체 값의 별도 승인을 받습니다. 장애의 필수 결과 확인은 NFR-022에 따라 질문 전에 우선합니다. 처리 중이면 권장 시간 뒤 사용자가 별도로 확인하도록 안내하고 자동 폴링하지 않습니다. 종결 뒤 요청은 새 턴으로 처리하며 과거 결과 불명을 소급 변경하지 않습니다. 결과 불명 실행의 사용자 확인 후 후속 실행은 REQ-105.manual_reexecution에 따라 최신 실행의 확인 내용과 새 승인을 받습니다. 후속 실행도 불명이면 그 시도에 대한 새 확인·새 승인으로 같은 절차를 거치며 자동 반복하지 않습니다. 새 턴/승인만으로 대상 시스템의 멱등성 키를 바꾸지 않고 REQ-105.idempotency_contract를 적용합니다.

SQL 재작성은 파싱·카탈로그 오류와 DBMS가 확인한 구문 오류에 한정한다. 연결·권한·타임아웃·알 수 없는 오류는 자동 재작성하지 않는다.
타임아웃은 업무 시스템의 미실행 증거가 아니다. 전송/시도한 상태 변경 실행은 자동·무확인 재전송하지 않고 결과 확인 또는 대상 시스템 수동 확인으로 연결한다. 원인인 응답 시간 초과와 업무 결과 확인 불가를 분리한다. 사용자 확인 후 새 승인으로 허용되는 후속 실행과 자동 재시도 차단을 구분해 안내한다(REQ-007·105, NFR-022).
복합 작업 최종 실패 시 독립 작업도 새로 시작하지 않는다. 수행·실패·미수행·불명을 표시하고 계속 여부와 재승인을 기존 규칙으로 처리한다(REQ-038).
최종 전달·도구 결과 재주입은 [DES-005](agent-history-sequences.md)의 감사 완료와 현재 권한·전송 통제를 거친다.

근거: ARCH-060, IF-004, NFR-015·021, REQ-303·305·306. 태그 검색은 항상 수행하며 벡터 검색 단독 구성은 없다.

```mermaid
sequenceDiagram
    autonumber
    participant G as agent 또는 admin
    participant D as 공용 AI DB
    participant H as 기록기
    participant M as 공통 임베딩 구현체
    participant E as 임베딩 모델
    G->>D: 임베딩 설정·모델/벡터 세대·내용 리비전·현재 권한 조회
    opt agent의 질의 검색
        G->>D: 승인·활성 지식의 태그 검색
    end
    alt 임베딩 비활성
        G->>G: 외부 임베딩 호출 없음, 질의는 태그 검색 결과 사용
    else 임베딩 사용
        G->>G: 외부 요청·동의 범위·입력 최소화·모델/벡터 설정 호환 확인
        G->>H: 호출 ID·입력 근거·귀속을 전송 전에 기록
        Note over G,H: 질의 키워드=해당 사용자, 지식 본문/재임베딩=시스템 비용
        H-->>G: 기록 완료
        G->>M: 동일 모델·동일 설정의 임베딩 요청
        M->>E: 허용 입력 전송
        E-->>M: 벡터·계량 또는 오류
        M-->>G: 정규화 결과
        G->>H: 성공/실패·사용량·계량 출처 기록
        H-->>G: 기록 완료
        alt agent 호출 성공
            G->>D: 권한 있는 활성 세대 벡터 검색·태그 결과와 병합
        else agent 호출 실패
            G->>G: NFR-021에 따라 태그 검색 결과로 계속
        else admin 지식 임베딩 성공
            G->>D: 대상 세트/리비전의 벡터 저장·기술 검토로 전달
            Note over G,D: 임베딩 성공만으로 후보 지식을 활성화하지 않음
        else admin 지식 임베딩 실패
            G->>G: 실패 기록·반영 세트 검토 미완료 처리
        end
    end
```

### S4 읽는 순서

1. 호출 주체가 임베딩 설정, 모델과 벡터의 세대, 내용 리비전, 현재 권한을 확인합니다. agent의 질의 검색이라면 승인·활성 지식에 대한 태그 검색을 먼저 수행합니다.
2. 임베딩을 사용하지 않는 설정이면 외부 임베딩을 호출하지 않습니다. 질의 검색은 태그 검색 결과로 진행합니다.
3. 임베딩을 사용하면 외부 전송이 허용된 최소 입력인지와 모델·벡터 설정이 맞는지 확인합니다. 호출 전에 입력 근거와 비용 귀속을 기록합니다. 질의 키워드 임베딩은 해당 사용자 사용량이고, 지식 본문·재임베딩은 시스템 비용입니다.
4. 공통 임베딩 구현체가 모델을 호출하고 벡터·계량 또는 오류를 받습니다. 성공 여부와 관계없이 호출 결과·사용량·계량 출처를 기록합니다.
5. agent의 질의 임베딩이 성공하면 권한 있는 활성 지식의 벡터 검색 결과와 태그 검색 결과를 합칩니다. 임베딩 호출 실패라면 기존 규칙에 따라 태그 검색 결과로 계속합니다. 필수 기록 실패는 정상적인 검색 폴백으로 감추지 않고 기록 실패 경로를 따릅니다.
6. admin의 지식 임베딩이 성공하면 해당 세트·리비전에 벡터를 저장하고 기술 검토로 넘깁니다. 성공만으로 지식을 활성화하지 않으며, 실패하면 반영 세트의 검토가 미완료인 것으로 처리합니다.
