# 사용자 메뉴얼 — 산출물 생성

`CLAUDE.md` §6.2. **`manual.md` 가 원본이고 나머지는 전부 파생이다.**

## 0. 먼저 — 목업이 있어야 한다

화면 그림은 **목업에서 나온다**(아래 *화면 그림*). 목업도 파생물이라 형상 관리에 없으므로
(`CLAUDE.md` §4-5) **새로 클론한 트리에는 없다.** 없으면 그림 없는 메뉴얼이 나간다.

```bash
node .claude/skills/mockup/scaffold.mjs --check
```

그림 키가 어긋난 화면이 나오면 **그 화면의 목업을 `/mockup` 으로 먼저 만든다.**
캡처(`screen.png`)만으로 갈 때는 `--shots=png` 를 쓴다 — 그때는 목업이 필요 없지만,
캡처가 없는 화면은 그림 없이 나간다.

```bash
node .claude/skills/manual-site/build.mjs
```

## 무엇이 나오나

**① 저장소 파생물** — 화면 문서의 파생물이다(§6.1). 소스 옆에서 본다.

```
documents/screen/{페이지경로}/manual.html
documents/screen/index.html                 좌측 메뉴 트리 + 본문
```

**② 제출 폴더** — **이 폴더를 통째로 복사해 고객사에 전달한다.**

```
build/manual/
    index.html        메뉴 트리를 보며 읽는 페이지 — 여기서 시작
    screens/          화면 하나짜리 메뉴얼 (한 화면만 보낼 때)
    print/            인쇄용 — 열고 Ctrl+P → PDF 로 저장
    slides/           요약 슬라이드(.pptx) — --pptx 일 때만
    assets/           화면 이미지 — 캡처가 있을 때만
    README.txt        받는 사람이 읽는 안내
```

형상 관리에 담지 않는다(`build/` 는 `.gitignore`). **전달할 때 만든다.**

## 옵션

| 옵션 | 값 | 기본 | 무엇 |
|---|---|---|---|
| `--split=` | `module` · `menu` · `all` | `module` | PDF·PPT 를 무엇으로 가르나 |
| `--shots=` | `auto` · `mockup` · `png` · `none` | `auto` | 화면 그림의 출처 |
| `--pptx` | — | 끔 | 슬라이드도 만든다 |
| `--out=` | 경로 | `build/manual` | 제출 폴더 위치 |
| `--no-dist` | — | 끔 | 제출 폴더 없이 저장소 파생물만 |

**분할 단위** — `module` 은 최상위 메뉴(시스템 · 샘플 · 대시보드), `menu` 는 그 바로 아래
(사용자 · 메뉴 관리 · 이력·로그 …), `all` 은 한 파일에 전부.

```bash
node .claude/skills/manual-site/build.mjs --split=menu --pptx
```

## 화면 그림

**기본은 목업이다.** 화면의 모습은 이미 목업이 갖고 있고, 메뉴얼용으로 따로 그리면 같은 화면의
그림이 두 벌이 된다(§4-3 과 같은 이유). **목업이 없으면 먼저 `/mockup` 으로 만든다**(위 §0) —
목업은 요건서의 파생물이라 형상 관리에 없다.

**그림은 여러 장이고 자리는 메뉴얼이 정한다.** 탭이 다섯이면 탭마다 모습이 다르므로 한 장으로는
*이 탭이 어떻게 생겼나* 에 답할 수 없다. 두 쪽이 키로 짝을 맺는다:

| 어디 | 무엇을 적나 |
|---|---|
| `mockup.html` | `<div class="screen …" id="tab-session" data-manual="tab-session">` — 이 블록이 그림이다 |
| `manual.md` | `[활성 세션 탭](mockup.html#tab-session)` — 줄 하나가 그 자리다 |

- **키를 하나라도 달면 키 없는 블록은 그림이 아니다.** 상태별 화면(빈 · 편집 · 검증 실패)이 메뉴얼에
  섞이지 않게 하는 규칙이며, 그래서 *목업에서 몇 번째인가* 라는 순서에 매이지 않는다.
- **키가 하나도 없는 목업**에서는 첫 화면이 대표 그림(`main`)이 되어 첫 구분선 앞에 들어간다 —
  그림 자리를 아직 안 적은 메뉴얼이 그림 없이 나가지 않게 하는 되돌림이다.
- **짝이 어긋나면 보고한다** — 부르는데 없는 그림, 있는데 아무도 안 부르는 그림 둘 다.

**캡처가 있으면 캡처가 이긴다.** `screen.png` 는 대표 그림, `screen-{키}.png` 는 그 키의 그림이다
(`documents/screen/{페이지경로}/` 안). 넣는 방법은 둘이고 **결과는 같다**:

- 손으로 캡처해 그 경로에 저장한다.
- 아래 캡처 스크립트를 돌린다(**옵션 · 의존성이 붙는다**).

```bash
npm i -D playwright && npx playwright install chromium      # 한 번만
node .claude/skills/manual-site/capture.mjs --id=<계정> --pw=<비밀번호>
node .claude/skills/manual-site/build.mjs --pptx            # 이제 캡처를 쓴다
```

**`capture.mjs` 는 대표 그림만 채운다** — 화면에 들어가 한 장을 찍는다. 탭별 캡처는 탭을 눌러 가며
찍어야 하므로 아직 없다. 탭 그림은 목업이거나, 손으로 넣은 `screen-{키}.png` 다.

로컬 앱이 떠 있어야 하고(`--base=http://localhost:3000`), 계정과 데이터가 있어야 한다.
**그 전제가 없는 환경에서도 메뉴얼은 나와야 하므로 캡처는 기본이 아니다** — 없으면 목업 그림이다.
계정은 인자나 `MANUAL_CAPTURE_ID` · `MANUAL_CAPTURE_PW` 로만 받는다. **소스에 적지 않는다.**

## 열람 페이지 — 트리와 테마

**좌측 트리는 접힌다.** 그룹 이름을 누르면 그 가지가 접히고, 왼쪽 위 `모두 접기` 로 한 번에 여닫는다.
메뉴얼은 한 번에 다 읽는 문서가 아니라 **필요할 때 그 절만 여는** 문서이므로 접은 상태를 기억한다.

- **고른 화면의 조상은 강제로 편다.** 접힌 가지 안의 메뉴를 주소(`#키`)로 열었을 때 본문만 바뀌고
  트리에 아무 표시도 없으면 *내가 어디를 보고 있나* 를 잃는다.
- 접은 상태·테마는 **그 브라우저에** 기억된다. 저장소를 막아 둔 환경에서는 기억되지 않고 매번 기본으로
  시작한다 — 기능이 죽지는 않는다.

### 라이트 · 다크

**열람 페이지(`index.html`) 왼쪽 위에서 고른다** — 라이트 · 다크 · **시스템**(기본).
고른 값은 그 브라우저에 기억된다. 화면별 메뉴얼(`screens/`)에는 고르개가 없고 시스템 설정을 따른다.

- **목업에서 오려 온 그림도 함께 바뀐다.** 목업은 자기 파일에서 혼자 살 때를 기준으로 쓰였으므로,
  생성기가 그 다크 규칙을 토글이 이길 수 있는 형태로 다시 편다(`themeAware`).
- **인쇄는 늘 흰 종이다.** 다크로 보던 사람이 그대로 인쇄하면 검은 바탕이 통째로 찍힌다 —
  잉크의 문제이기 전에 읽을 수 없는 문서가 된다.

## PDF · PPT

**PDF 는 브라우저가 만든다.** `print/` 의 파일을 열고 `Ctrl+P` → *PDF 로 저장*.
헤드리스 브라우저를 넣지 않기로 한 결과이며(무의존 · 폐쇄망 — §1), 대신 **페이지가 나뉘는 자리를
인쇄 CSS 가 정한다**: 표가 경계에서 잘리지 않고, 제목만 남고 본문이 넘어가지 않으며, 화면 그림이
쪼개지지 않는다. 인쇄에서 빠지는 것은 `.noprint`(좌측 트리 · 생성물 표시)다.

**PPT 는 화면이 먼저다.** 그림 하나당 슬라이드 하나가 앞에 서고(대표 화면 · 탭마다 하나),
그 뒤에 절별 요약이 온다. 발표에서 첫 물음이 *어느 화면인가* 인데 글 몇 줄로는 답이 안 된다.

**화면은 파워포인트 도형으로 다시 그린다.** PPT 는 HTML 을 담지 못하고 — 이미지가 아니면 못 들어간다 —
브라우저 없이 HTML 을 이미지로 굽는 방법이 없다. 그래서 목업에서 **구조만** 뽑아 옮긴다:

| 목업 | 슬라이드 |
|---|---|
| `.bar` 주소줄 | 회색 띠 |
| `.sf` 조회조건 | 칸 이름만 한 줄로 |
| `.tabs` 탭바 | 탭 상자들 — 활성 탭만 색이 다르다 |
| `.tb` 툴바 | 왼쪽 제목 · 오른쪽 단추(최대 5개, 마지막이 주 단추) |
| `.grid` 그리드 | **파워포인트의 진짜 표** — 머리 1줄 + 최대 5줄 · 최대 7칸 |

- **순서를 지어내지 않는다.** 목업에 나온 순서 그대로 쌓는다 — 종류별로 모으면 마스터-디테일에서
  아래쪽 탭이 위쪽 그리드 앞으로 올라가, 배치를 보이는 그림이 배치를 틀리게 말한다.
- **표는 이미지가 아니라 표다.** 열어서 고칠 수 있고 글자를 고를 수 있다.
- **픽셀이 같지는 않다.** 목업도 픽셀 충실도를 목표로 하지 않는다 — 같은 것은 *무엇이 어디 있는가* 다.
- **캡처 PNG 가 있으면 그쪽이 이긴다.** 실물이 있는데 다시 그릴 이유가 없다.

**절별 요약은 글이다.** 표와 절차를 슬라이드에 그대로 담지 않는다 — 넣으면 글자가 6pt 가 되고 아무도
못 읽는다. **자세한 것은 PDF 가 갖는다.**
`.pptx` 는 XML 을 담은 ZIP 이라 라이브러리 없이 쓴다.

> **PPTX 는 PowerPoint 로 열어 확인한다.** 생성기가 검사할 수 있는 것은 ZIP 이 풀리는가와
> XML·관계가 온전한가까지다. 규격을 지켰다는 것이 *그 프로그램이 연다* 와 같은 말은 아니다.

## 언제 돌리나

| 시점 | 왜 |
|---|---|
| `manual.md` 를 고친 뒤 | 나머지는 전부 파생이다. 안 돌리면 두 파일이 다른 말을 한다 |
| 요건서를 고쳐 `/mockup` 을 다시 돌린 뒤 | 메뉴얼의 화면 그림이 목업에서 온다 |
| `menu-tree.yaml` → `generateMenuSeed` 뒤 | 트리·이름·순서가 바뀌었다 |
| 메뉴 이름 메시지(`menu.*`)를 고친 뒤 | 좌측 트리의 글자가 거기서 온다 |
| **고객사에 전달하기 전** | 제출 폴더를 새로 만든다 |

## 커밋

**정본만 커밋한다**(§9). `manual.html` · `index.html` · `build/manual/` 은 전부 파생이라
`.gitignore` 대상이다(CLAUDE.md §4-5) — 담을 것은 `manual.md` 하나다.

```bash
git commit -F - -- documents/screen/{경로}/manual.md <<'EOF'
docs: <현상> — <조치>
EOF
```

## 고치지 않는 것

- **`manual.html` · `index.html` · `build/manual/` 을 직접 고치지 않는다.** 다음 생성에서 사라진다.
  피드백은 `manual.md` 에, **화면 모양은 `requirements.md` 에** 반영하고 `/mockup` 을 다시 돌린다 —
  목업도 파생물이라 손으로 고치면 사라진다.
- 모양을 바꿔야 하면 `lib/page.mjs` 의 `DOC_STYLE` · `PRINT_STYLE` · `SITE_STYLE` 을 고친다.
- 마크다운 렌더러(`lib/markdown.mjs`)는 **메뉴얼이 쓰는 문법만** 다룬다. 새 문법이 필요해졌다면
  먼저 *그것이 운영자에게 필요한가* 를 묻는다 — 대개는 아니다.

```

    build.mjs        오케스트레이터 — 옵션과 산출물

    lib/menu.mjs     메뉴 트리 · 분할 단위 (실제 시드 데이터에서 읽는다)
    lib/markdown.mjs 마크다운 → HTML · 슬라이드 뼈대
    lib/figure.mjs   화면 그림 — 목업 오리기 · 캡처 PNG
    lib/page.mjs     모양 — 본문 · 인쇄 · 열람 스타일
    lib/slideshot.mjs 목업 화면 → 슬라이드가 그릴 뼈대
    lib/pptx.mjs     PPTX 작성기 (ZIP + OOXML, 무의존)
```
