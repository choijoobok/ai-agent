# 화면 문서 셋 — 시작 · 현행화 · 점검

규칙은 [`CLAUDE.md` §6](../../../CLAUDE.md) 가, **형식은 [`documents/screen/_TEMPLATE/`](../../../documents/screen/_TEMPLATE/) 의 머리 주석이** 갖는다.
**이 스킬은 형식을 재정의하지 않는다** — 순서와 대조 방법만 정한다.

인자로 화면을 받는다: 페이지 경로(`/user`) · 메뉴코드(`USER_MGMT`) · 기능 폴더(`user`) 아무거나.
인자가 없으면 **③ 전수 점검**을 돌린다.

---

## 0. 먼저 — 대상을 확정한다

```bash
node .claude/skills/menu-doc/screens.mjs
```

페이지 경로 · 메뉴코드 · 기능 폴더 · 문서 셋 유무를 한 표로 낸다. **여기 없는 화면은 없는 화면이다** —
`screenRegistry.ts` 와 `menu-tree.yaml` 이 소유하고, 문서가 그 목록을 늘리지 않는다.

대상이 목록에 없으면 **거기서 멈추고 사용자에게 묻는다.** 화면을 먼저 등록할 일인지, 경로를 잘못 들은 것인지는 판단이다.

---

## ① 새 화면 — 요건서를 먼저 쓴다

**승인 전 BE/FE/시드 착수 금지**(§5.3). 순서를 바꾸지 않는다.

1. `cp -r documents/screen/_TEMPLATE documents/screen/{페이지경로}` — 셋이 함께 생긴다.
2. **`requirements.md` 를 채운다.** 머리 주석의 작성 원칙을 그대로 따른다. 특히:
   - *무엇을* 적고 *어떻게* 는 적지 않는다. 컴포넌트·prop·훅 이름은 표준과 AI 의 몫이다.
   - **DB 테이블·컬럼명 · 공통코드 그룹 · 메시지 키 · 페이지 경로 · 메뉴코드는 명시**한다.
   - 이미 표준인 공통 동작(그리드 크롬·감사 넷·조회/저장 흐름·엑셀 두 갈래)은 **적지 않는다.**
   - 해당 없는 절은 **"없음" 이라고 쓴다.** 섹션을 지우지 않는다.
3. **모르는 것을 추정으로 메우지 않는다** — §9 미결에 남기고 사용자에게 묻는다(`CLAUDE.md` §2).
4. **사용자 검토를 받는다.** 승인 뒤에 구현으로 간다.
5. 구현과 **동시에** `mockup.html` · `manual.md` 를 만든다. 셋 중 하나만 있는 상태로 커밋하지 않는다.
   - `mockup.html` 은 `_TEMPLATE` 의 `<style>` 블록을 **그대로 복사**한다. 외부 CSS·JS 를 쓰지 않는다.
   - 테스트케이스에 **되면 안 되는 것**을 반드시 넣는다. 근거 칸이 빈 케이스는 지어낸 것이다.
   - `manual.html` 은 만들지 않는다 — `/manual-site` 가 생성한다.

**기존 화면의 문서를 처음 쓰는 경우**(소스가 이미 있다)는 순서가 반대다. 실물에서 역작성하고,
**그 사실을 요건서 머리에 적는다** — [`documents/screen/user/requirements.md`](../../../documents/screen/user/requirements.md) 가 그 형태의 실물이다.

## ② 현행화 — 소스가 바뀌었다

**일치하면 고치지 않는다.** 고칠 것이 있을 때만 고친다.

읽는 순서 — 화면 하나에 이만큼이면 대조가 된다:

| 무엇을 | 어디서 | 문서의 어디와 맞대나 |
|---|---|---|
| 컬럼 · 편집 가능 · 검증 | `features/{도메인}/pages/*.tsx` 의 `buildColumns` | req §4 |
| 조회조건 | 〃 `buildSearchFields` | req §2 |
| 버튼 · 액션 · 경고 | 〃 `api.actions` · `warn` | req §5 |
| API 경로 · 액션 | `features/{도메인}/api/endpoints.ts` | req §7 |
| DB 컬럼 · 널 허용 | `db/changelog/schema/*.yaml` | req §4 · §6-2 |
| 서버 검증 · 오류 | `domain/.../{도메인}/*ErrorCode.java` · `*Service.java` | req §6-1 |
| 조회 화이트리스트 · 기본 정렬 | `domain/.../{도메인}/*Spec.java` | req §2 · §3-2 |
| 화면 문구 | `db/changelog/data/*-init-message.csv` 의 `ko` 값 | manual §4 · mockup |

- **소스가 이긴다**(§2). 어긋나면 고칠 것은 문서다. 단, **어긋남을 보고 없이 지나가지 않는다.**
- 문구를 인용할 때는 **메시지 CSV 의 실제 값**을 쓴다. 화면에 뜨지 않는 말을 메뉴얼에 적으면 사용자가 검색해도 못 찾는다.
- `manual.md` 를 고쳤으면 **`/manual-site` 로 HTML 을 다시 만든다.** HTML 을 직접 고치면 다음 생성에서 사라진다.
- **소스와 문서를 같은 커밋에 담는다**(§5.3). 나누면 그 사이의 커밋이 거짓말을 한다.

## ③ 전수 점검 — 인자 없이 불렀을 때

`screens.mjs` 의 표를 그대로 보고하고, **문제부터** 쓴다(§4-10):

1. 문서 셋이 **없는** 화면 — 몇 개인지, 어느 것인지.
2. 셋 중 **일부만** 있는 화면 — 어느 파일이 빠졌는지.
3. `documents/screen/` 에는 있는데 **`screenRegistry.ts` 에는 없는** 폴더 — 경로가 바뀌었는데 폴더를 안 옮긴 것이다(§5.1). `git mv` 대상이다.

셋 다 없으면 그렇게 보고한다. **비어 있는 점검 결과를 채우려고 문서를 새로 만들지 않는다** — 무엇을 만들지는 사용자가 정한다.
