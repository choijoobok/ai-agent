# @feat 태그 면제 명단 — 백오피스 템플릿이 추적성 체계보다 먼저 들어왔다.
#
# 이 파일에 있는 경로는 T10 이 세지 않는다. **밖의 새 파일은 센다.**
# 그래서 규칙이 새 코드에서 살아 있고, 게이트가 영구히 빨갛지 않다.
#
# **줄어들기만 해야 한다.** 태그를 단 파일은 여기서 지운다. 새 파일을 여기에
# 더하는 것은 규칙을 끄는 것이며, 그럴 이유가 있으면 커밋 메시지에 적는다.
#
# **예외 하나 — 템플릿 안에서의 이동.** 면제의 기준은 날짜가 아니라 *템플릿의 코드인가* 다.
# 템플릿 파일을 쪼개 새 파일이 생기면 빚이 는 것이 아니라 옮겨 간 것이므로 명단도 따라간다.
#
# ── 여기 없어도 되는 것 ───────────────────────────────────────────────
#
# **기능 없는 층은 이 명단에 두지 않는다** — lib.mjs 의 FEATURELESS 가 영구 규칙으로 덮는다
# (core·support·bootstrap·shared·layouts·app·locales·진입점·빌드 설정). 2026-09-06 에 그
# 219줄을 걷어 냈다. 한 파일을 둘이 함께 덮으면 층 규칙을 고쳐도 아무 일도 일어나지 않는다.
#
# 그래서 이 명단의 뜻은 하나다 — **템플릿이 남긴 기능 코드의 빚.**
#
# 손으로 관리한다(생성기가 없다). 지울 때는 그 파일에 @feat 를 단 커밋에서 함께 지운다.
